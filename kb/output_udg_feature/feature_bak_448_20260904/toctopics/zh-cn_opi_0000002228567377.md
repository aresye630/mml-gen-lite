## 操作场景

仅当UDG网元需要部署媒体中继功能时，才需要安装RELAY服务。媒体中继相关功能介绍及业务配置请参考：5G Core 媒体中继解决方案。

**说明** 

仅部分VNFD模板支持RELAY服务。如需安装RELAY服务，请先联系华为技术支持确认使用的VNFD模板是否支持。

版本配套需满足以下版本才能支持RELAY服务功能：

| 部件名称         | 依赖版本                                     |
|:-------------|:-----------------------------------------|
| MAE-CN       | V100R024C10SPC220及以后版本                   |
| VNFM-Agent   | MAE-CN VNFM-Agent V100R025C10SPC120及以后版本 |
| FusionSphere | 24.1.0 + SPH35及以后版本                      |
| FusionStage  | 25.1.0及以后版本                              |
| UDG          | 20.15.2及以后版本                             |

安装RELAY服务场景：

**场景一**

**（静态上线）**

：UDG网元和RELAY服务

**同时实例化**

。实例化UDG

前

填写如下VNFD参数。

- 配置媒体中继主机所在机框与连接板所在机框互联参数：
  - NP卡场景：配置“Inter-Subrack NP Direct Connect Port”。
  - 标卡场景：配置“NPFabricTrunkCfg”。

- 配置RELAY服务的独立业务主机组：配置Cluster\_Relay\_Id，参考“网设工具 > NFV LLD文档 > **计算资源设计** > DC配置规划 > Host Aggregate名称”。

- 配置PBU\_P-N\_C4N1\_ARM虚机指定NUMA1部署：配置NUMA\_ID\_PBU\_P-N\_C4N1\_ARM值，指定为1。

- 配置VM：基于ARM虚拟机，PBU\_E-R\_ARM\_Num和PBU\_P-N\_C4N1\_ARM\_Num)。

- 配置Pod：“RELAY\_Instance\_Num”，“RELAYCTRL\_Instance\_Num”，“PBU\_P-N\_C4N1\_Instance\_Num”，“NPCTRL\_Instance\_Num”（仅ARM标卡模版需要配置该参数，NP卡模版不涉及该参数）。

配置NF：

- FunctionSet List参数需添加“RELAY”。例如：添加后为"UDG/RELAY"；当多个可选服务一起静态上线时，服务之间以“/”拼接，例如："UDG/RPT/RELAY"。

whether to initialize relay\_stack设置为true。

## 操作步骤

- 动态上线本服务前，必须根据客户的业务容量和设备现状进行严格的**扩容评估**。

  确保上线服务所需的I层资源、License资源、各类网络资源（如外联口网络）是充足的，如果不充足，则要**先扩容这些资源**，然后**再上线本服务**。

  由华为网设工程师进行网络设计，规划计算资源、存储资源、网络资源。

  将规划数据合入《NFV LLD文档》，作为后续操作的输入。

  - **计算资源**：承载虚拟机的主机（服务器）、主机组、虚拟机名称、虚拟机个数、容器名称、容器个数。
  - **存储资源**：承载本服务的磁盘空间。
  - **网络资源**：承载虚拟机的网络。承载容器的网络。承载业务的物理网口、业务网络。例如虚拟机的Base网络、容器Base网络、外联口网络、外联口Subport。

- 参考《UDG边缘侧扩缩容指导书（扩容机框）》，基于《NFV LLD文档》，完成机框扩容、媒体中继主机扩容，并完成VNF扩容前改造。

  参考《UDG边缘侧扩缩容指导书（扩容机框）》指导书中，章节“**1.1 使用场景** > **表1 针对媒体中继服务上线扩容机框、主机，请按顺序执行如下章节**”，执行对应章节操作。媒体中继主机扩容时，媒体中继主机的磁盘规划，参考《NFV LLD文档》。需要新创建卷组“fsp\_RelayVG”。示例如下：

  **须知** 

  VNF扩容前改造操作：

  - NP卡场景：需要参考“配置NP级联接口”章节，完成对应MML命令配置，使两个机框之间的级联接口生效。
  - 标卡场景：需要参考“配置NP与DC-GW互联口”章节，完成对应MML命令配置，使NP与DC-GW互联口生效。

    注意：VNF扩容前改造操作，如果配置不完整或不正确，会导致主机间通信异常，导致后续扩容虚机、Pod失败，请务必按照操作指导正确配置。

- 检查**软件包**，确保已经上传依赖的软件包。登录MAE-VNF LCM/U2020 VNF LCM，单击“包管理 > VNFD > 单击VNFD模板，查看VNFD模板详情 > 依赖的服务镜像”。

  - 若“UDG-Relay\_xx.x.x\_Docker\_ARM.zip、UDG-Relay\_xx.x.x\_PLUGIN\_RelayTrace\_ARM.zip。”（带补丁安装需要检查：UDG-Relay\_xx.x.x.x\_Docker\_ARM.zip、UDG-Relay\_xx.x.x.x\_Docker\_PATCH\_ARM.zip以及UDG-Trace\_xx.x.x.x\_PLUGIN\_RelayTrace\_ARM三个软件包）的状态为“已经存在”，说明已经上传软件包，则跳过4.上传服务镜像文件。，执行后续步骤。

- **上传服务镜像文件**。

  **说明** 

  如果执行LST ME命令查询的架构模式为X86，且LCM上提示ARM的包为必选时，可以忽略“是否必需上传”的提示，无需上传ARM后缀的依赖的服务镜像。

  1. 在“依赖的服务镜像”区域，单击“上传”，弹出“上传服务镜像”窗口。

  3. 单击“完成”。
  4. 上传完成后，“状态”均显示为“已经存在”。上传时长依赖于现场网络情况。

  上传镜像后需要同步镜像包到边缘站点。

  1. 在“VNFD”窗口中，**选择已导入的VNFD**。
  2. 单击图标。
  3. 在“边缘站点列表”区域中选择目标站点。
  4. 单击“确定”。

     **图1** 同步文件到边缘站点

- 更新VNFD媒体中继服务相关input参数：

  1. 选择“VNF生命周期管理>VNF总览”。在“VNF总览”页面单击待操作网元行“操作”列的  图标，手动更新VNFD。

     可通过关键字搜索待操作VNF的名称，筛选出待操作网元行；或直接查找到待操作网元行。
  2. 在更新VNFD界面，选择网元的VNFD以及VNFD计划。“VNFD”与“正在使用的VNFD”保持一致。“VNFD计划”与“正在使用的VNFD计划”保持一致。
  3. 在“公共参数”区域修改以下几个参数取值，再单击“确定”。
     - 配置RELAY服务的独立业务主机组：配置**Cluster\_Relay\_Id**，参考“NFV LLD文档 > **计算资源设计** > DC配置规划 > Host Aggregate名称”。
     - 配置PBU\_P-N\_C4N1\_ARM虚机指定NUMA1部署：配置**NUMA\_ID\_PBU\_P-N\_C4N1\_ARM**值，指定为1。
  4. 在弹出的“VNFD参数变更”提示框中，单击“确认”。
  5. 更新VNFD、扩容VM等操作，需要进行二次鉴权，请输入对应的用户名和密码后，点击“确认”继续操作。
  6. VNFD更新完成之后，可以通过如下方式查询VNFD是否更新成功：
     1. 在LCM的“VNF总览”页面选择执行过VNFD更新的VNF。
     2. 点击“事件记录”，可以看到VNFD是否更新成功的日志打印。存在多条VNFD更新记录时，请基于操作时间查看本次更新VNFD的日志打印。

- 参考《UDG边缘侧扩缩容指导书（扩容机框）》，完成扩容操作，扩容出计算资源、存储资源、网络资源。

  首次上线的服务仅需要参考扩容指导书，扩容出对应的VM即可，无需扩容pod。VM与pod的对应关系请参考表1 虚拟机与pod对应关系。

  - 上线媒体中继服务堆栈前，需要先完成npctrl-pod扩容（仅ARM标卡模版需要，NP卡模版不需要），再完成PBU\_P-N\_C4N1\_ARM虚机扩容、femu-c4n1-pod扩容。
  - 如在此步骤进行了PBU\_E-R\_ARM的扩容操作，则7-b-iii**不需要勾选**“进行虚拟机扩缩容”。
  - 如在此步骤不进行PBU\_E-R\_ARM扩容，请在7-b-iii选择进“进行虚拟机扩缩容”。

    **注意** 

    完成扩容femu-c4n1-pod后，请检查网元是否存在新增告警。如果存在新增告警，请务必按照对应告警指导解决后再进行后续操作。

    如果存在“ALM-100338 Fabric平面状态为Down”的告警，会导致后续上线媒体中继服务失败。请先检查VNF扩容前改造操作中，框间级联口是否正确配置。如果确认配置正确，请联系华为技术支持解决。
