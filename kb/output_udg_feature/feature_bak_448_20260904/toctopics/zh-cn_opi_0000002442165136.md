# 配置内容计费

- 操作场景
- 必备事项
- 任务示例

## 操作场景

用户访问园区业务时，智能分流SMF发起园区会话创建，数据流被分流到专网UPF上，需要在专网SMF和专网UPF上针对园区业务配置内容计费规则。

场景一：运营商对于园区业务未规划单独费率，则使用缺省费率（RG= 2000000002）。

场景二：运营商对于园区业务的费率有单独规划，按照运营商规划配置对应的费率；

**说明** 

此配置页面中的内容计费中的URR、PCCPOLICYGRPNM、RULE名称、UP名称等需要与专网SMF中的名称保持一致。

## 任务示例

任务描述

任务一：园区业务未规划单独费率，则使用现网普通2C用户的兜底计费规则（费率为2000000002），在园区DNN下默认绑定兜底计费规则。

任务二：园区业务规划有单独的费率，则根据园区规划，规划单独的费率，在UPF配置对应的计费策略，并且需要PCF针对该计费规则做下发。

脚本

场景一. 园区业务未规划单独费率，使用缺省费率。

1. 配置L34Filter，如果设备中已经按照运营商规范配置（执行LST FILTER:FILTERNAME="any";以及LST FILTER:FILTERNAME="any\_ipv6";命令查询），无需重复执行。

   ```
   ADD FILTER:FILTERNAME="any", L34PROTTYPE=STRING, L34PROTOCOL=ANY, MSSTARTPORT=0, MSENDPORT=65535, SVRSTARTPORT=0, SVRENDPORT=65535;
   ADD FILTERIPV6:FILTERNAME="any_ipv6", L34PROTOCOL=ANY, MSSTARTPORT=0, MSENDPORT=65535, SVRSTARTPORT=0, SVRENDPORT=65535, L34PROTTYPEV6=STRING;
   ```
2. 配置Flowfilter并与L34Filter绑定，如果设备中已经按照运营商规范配置（执行LST FLOWFILTER:FLOWFILTERNAME ="any\_f\_f";以及LST FLOWFILTER:FLOWFILTERNAME ="any\_ipv6\_f\_f";命令），无需重复执行。

   ```
   ADD FLOWFILTER:FLOWFILTERNAME="any_f_f", TETHERDETFLAG=NONE, FLOWFILTERTYPE=USERCONFIG;
   ADD FLTBINDFLOWF:FLOWFILTERNAME="any_f_f", FILTERNAME="any";
   ADD FLOWFILTER:FLOWFILTERNAME="any_ipv6_f_f", TETHERDETFLAG=NONE, FLOWFILTERTYPE=USERCONFIG;
   ADD FLTBINDFLOWF:FLOWFILTERNAME="any_ipv6_f_f", FILTERNAME="any_ipv6";
   ```
3. 配置计费策略组，如果设备中已经按照运营商规范配置，无需重复执行。

   ```
   ADD URR:URRNAME="common_01_cbb_online", URRID=2000000002, USAGERPTMODE=ONLINE, ONLMETERINGTYPE=VOLUME;
   ADD URR:URRNAME="common_01_cbb_offline", URRID=2000010002, USAGERPTMODE=OFFLINE, OFFMETERINGTYPE=VOLUME;
   ADD URRGROUP:URRGROUPNAME="common_01_ch_p", UPURRNAME1="common_01_cbb_offline", DOWNURRNAME1="common_01_cbb_offline", UPURRNAME2="common_01_cbb_online", DOWNURRNAME2="common_01_cbb_online";
   ```
4. 配置pcc策略组并绑定计费策略组，如果设备中已经按照运营商规范配置，无需重复执行。

   ```
   ADD PCCPOLICYGRP:PCCPOLICYGRPNM="common_01_pcc_p_g", FUPSESSIONEXC=DISABLE, SIGNALASSOCIATE=ENABLE, ADCMUTEFLAG=ENABLE, HTTP2DEGRADESW=INHERIT, TOKENFUNCFLAG=DISABLE, URRGROUPNAME="common_01_ch_p", SIGURRGRPNAME="common_01_ch_p";
   ```
5. 配置rule，如果设备中已经按照运营商规范配置，无需重复执行。

   ```
   ADD RULE:RULENAME="common_any", POLICYTYPE=PCC, FLOWFILTERNAME="any_f_f", PRIORITY=65000, POLICYNAME="common_01_pcc_p_g", FILTERINGMODE=FLOWFILTER;
   ADD RULE:RULENAME="common_any_ipv6_r", POLICYTYPE=PCC, FLOWFILTERNAME="any_ipv6_f_f", PRIORITY=65010, POLICYNAME="common_01_pcc_p_g", FILTERINGMODE=FLOWFILTER;
   ```

   **说明** 

   如果UPF已有大网的缺省User Profile（u\_p\_xxx\_common），则使用ADD RULE命令配置的园区规则的优先级PRIORITY需要高于u\_p\_xxx\_common下所有规则的优先级，按局点的实际情况规划。

   **说明** 

   - 建议在专网PCF上为专用DNN策略配置隔离条件组，对专网会话仅下发专网业务，不下发大网业务，专网UPF独立部署时也不需要配置大网的User Profile。
   - 当以下两个条件都满足时，在专网UPF上参考第6步使用ADD USERPROFILE配置大网的缺省User Profile（u\_p\_xxx\_common）以及园区用户要使用的大网的User Profile （两个user profile可以不绑定任何规则）：

     -专网PCF上没有配置隔离条件组或者专网PCF为20.11.2之前版本不支持配置隔离条件组功能

     -专网PCF上大网策略没有将common.dnn通用DNN作为过滤条件

     通过上述操作，可以在专网UPF上增加大网相关User Profile，避免业务失败。原因是，当专网SMF使用专用DNN向专网PCF请求策略时，专网PCF会将大网User Profile策略一同下发，包括大网的缺省User Profile以及专网PCF上为园区用户配置了其它的大网User Profile。

   当PCF下发缺省的内容计费规则对应的用户模板时，添加园区缺省计费规则对应的UserProfile，需要配置如下步骤6、7、8。USERPROFILE的名称统一规划，保证在PCF、SMF、UPF间名称一致。不一致时PCF下发的策略无法生效。
6. 配置User Profile。

   ```
   ADD USERPROFILE:USERPROFILENAME="u_p_multi_default", ALIASMARKFLAG=DISABLE, DDOSCHECK=DISABLE, CAPMODETHRES=0, LOCRPTSWITCH=INHERIT, TETHERINGMAXNUM=255, V6TCPMSSVALUE=0, V4TCPMSSVALUE=0;
   ```
7. 绑定User Profile。

   ```
   ADD RULEBINDING:USERPROFILENAME="u_p_multi_default", RULENAME="common_any", POLICYTYPE=PCC;
   ADD RULEBINDING:USERPROFILENAME="u_p_multi_default", RULENAME="common_any_ipv6_r", POLICYTYPE=PCC;
   ```
8. 设置用户模板的URR组绑定关系。

   ```
   SET URRGRPBINDING:USERPROFILENAME="u_p_multi_default", DFTURRGRPNAME="common_01_ch_p", DFTSIGURRGNAME="common_01_ch_p";
   ```

   **说明** 

   【注意】每个userprofile都要增加缺省URR组以及缺省信令URR组，如果都未配置可能会导致无法计费。
9. 业务生效。

   ```
   SET REFRESHSRV:REFRESHTYPE=ALL;
   ```
