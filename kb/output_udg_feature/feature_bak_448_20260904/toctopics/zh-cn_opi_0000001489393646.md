## 操作场景

TWAMP（Two-Way Active Measurement Protocol）特性用于在IP传输网络下实时检测UDG与对端设备间IP链路QoS变化情况，并将QoS统计结果以性能指标的方式上报到MAE，可以有效地监控IP传输网络QoS，包括时延、抖动和丢包率，及时进行故障检测与定位。

TWAMP功能由IPAPM微服务承载，仅当网元需要TWAMP功能时，才需要安装IPAPM服务。

安装IPAPM服务场景：

**场景一**

**（静态上线）**

：UDG网元和IPAPM服务

。实例化UDG

- 配置VM：基于X86虚拟机（PBU\_P-T\_Num）。基于ARM虚拟机(PBU\_P-T\_ARM\_Num)。

配置Pod：“IPAPMEXEC\_Instance\_Num”，“IPAPMCTRL\_Instance\_Num”。

## 必备事项

前提条件

- 已经实例化UDG。已经安装后检查，UDG正常工作。
- IPAPM服务依赖的软件包为：X86为UDG-IPapm\_xx.x.x\_Docker\_X86.zip。ARM为UDG-IPapm\_xx.x.x\_Docker\_ARM.zip。如果在安装UDG时没有上传本软件包，则需要在上线IPAPM前上传软件包，否则无需再次上传。

**须知** 

- 当系统进行动态上下线操作期间，不允许再同时进行扩缩容操作。同理，当系统进行扩缩容期间，不允许再进行动态上下线操作。
- 上下线本服务时，不能同时上下线其他部件。
- 当动态上线一个服务的任务失败；必须先动态下线此服务，再重新触发动态上线任务。如果是动态下线失败，继续重新触发动态下线任务。

## 操作步骤

1. 动态上线本服务前，必须根据客户的业务容量和设备现状进行严格的**扩容评估**。

   确保上线服务所需的I层资源、License资源、各类网络资源（如外联口网络）是充足的，如果不充足，则要**先扩容这些资源**，然后**再上线本服务**。

   由华为网设工程师进行网络设计，规划计算资源、存储资源、网络资源。

   将规划数据合入《NFV LLD文档》，作为后续操作的输入。

   - **计算资源**：承载虚拟机的主机（服务器）、主机组、虚拟机名称、虚拟机个数、容器名称、容器个数。
   - **存储资源**：承载本服务的磁盘空间。
   - **网络资源**：承载虚拟机的网络。承载容器的网络。承载业务的物理网口、业务网络。例如虚拟机的Base网络、容器Base网络、外联口网络、外联口Subport。
2. 检查**软件包，**确保已经上传依赖的软件包。

   登录MAE-VNF LCM/U2020 VNF LCM，单击“包管理 > VNFD > 单击VNFD模板，查看VNFD模板详情 > 依赖的服务镜像”。

   - 若“UDG-IPapm\_xx.x.x\_Docker\_X86.zip”“UDG-IPapm\_xx.x.x\_Docker\_ARM.zip”软件包的状态为“已经存在”，说明已经上传软件包，则跳过步骤 3，执行后续步骤。
   - 若软件包的状态为“等待上传”，则需要执行步骤 3。
3. **上传服务镜像文件**。

   **说明** 

   如果执行LST ME命令查询的架构模式为X86，且LCM上提示ARM的包为必选时，可以忽略“是否必需上传”的提示，无需上传ARM后缀的依赖的服务镜像。

   1. 在“依赖的服务镜像”区域，单击“上传”，弹出“上传服务镜像”窗口。
   2. 在“单包”页面，单击“选择文件”，选择依赖的服务镜像包和对应的cms文件。
   3. 单击“完成”。
   4. 上传完成后，“状态”均显示为“已经存在”。上传时长依赖于现场网络情况。

   上传镜像后需要同步镜像包到边缘站点。

   1. 在“VNFD”窗口中，**选择已导入的VNFD**。
   2. 单击图标。
   3. 在“边缘站点列表”区域中选择目标站点。
   4. 单击“确定”。

      **图1** 同步文件到边缘站点
4. 参考《UDG中心侧扩缩容指导书(基于LCM)》或《UDG中心侧扩缩容指导书(基于NFVO)》，完成扩容操作，扩容出计算资源、存储资源、网络资源。上线可选服务时只扩容VM，无需扩容POD。

   由华为工程师登录华为Support网站，在技术支持>知识库>云核心网>Mobile Packet Core>5G Packet Core>UDG>技术指导，中搜索《UDG中心侧扩缩容指导书(基于LCM)》或《UDG中心侧扩缩容指导书(基于NFVO)》。

   **注意** 

   非SDN组网模式下使用《UDG中心侧扩缩容指导书(基于LCM)》，SDN组网模式请使用《UDG中心侧扩缩容指导书(基于NFVO)》。
5. 登录UDG OM Portal。
6. 执行命令，查询pod是否存在。

   ```
   DSP POD: TYPE=byType, PODTYPE="ipapmctrl-pod";
   DSP POD: TYPE=byType, PODTYPE="ipapmexec-pod";
   ```

   - 如果所查到的原Pod数**为0**；说明系统中并没有实例化该服务，请执行后续步骤，进行实例化该服务。
   - 如果所查到的原Pod数为**非0**；则说明该Pod已实例化完毕。
     1. 当查询pod个数为**非0**，且**不等于规划值**，请参考《UDG基于LCM的扩缩容指导》，**在VNF LCM上扩容**pod个数为规划值。
     2. 当查询pod个数为**非0**，且**与规划值相等**，表示当前服务已完成实例化，无需执行后续步骤。
7. 执行命令，动态上线IPAPM Pod。

   ```
   OPR FEATUREENABLE: PODINSTANCENUM="ipapmctrl-pod:pod个数/ipapmexec-pod:pod个数", FUNCTIONSETNAME="IPAPM";
   ```

   （1）ipapmctrl-pod固定值为2；ipapmexec-pod取值2~8。（ipapmexec-pod取值与VM个数保持一致，VM个数取值范围为2~8，ipapmexec-pod个数限制为2~8。）

   （2）无需配置“EXTENDEDATTR(扩展属性)”参数。

   （3）参数“FUNCTIONSETNAME”填写为“IPAPM”。

   （4）参数“PODINSTANCENUM”填写为网设规划值，例如：pod1:num1/pod2:num2/pod3:num3
8. 执行命令，确认已经成功实例化IPAPM Pod。

   ```
   DSP FEATUREOPRHIST:;
   ```

   回显为“处理结果=处理成功”。

   ```
   DSP POD: MEID="网元ID", TYPE=byType, PODTYPE="ipapmctrl-pod";
   DSP POD: MEID="网元ID", TYPE=byType, PODTYPE="ipapmexec-pod";
   ```

   回显pod个数和规划一致，且“Pod状态”为“Running”。
9. 执行命令，查询进程的状态。

   ```
   DSP CELLSTAT: OBJECT=PODTYPE, PODTYPE="ipapmctrl-pod";
   DSP CELLSTAT: OBJECT=PODTYPE, PODTYPE="ipapmexec-pod";
   ```

   预期结果：“未就绪进程数”和“故障进程数”均为0。

## 任务示例

任务描述

UDG实例化时，已采用网元类型为UPF的VNFD模板，已在MAE-VNF LCM/U2020 VNF LCM上传UDG-IPapm\_xx.x.x\_Docker\_X86.zip或UDG-IPapm\_xx.x.x\_Docker\_ARM.zip软件包。

已经参考《UDG中心侧扩缩容指导书(基于LCM)》或《UDG中心侧扩缩容指导书(基于NFVO)》，完成扩容操作，扩容出计算资源、存储资源、网络资源。例如已在VNF LCM或NFVO上扩容出IPAPM服务自身VM（PBU\_P-T）。

在上述场景中动态上线IPAPM服务。

脚本

1. 执行命令，pod是否存在。

   ```
   DSP POD: TYPE=byType, PODTYPE="ipapmctrl-pod";
   DSP POD: TYPE=byType, PODTYPE="ipapmexec-pod";
   ```
2. 执行命令，动态上线IPAPM Pod。

   ```
   OPR FEATUREENABLE: PODINSTANCENUM="ipapmctrl-pod:2/ipapmexec-pod:2", FUNCTIONSETNAME="IPAPM";
   ```
3. 执行命令，确认已经成功实例化IPAPM Pod。

   ```
   DSP FEATUREOPRHIST:;
   ```

   回显为“处理结果=处理成功”。

   ```
   DSP POD: MEID="0", TYPE=byType, PODTYPE="ipapmctrl-pod";
   DSP POD: MEID="0", TYPE=byType, PODTYPE="ipapmexec-pod";
   ```

   回显pod个数和规划一致，且“Pod状态”为“Running”。
4. 执行命令，查询进程的状态。

   ```
   DSP CELLSTAT: OBJECT=PODTYPE, PODTYPE="ipapmctrl-pod";
   DSP CELLSTAT: OBJECT=PODTYPE, PODTYPE="ipapmexec-pod";
   ```

   预期结果：“未就绪进程数”和“故障进程数”均为0。
