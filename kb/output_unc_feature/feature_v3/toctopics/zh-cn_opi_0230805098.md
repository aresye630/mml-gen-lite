## 操作场景

当网络中有PCRF，用户激活为PCC用户，需要为用户或用户业务提供灵活策略控制时，需要开启动态PCC功能，并根据业务情况来部署预定义规则/预定义规则组或动态规则。

* 预定义规则/预定义规则组

  当需要对报文进行七层解析或业务规划时针对用户的规则内容在用户激活前可以预先确定，建议采用预定义规则方式，以减少GGSN/PGW-C与PCRF之间的交互和对缓存资源的占用。即相应的QoS管理、计费控制策略等在GGSN/PGW-C上通过rule或者UserProfile配置，PCRF上只配置预定义规则名称/预定义规则组名称。
* 动态规则

  当用户激活前用户的规则内容无法确定，需要根据用户访问业务时的协商结果由AF（应用服务器）或其他网元发送请求给PCRF，请求建立动态规则时，建议采用动态规则方式。即GGSN/PGW-C上只需开启PCC功能开关，相应的QoS管理、计费控制策略等均在PCRF上配置。

GGSN/PGW-C可以基于APN、特定号段、全局选择PCRF组，并触发PCC功能，GGSN/PGW-C上基于不同粒度开启PCC功能的规划如表1所示。

**表1** PCRF选择原则

| 选择的PCRF组 | 全局PCC功能（**SET PCCFUNC**） | APN下的PCC功能（**SET APNPCCFUNC**） | 说明 |
| --- | --- | --- | --- |
| 选择APN下绑定的PCRF组 | ENABLE | ENABLE | 指定APN下绑定PCRF组。 |
| 选择指定号段绑定的PCRF组 | ENABLE | INHERIT | 指定号段绑定PCRF组。 |
| 选择全局缺省的PCRF组 | ENABLE | INHERIT | 指定全局缺省的PCRF组，且指定号段未绑定PCRF组。 |

适用于GGSN、PGW-C。

## 操作流程

采用不同规则方式时需要执行的操作步骤如下：

* PCRF下动态规则时，需要执行步骤 2～步骤 8。
* PCRF下预定义规则时，需要执行步骤 2～步骤 10。
* PCRF下预定义规则组时，需要执行步骤 2～步骤 11。

配置动态PCC功能的流程如下：

1. （可选）配置IMSI或MSISDN号码段。
2. 配置PCRF分组信息。
3. 配置全局缺省的PCC开关。
4. 配置APN的PCC开关，并绑定PCRF group到APN下。
5. （可选）配置本地规则。
6. （可选）配置业务策略组合。

## 操作步骤

1. 进入“MML命令行-UNC”窗口。
2. 打开本特性的License配置开关。

   **SET LICENSESWITCH**
3. **可选：**配置IMSI或MSISDN号码段。

   **ADD IMSIMSISDNSEG**

   规划特定号段的用户触发PCC功能时需要配置。
4. 配置PCRF分组信息。
   1. 配置PCRF。

      **ADD PCRF**
   2. 配置PCRF分组。

      **ADD PCRFGROUP**
   3. 添加指定的PCRF到指定的PCRF分组中。

      **ADD PCRFBINDGRP**
   4. **可选：**如果PCRF组的工作模式为主备模式，可使用如下命令修改PCRF分组内的缺省主用PCRF。

      **SET MASTERPCRF**
   5. **可选：**基于IMSI号段选择PCRF分组时，需要将指定的PCRF分组绑定到指定的号码段。

      **ADD GLBPCRFGROUP**
5. **可选：**配置基于整机粒度控制在激活过程中根据PCRF返回的重定向指示重选PCRF。缺省不支持。

   **SET PCCPCRFMSGATTR**
6. 开启全局缺省PCC开关。
   1. 设置全局缺省的PCRF分组的名称。

      **SET DFTGLBPCRFGRP**
   2. 针对全局配置PCC使能开关。

      **SET PCCFUNC**

      缺省REPORTLEVEL、缺省METERMETHOD和PCC用户激活时Common Policy的选择原则为可选配置，缺省使用默认值。
7. 开启APN下的PCC开关，并将指定的PCRF分组绑定到该APN下。
   1. 将指定的PCRF分组及号段信息绑定到指定APN。

      **ADD PCRFGRPBNDAPN**

      号段信息为可选配置。APN下只允许配置一个不带号段信息的PcrfGroup。
   2. **可选：**添加PCC模板，配置在激活过程中根据PCRF返回的重定向指示重选PCRF；配置缺省REPORTLEVEL和缺省METERMETHOD，缺省使用默认值。

      **ADD PCCTEMPLATE**
   3. 针对指定的APN配置PCC使能开关，并将PccTemplate绑定到APN下。

      **SET APNPCCFUNC**
8. **可选：**配置specific APN。

   **ADD SPECIFICAPNVAL**

   GGSN/PGW-C向PCRF上报APN时，不仅能携带Request APN/Service APN，GGSN/PGW-C支持上报指定的APN，该APN可以是系统中配置的任一APN实例名称或者APN别名名称。

   当配置了specific APN，在上报APN时，specific APN优先级最高，其次是别名APN、虚拟APN、真实APN。
9. PCRF下发预定义规则时，需要在GGSN/PGW-C上配置预定义规则对应的本地业务规则。

   **ADD RULE**
10. **可选：**配置rule和DNAI关联。可选配置，将rule下发给指定DNAI的辅锚点PGW-U时需要配置。

    **ADD RULEBINDDNAI**
11. PCRF下发预定义规则组时，需要在GGSN/PGW-C上配置预定义规则组对应的本地业务策略组合。
    1. 配置UserProfile。

       **ADD USERPROFILE**
    2. **可选：**配置UserProfile和DNAI关联。可选配置，将UserProfile下发给指定DNAI的辅锚点PGW-U时需要配置。

       **ADD USRPROBINDDNAI**
    3. 将已配置的rule绑定到UserProfile。

       **ADD RULEBINDING**

## 任务示例

任务描述

GGSN/PGW-C上规划全局使能PCC功能，APN“apn-test1”下使能PCC功能，APN“apn-test2”下继承全局使能开关。相应号段的用户通过指定APN接入时是否激活为PCC用户及GGSN/PGW-C选择哪个PCRF分组进行交互，如表2所示。

**表2** 用户选择的PCRF分组与配置的关系

| 用户号段 | 接入的APN名称 | APN下的PCC开关 | 选择的PCRF分组 | 是否激活为PCC用户 |
| --- | --- | --- | --- | --- |
| 不区分号段 | apn-test1 | ENABLE | pcrf\_group\_2 | 是 |
| 18900000000～18949999999 | apn-test2 | INHERIT | pcrf\_group\_1（MSISDN号段绑定的PCRF分组） | 是 |
| 18950000000～18999999999 | apn-test2 | INHERIT | pcrf\_group\_2（MSISDN号段绑定的PCRF分组） | 是 |
| 其他号段 | apn-test2 | INHERIT | pcrf\_group\_1（全局缺省PCRF分组） | 是 |

脚本

1. 打开本特性的License配置开关。

   ```
   SET LICENSESWITCH:LICITEM="LKV3W9SPCC11",SWITCH=ENABLE;
   ```
2. 配置MSISDN号段。

   ```
   ADD IMSIMSISDNSEG:SEGMENTNAME="msisdnseg1",SEGMENTTYPE=MSISDN,SEGSTART="18900000000",SEGEND="18949999999";
   ```

   ```
   ADD IMSIMSISDNSEG:SEGMENTNAME="msisdnseg2",SEGMENTTYPE=MSISDN,SEGSTART="18950000000",SEGEND="18999999999";
   ```
3. 配置PCRF分组信息，设置pcrf\_group\_1组内的PCRF按配置比例进行负荷分担，pcrf\_group\_2组内的PCRF之间为主备备份。

   ```
   ADD PCRF:HOSTNAME="pcrf_1",REALMNAME="pcrf.huawei.com";
   ```

   ```
   ADD PCRF:HOSTNAME="pcrf_2",REALMNAME="pcrf.huawei.com";
   ```

   ```
   ADD PCRF:HOSTNAME="pcrf_3",REALMNAME="pcrf.huawei.com";
   ```

   ```
   ADD PCRF:HOSTNAME="pcrf_4",REALMNAME="pcrf.huawei.com";
   ```

   ```
   ADD PCRFGROUP:PCRFGRPNAME="pcrf_group_1",LOADBALANCEMODE=LOAD_BALANCE;
   ```

   ```
   ADD PCRFBINDGRP:PCRFGRPNAME="pcrf_group_1",PCRFHOSTNAME="pcrf_1",WEIGHT=40;
   ```

   ```
   ADD PCRFBINDGRP:PCRFGRPNAME="pcrf_group_1",PCRFHOSTNAME="pcrf_2",WEIGHT=60;
   ```

   ```
   ADD PCRFGROUP:PCRFGRPNAME="pcrf_group_2",LOADBALANCEMODE=MASTER_SLAVE;
   ```

   ```
   ADD PCRFBINDGRP:PCRFGRPNAME="pcrf_group_2",PCRFHOSTNAME="pcrf_3";
   ```

   ```
   ADD PCRFBINDGRP:PCRFGRPNAME="pcrf_group_2",PCRFHOSTNAME="pcrf_4";
   ```
4. 将指定的PCRF组和号码段绑定，并设置PCRF组“pcrf\_group\_1”为全局缺省的PCRF组。

   ```
   ADD GLBPCRFGROUP:IMSIMSISDNSEG="msisdnseg1",PCRFGRPNAME="pcrf_group_1",PRIORITY=1;
   ```

   ```
   ADD GLBPCRFGROUP:IMSIMSISDNSEG="msisdnseg2",PCRFGRPNAME="pcrf_group_2",PRIORITY=2;
   ```

   ```
   SET DFTGLBPCRFGRP:PCRFGRPNAME="pcrf_group_1";
   ```
5. 配置全局缺省的PCC开关。

   ```
   SET PCCFUNC:HOMEPCCSWITCH=ENABLE,ROAMPCCSWITCH=ENABLE,VISITPCCSWITCH=ENABLE,COMPOLICY=LOCALAAA;
   ```
6. 配置2个APN下的PCC开关，其中APN apn-test1的PCC开关为“ENABLE”，并绑定PCRF组“pcrf\_group\_2”，APN apn-test2的PCC开关为“INHERIT”，当通过该APN接入的用户的特定号段未与PCRF组绑定时，使用全局缺省的PCRF组“pcrf\_group\_1”。

   ```
   ADD PCRFGRPBNDAPN:APN="apn-test1",DEFAULTFLAG=DEFAULT,PCRFGRPNAME="pcrf_group_2";
   ```

   ```
   SET APNPCCFUNC:APN="apn-test1",HOMEPCCSWITCH=ENABLE,ROAMPCCSWITCH=ENABLE,VISITPCCSWITCH=ENABLE;
   ```

   ```
   SET APNPCCFUNC:APN="apn-test2",HOMEPCCSWITCH=INHERIT,ROAMPCCSWITCH=INHERIT,VISITPCCSWITCH=INHERIT;
   ```
