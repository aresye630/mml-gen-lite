## 操作场景

PCF通过ADC功能感知到特定应用数据流，并为该特定应用数据流提供QoS保证等时，需要在UPF上配置ADC基本功能。

UPF检测应用数据流（应用数据流通过L3/4、L7或L3/4+L7识别）开始、结束时，通过SMF上报给PCF。

## 必备事项

前提条件

* 请仔细阅读UPF特性之《GWFD-020357 增强的ADC基本功能》。
* 完成加载License（如果有需求，请联系华为技术支持工程师）。
* 已通过学习SM策略E2E实现原理、业务配置方法及E2E业务调测了解了SM策略的配置原理及方法。

数据

如果用户访问的特定视频流可通过L3/4层协议做区分，则仅需配置三四层过滤条件即可进行业务流识别。

**表1** 三四层过滤条件

| 类别 | 参数名称 | 取值样例 | 获取方法 | 说明 |
| --- | --- | --- | --- | --- |
| **ADD FLOWFILTER** | 流过滤器名称（FLOWFILTERNAME） | flow\_ADC | 本端规划 | 不同流过滤器之间，该参数不能重复。  PCF下发动态规则携带appId时，SMF、UPF、PCF三个网元上的该参数必须一致，否则无法正常上报。  PCF通过预定义规则下发APP\_STA和APP\_STO事件时，FlowFilter与ADC功能无关。 |
| **ADD FILTER** | 过滤器名称（FILTERNAME） | filter\_test | 本端规划 | 不同过滤器之间，该参数不能重复。三四层过滤条件。 |
|  | 三四层IPv4协议输入类型（L34PROTTYPE） | ANY | 本端规划 | - |
|  | 服务器IP地址配置模式（SVRIPMODE） | IP | 根据用户实际业务类型进行规划 | - |
|  | 服务器IP地址（SVRIP） | 10.27.3.56 | 根据用户实际业务类型进行规划 | 特定视频应用对应的服务器IP地址。在测试场景，终端侧一般可通过FTP软件等起FTP服务的方式生成服务器IP地址。 |
| **ADD FLTBINDFLOWF** | 流过滤器名称（FLOWFILTERNAME） | flow\_ADC | 已配置数据中获取 | 使用**ADD FLOWFILTER**命令定义的流过滤器名称。 |
|  | 过滤器名称（FILTERNAME） | filter\_test | 已配置数据中获取 | 使用**ADD FILTER**命令定义的过滤器名称。 |

如果用户访问的特定视频流须通过L7层协议做区分，则须配置七层过滤条件进行业务流识别。

**表2** 七层过滤条件

| 类别 | 参数名称 | 取值样例 | 获取方法 | 说明 |
| --- | --- | --- | --- | --- |
| **ADD FLOWFILTER** | 流过滤器名称（FLOWFILTERNAME） | flow\_ADC | 本端规划 | 不同流过滤器之间，该参数不能重复。  PCF下发动态规则携带appId时，SMF、UPF、PCF三个网元上的该参数必须一致，否则无法正常上报。  PCF通过预定义规则下发APP\_STA和APP\_STO事件时，FlowFilter与ADC功能无关。 |
| **ADD L7FILTER** | 七层过滤器名称（L7FILTERNAME） | l7filter\_test | 本端规划 | 不同的七层过滤器，其名称不能相同。 |
|  | 子七层过滤器名称（SUBL7FLTNAME） | sl7\_test\_1 | 本端规划 | 同一个七层过滤器包含的多个子七层过滤器名称不能相同。 |
|  | URL（URL） | www.huawei.com（特定业务流） | 与对端协商 | 根据应用服务器的URL规划。  采用基于URL时，需要规划；仅采用基于HTTP协议时，不需要规划该数据。 |
| **ADD PROTBINDFLOWF** | 流过滤器名称（FLOWFILTERNAME） | flow\_ADC | 已配置数据中获取 | 使用**ADD FLOWFILTER**命令定义的流过滤器名称。 |
|  | 协议名称（PROTOCOLNAME） | http | 本端规划 | 使用样例值。 |
|  | 七层过滤器名字（L7FILTERNAME） | l7filter\_test | 已配置数据中获取 | 使用**ADD L7FILTER**命令定义的七层过滤器名称。  采用基于URL时，需要规划；仅采用基于HTTP协议时不需要规划。 |

上述两种业务流识别方式根据实际情况选择一种即可。

## 操作步骤

1. 打开PCC基本功能的License配置开关。

   ```
   SET LICENSESWITCH:LICITEM="LKV3G5PCCB01",SWITCH=ENABLE;
   ```
2. 打开ADC基本功能的License配置开关。

   ```
   SET LICENSESWITCH:LICITEM="LKV3G5ADCF01",SWITCH=ENABLE;
   ```
3. 如果采用了L3/4层过滤则须配置ADC业务使用的三四层过滤条件。
   1. 配置ADC业务使用的三四层过滤条件。

      ```
      ADD FILTER: FILTERNAME="filter_test1", L34PROTTYPE=STRING, L34PROTOCOL=ANY, SVRIPMODE=IP, SVRIP="10.27.3.56", SVRIPMASKTYPE=LENGTHTYPE, SVRIPMASKLEN=32, MSSTARTPORT=0, MSENDPORT=65535, SVRSTARTPORT=0, SVRENDPORT=65535;
      ```
   2. 配置流分类器。

      ```
      ADD FLOWFILTER:FLOWFILTERNAME="flow_ADC";
      ```

      PCF通过动态规则下发appId时，动态规则中携带的appId映射到本地配置的FlowFilter。
   3. 绑定三四层过滤信息。

      ```
      ADD FLTBINDFLOWF:FLOWFILTERNAME="flow_ADC",FILTERNAME="filter_test1";
      ```
   4. 将新配置的Filter置为生效。

      ```
      SET REFRESHSRV:REFRESHTYPE=ALL;
      ```

      修改完流信息后需执行**SET REFRESHSRV**命令刷新流配置才能立即生效。
4. 如果采用了L7层过滤配置ADC业务使用的七层过滤条件。
   1. 配置七层过滤器。

      ```
      ADD L7FILTER:L7FILTERNAME="l7filter_test_01",SUBL7FLTNAME="sl7_test_1",URL="www.huawei.com";
      ```
   2. 配置流分类器。

      ```
      ADD FLOWFILTER:FLOWFILTERNAME="flow_ADC";
      ```
   3. 绑定七层过滤信息。

      ```
      ADD PROTBINDFLOWF:FLOWFILTERNAME="flow_ADC",PROTOCOLNAME="http",L7FILTERNAME="l7filter_test_01";
      ```
   4. 将新配置的L7Filter置为生效。

      ```
      SET REFRESHSRV:REFRESHTYPE=ALL;
      ```

## 任务示例

任务描述

PCF下发携带Application ID（即appId（flow\_ADC））的动态规则给SMF，SMF将其传递给UPF。UPF配置需要识别的URL和上报的应用，实现对HTTP业务的QoS保障等。流信息上报开关以SMF下发的为准。

脚本

业务导入脚本：UPF MML

业务回退脚本：UPF\_MML\_Deleting
