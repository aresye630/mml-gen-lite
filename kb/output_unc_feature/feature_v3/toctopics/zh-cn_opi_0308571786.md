## 操作场景

该场景根据整体方案设计需配置1个业务，该业务挂载在1个策略，该策略包含2个规则：

* 规则1（Rule\_Normal）：
  + 条件：QuotaStatus=Normal
  + 动作：maxbrUL=100 Mbit/s，maxbrDL=100 Mbit/s
* 规则2（up\_Exhaust），需挂载短信通知：
  + 条件：QuotaStatus=Exhaust
  + 动作：maxbrUL=1 Kbit/s，maxbrDL=1 Kbit/s，重定向到http://www.example.com

## 对系统的影响

该业务对系统无影响。

## 必备事项

前提条件

已通过学习SM策略E2E实现原理、业务配置方法及业务调测方法了解了SM策略的配置原理及方法。

数据

无。

6. 配置“5G动作组”。

   导航入口为“策略管理 > 策略 > 5G动作组”。

   此场景配置5G动作组需要考虑流信息、业务流开关、流量上报和带宽调整，则需配置动作：FlowInformation、TrafficControlData、UsageMonitoringData和QoSData。相关应用场景如下：
   * FlowInformation：当需要下发流信息时需配置此动作。
   * TrafficControlData：当需要做门限控制时，配置此动作。在下发流描述时，如果不配默认为放通该流，当需要限制流时，此动作必须配置。
   * UsageMonitoringData：当需要进行流量上报时，配置此动作。
   * QoSData：当需要进行带宽控制时，配置此动作。

   其中，TrafficControlData包括重定向参数，用于设置是否开启重定向功能，重定向的地址等。

   根据业务配置逻辑章节介绍的5G场景中QoS Flow的建立方法，此处示例采用“仅使用DynamicPccRule类型动作建立缺省QoS Flow”的方法进行配置。根据整体方案设计步骤可知，该业务场景须建立两条规则，对应需要配置2个“DynamicPccRule”类型的5G动作组，分别用于在用户“配额未耗尽”和“配额耗尽”时动作的下发。详细动作组参数可参见“UPCF产品文档>UPCF WebUI GUI参考>策略管理>5G动作组”。

10. **开户。**

    **登录“UPCF PGW Web LMT>UPCF 业务管理”窗口**，将配置完成的业务通过UPCF开户签约系统进行下发。

    执行**ADD PSUB**增加一个用户。

    ```
    ADD PSUB: USRIDENTIFIER="46000120010****", USRMSISDN="861390010****", USRSTATE=Normal, USRPAIDTYPE=NULL, USRSTATION=Master, USRCONTACTMETHOD=SMS, USRBILLCYCLEDATE=NULL, USRSUBNETTYPE=eMBB-SA, USRLANGUAGE=NULL, USRSMSRECEIVEFLAG=All, USRVERSTATUS=Normal;
    ```

    针对需要向用户发送通知的场景，必须通过**ADD PSUB**命令配置添加“USRMSISDN”，否则会导致短信发送失败。
11. **业务发放。**

    在“UPCF PGW Web LMT>UPCF 业务管理”窗口继续执行**ADD PSRV**给用户签约业务。

    ```
    ADD PSRV: USRIDENTIFIER="46000120010****", SRVNAME="Redirection_Service", SRVUSAGESTATE=Normal, SRVROAMINGTYPE=NULL;
    ```
