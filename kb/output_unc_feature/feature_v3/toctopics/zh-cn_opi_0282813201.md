# 激活基于原因值的UE行为调整（SMF）

## 操作场景

当用户接入5G网络，当系统内部以及周边网元异常导致流程失败时，SMF可以控制给终端下发的NAS原因值以调整终端的行为，辅助运营商实现对现网设备兼容性控制的需求。

给UE下发的原因值变化可能会导致相应拒绝类话统指标的变化，并对终端行为产生影响，在部署前需要评估影响。关于不同原因值的含义及对终端行为的影响请参见协议3GPP TS 24.501。

## 必备事项

前提条件

请仔细阅读WSFD-011301 基于原因值的UE行为调整 （适用于SMF）特性概述。

数据

| 类别 | 参数名称 | 取值样例 | 获取方法 | 说明 |
| --- | --- | --- | --- | --- |
| **ADD SMFCAUSECTRL** | 流程类型(PROCEDURETYPE) | PDU\_SESSION\_EST\_PROC | 全网规划 | 配置SMF流程中NAS原因值控制参数 |
|  | 异常来源(NFTYPE) | UPF |  |  |
|  | NF拒绝导致流程拒绝原因值组号(CAUSEGROUPID) | 17 |  |  |
|  | 响应超时导致流程拒绝的NAS原因值(CAUSEEXPIRATION) | 0 |  |  |
| **ADD SMCAUSEGRP** | 原因值组标识(CAUSEGRPID) | 17 | 全网规划 | 配置SMF原因值映射组 |
|  | 原因值组名称(CAUSEGRPNM) | Default1 |  |  |
| **ADD SMCAUSEMAP** | 原因值组标识(CAUSEGRPID) | 17 | 全网规划 | 配置SMF原因值映射关系 |
|  | 原因值范围(CAUSERANGE) | DEFAULT |  |  |
|  | 起始原始原因值(BGCAUSE) | 0 |  |  |
|  | 终止原始原因值(EDCAUSE) | 200 |  |  |
|  | 目标原因值(TCAUSE) | 27 |  |  |

## 操作步骤

1. 进入“MML命令行-UNC”窗口。
2. 配置SMF原因值映射组。

   **ADD SMCAUSEGRP**
3. 配置SMF流程中NAS原因值控制参数。

   **ADD SMFCAUSECTRL**
4. 配置SMF原因值映射关系。

   **ADD SMCAUSEMAP**

## 任务示例

任务描述

配置SMF会话创建流程异常情况下给UE下发的NAS原因值，其中异常来源为UPF，希望UPF响应失败后UE收到原因值后能尝试再次接入，且如果当某APN不允许该UE创建会话，希望UE收到原因值后不再尝试使用该APN继续创建会话。

脚本

//配置SMF原因值映射组。

```
ADD SMCAUSEGRP: CAUSEGRPID=17, CAUSEGRPNM="Default1";
```

//配置SMF流程中NAS原因值控制参数。

```
ADD SMFCAUSECTRL: PROCEDURETYPE=PDU_SESSION_EST_PROC,  NFTYPE=UPF, CAUSEGROUPID=17, CAUSEEXPIRATION=0;
```

//配置SMF原因值映射关系。

```
ADD SMCAUSEMAP: CAUSEGRPID=17, CAUSERANGE=DEFAULT, TCAUSE=27;
```
