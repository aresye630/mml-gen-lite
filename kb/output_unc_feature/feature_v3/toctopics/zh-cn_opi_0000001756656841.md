## 操作场景

当运营商希望通过地理容灾确保业务所在地发生重大灾难NRF依然能够提供正常的数据业务，保证5GC中各NF业务流程的可靠性时，部署此特性。

本操作指导介绍在运行网络中分别在两个DC新增2台NRF用于设备间地理容灾或者将2个单机运行的NRF改造组成主备容灾的操作过程。

* 适用于NRF。
* NRF容灾部署不建议使用NRF主备容灾，推荐使用NRF双活容灾，NRF双活容灾可靠性更高，也更符合NRF内部容灾的实现原理。

## 必备事项

前提条件

* 请仔细阅读WSFD-114001 NRF主备容灾特性概述。
* 完成加载License。
* 待改造的2个单机的NRF需要先升级到UNC 20.6.0及后续版本。
* 已按照自身组网完成两个NRF之间的路由配置，对于IPv4组网，各配置场景请参考“初始配置与调测”中自动部署配置动态路由OSPF+BFD组网（IPv4）、配置静态路由+BFD组网（IPv4）、配置BGP over OSPF/静态路由+BFD（IPv4）或手动部署配置动态路由OSPF+BFD组网（IPv4）、配置静态路由+BFD组网（IPv4）、配置BGP over OSPF/静态路由+BFD（IPv4）。
* 已按照自身组网完成两个NRF之间的路由配置，对于IPv6组网，各配置场景请参考“初始配置与调测”中自动部署配置动态路由OSPFv3+BFD组网（IPv6）、配置静态路由+BFD组网（IPv6）、配置BGP over OSPFv3/静态路由+BFD（IPv6）或手动部署配置动态路由OSPFv3+BFD组网（IPv6）、配置静态路由+BFD组网（IPv6）、配置BGP over OSPFv3/静态路由+BFD（IPv6）。
* 各NF已完成配置到两个NRF的数据，对接的2个NRF区分高低优先级。

数据

| 类别 | 参数名称 | 取值样例 | 获取方法 | 说明 |
| --- | --- | --- | --- | --- |
| **ADD DRINST** | 容灾实例标识(DRINSTID) | * 0 * 1 | 全网规划 | - |
|  | 容灾实例名称(DRINSTNAME) | * nrf1 * nrf2 | 全网规划 |  |
| **ADD DRCOMM** | 容灾实例标识(DRINSTID) | * 0 * 1 | 全网规划 | IP地址用于NRF数据同步通道通信，此IP地址为NRF本端规划的。 |
|  | IP版本号(IPVERSION) | COMM\_IPV4 | 全网规划 |  |
|  | 通信IPv4地址(COMMIPV4) | * 10.5.5.1 * 10.5.5.2 | 本端规划 |  |
|  | VPN实例名称(VPNNAME) | \_public\_ | 全网规划 |  |

如果采用MML配置导出再导入的方式（准备的数据来源为系统中已配置的主备数据），针对此特性MML配置导出脚本和实际操作步骤顺序会有差异，请确保按照如下操作步骤中的顺序调整MML配置脚本后，再进行导入。

## 操作流程

请严格按照操作步骤的顺序进行操作。

## 操作步骤

1. 在NRF1和NRF2上分别配置容灾组。
   1. 配置容灾实例。

      **ADD DRINST**
   2. 配置主备NRF容灾实例通信地址信息，用于数据同步通道建立。

      **ADD DRCOMM**

      此命令针对每个NRF需要配置两次，分别为本端NRF实例通信地址信息和对端NRF实例通信地址信息，并且需要先配置本端NRF实例通信地址信息。
2. NRF1和NRF2上的1都完成后，在NRF1和NRF2上分别打开主备容灾的License开关。

   **SET LICENSESWITCH**
3. **可选：**NRF1和NRF2上的2都完成后，在NRF1和NRF2上分别先关闭容灾通道开关，打开主备备份状态忽略开关。

   如果是新建的2个NRF组成主备NRF，则不需要执行此步骤。

   1. 初始先关闭容灾通道开关。

      **SET DBSOFTPARA**
   2. 打开主备备份状态忽略开关，忽略数据备份状态，NRF允许直接处理业务。

      **SET NRFDRRTSTASW**
4. **可选：**在NRF1和NRF2上分别再打开容灾通道开关，关闭主备备份状态忽略开关，触发NRF间数据同步。

   如果是新建的2个NRF组成主备NRF，则不需要执行此步骤。

   1. 对同一个NRF，请在3.a执行关闭容灾通道开关1分钟后，打开容灾通道开关，数据可以实时同步。

      **SET DBSOFTPARA**
   2. 关闭主备备份状态忽略开关，NRF进入实时备份状态时，才允许处理业务。

      **SET NRFDRRTSTASW**

## 任务示例

任务描述

现网2个单机运行的NRF组成主备容灾组，NRF信息如下：

NRF1：容灾实例标识为0，用于数据同步的通信IP地址为10.5.5.1。

NRF2：容灾实例标识为1，用于数据同步的通信IP地址为10.5.5.2。

脚本

**//配置NRF1。**

//配置主备容灾实例。

```
ADD DRINST:DRINSTID=0, DRINSTNAME="nrf1";
```

//配置主备NRF容灾实例通信地址信息，用于数据同步通道建立。

```
ADD DRCOMM: DRINSTID=0, IPVERSION=COMM_IPV4, COMMIPV4="10.5.5.1", VPNNAME="_public_";
ADD DRCOMM: DRINSTID=1, IPVERSION=COMM_IPV4, COMMIPV4="10.5.5.2", VPNNAME="_public_";
```

**//配置NRF2。**

//配置主备容灾实例。

```
ADD DRINST:DRINSTID=1, DRINSTNAME="nrf2";
```

//配置主备NRF容灾实例通信地址信息，用于数据同步通道建立。

```
ADD DRCOMM: DRINSTID=1, IPVERSION=COMM_IPV4, COMMIPV4="10.5.5.2", VPNNAME="_public_";
ADD DRCOMM: DRINSTID=0, IPVERSION=COMM_IPV4, COMMIPV4="10.5.5.1", VPNNAME="_public_";
```

**//配置NRF1。**

//打开NRF主备容灾特性开关。

```
SET LICENSESWITCH: LICITEM="LKV2ASNRR01", SWITCH=ENABLE;
```

**//配置NRF2。**

//打开NRF主备容灾特性开关。

```
SET LICENSESWITCH: LICITEM="LKV2ASNRR01", SWITCH=ENABLE;
```

**//配置NRF1。**

//初始先关闭容灾通道开关。

```
SET DBSOFTPARA: PARAID=7, PARAVALUE=1;
```

//打开主备备份状态忽略开关，忽略数据备份状态，NRF允许直接处理业务。

```
SET NRFDRRTSTASW: FCSWITCH=FUNC_ON;
```

**//配置NRF2。**

//初始先关闭容灾通道开关。

```
SET DBSOFTPARA: PARAID=7, PARAVALUE=1;
```

//打开主备备份状态忽略开关，忽略数据备份状态，NRF允许直接处理业务。

```
SET NRFDRRTSTASW: FCSWITCH=FUNC_ON;
```

**//配置NRF1。**

//NRF1正常运行且与NRF2通信正常，在NRF1上关闭容灾通道开关1分钟后，再打开容灾通道开关，数据可以实时同步。

```
SET DBSOFTPARA: PARAID=7, PARAVALUE=0;
```

//关闭主备备份状态忽略开关，NRF进入实时备份状态时，才允许处理业务。

```
SET NRFDRRTSTASW: FCSWITCH=FUNC_OFF;
```

**//配置NRF2。**

//NRF2正常运行且与NRF1通信正常，在NRF2上关闭容灾通道开关1分钟后，再打开容灾通道开关，数据可以实时同步。

```
SET DBSOFTPARA: PARAID=7, PARAVALUE=0;
```

//关闭主备备份状态忽略开关，NRF进入实时备份状态时，才允许处理业务。

```
SET NRFDRRTSTASW: FCSWITCH=FUNC_OFF;
```
