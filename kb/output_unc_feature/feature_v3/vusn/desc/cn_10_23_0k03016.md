## 操作场景

本节以举例来描述Pool区回退到非Pool区的配置过程。

本场景适用于将Pool区回退成非Pool区。Pool组网回退到非Pool组网，可以分为紧急回退和一般回退。

回退时，在eNodeB上将其他MME链路删除（与eNodeB相连的MME除外），根据回退的目的，决定是否需要修改eNodeB、MME的配置数据。

如果只是临时回退，后续还需要组Pool的情况下，不需要修改eNodeB、MME的配置数据，断开多余的S1链接后进行业务拨测正常即可，否则分别修改eNodeB、MME的配置数据，完成彻底的回退。

紧急回退对用户影响较大，被断开的链接上的正在进行PS业务的用户都会发生业务中断，必须重新接入后才能使用业务。

图1是4G网络演进目标示意图。

回退MME上配置数据的过程如下：

1. eNodeB上将新接入的某个或某几个MME的链路删除（接入Pool之前所连接的MME仍是可用的，保留正常业务接入到原MME）。
2. DNS上删除新增的相关配置。

   MMEID的域名解析无需删除，TA对应的SGW域名解析无需删除。
3. eNodeB对应的TA的域名解析需要区分直连和非直连MME，非直连MME的GTPc地址全部删除，直连关系的MME地址要保留。
4. MME上删除新增的数据配置。

   删除新增TALIST。
5. 完成从Pool区内分离的MME和eNodeB的基本功能测试。

## 操作步骤

1. Pool参数配置阶段回退。

   删除MME侧配置的Pool参数。

   此处只以MME1为例，MME2/MME3相似。

   1. 在MME1上将负载权重修改为原来的值。

      ```
      SET SYS: CAP=50;
      ```
   2. 重复执行本阶段步骤，删除其他MME配置的Pool参数，本例为MME2，MME3。
   3. 如果修改了MMEID，参见MME ID调整。

      修改MMEID会导致用户在一段时间内导致业务失败。
2. 割接阶段回退。
   1. 删除DNS Server的TA记录中扩展的MME IP地址。
   2. 删除eNodeB侧多余的链路配置。
   3. 删除S1ap层以下的配置。
   4. 删除MME测新增配置。

      删除新增TALIST：

      ```
      RMV TALST: TALISTID=0, TAI="123033101";
      RMV TALST: TALISTID=0, TAI="123033102";
      RMV TALST: TALISTID=0, TAI="123033103";
      RMV TALST: TALISTID=0, TAI="123033104";
      RMV TALST: TALISTID=0, TAI="123033105";
      RMV TALST: TALISTID=0, TAI="123033201";
      RMV TALST: TALISTID=0, TAI="123033202";
      RMV TALST: TALISTID=0, TAI="123033203";
      RMV TALST: TALISTID=0, TAI="123033204";
      RMV TALST: TALISTID=0, TAI="123033205";
      RMV TALST: TALISTID=0, TAI="123033301";
      RMV TALST: TALISTID=0, TAI="123033302";
      RMV TALST: TALISTID=0, TAI="123033303";
      RMV TALST: TALISTID=0, TAI="123033304";
      RMV TALST: TALISTID=0, TAI="123033305";
      ```
   5. 执行Pool参数配置阶段回退。
   6. 执行链路准备阶段回退。
3. 改造完成阶段回退。
   1. 执行割接阶段回退。
   2. 执行Pool参数配置阶段回退。
   3. 执行链路准备阶段回退。

## 验证方法

1. 检查数据一致性

   检查MME覆盖的TA区域：

   通过**LST S1PAGING**命令检查MME3只配置了eNodeB3覆盖的路由区。MME1、MME2配置了eNodeB1、eNodeB2覆盖的路由区。
2. 基本业务调测

   检查MME3到MME3的链路建立及服务是否正常，具体操作步骤请参考《UNC初始配置与调测》。

   做用户在MME1、MME2到MME3的Inter-MME TAU和Inter-MME handover，检查业务流程是否正常。

在MME3和eNodeB3从Pool分离之后，如果用户在eNodeB1或者eNodeB2到eNodeB3上的切换时，这时应该发起的Inter-MME handover流程，非Intra-MME handover流程。
