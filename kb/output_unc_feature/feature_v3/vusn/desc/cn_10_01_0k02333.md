## 操作步骤

1. 准备阶段。
   1. 割接前一周，检查待组建POOL的各SGSN的MML脚本，进行割接前的相关事项检查，并确保相关接口功能已配置完成。确认无误后，务必备份各SGSN的MML脚本。
   2. 割接前3天，提前准备以下脚本，并完成和华为技术支持的审核确认。

      1. 各SGSN与待割接的BSC的新建Gb接口配置脚本。
      2. 各SGSN上的POOL配置相关脚本。
      3. DNS Server（可能是客户设备）上的配置脚本。

      待割接的BSC1当前所连接的SGSN上已经有此BSC1相关的配置数据，不用新增，只需在其他SGSN上配置BSC1相关数据。
2. 配置同步阶段。
   1. 割接前一天或当晚，在各SGSN上，加载License文件，License中开启Gb-flex功能（LKV2GBFLEX02）、“SGSN负荷分担”功能(可选)、SGSN Pool用户迁移（可选，LKV2SGSNMG02）功能。
   2. 割接前一天或当晚，在U2020/MAE上，加载支持SGSN POOL管理的License文件。（包括SGSN Pool管理、SGSN Pool负载均衡管理、SGSN Pool用户定位。）
   3. 各SGSN配置参数同步。

      比如移动性管理，会话管理相关配置。
3. 设置SGSN1的Pool ID和NRI长度。

   **ADD POOL**: POOLID=0, NRILENGTH=5;

   目前NRI长度等于7bit仅在中国部署。在海外部署时，NRI长度采用5bit。

   配置举例以配置SGSN1为例，SGSN2、SGSN3配置类似。
4. 在SGSN1上配置本局NRI信息，在P-TMSI分配时将填写设定的NRI值。

   **ADD LOCALNRI**: POOLID=0, NRIVBGN=1, NRINUM=1;

   在用户迁移过程中，不可以通过ADD LOCALNRI增加本局NRI。

   不建议在高峰期执行ADD LOCALNRI命令。如果在高峰期执行ADD LOCALNRI命令失败，请执行如下命令，直到执行ADD LOCALNRI命令成功为止（以增加一条POOLID为1，NRI的值为10，NRI个数为1的本局NRI失败为例）。

   **BLK LOCALNRI**: POOLID=1, NRIVBGN=10;

   **RMV LOCALNRI**: POOLID=1, NRIVBGN=10;

   **ADD LOCALNRI**: POOLID=1, NRIVBGN=10, NRINUM=1;
5. 配置SGSN1侧的CN ID。

   **SET SYS**: CNID=1;
6. 配置SGSN1的Pool参数。
   1. 在SGSN1上配置Pool区内其他SGSN的NRI信息。

      **ADD POOLNRI**: POOLID=0, NRIV=2, IPTYPE=IPV4, IPV4="10.168.155.2", SGSNN="SGSN2";

      **ADD POOLNRI**: POOLID=0, NRIV=3, IPTYPE=IPV4, IPV4="10.168.151.3", SGSNN="SGSN3";
   2. SGSN1（待割接BSC直连的SGSN）上的待割接BSC的Flex开关。

      * 方案一

        在SGSN1（待割接BSC直连的SGSN）上打开待割接BSC的Flex开关。

        + Gb接口静态配置：**MOD NSE**: NSEI=1001, GB\_FLEX=YES;
        + Gb接口动态自动配置：**MOD GBNSECFGPARA**: PARAINDEX=1, GB\_FLEX=YES;

        这里需要添加该配置的SGSN为直连SGSN，比如BSC1原来连接的是SGSN1，则在组SGSN POOL的时候只有SGSN1需要执行此操作，SGSN2和SGSN3在配置的时候不需要执行。
      * 方案二

        在这里不打开SGSN1（原SGSN）上待割接BSC的Flex开关。
   3. 可选:系统已销售和支持迁移功能时需执行，在各个SGSN上，配置规划好的OFFLOADINFO（配置本SGSN迁移数据）和NONRAI（在本SGSN上增加Pool区内其它SGSN的非广播路由区信息）。

      **SET OFFLOADINF**: OFFLOADTMR=4, FIRSTTM=54, NONRAI="12300611111", POOLID=0, NULLNRIV=0;

      **ADD NONRAI**: NONRAI="12300612222", IPTYPE=IPV4, IPV4="10.168.155.2", SGSNN="SGSN2";

      **ADD NONRAI**: NONRAI="12300613333", IPTYPE=IPV4, IPV4="10.168.151.3", SGSNN="SGSN3";
   4. 打开SGSN1 license控制配置中的Gb-flex开关。

      **SET LICENSESWITCH**: LICITEM="LKV2GBFLEX02", SWITCH=ENABLE;
   5. 如果SGSN是使用UNC作为融合节点支持MME POOL，在SGSN1上配置Mapping的GUMMEI。

      * 如果值配置LAC，会向MME连接的所有eNodeb下发对应的Mapping的GUMMEI。

        **ADD POOLLA**: LAC="0011";

        **ADD POOLLA**: LAC="0012";

        **ADD POOLLA**: LAC="0060";
      * 配置TA和LA的对应关系，只向LA对应的TA所覆盖的eNodeb下发响应的Mapping的GUMMEI。

        **ADD POOLLA**: BGNTAI="1230033101", ENDTAI="1230033105", LAC="0011";

        **ADD POOLLA**: BGNTAI="1230033101", ENDTAI="1230033105", LAC="0012";

        **ADD POOLLA**: BGNTAI="1230033101", ENDTAI="1230033105", LAC="0060";

        **ADD POOLLA**: BGNTAI="1230033201", ENDTAI="1230033205", LAC="0012";

        **ADD POOLLA**: BGNTAI="1230033301", ENDTAI="1230033305", LAC="0060";

      POOLLA只有在融合节点同时支持SGSN POOL和MME POOL的时候才需要配置，支持一个POOL时，不需要。
   6. 在SGSN1上打开鉴权开关。

      * 方案一

        打开2G鉴权开关（包括PDP激活鉴权开关、签名不匹配开关和无签名开关）。

        **MOD GBAUTHCIPH**: SUBRANGE=ALL\_USER, SECPLC=AUTHONLY, AUTHEVENT=PROD\_RAU-1&SMS\_MT-1&SMS\_MO-1&DETACH-1&INTER\_RAU-1&INTRA\_RAU-1&PTMSI\_ATTACH-1&IMSI\_ATTACH-1&PTMSI\_SIG\_NOMATCH-1&PTMSI\_SIG\_NOSIG-1&SM\_PDP-1&LCS-1&SYSTEM\_CHANGE\_INTRA\_RAU-1;
      * 方案二

        本步骤不执行任何操作，直接进行后续操作。
   7. 打开P-TMSI重分配开关。

      **SET GMMPTMSIREALLOC**: WITHRAUPROC=YES, REALLOCTMR=1, REALLOCCOND=IN\_READY\_STATE;
   8. P-TMSI重分配完成。

      * 方案一

        经过1.5个周期路由更新时长，P-TMSI重分配完成之后，在各SGSN上恢复2G鉴权开关，再进行后续操作。

        **MOD GBAUTHCIPH**: SUBRANGE=ALL\_USER, SECPLC=AUTHONLY, AUTHEVENT=PROD\_RAU-0&SMS\_MT-0&SMS\_MO-0&DETACH-0&INTER\_RAU-1&INTRA\_RAU-0&PTMSI\_ATTACH-1&IMSI\_ATTACH-1&PTMSI\_SIG\_NOMATCH-0&PTMSI\_SIG\_NOSIG-0&SM\_PDP-0&LCS-0&SYSTEM\_CHANGE\_INTRA\_RAU-0;

        鉴权开关的恢复取值需要根据原有配置规划或网络状态进行。
      * 方案二

        本步骤不执行任何操作，直接进行后续操作。
7. 重复上述步骤3~7，配置其他SGSN的Pool参数，本例中需要配置SGSN2、SGSN3的数据。
8. 各SGSN配置完成后，执行Flex功能检查，详细检查项如表1所示。

   **表1** Flex功能Checklist

   | Flex功能检查 | 要求结果 |
   | --- | --- |
   | 鉴权开关 | 与规划数据一致 |
   | 系统容量 | 和规划一致 |
   | Pool ID | 一致 |
   | NRI长度 | 一致 |
   | CN ID | 不重复，与规划数据一致 |
   | Pool NRI | 所有SGSN均配置了Pool内其他SGSN的NRI和IP地址的对应关系，且IP地址配置一致。 |
   | 建立待割接的第一个BSC的所有RAI的性能测量任务 | 已经建立 |
   | OFFLOADINFO（可选） | 与规划数据一致 |
   | NONRAI | 不重复，与规划数据一致 |
   | Local NRI | 不重复，与规划数据一致 |
   | POOLLA | 与规划数据一致 |
   | license控制(LICENSESWITCH) | Gb-flex开启 |
9. 割接阶段。

   第一次割接（预割接）2个或1个BSC，按照如下几个方面进行操作。

   在大容量局点，推荐首次测试或预割接时必须同时有2个BSC，目的是预割接时充分验证2个BSCPTMSI\_ATTACH-1的POOL负荷分担效果以及POOL内Intra-RAU流程发生时的NRI分配效果。

   此配置举例以割接BSC1为例，BSC2、BSC3割接过程类似。

   1. **可选：**仅方案二需要执行此步骤：在SGSN1上打开鉴权开关。

      打开2G鉴权开关（包括2G PDP激活鉴权开关、签名不匹配开关和无签名开关）。

      **MOD GBAUTHCIPH**: SUBRANGE=ALL\_USER, SECPLC=AUTHONLY, AUTHEVENT=PROD\_RAU-1&SMS\_MT-1&SMS\_MO-1&DETACH-1&INTER\_RAU-1&INTRA\_RAU-1&PTMSI\_ATTACH-1&IMSI\_ATTACH-1&PTMSI\_SIG\_NOMATCH-1&PTMSI\_SIG\_NOSIG-1&SM\_PDP-1&LCS-1&SYSTEM\_CHANGE\_INTRA\_RAU-1;
   2. 按照之前准备的脚本，配置新增连接的BSC与SGSN之间的链路数据，调通Gb链路。

      1. 核心网侧：在各SGSN上，分别配置与各个待割接的BSC的Gb接口IP链路数据，然后调通Gb接口链路。
      2. 无线侧：在各个待割接的BSC上，分别配置与各个SGSN之间的Gb接口链路数据，然后调通Gb接口链路。
   3. 核心网SGSN侧

      1. BSC的Flex开关
         * 方案一

           在SGSN2、SGSN3（割接前非直连SGSN）上，打开待割接BSC的Flex开关：

           + Gb接口静态配置：**MOD NSE**: NSEI=1002, GB\_FLEX=YES;
           + Gb接口动态自动配置：**MOD GBNSECFGPARA**: PARAINDEX=1, GB\_FLEX=YES;

           对于方案一，割接前直连的SGSN1的该配置在组SGSN Pool的时候已经修改了，本步骤不需要再修改。
         * 方案二

           在POOL内所有SGSN上打开待割接BSC的Flex开关：

           + Gb接口静态配置：**MOD NSE**: NSEI=1001, GB\_FLEX=YES;
           + Gb接口动态自动配置：**MOD GBNSECFGPARA**: PARAINDEX=1, GB\_FLEX=YES;
      2. 检查2G的PAGING表是否上报

         2G的PAGING表是自动上报的，链路配置完成之后，使用命令检查LST GBPAGING，查询小区上报是否符合规划。
   4. DNS Server上的Default SGSN配置。

      Default SGSN需要基于路由区进行规划，且保证分摊均匀。其中的路由区包括待割接BSC下所有POOL内的RAI。

      考虑容灾备份，最好对同一个路由区至少有两个SGSN互为备份。本例中，对于域名“LAC0011.RAC0001.MNC000.MCC123.GPRS.”，将SGSN1和SGSN2配置为Default SGSN，即在DNS上将BSC1的路由区域名解析成为SGSN1和SGSN2的GTPC地址。并通知与该BSC1覆盖范围相邻的非本SGSN Pool的其他SGSN做相应的数据修改。

      通常地，本网内有一个本地DNS Server，上一级DNS Server不在本地。这种情况下，当核心网内多个SGSN改造成POOL后，该DNS Server可以视作POOL外的DNS Server，也可以视作POOL内的DNS Server，它除了保留原有的域名解析数据、解析功能外，还需要为SGSN POOL增加Default SGSN的数据配置。以华为DNS Server为例：

      * 方式一：在华为DNS Server的LMT上配置，主备均需要：

        ```
        ADD RESREC: TYPE=A, NAME="MNC000.MCC123.gprs", DOMAIN="RAC0001.LAC0011", IP="10.166.155.2";
        ```
      * 方式二：在不带LMT的DNS Server上，在named.ra文件中增加A记录（详细参见《DNS产品文档》）：

        ```
        RAC0001.LAC0011
                              IN       A        10.166.155.2
        ```

      以下为DNS Server上原有配置，不需新增：

      * 方式一：在华为DNS Server上：

        ```
        ADD RESREC: TYPE=A, NAME="MNC000.MCC123.gprs", DOMAIN="RAC0001.LAC0011", IP="10.166.153.1";
        ```
      * 方式二：在不带LMT的DNS Server上：

        ```
        RAC0001.LAC0011                       IN       A        10.166.153.1
        ```

      1. 如果本网的运营商除了本地DNS Server外，还有上一级的DNS Server也在本地，在改造成SGSN POOL后，POOL内有一个DNS Server A，POOL外还有一个上级的DNS Server B，则，Default SGSN的数据配置就需要在DNS Server B上完成。这种情况比较少见。
      2. 如果POOL内某个SGSN下扩容BSC/RNC网元，在POOL内的DNS Server上，需要在扩容操作阶段，新增加该BSC/RNC的全部RAI的相关A记录（对应哪几个SGSN作为DefaultSGSN，需在扩容前完成规划），并且增加RNCID的相关A记录。
      3. 修改了DNS服务器上的配置的，需要在清除各SGSN的cash记录。
   5. BSC上的配置。

      * 在待割接的BSC上，配置各SGSN的NRI长度、CN ID、NRI数值、负荷分担比例。

        该步骤可在割接前提前完成。
      * 在待割接的BSC上，打开Gb-flex开关（不同厂家可能实现不同，如无具体命令，则有相应Flex启动或生效的类似操作）。

        该步骤在割接当晚，上述全部操作（SGSN侧、DNS Server、RAN侧）完成后，执行。
   6. 核心网配置检查。

      **表2** 核心网配置检查Checklist

      | 核心网配置检查 | 要求结果 |
      | --- | --- |
      | 鉴权开关（Inter RAU 、2G PDP激活鉴权、Attach、签名不匹配、无签名等） | 打开 |
      | P-TMSI重分配开关 | 打开 |
      | BSC | Flex开关已打开 |
      | DNS | 配置与规划一致 |
   7. 接入网络测试（对割接入的BSC进行业务拨测）。

      * 基本上网业务拨测。
      * POOL功能业务拨测。

        如果拨测失败且无法定位，Pool基本功能验证失败，需收集各设备上的配置信息和相关，进行POOL回退，参见Pool改造回退。
      * 拨测成功后，观察网络运行状况。

        1. 观察割接后SGSN的话统指标，在各个SGSN侧观察激活成功率，附着成功率，路由更新成功率的指标，其指标应该与割接前基本保持一致，以及BSC侧的话统结果，如果指标明显异常，需要倒回，参见Pool改造回退。
        2. 观察各SGSN和U2020/MAE上的告警。
        3. 在U2020/MAE上组建SGSN POOL，将已进入POOL运行状态的各个SGSN纳入SGSN POOL，进行后续SGSN POOL管理。在U2020/MAE上登记SGSN POOL的相关KPI指标（具体参见U2020/MAE上的界面操作指导）。
      * 在割接后的第二天及一周内观察和分析相应数据是否正常。

        割接后话统明显异常，需要启动倒回流程，参见Pool改造回退。
   8. **可选：**仅方案二需要执行此步骤：等待P-TMSI重分配完成。

      需要经过1.5个周期路由更新时长，P-TMSI重分配完成之后，在各SGSN上恢复割接之前鉴权开关，再进行后续操作。
   9. 重复步骤a~h，以相同的方式割接剩余的BSC，本例中为BSC2、BSC3。
10. 在各SGSN上执行用户迁移保证负荷均衡。

    具体请参见《U2020 MBB网络管理系统 虚拟化产品文档》 / 《iMaster MAE产品文档》的手工迁移用户部分。
