# 改造业务

* 操作场景
* 必备事项
* 操作步骤

## 操作场景

本操作指导适用于描述4G现网演进成MME Pool的配置过程。

## 必备事项

前提条件

已经完成MME Pool用户迁移。

数据

本场景无需准备数据。

## 操作步骤

1. 配置准备阶段
   1. 割接前一周，检查待组建Pool的各MME的MML脚本，进行割接前的事项检查，确认无误后，备份各MME的MML脚本。
   2. 割接前3天，提前准备以下脚本，并完成和华为技术支持的审核确认。

      * 各MME与待割接的eNodeB的新建S1接口配置脚本
      * 各MME上的Pool配置相关脚本
      * DNS Server（可能是客户设备）上的配置脚本

      待割接的eNodeB1当前所连接的MME上已经有此eNodeB1关的配置数据，不用新增，只需在其他MME上配置eNodeB1相关数据。
2. 配置同步阶段
   1. 割接前一天或当晚，在各MME上，加载License文件，“MME Pool”(LKV2POOL02)、“Subscriber Migration in MME Pool”（可选，LKV2MMEMG02）功能。
   2. 割接前一天或当晚，在U2020/MAE上，加载支持MME Pool管理的License文件。
   3. 各MME配置参数同步。因为在改造之前，各MME上的配置可能有一些差别，如移动性管理和会话管理的相关配置，在组建Pool之后，需要保持一致。
3. Pool参数配置阶段。

   根据场景描述中的网络规划规则，对网络进行规划，为每一台设备分配规划数据。

   此配置举例以配置MME1为例，MME2、MME3配置类似。

   1. **可选：**修改MMEID，比如需要将MME Code(Begin)从6修改为8，请参见MME ID调整。

      修改MMEID会导致用户在一段时间内导致业务失败。
   2. 在MME1上配置本MME的权重信息。
   3. **可选：**在使用UNC作为融合节点同时支持SGSN Pool功能和MME Pool功能的场景下，如果MME需要通过S1接口下发LTE GUMMEI和Mapped GUMMEI，需要进行如下操作。

      * 没有规划TA和LA对应关系。

        **ADD POOLLA**: LAC="1011";

        **ADD POOLLA**: LAC="1012";

        **ADD POOLLA**: LAC="6001";
      * 规划了TA和LA的对应关系。

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="1011";

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="1012";

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="6001";

        **ADD POOLLA**: BGNTAI="123033201", ENDTAI="123033205", LAC="1012";

        **ADD POOLLA**: BGNTAI="123033201", ENDTAI="123033205", LAC="6001";
   4. 重复步骤3中步骤 3.a~步骤 3.c，配置其他MME的Pool参数，本例中需要配置MME2、MME3的数据。
   5. 参数配置完成后，需要进行数据配置一致性检查。

      **表1** Pool参数配置阶段Checklist

      | 数据配置的一致性检查 | 要求结果 |
      | --- | --- |
      | MMEID | 一致 |
      | 权重信息 | 一致 |
      | 建立待割接的所有TAI的性能测量任务 | 已经建立 |
4. 割接阶段。

   * 在大容量局点，推荐首次割接或预割接时必须同时有2个eNodeB节点，目的是预割接时充分验证2个eNodeB节点的Pool负荷分担效果以及Pool内Guti分配效果。
   * 割接阶段就是将eNodeB逐个接入Pool的过程，此配置举例以割接eNodeB1为例，eNodeB2和eNodeB3割接过程类似。

   第一次割接(预割接)的2个或1个eNodeB，按照如下几个方面进行操作：

   1. 按照之前准备的脚本，配置新增连接的eNodeB与MME之间的链路数据，调通S1链路通信。

      * 核心网侧：在各MME上，分别配置与各个待割接的eNodeB的S1接口IP链路数据，然后调通各接口通信。
      * 无线侧：在各个待割接的eNodeB上，分别配置与各个MME之间的S1接口链路数据，然后调通各接口通信。
   2. 核心网MME（非eNodeB1原直连的MME（MME2、MME3））侧：

      * 检查4G的PAGING表是否上报。

        4G的PAGING表是自动上报的，链路配置完成之后，使用命令检查LST S1PAGING，查询TA上报是否符合规划。
      * 可选：如果TA对应的S-GW的域名解析使用DNS Server配置，可以跳过此步。如果TA对应S-GW的域名解析使用的是MME上的hostfile，需要在MME上配置对应S-GW的域名解析。
        + 增加IPV4DNSH解析

          ```
          ADD IPV4DNSH: HSINDEX=20, HOSTNAME="TOPON.SGW.SGW1.NODES.EPC.ENVID50.MNC03.MCC123.3GPPNETWORK.ORG", ADDRSECTION=SECTION1, IPV4ADDR1="10.168.163.1";
          ```
        + 增加DNSN解析

          ```
          ADD DNSN: FQDN="TAC-LB04.TAC-HB31.TAC.EPC.MNC003.MCC123.3GPPNETWORK.ORG", HSINDEX=20, ENTITY=SGW, INTYPE=S11;
          ```

          如果S-GW使用的是MME的hostfile解析，增加TA到MME对应S-GW的域名解析。如果S-GW是使用DNS Server解析，跳过。
      * 增加TALIST配置

        ```
        ADD TALST: TALISTID=0, TAI="123033101";
        ADD TALST: TALISTID=0, TAI="123033102";
        ADD TALST: TALISTID=0, TAI="123033103";
        ADD TALST: TALISTID=0, TAI="123033104";
        ADD TALST: TALISTID=0, TAI="123033105";
        ADD TALST: TALISTID=0, TAI="123033201";
        ADD TALST: TALISTID=0, TAI="1230331";
        ADD TALST: TALISTID=0, TAI="123033203";
        ADD TALST: TALISTID=0, TAI="123033204";
        ADD TALST: TALISTID=0, TAI="123033205";
        ADD TALST: TALISTID=0, TAI="123033301";
        ADD TALST: TALISTID=0, TAI="123033302";
        ADD TALST: TALISTID=0, TAI="123033303";
        ADD TALST: TALISTID=0, TAI="123033304";
        ADD TALST: TALISTID=0, TAI="123033305";
        ```

        在进行eNodeB割接时同一个TALIST下的所有eNodeB需要同时割接，不能分批进行割接。
   3. **可选：**增加TAILAI配置。

      ```
      ADD TAILAI: BGNTAI="123033101", ENDTAI="123033105", LAI="123031011";
      ```

      如有CSFB部署的场景，对于新增TA，根据规划增加TAILAI配置 。
   4. 配置Pool内TA区对应Pool内MME的域名解析。

      为了保证从Pool外MME到Pool内MME的切换分摊均匀，需要在DNS Server或Hostfile上针对所有Pool内TA区增加Pool内其他MME的IP。

      配置MME的域名解析有两种方式：
      * 方式一：DNS配置方式。
      * 方式二：Hostfile配置方式。

      对于Hostfile配置方式，需要在Pool区外周边TA区对应的MME上配置。

      本例中，对于域名“TAC-LB04.TAC-HB31.TAC.EPC.MNC003.MCC123.3GPPNETWORK.ORG”，将在DNS上将eNodeB1的路由区域名解析成为MME1、MME2和MME3的GTPC地址。

      通常地，本网内有一个本地DNS Server，上一级DNS Server不在本地。这种情况下，当核心网内多个MME改造成Pool后，该DNS Server可以视作Pool外的DNS Server，也可以视作Pool内的DNS Server，它除了保留原有的域名解析数据、解析功能外，还需要为MME Pool增加TA对应的IP地址配置。

      以华为DNS Server为例：

      * 方式一：在华为DNS Server的LMT上配置，主备均需要：

        ```
        ADD RESREC: TYPE=A, ZONE="MNC0000.MCC0123.gprs", DOMAIN=" TAC-LB04.TAC-HB31.TAC.EPC ", IP="10.166.155.2";
        ADD RESREC: TYPE=A, ZONE="MNC0000.MCC0123.gprs", DOMAIN=" TAC-LB04.TAC-HB31.TAC.EPC ", IP="10.166.151.3";
        ```
      * 方式二：在不带LMT的DNS Server上，在named.ra文件中增加A记录（详细参见《DNS产品文档》）：

        ```
        TAC-LB04.TAC-HB31.TAC.EPC                       IN       A        10.166.155.2
        TAC-LB04.TAC-HB31.TAC.EPC                       IN       A        10.166.151.3
        ```

        + 如果本网的运营商除了本地DNS Server外，还有上一级的DNS Server也在本地，在改造成MME Pool后，PooL内有一个DNS Server A，Pool外还有一个上级的DNS Server B，则，TA对应IP地址的数据配置就需要在DNS Server B上完成。这种情况比较少见。
        + 修改了DNS Server的记录，需要清除各MME上的cash记录
   5. 核心网配置检查，上述全部操作（MME侧、DNS Server、eNodeB侧）完成后，在割接当晚执行该步骤。

      **表2** 核心网配置检查Checklist

      | 核心网配置检查 | 要求结果 |
      | --- | --- |
      | S1 Paging表 | 查询结果中包含割接eNodeB的TA信息 |
      | TA LIST | 查询结果中包含割接eNodeB的TA信息 |
      | TA对应S-GW解析 | 查询结果中包含割接eNodeB的TA信息 |
      | DNS Server配置 | 与规划的一致 |
   6. 接入网络测试（对割接入的eNodeB进行业务拨测）。

      * 基本上网业务拨测。
      * Pool功能业务拨测。

        如果拨测失败且无法定位，Pool基本功能验证失败，需收集各设备上的配置信息和相关，进行Pool回退，参见回退业务。
      * 拨测成功后，观察网络运行状况。
        1. 观察割接后MME的话统指标，在各个MME侧观察激活成功率，附着成功率，路由更新成功率的指标，其指标应该与割接前基本保持一致，以及BSC侧的话统结果。如果指标明显异常，需要倒回，参见回退业务。
        2. 观察各MME和U2020/MAE上的告警。
        3. 在U2020/MAE上组建MME Pool，将已进入Pool运行状态的各个MME纳入MME Pool，进行后续MME Pool管理。
      * 在割接后的第二天及一周内观察和分析相应数据是否正常。

        割接后话统明显异常，需要启动倒回流程，参见回退业务。
   7. 重复步骤a~e，以相同的方式割接剩余的eNodeB，本例中为eNodeB2、eNodeB3。
5. **可选：**执行用户迁移保证负荷均衡。

   请参见《U2020 MBB网络管理系统 虚拟化产品文档》（“操作与维护 > 核心网管理 > MME Pool管理 > MME Pool日常维护 > 均衡MME Pool负荷 > 手工迁移MME Pool用户”章节）/《iMaster MAE产品文档》（“操作与维护 > MAE-Access操作与维护 > 核心网管理 > MME Pool管理 > MME Pool日常维护 > 均衡MME Pool负荷 > 手工迁移MME Pool用户”章节）。
