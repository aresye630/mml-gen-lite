## 操作场景

本操作指导适用于所有MME为新建设备，eNodeB侧为现网设备的搬迁场景。

## 必备事项

前提条件

* 网元基础数据配置完成。
* 已经完成MME Pool用户迁移。

数据

需要准备的数据请参考数据规划。

## 操作步骤

1. 准备阶段。
   1. 申请并加载具有“MME Pool”(LKV2POOL02)、“Subscriber Migration in MME Pool”（可选，LKV2MMEMG02）。
   2. 准备S1接口的路由配置信息。
2. Pool参数配置阶段。

   配置新建MME的Pool参数。

   1. 在MME上增加MMEID。

      **ADD MMEID**: MCC="123", MNC="00", MMEGI="8001", MMEC="8", MMECNUM=1;
   2. 在MME上打开“S1-Flex”开关。

      **SET LICENSESWITCH**: LICITEM="LKV2POOL02", SWITCH=ENABLE;
   3. 在MME1上配置本MME的权重信息。

      **SET SYS**: CAP=100;

      * MME新建普通组网下：

        **SET SYS**: CAP=100;
      * MME新建按区域主备组网下：

        ****ADD MMECAPBYTA****: MCC="123", MNC="03", TAC="0x3101", CAP=255;

        **ADD MMECAPBYTA**: MCC="123", MNC="03", TAC="0x3102", CAP=255;

        **ADD MMECAPBYTA**: MCC="123", MNC="03", TAC="0x3103", CAP=255;

        **ADD MMECAPBYTA**: MCC="123", MNC="03", TAC="0x3104", CAP=0;

        **ADD MMECAPBYTA**: MCC="123", MNC="03", TAC="0x3105", CAP=0;
   4. 配置MME的域名解析。

      为了保证其他MME能通过GUTI找到对应的MME，需要在增加该MME的域名解析。

      配置MME的域名解析有两种方式：
      * 方式一：DNS配置方式。
      * 方式二：Hostfile配置方式。

      本例中，对于域名“MMEC8.MMEGI8001.MME.EPC.MNC003.MCC123.3GPPNETWORK.ORG”，将在DNS上配置成为MME1的GTPC地址。
   5. **可选：**在使用UNC作为融合节点同时支持SGSN Pool功能和MME Pool功能的场景下，如果MME需要通过S1接口下发LTE GUMMEI和Mapped GUMMEI，需要进行如下操作。

      * 没有规划TA和LA对应关系。

        **ADD POOLLA**: LAC="1011";

        **ADD POOLLA**: LAC="1012";

        **ADD POOLLA**: LAC="6001";
      * 规划了TA和LA的对应关系。

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="1011";

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="1012";

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="6001";

        **ADD POOLLA**: BGNTAI="123033201", ENDTAI="123033205", LAC="1012";

        **ADD POOLLA**: BGNTAI="123033201", ENDTAI="123033205", LAC="6001";
   6. Pool参数配置完成后，需要进行数据配置一致性检查。

      **表1** Pool参数配置阶段Checklist

      | 数据配置的一致性检查 | 要求结果 |
      | --- | --- |
      | MMEID | 与规划一致 |
      | 权重信息 | 与规划一致 |
      | POOLLA | 与规划一致 |
      | 建立待割接的第一个eNodeB的所有TAI的性能测量任务 | 已经建立 |
3. 链路配置阶段。
4. 割接阶段。

   将eNodeB从旧MME上割接到新的MME上。

   1. 根据之前准备的脚本进行链路配置，将S1接口配通。
   2. 配置各新侧MME和带割接eNodeB的相关信令和链路数据。

      本步骤具体配置请参考《UNC初始配置与调测》。

      * 在eNodeB上检查每个MME的MMEID和权重是否正确。
      * 在MME上检查4G的PAGING表是否上报。

      4G的PAGING表是自动上报的，链路配置完成之后，使用命令检查**LST S1PAGING**，查询TA上报是否符合规划。
   3. **可选：**如果TA对应的S-GW的域名解析使用DNS Server配置，可以跳过此步。如果TA对应S-GW的域名解析使用的是MME上的hostfile，需要在MME对应S-GW的域名解析。

      * 增加IPV4DNSH解析。

        **ADD IPV4DNSH**: HSINDEX=20, HOSTNAME="TOPON.SGW.SGW1.NODES.EPC.ENVID50.MNC03.MCC123.3GPPNETWORK.ORG", ADDRSECTION=SECTION1, IPV4ADDR1="10.168.163.1";
      * 增加DNSN解析。

        **ADD DNSN**: FQDN="TAC-LBTAC-LB04.TAC-HB31.TAC.EPC.MNC003.MCC123.3GPPNETWORK.ORG", HSINDEX=20, ENTITY=SGW, INTYPE=S11;
   4. 在MME1上配置eNodeB1相关的TALIST。

      ```
      ADD TALST: TALISTID=0, TAI="123033101";
      ADD TALST: TALISTID=0, TAI="123033102";
      ADD TALST: TALISTID=0, TAI="123033103";
      ADD TALST: TALISTID=0, TAI="123033104";
      ADD TALST: TALISTID=0, TAI="123033105";
      ```

      在进行eNodeB割接时同一个TALIST下的所有eNodeB需要同时割接，不能分批进行割接。
   5. **可选：**增加TAILAI配置。

      ```
      ADD TAILAI: BGNTAI="123033101", ENDTAI="123033105", LAI="123031011";
      ```

      如有CSFB部署的场景，对于新增TA，根据规划增加TAILAI配置 。
   6. DNS Server上增加MME IP。

      为了保证从Pool外MME到Pool内MME的切换分摊均匀，需要在DNS Server上针对所有Pool内TA区增加Pool内其他MME的IP。

      本例中，对于域名“TAC-LB04.TAC-HB31.TAC.EPC.MNC003.MCC123.3GPPNETWORK.ORG”，将在DNS上将eNodeB1的路由区域名解析成为MME1、MME2和MME3的GTPC地址。并通知与该eNodeB1覆盖范围相邻的非本MME Pool的其他MME做相应的数据修改。

      通常地，本网内有一个本地DNS Server，上一级DNS Server不在本地。这种情况下，当核心网内多个MME改造成Pool后，该DNS Server可以视作Pool外的DNS Server，也可以视作Pool内的DNS Server，它除了保留原有的域名解析数据、解析功能外，还需要为MME Pool增加TA对应的IP地址配置。

      以华为DNS Server为例：

      * 方式一：在华为DNS Server的LMT上配置，主备均需要：

        **ADD RESREC**: TYPE=A, NAME="MNC0000.MCC0123.gprs", DOMAIN="TAC-LB04.TAC-HB31.TAC.EPC", IP="10.168.155.2";

        **ADD RESREC**: TYPE=A, NAME="MNC0000.MCC0123.gprs", DOMAIN="TAC-LB04.TAC-HB31.TAC.EPC", IP="10.168.151.3";
      * 方式二：在不带LMT的DNS Server上，在named.ra文件中增加A记录（详细参见《DNS产品文档》）：

        TAC-LB04.TAC-HB31.TAC.EPC IN A 10.168.155.2

        TAC-LB04.TAC-HB31.TAC.EPC IN A 10.168.151.3

      * 如果本网的运营商除了本地DNS Server外，还有上一级的DNS Server也在本地，在改造成MME Pool后，Pool内有一个DNS Server A，Pool外还有一个上级的DNS Server B，则，TA对应IP地址的数据配置就需要在DNS Server B上完成。这种情况比较少见。
      * 如果修改了DNS Server的数据，需要清除各MME的cash数据。
   7. 进行业务拨测。
   8. 删除旧侧MME的配置。

      * 删除eNodeB相关链路配置。
      * 删除DNS中旧测MME对应的MMEID记录。
      * 删除DNS中TAI对应的旧侧MME IP记录。
   9. 重复步骤 4.a~步骤 4.h，以相同的方式割接剩余的eNodeB。
5. **可选：**执行用户迁移保证负荷均衡。

   当出现负荷不均衡告警时可执行本步骤，具体操作步骤请参见《U2020 MBB网络管理系统 虚拟化产品文档》（“操作与维护 > 核心网管理 > MME Pool管理 > MME Pool日常维护 > 均衡MME Pool负荷 > 手工迁移MME Pool用户”章节）/《iMaster MAE产品文档》（“操作与维护 > MAE-Access操作与维护 > 核心网管理 > MME Pool管理 > MME Pool日常维护 > 均衡MME Pool负荷 > 手工迁移MME Pool用户”章节）。
