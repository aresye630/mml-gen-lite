## 操作场景

本操作指导适用于所有SGSN为新建设备，RAN侧为现网设备的搬迁场景。

如图1所示为新建SGSN设备的组Pool实例。

## 必备事项

前提条件

网元基础数据配置完成。

数据

需要准备的数据请参考数据规划。

## 操作步骤

1. 链路准备阶段。
   1. 为各SGSN上申请并加载具有Iu-flex（LKV2IUFLEX02）、Gb-flex（LKV2GBFLEX02）和SGSN Pool用户迁移（LKV2SGSNMG02）功能的License控制项。
   2. 准备各SGSN上Iu接口和Gb接口的路由配置信息。
2. 设置SGSN1的Pool ID和NRI长度。

   **ADD POOL**: POOLID=0, NRILENGTH=5;

   目前NRI长度等于7bit仅在中国部署。在海外部署时，NRI长度采用5bit。
3. 配置SGSN1的本局NRI，SGSN1在P-TMSI分配时将使用此处设定的NRI值。

   **ADD LOCALNRI**: POOLID=0, NRIVBGN=1, NRINUM=1;
4. 设置SGSN1的CN ID。

   **SET SYS**: CNID=1;
5. 配置SGSN1的Pool参数。

   1. 在SGSN1上配置Pool区内其他SGSN的NRI信息。一般情况下，建议在DNS Server中配置，如果运营商采用POOLNRI配置，则命令如下：

      **ADD POOLNRI**: POOLID=0, NRIV=2, IPTYPE=IPV4, IPV4="10.168.155.2", SGSNN="SGSN2";

      **ADD POOLNRI**: POOLID=0, NRIV=3, IPTYPE=IPV4, IPV4="10.168.151.3", SGSNN="SGSN3";
   2. 设置Pool区内其它SGSN的非广播路由区信息。一般情况下，建议在DNS Server中配置，如果运营商采用NONRAI配置，则命令如下：

      //设置SGSN2的非广播路由区信息

      **ADD NONRAI**: NONRAI="12300615555", IPTYPE=IPV4, IPV4="10.168.155.2", SGSNN="SGSN2";

      //设置SGSN3的非广播路由区信息

      **ADD NONRAI**: NONRAI="12300616666", IPTYPE=IPV4, IPV4="10.168.151.3", SGSNN="SGSN3";

      Pool区内其它SGSN的非广播路由区信息，主要是在迁移模式下的Attach和Inter Rau流程时，根据非广播路由区与IP地址的对应关系获取对端SGSN的地址信息。

      如果SGSN存在多个GTPC地址时，选择其中一个来配置到其他的SGSN上。如果为了负载均衡，可以考虑在不同的SGSN配置本SGSN GTPC地址不同。
   3. 在SGSN1上打开需要加入Pool的RNC/BSC的Flex开关。

      Iu-Flex：**MOD RNC**: RNCX=0, IU\_FLEX=YES;

      Gb-Flex：
      * Gb接口静态配置：**MOD NSE**: NSEI=0, GB\_FLEX=YES;
      * Gb接口动态自动配置：**MOD GBNSECFGPARA**: PARAINDEX=1, GB\_FLEX=YES;
   4. 打开SGSN1 License配置中的Flex开关。

      **SET LICENSESWITCH**: LICITEM="LKV2IUFLEX02", SWITCH=ENABLE;

      **SET LICENSESWITCH**: LICITEM="LKV2GBFLEX02", SWITCH=ENABLE;
   5. 配置迁移相关参数。

      **SET OFFLOADINF**: OFFLOADTMR=4, FIRSTTM=54, NONRAI="12300611111", POOLID=0, NULLNRIV=0;
   6. 可选：如果没有规划POOLLA，跳过此步。

      如果规划了POOLLA，即MME是使用UNC作为融合节点同时支持SGSN POOL功能和MME POOL功能，进行如下操作。

      * 没有规划TA和LA对应关系

        **ADD POOLLA**: LAC="1011";

        **ADD POOLLA**: LAC="1012";

        **ADD POOLLA**: LAC="6001";
      * 规划了TA和LA的对应关系

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="1011";

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="1012";

        **ADD POOLLA**: BGNTAI="123033101", ENDTAI="123033105", LAC="6001";

        **ADD POOLLA**: BGNTAI="123033201", ENDTAI="123033205", LAC="1012";

        **ADD POOLLA**: BGNTAI="123033301", ENDTAI="123033305", LAC="6001";
6. 重复上述步骤2~6，配置其他新建SGSN的Pool参数。
7. 各SGSN配置完成后，进行数据配置一致性检查。

   **表1** 数据配置一致性检查

   | 数据配置的一致性检查 | 要求结果 |
   | --- | --- |
   | Pool ID | 一致 |
   | NRI长度 | 一致 |
   | Local NRI | 不重复，与规划数据一致 |
   | CN ID | 不重复，与规划数据一致 |
   | Pool NRI | 所有SGSN均配置了Pool内其他SGSN的NRI和IP地址的对应关系，且IP地址配置一致。 |
   | Flex开关（LICENSESWITCH） | Iu-flex开启 |
   | 鉴权开关 | 与规划一致 |
   | 建立待割接的第一个RNC的所有RAI的性能测量任务 | 已经建立 |
8. 链路配置阶段。
9. 割接阶段。

   * 将RAN从旧SGSN上割接到新的SGSN上。

   1. 根据之前准备的脚本进行链路配置，将Gb接口和Iu接口配通。
   2. 配置割接新侧SGSN。

      1. 配置新割接的RAN的NSE或RNC记录。

         本步骤具体配置请参考《UNC初始配置与调测》。
      2. 在新建SGSN上配置IuPaging表，以及基于规划扩展DNS中的RAI记录。

         **ADD IUPAGING**: LAI="123000011", RAC="01", RNCINDEX=1;

         **ADD IUPAGING**: LAI="123000012", RAC="01", RNCINDEX=2;
   3. 配置RAN侧Pool参数。

      1. **可选：**如果新建RAN侧为BSC，则需要配置NSE记录。
      2. 在RAN上配置SGSN的CN ID、NRI值、负荷权重。
      3. 在RAN上打开Flex功能开关。
   4. DNS Server上Default SGSN配置。

      Default SGSN需要基于路由区进行规划，且保证分摊均匀。其中的路由区包括待割接RNC下所有POOL内的RAI。

      考虑容灾备份，最好对同一个路由区至少有两个SGSN互为备份。本例中，对于域名“RAC0001.LAC0011.MNC000.MCC123.GPRS.”，将SGSN1和SGSN2配置为Default SGSN，即在DNS上将BSC1的路由区域名解析成为SGSN1和SGSN2的GTPC地址。并通知与该BSC1覆盖范围相邻的非本SGSN Pool的其他SGSN做相应的数据修改。

      通常地，本网内有一个本地DNS Server，上一级DNS Server不在本地。这种情况下，当核心网内多个SGSN改造成POOL后，该DNS Server可以视作POOL外的DNS Server，也可以视作POOL内的DNS Server，它除了保留原有的域名解析数据、解析功能外，还需要为SGSN POOL增加Default SGSN的数据配置。 以华为DNS Server为例：

      * 方式一：在华为DNS Server的LMT上配置，主备均需要：

        ADD RESREC: TYPE=A, NAME="MNC000.MCC123.gprs", DOMAIN="RAC0001.LAC0011", IP="10.166.155.2";
      * 方式二：在不带LMT的DNS Server上，在named.ra文件中增加A记录（详细参见《DNS产品文档》）：

        ```
        RAC0001.LAC0011                       IN       A        10.166.155.2
        ```

      以下为DNS Server上原有配置，不需新增：

      * 方式一：在华为DNS Server上：

        ```
        ADD RESREC: TYPE=A, NAME="MNC000.MCC123.gprs", DOMAIN="RAC0001.LAC0011", IP="10.166.153.1";
        ```
      * 方式二：在不带LMT的DNS Server上：

        ```
        RAC0001.LAC0011                       IN       A        10.166.153.1
        ```

      1. 如果本网的运营商除了本地DNS Server外，还有上一级的DNS Server也在本地，在改造成SGSN POOL后，POOL内有一个DNS Server A，POOL外还有一个上级的DNS Server B，则，Default SGSN的数据配置就需要在DNS Server B上完成。这种情况比较少见。
      2. 如果POOL内某个SGSN下扩容BSC/RNC网元，在POOL内的DNS Server上，需要在扩容操作阶段，新增加该BSC/RNC的全部RAI的相关A记录（对应哪几个SGSN作为DefaultSGSN，需在扩容前完成规划），并且增加RNCID的相关A记录。
      3. 如果修改了DNS Server的数据，需要清除各SGSN的cash记录。
   5. 配置旧侧SGSN。

      断开旧SGSN上与待割接RAN的连接，进行业务拨测。

      删除旧侧SGSN的配置：

      1. 删除NSE记录或RNC相关链路配置。
      2. 删除IuPaging中对应的RAI记录，删除DNS中RAI对应的旧侧SGSN IP记录。
   6. 重复步骤3，步骤4，以相同的方式割接剩余的RAN。
10. **可选：**执行用户迁移保证负荷均衡。

    当出现负荷不均衡告警时可执行本步骤，具体请参见《U2020 MBB网络管理系统 虚拟化产品文档》中的“操作与维护 > 核心网管理 > MME Pool管理 > MME Pool日常维护 > 均衡MME Pool负荷 > 手工迁移MME Pool用户”章节。
