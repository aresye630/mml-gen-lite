## 操作场景

本操作指导用实例描述3G现网演进成SGSN Pool的配置过程。

## 操作步骤

1. 配置准备阶段。
   1. 割接前一周，检查待组建POOL的各SGSN的MML脚本，进行割接前的事项检查，并确保相关接口已配置完成。确认无误后，务必备份各SGSN的MML脚本。
   2. 割接前3天，提前准备以下脚本，并完成和华为技术支持的审核确认。

      1. 各SGSN与待割接的RNC的新建Iu接口配置脚本。
      2. 各SGSN上的POOL配置相关脚本。
      3. DNS Server（可能是客户设备）上的配置脚本。

      待割接的RNC1当前所连接的SGSN上已经有此RNC1相关的配置数据，不用新增，只需在其他SGSN上配置RNC1相关数据。
2. 配置同步阶段。
   1. 割接前一天或当晚，在各SGSN上，加载License文件，License中开启Iu-flex功能（LKV2IUFLEX02）、“SGSN负荷分担”功能、用户迁移（可选，LKV2SGSNMG02）功能。
   2. 割接前一天或当晚，在U2020/MAE上，加载支持SGSN POOL管理的License文件。
   3. 各SGSN配置参数同步。

      因为在改造之前，各SGSN上的配置可能有一些差别，如移动性管理、会话管理的相关配置，在组建POOL之后，需要保持一致。
3. 设置SGSN1的Pool ID和NRI长度。

   **ADD POOL**: POOLID=0, NRILENGTH=5;

   目前NRI长度等于7bit仅在中国部署。在海外部署时，NRI长度采用5bit。

   配置举例以配置SGSN1为例，SGSN2、SGSN3配置类似。
4. 配置SGSN1本局NRI信息，SGSN1在P-TMSI分配时将填写设定的NRI值。

   **ADD LOCALNRI**: POOLID=0, NRIVBGN=1, NRINUM=1;

   在用户迁移过程中，不可以通过ADD LOCALNRI增加本局NRI。

   不建议在高峰期执行ADD LOCALNRI命令。如果在高峰期执行ADD LOCALNRI命令失败，请执行如下命令，直到执行ADD LOCALNRI命令成功为止（以增加一条POOLID为1，NRI的值为10，NRI个数为1的本局NRI失败为例）

   **BLK LOCALNRI**: POOLID=1, NRIVBGN=10;

   **RMV LOCALNRI**: POOLID=1, NRIVBGN=10;

   **ADD LOCALNRI**: POOLID=1, NRIVBGN=10, NRINUM=1;
5. 设置SGSN1的CN ID。

   **SET SYS**:CNID=1;
6. 配置SGSN1的Pool参数。
   1. 在SGSN1上配置Pool区内其他SGSN的NRI信息。一般情况下，建议在DNS Server中配置，如果运营商采用POOLNRI配置，则命令如下：

      **ADD POOLNRI**: POOLID=0, NRIV=2, IPTYPE=IPV4, IPV4="10.168.155.2", SGSNN="SGSN2";

      **ADD POOLNRI**: POOLID=0, NRIV=3, IPTYPE=IPV4, IPV4="10.168.151.3", SGSNN="SGSN3";
   2. SGSN1（待割接RNC直连的SGSN）上的待割接RNC的Flex开关。

      * 方案一

        在SGSN1（待割接RNC直连的SGSN）上打开待割接RNC的Flex开关。

        **MOD RNC**: RNCX=11, RNCID=1, IU\_FLEX=YES;

        这里需要添加该配置的SGSN为直连SGSN，比如RNC1原来连接的是SGSN1，则在组SGSN POOL的时候只有SGSN1需要执行此操作，SGSN2和SGSN3在配置的时候不需要执行。
      * 方案二

        在这里不打开SGSN1（原SGSN）上待割接RNC的Flex开关。
   3. 可选:系统已销售和支持迁移功能时需执行，在各个SGSN上，配置规划好的OFFLOADINFO（配置本SGSN迁移数据）和NONRAI（在本SGSN上增加Pool区内其它SGSN的非广播路由区信息）。

      配置本SGSN迁移数据。

      **SET OFFLOADINF**: OFFLOADTMR=4, FIRSTTM=54, NONRAI="12300611111", POOLID=0, NULLNRIV=0;

      在本SGSN上增加Pool区内其它SGSN的非广播路由区信息。一般情况下，建议在DNS Server中配置，如果运营商采用NONRAI配置，则命令如下：

      **ADD NONRAI**: NONRAI="12300612222", IPTYPE=IPV4, IPV4="10.168.155.2", SGSNN="SGSN2";

      **ADD NONRAI**: NONRAI="12300613333", IPTYPE=IPV4, IPV4="10.168.151.3", SGSNN="SGSN3";
   4. 可选：如果没有规划POOLLA，跳过此步。

      如果规划了POOLLA，即MME是使用UNC作为融合节点同时支持SGSN POOL功能和MME POOL功能，进行如下操作。

      1. 没有规划TA和LA对应关系

         **ADD POOLLA**: LAC="0001";

         **ADD POOLLA**: LAC="0002";

         **ADD POOLLA**: LAC="0003";
      2. 规划了TA和LA的对应关系

         **ADD POOLLA**: BGNTAI="1230033101", ENDTAI="1230033105", LAC="0001";

         **ADD POOLLA**: BGNTAI="1230033101", ENDTAI="1230033105", LAC="0002";

         **ADD POOLLA**: BGNTAI="1230033101", ENDTAI="1230033105", LAC="0003";

         **ADD POOLLA**: BGNTAI="1230033201", ENDTAI="1230033205", LAC="0002";

         **ADD POOLLA**: BGNTAI="1230033301", ENDTAI="1230033305", LAC="0003";
   5. 打开SGSN license控制中的Iu-flex开关。

      **SET LICENSESWITCH**: LICITEM="LKV2IUFLEX02", SWITCH=ENABLE;
   6. 在SGSN1上打开鉴权开关。

      * 方案一

        打开鉴权开关（包括Service Request、Paging Response、签名不匹配、无签名开关等）。

        **MOD IUAUTHCIPH**: SUBRANGE=ALL\_USER, SECPLC=AUTHANDPROTECTED, AUTHEVENT=PROD\_RAU-1&PAGING\_RSP-1&MS\_SERVICE\_REQ-1&DETACH-1&INTER\_RAU-1&INTRA\_RAU-1&PTMSI\_ATTACH-1&IMSI\_ATTACH-1&PTMSI\_SIG\_NOMATCH-1&PTMSI\_SIG\_NOSIG-1&INTRA\_RAU\_AFTER\_RELOCATOIN-1&INTER\_RAU\_AFTER\_RELOCATOIN-1&SYSTEM\_CHANGE\_INTRA\_RAU-1;
      * 方案二

        本步骤不执行任何操作，直接进行后续操作。
   7. 打开P-TMSI重分配开关。

      **SET PMMPTMSIREALLOC**: WITHRAUPROC=YES, REALLOCTMR=1, REALLOCCOND=IN\_PMM\_CONNECTED\_STATE;
   8. 等待P-TMSI重分配完成。

      * 方案一

        需要经过1.5个周期路由更新时长，恢复鉴权开关。

        **MOD IUAUTHCIPH**: SUBRANGE=ALL\_USER, SECPLC=AUTHANDPROTECTED, AUTHEVENT=PAGING\_RSP-0&MS\_SERVICE\_REQ-0;

        鉴权开关的恢复取值需要根据原有配置规划或网络状态进行。此处以原有配置仅Paging Response和Service Request鉴权开关关闭为例。
      * 方案二

        本步骤不执行任何操作，直接进行后续操作。
7. 重复步骤3~7，配置其他SGSN的Pool参数，本例中需要配置SGSN2、SGSN3的数据。
8. 各SGSN配置完成后，执行Flex功能检查，详细检查项如表1所示。

   **表1** Flex功能Checklist

   | Flex功能检查 | 要求结果 |
   | --- | --- |
   | 鉴权开关 | 与规划数据一致 |
   | 系统容量 | 和规划一致 |
   | Pool ID | 一致 |
   | NRI长度 | 一致 |
   | CN ID | 不重复，与规划数据一致 |
   | Pool NRI | 所有SGSN均配置了Pool内其他SGSN的NRI和IP地址的对应关系，且IP地址配置一致。 |
   | 建立待割接的第一个RNC的所有RAI的性能测量任务 | 已经建立 |
   | POOLLA | 与规划数据一致 |
   | LocalNRI | 不重复，与规划数据一致 |
   | License控制(LICENSESWITCH) | Iu-flex开启 |
9. 割接阶段。

   第一次割接（预割接）2个或1个RNC，按照如下几个方面进行操作。

   在大容量局点，推荐首次割接或预割接时必须同时有2个RNC节点，目的是预割接时充分验证2个RAN节点的POOL负荷分担效果以及POOL内Intra-RAU流程发生时的NRI分配效果。

   割接阶段就是将RNC逐个接入Pool的过程，此配置举例以割接RNC1为例，RNC2和RNC3割接过程类似。

   1. **可选：**仅方案二需要执行此步骤：在各SGSN上打开鉴权开关。

      打开鉴权开关（包括Service Request、Paging Response、签名不匹配、无签名开关等）。

      **MOD IUAUTHCIPH**: SUBRANGE=ALL\_USER, SECPLC=AUTHANDPROTECTED, AUTHEVENT=PROD\_RAU-1&PAGING\_RSP-1&MS\_SERVICE\_REQ-1&DETACH-1&INTER\_RAU-1&INTRA\_RAU-1&PTMSI\_ATTACH-1&IMSI\_ATTACH-1&PTMSI\_SIG\_NOMATCH-1&PTMSI\_SIG\_NOSIG-1&INTRA\_RAU\_AFTER\_RELOCATOIN-1&INTER\_RAU\_AFTER\_RELOCATOIN-1&SYSTEM\_CHANGE\_INTRA\_RAU-1;
   2. 按照之前准备的脚本，配置新增连接的RNC1与SGSN之间的链路数据，调通Iu各接口通信。

      * 核心网侧：在各SGSN上，分别配置与各个待割接的RNC的Iu接口IP链路数据，然后调通各接口链路。
      * 无线侧：在各个待割接的RNC1上，分别配置与各个SGSN之间的Iu接口链路数据，然后调通各接口通信。
   3. 核心网SGSN侧。

      * SGSN上的Flex开关。

        打开所有POOL内各SGSN上带割接RNC1的Flex开关。

        **MOD RNC**: RNCX=11, RNCID=1, IU\_FLEX=YES;
      * 添加待割接RNC1的RAI到POOL内所有的SGSN上面IUPAGING列表中：

        **ADD IUPAGING**: LAI="123000001", RAC="01", RNCINDEX=1;

        原直连SGSN已经添加过不需要添加。
   4. DNS Server上的Default SGSN配置。

      Default SGSN需要基于路由区进行规划，且保证分摊均匀。其中的路由区包括待割接RNC下所有POOL内的RAI。

      考虑容灾备份，最好对同一个路由区至少有两个SGSN互为备份。本例中，对于域名“RAC0001.LAC0001.MNC000.MCC123.GPRS.”，将SGSN1和SGSN2配置为Default SGSN，即在DNS上将RNC1的路由区域名解析成为SGSN1和SGSN2的GTPC地址。并通知与该RNC1覆盖范围相邻的非本SGSN Pool的其他SGSN做相应的数据修改。

      通常地，本网内有一个本地DNS Server，上一级DNS Server不在本地。这种情况下，当核心网内多个SGSN改造成POOL后，该DNS Server可以视作POOL外的DNS Server，也可以视作POOL内的DNS Server，它除了保留原有的域名解析数据、解析功能外，还需要为SGSN POOL增加Default SGSN的数据配置。以华为DNS Server为例：

      * 方式一：在华为DNS Server的LMT上配置，主备均需要：

        ```
        ADD RESREC: TYPE=A, NAME="MNC456.MCC123.gprs", DOMAIN="RAC0001.LAC0001", IP="10.166.155.2";
        ```
      * 方式二：在不带LMT的DNS Server上，在named.ra文件中增加A记录（详细参见《DNS产品文档》）：

        ```
        RAC0001.LAC0001       
                       IN       A        10.166.155.2
        ```

      以下为DNS Server上原有配置，不需新增：

      * 方式一：在华为DNS Server上：

        ```
        ADD RESREC: TYPE=A, NAME="MNC000.MCC123.gprs", DOMAIN="RAC0001.LAC0001", IP="10.166.153.1";
        ```
      * 方式二：在不带LMT的DNS Server上：

        ```
        RAC0001.LAC0001                       IN       A        10.166.153.1
        ```

      1. 如果本网的运营商除了本地DNS Server外，还有上一级的DNS Server也在本地，在改造成SGSN POOL后，POOL内有一个DNS Server A，POOL外还有一个上级的DNS Server B，则，Default SGSN的数据配置就需要在DNS Server B上完成。这种情况比较少见。
      2. 如果POOL内某个SGSN下割接RNC网元，在POOL内的DNS Server上，需要在扩容操作阶段，新增加该RNC的全部RAI的相关A记录（对应哪几个SGSN作为DefaultSGSN，需在扩容前完成规划），并且增加RNCID的相关A记录。
      3. 如果修改了DNS Server数据，需要清除各SGSN上的cash数据。
   5. RNC上的配置。

      * 在待割接的RNC上，配置各SGSN的NRI长度、CN ID、NRI数值、负荷分担比例。

        该步骤可在割接前提前完成。
      * 在待割接的RNC上，打开Iu-flex开关（不同厂家可能实现不同，如无具体命令，则有相应Flex启动或生效的类似操作）。

        该步骤在割接当晚，上述全部操作（SGSN侧、DNS Server、RAN侧）完成后，执行。
   6. 核心网配置检查。

      **表2** 核心网配置检查Checklist

      | 核心网配置检查 | 要求结果 |
      | --- | --- |
      | RNC | Flex开关已打开 |
      | IUPaging表 | 查询结果中包含割接RNC的RAI信息 |
      | DNS Server配置 | 配置与规划一致 |
   7. 接入网络测试（对割接入的RNC进行业务拨测）。

      * 基本上网业务拨测。
      * POOL功能业务拨测。

        如果拨测失败且无法定位，Pool基本功能验证失败，需收集各设备上的配置信息和相关，进行POOL回退，参见Pool改造回退。
      * 拨测成功后，观察网络运行状况。

        1. 观察割接后SGSN的话统指标，在各个SGSN侧观察激活成功率，附着成功率，路由更新成功率的指标，其指标应该与割接前基本保持一致，以及RNC侧的话统结果，如果指标明显异常，需要倒回，参见Pool改造回退。
        2. 观察各SGSN和U2020/MAE上的告警。
        3. 在U2020/MAE上组建SGSN POOL，将已进入POOL运行状态的各个SGSN纳入SGSN POOL，进行后续SGSN POOL管理。在U2020/MAE上登记SGSN POOL的相关KPI指标（具体参见U2020/MAE的界面操作指导）
      * 在割接后的第二天及一周内观察和分析相应数据是否正。

        割接后话统明显异常，需要启动倒回流程，参见Pool改造回退。
   8. **可选：**等待P-TMSI重分配完成。

      * 方案一

        在P-TMSI重分配的阶段就完成，这个步骤可以跳过。
      * 方案二

        需要经过1.5个周期路由更新时长，恢复鉴权开关。
   9. 重复步骤a~h，以相同的方式割接剩余的RNC，本例中为RNC2、RNC3。
10. 在各SGSN上恢复功能开关初始配置。
    1. 改造完成后恢复链接态的P-TMSI重分配时长至割接前状态，但P-TMSI重分配开关不必恢复。
    2. **可选：**执行用户迁移保证负荷均衡。

       具体请参见《U2020 MBB网络管理系统 虚拟化产品文档》 / 《iMaster MAE产品文档》的手工迁移用户部分。
