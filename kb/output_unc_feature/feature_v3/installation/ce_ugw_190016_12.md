## 操作场景

VNF与对端设备可通过静态路由绑定静态BFD探测的方式进行组网连接。在网络拓扑结构比较简单时，通常使用静态路由方式组网，合理的静态路由可以改进网络性能，并为业务保证带宽。同时，利用BFD双向/单臂echo转发检测机制为链路提供双向/单向、轻负荷且持续时间短的快速检测功能，提高链路可靠性。

* 图1为VNF与周边网元的静态路由互通组网示意图。VNF与网关侧运行静态路由协议而接入运营商网络（IP骨干网），网关推荐使用DC-GW，也可以使用运营商的PE（Provider Edge）交换机，或者EOR（End of Row）交换机。无论哪种方式，VNF的配置相同，没有差异。PE的路由配置请参考运营商的网络规划配置，DC-GW/EOR的配置请参考对应型号设备的产品文档。
* 图2为VNF与周边网元的静态路由互通组网示意图。VNF与网关侧运行静态路由协议而接入运营商网络（IP骨干网），DC-GW作为网关设备。VNF和DC-GW之间采用单臂BFD探测。DC-GW的配置请参考对应型号设备的产品文档。

## 必备事项

前提条件

* 请阅读并熟悉特性IPFD-014003 静态路由和IPFD-012003 BFD特性概述。
* 具备管理员权限的操作人员已经登录华为操作维护系统（登录U2020/MAE客户端或登录OM Portal）。

* VNF与网络实体之间的网络环境已经构建完成。

数据

VNF使用静态路由绑定静态BFD检测功能与对端设备建立可靠的IP连接。

* 在VNF上配置静态路由与对端建立链路。
* 在VNF上配置静态BFD功能增强链路检测可靠性。
* 在VNF上推荐采用子接口的外联口与外部网络对接。

本文以一组外联口子接口为例进行说明，一组外联口（对应一个逻辑接口）分别在每个CSLB各规划2个子接口负荷分担承载流量，后续扩容CSLB后自动在每个CSLB上扩展2个子接口承载流量。实际场景可根据网设规划进行适配。

## 操作步骤

1. 配置外联口的VPN实例。

   ```
   ADD L3VPNINST:VRFNAME="VPN_Access";
   ADD VPNINSTAF:VRFNAME="VPN_Access",AFTYPE=ipv4uni;
   ```

   一条通信路径上所有节点绑定的VPN实例要一致，才能正常通信，例如VNF逻辑接口、VNF外联口、网关上的VPN，否则从逻辑接口发出去的报文会查询路由失败。
2. 全局激活BFD。

   ```
   SET BFD: BFDENABLE=TRUE;
   ```
3. 关闭自动配置开关。

   1. 查询自动配置开关。

      ```
      LST AUTOCONFIG:;
      ```

      如果自动配置开关值为“TRUE”，需要执行如下步骤关闭自动配置开关。
   2. 查询自动部署维护助手“autoscaling\_autoconfig.py”的状态，确保状态为“准备好状态（Ready）”或者查询无该脚本，以保证当前设备不在自动部署过程中。因为若系统当前有正在进行的自动部署，而自动部署生效有时延，此时若关闭自动配置开关，会影响系统配置效果。

      ```
      DSP OPSASSISTSTATE:;
      ```
   3. 关闭自动配置开关。自动化配置命令只有在自动配置开关为关闭的状态下才可执行，因此需要提前关闭。

      ```
      SET AUTOCONFIG:SWITCHFLAG=FALSE;
      ```
4. 配置外联口自动部署模板。

   ```
   ADD AUTOSCALINGSERVICE:SERVICENAME="ServName_Access_100",VPNNAME="VPN_Access",AFTYPE=IPv4,IPALLOCTYPE4=USER_CONFIG,VNICID=4,VLANID=100, BEGINADDR4="192.168.89.2", ENDADDR4="192.168.89.30", MASKLEN=27;  
   ADD AUTOSCALINGSERVICE:SERVICENAME="ServName_Access_200",VPNNAME="VPN_Access",AFTYPE=IPv4,IPALLOCTYPE4=USER_CONFIG,VNICID=5,VLANID=200, BEGINADDR4="192.168.89.34", ENDADDR4="192.168.89.62", MASKLEN=27;
   ```

   * 如果规划外联口使用IPv4v6双栈地址，则分别执行该命令对同一vNIC配置IPv4和IPv6地址。
   * 参数“虚拟网卡ID（VNICID）”使用的是cslbip-pod.yaml中定义的网卡ID。EVS/OVS等非SR-IOV场景中，默认情况下，“虚拟网卡ID（VNICID）”取值=I层网络的vNIC号+2。
5. 增加BFD自动部署模板。

   BFD双向检测时，增加静态路由的动态BFD自动部署模板：

   ```
   ADD AUTOSCALINGSRBFD: SERVICENAME="ServName_Access_100", IPVERSION=IPv4, MINRXINTERVAL=500, MINTXINTERVAL=500, MULTIPLIER=4; 
   ADD AUTOSCALINGSRBFD: SERVICENAME="ServName_Access_200", IPVERSION=IPv4, MINRXINTERVAL=500, MINTXINTERVAL=500, MULTIPLIER=4;
   ```

   BFD单臂echo检测时，增加BFD会话自动部署模板：

   ```
   ADD AUTOSCALINGBFD: TEMPLATENAME="BFD_1", BFDTYPE=Static, SERVICENAME="ServName_Access_100", IPVERSION=IPv4, DESTADDR4="192.168.89.1", MINECHORXINT=500, DETECTMULTI=4, ONEARMECHO=TRUE;
   ADD AUTOSCALINGBFD: TEMPLATENAME="BFD_2", BFDTYPE=Static, SERVICENAME="ServName_Access_200", IPVERSION=IPv4, DESTADDR4="192.168.89.33", MINECHORXINT=500, DETECTMULTI=4, ONEARMECHO=TRUE;
   ```
6. 增加静态路由自动部署模板。

   BFD双向检测时：

   ```
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_100", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.53.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.1", BFDENABLE=TRUE, DESCRIPTION="VPN_Access_ROUTE1"; 
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_200", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.53.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.33", BFDENABLE=TRUE, DESCRIPTION="VPN_Access_ROUTE2";
   ```

   ```
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_100", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.54.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.1", BFDENABLE=TRUE, DESCRIPTION="VPN_Access_ROUTE1"; 
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_200", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.54.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.33", BFDENABLE=TRUE, DESCRIPTION="VPN_Access_ROUTE2";
   ```

   BFD单臂echo检测时：

   ```
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_100", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.53.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.1", BFDENABLE=TRUE, BFDTEMPLATENAME="BFD_1", DESCRIPTION="VPN_Access_ROUTE1"; 
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_200", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.53.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.33", BFDENABLE=TRUE, BFDTEMPLATENAME="BFD_2", DESCRIPTION="VPN_Access_ROUTE2";
   ```

   ```
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_100", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.54.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.1", BFDENABLE=TRUE, BFDTEMPLATENAME="BFD_1", DESCRIPTION="VPN_Access_ROUTE1"; 
   ADD AUTOSCALINGSRROUTE: SERVICENAME="ServName_Access_200", VRFNAME="VPN_Access", IPVERSION=IPv4, PREFIX4="192.168.54.4", MASKLENGTH=32, NEXTHOPALLOCTYPE4=CONFIG, NEXTHOP4="192.168.89.33", BFDENABLE=TRUE, BFDTEMPLATENAME="BFD_2", DESCRIPTION="VPN_Access_ROUTE2";
   ```
7. 打开自动配置开关。

   * 从自动部署开关打开到自动部署功能生效有时延，因此执行其他操作前（例如手动部署路由互通、关闭自动部署开关），务必先执行****DSP OPSASSISTSTATE****命令查询自动部署维护助手“autoscaling\_autoconfig.py”的状态为“准备好状态（Ready）”，否则结果不可预期。
   * 在网关侧上配置到VNF的回程路由，目的地址为VNF上各逻辑接口的IP地址，下一跳为VNF上配置的各逻辑接口对应的外联口的IP地址。

     需要说明的是，配置VNF与DN/PDN通信的回程路由时，目的地址为UE的网段地址。下一跳为VNF上外联口的IP地址，由于自动部署时外联口的IP地址是系统自动分配的，因此建议首先通过命令**LST IFIPV4ADDRESS**查看外联口的IP地址。

   ```
   SET AUTOCONFIG: SWITCHFLAG=TRUE;
   ```

## 验证方法

1. 查看各网元间的路由连接是否正常。

   执行**PING**命令，查看VNF与对端设备间的路由连接是否正常。

   ```
   PING:IPVERSION=IPv4,VPNNAME="VPN_Access",DESTIPV4ADDRESS="对端网关地址";
   ```

   如果使用了VPN组网，还需使用“VPN实例名称（VPNNAME）”指定VPN实例，这样才能验证VPN实例路由是否正常。

   * 如果收到对端网元的响应且响应报文中有成功收发包的个数，表明连接正常，调测结束。
   * 如果连续出现timeout，表明链路不通，请检查本端或承载网是否存在物理接口故障或者路由配置错误，请执行2。
2. 查看接口状态及信息是否与规划数据一致。

   **LST INTERFACE**:;

   * 如果一致，请执行4。
   * 如果不一致，请执行3，再次执行1。
3. 修改外联口自动部署模板。
   1. 关闭自动化配置开关。

      ```
      SET AUTOCONFIG: SWITCHFLAG=FALSE;
      ```
   2. 查询需要修改的外联口自动部署模板并记录服务名称、起始地址和结束地址等参数。

      ```
      LST AUTOSCALINGSERVICE:;
      ```
   3. 查询需要修改的子接口并记录查询结果。记录哪些接口的IP地址在3.b中记录的起始地址和结束地址范围内。

      ```
      LST IFIPV4ADDRESS:;
      ```
   4. 删除3.c中记录的所有子接口。

      **RMV INTERFACE**
   5. 修改外联口自动部署模板。仅填写必选参数和待修改的参数，其他参数不用填写。

      **MOD AUTOSCALINGSERVICE**

      如参数不支持修改，请先删除自动部署模板，然后重新配置自动部署模板。
   6. 打开自动化配置开关。

      ```
      SET AUTOCONFIG: SWITCHFLAG=TRUE;
      ```
4. 检查BFD会话状态是否为up。

   **DSP BFDSESSION**:;

   * 如果状态为up，请执行5。
   * 如果为其他状态，请参考“操作步骤”重新配置。
5. 检查生成的IPv4静态路由是否与规划数据一致。

   ****DSP SRROUTE****:;
   * 如果一致，请执行7。
   * 如果不一致，请执行6，再次执行1，如果问题还存在，则执行7。
6. 修改静态路由自动化部署模板。
   1. 关闭自动化配置开关。

      ```
      SET AUTOCONFIG: SWITCHFLAG=FALSE;
      ```
   2. 查询需要修改的静态路由自动部署模板并记录服务名称、VPN实例名称、路由前缀、路由掩码长度和路由下一跳等参数。

      ```
      LST AUTOSCALINGSRROUTE:;
      ```
   3. 查询需要修改的静态路由并记录查询结果。通过和6.b中的记录结果对比，记录待删除的静态路由。

      ```
      LST SRROUTE:;
      ```
   4. 删除6.c中记录的静态路由。

      **RMV SRROUTE**
