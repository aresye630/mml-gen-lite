# 激活NF授权访问和NF认证功能

- 操作场景
- 必备事项
- 操作步骤
- 验证方法

## 操作场景

- FQDN为“huawei1.com.apn.epc.mnc456.mcc123.3gppnetwork.org”的SMF通过在NRF上设置访问授权，设定只允许AMF访问。
- AMF与NRF之间使用TLS证书认证，保证传输层安全。
- AMF向NRF申请Token，NF间认证，保证应用层安全。NRF支持NF的Access Token申请，NF申请后使用Token进行NF认证。NF服务提供者对NF服务消费者进行认证，利用公钥来校验Access Token中的签名是否正确（NRF上使用私钥，NF上使用公钥）。为保证安全，NRF上使用的私钥是加密保存的。NRF上Access Token的签名算法和NRF上Access Token签名的私钥以及对应的NF侧密钥需要配置。

  **说明** 

  需要提前规划用于Token签名的公私钥对，NRF侧的私钥与此处NF侧配置的公钥配对。

## 必备事项

前提条件

- 需要提前规划用于Token签名的公私钥对，NF侧已经具备了Token安全能力，且NF侧的公钥与NRF上此处配置的私钥配对。
- 完成加载License。
- 已获取商用证书：客户申请。

  **注意** 

  - 如需开启证书域名校验功能，则证书中的域名必须与实际域名保持一致。否则将导致域名校验失败，从而导致NF间建链失败。
  - 华为建议客户通过部署PKI系统对现网设备和软件进行证书的签发，并做好证书的生命周期管理（为保证安全性推荐使用最短有效期的证书）。

## 操作步骤

任务场景1：FQDN为“huawei1.com.apn.epc.mnc456.mcc123.3gppnetwork.org”的SMF通过在NRF上设置访问授权，设定只允许AMF访问。

- NRF侧配置，NF侧不需要配置。

  ```
  //打开授权访问开关。
  SET NRFFUNCSW: AUTHSW=FUNC_ON;
  //在NRF上配置SMF只允许AMF访问。
  ADD ALLOWEDOBJNAME:OBJNAME="objname001";
  ADD ALLOWEDOBJ:OBJNAME="objname001",FQDN="huawei1.com.apn.epc.mnc456.mcc123.3gppnetwork.org";
  ADD ALLOWEDNFTYPES: OBJNAME="objname001", ALLOWEDNFTYPE=AMF;
  CMT ALLOWPLCY: CMTTYPE=ALL;
  ```

任务场景2：NF与NRF之间使用TLS证书认证，保证传输层安全。

- NRF侧配置

  ```
  //上传、增加、关联TLS证书。
  //首先通过NRF的OM Portal上传准备的设备证书和CA证书。
  //增加NRF的TLS证书场景。
  ADD TLSSCENE:INDEX=3, SCENE="NESCENE", TYPE=SCENE_NE, DESC="NRFNESCENE";
  ADD TLSSCENE:INDEX=4, SCENE="CASCENE", TYPE=SCENE_CA, DESC="NRFCASCENE";

  //配置TLS参数和修改服务化接口参数。
  //增加NRF作为服务器端的TLS参数。
  ```

## 验证方法

**操作场景**

该任务用于调测以下功能：

1. SMF只允许AMF访问。
2. NF间Token认证。

**必备事项**

- 前提条件

  操作步骤已配置完成。
- 数据

  该操作无需准备数据。
- 工具

  OM Portal跟踪
