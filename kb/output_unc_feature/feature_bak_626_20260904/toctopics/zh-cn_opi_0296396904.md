## 操作场景

NRF支持NF的自动注册、更新、去注册、NF订阅/通知。本章节介绍AMF如何通过配置实现到NRF的自动注册、更新、去注册、NF订阅/通知。

**说明** 

本章节只是举例重点介绍NF和NRF对接部署逻辑，具体各NF侧的详细配置详见各产品的“初始配置与调测”。

## 必备事项

前提条件

- 具备管理员权限的操作人员已经登录华为操作维护系统（登录U2020/MAE客户端或登录OM Portal）。
- 完成加载License。

- UNC软件安装已完成。

- 请了解UNC各类接口的类型及协议，具体内容请参见业务组网与逻辑接口介绍。
- 对于IPv4组网，已完成自动部署配置动态路由OSPF+BFD组网（IPv4）、配置静态路由+BFD组网（IPv4）、配置BGP over OSPF/静态路由+BFD（IPv4）或手动部署配置动态路由OSPF+BFD组网（IPv4）、配置静态路由+BFD组网（IPv4）、配置BGP over OSPF/静态路由+BFD（IPv4）。
- 对于IPv6组网，已完成自动部署配置动态路由OSPFv3+BFD组网（IPv6）、配置静态路由+BFD组网（IPv6）、配置BGP over OSPFv3/静态路由+BFD（IPv6）或手动部署配置动态路由OSPFv3+BFD组网（IPv6）、配置静态路由+BFD组网（IPv6）、配置BGP over OSPFv3/静态路由+BFD（IPv6）。

## 操作步骤

任务场景1：该任务用于指导AMF向NRF的注册/去注册/更新，NF的订阅/通知功能。

- NRF侧配置

  ```
  //NRF侧路由配置已完成。

  //配置运营商相关信息。
  //配置运营商信息。
  ADD NGMNO: NOID=0, FULLNAME="Operator A", SHORTNAME="OA";
  //配置运营商签约用户的Home PLMN
  ADD NGHPLMN: NOID=0, MCC="123", MNC="03";

  //配置NRF实例信息，此步骤配置后系统会为NRF自动分配InstanceID信息。
  ADD NFUUID: NFTYPE=NfNRF, NFINSTANCENAME="NRF_INSTANCE_0";

  //配置NRF服务化接口数据，使NRF“挂在总线上”，用于跟其他NF对接交互。
  //增加NRF服务化接口的IP地址。
  ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.0.7", VPNINSTNAME="VRF_SBI", DESC="FOR SBI Server";
  ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.0.8", VPNINSTNAME="VRF_SBI", DESC="FOR SBI Client";
  //配置Nnrf接口的HTTP信息。
  ADD HTTPLEGRP: INDEX=3, DESC="NRF";
  //增加NRF作为服务器端的HTTP本端实体。
  ADD HTTPLE: INDEX=5, HTTPLEGRPIDX=3, LETYPE=SERVER, IPTYPE=IPv4, IPV4="172.16.0.7", PORT=8080, VPNNAME="VRF_SBI", TLSFLG=NO, DESC="NRF Server";
  //增加NRF作为客户器端的HTTP本端实体。
  ADD HTTPLE: INDEX=6, HTTPLEGRPIDX=3, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="172.16.0.8", VPNNAME="VRF_SBI", DESC="NRF Client";
  //配置服务化接口的接入点信息。
  ADD SBIAPLE: INDEX=3, HTTPLEGRPIDX=3, NFTYPE=NFTypeNRF, DESCRIPTION="NRF";

  //配置HTTP属性。当NF Profile中包含信元的元素个数超多时，NF的注册、更新、发现等相关请求或响应都可能为产生超大报文，为了避免接收HTTP响应/请求消息体等超时时间内超大报文未发送完成导致业务失败的情况，此NF上可以通过规划配置HTTP属性，协助完成超大报文消息的成功发送，避免发送/请求报文不完整，导致业务处理异常。
  SET HTTPCONF: CLIENTRCVRSPTMT=15, SERVERRCVBDTMT=15, SERVERSNDRSPTMT=15, MAXBODYSIZE=10, MAXJSONLEAFNUM=100000;

  //配置NRF可选信息。
  //修改NRF定时器。
  SET NRFTIMER: NFTYPE=AMF, HBTIMES=3, HEARTBEATTIMER=5, DISCVALIDTIMER=86400, SUBVALIDTIMER=86400;
  ```

  ```
  //打开NRF基本功能（NF注册/更新/去注册、NF订阅/通知）的License。
  SET LICENSESWITCH: LICITEM="LKV2NFBNR01", SWITCH=ENABLE;
  ```

  ```
  //可选：如果号段类NF注册时没有携带支持的号段信息，在NRF上也没有通过配置命令或号段导入的方式配置支持的号段信息，NRF上可以配置这种号段类NF注册后不能被发现或检索，后续变更NRF也不会触发通知，避免由于号段未配置完成/漏配置被认为支持所有号段信息导致基本流程失败。
  SET NRFTAKEPARARULE:NFTYPE=UDM,NOSEGGUARDSW=FUNC_ON;

  //可选：独立部署IMS的PCF支持全网号段的用户，不属于未配置/漏配号段信息的情况，针对这种PCF，NRF支持控制此类PCF注册后能够被发现、订阅/通知或检索，运营商需要提前在NRF上配置独立部署IMS的PCF支持的DNN以便NRF识别和控制其注册后可用。
  ADD NRFIMSDNN: DNN="huawei.com";

  //配置可靠传输能力。
  SET SDRTRANS: FLATTYPE=FABRIC, TRANSABILITY=RELIABILITY, OPT=NOTSET;

  //打开订阅流程开关。
  ADD NRFPARA: NRFINSTANCENAME="NRF_Instance_0", SUBSCRISWITCH=ON;
  ```

  **说明** 

  NF状态通知：NRF根据NF的订阅请求，当收到符合订阅条件的NF发生变化时，NRF自动触发状态通知，不需要额外配置。

| 调测步骤 | 执行LST NFGROUP命令，查看NRF配置的实例组信息是否和规划的一致。如果NRF配置的实例组信息和规划值一致，执行2。如果NRF配置的实例组信息和规划值不一致，再次进行配置后仍无法解决问题请执行4。 执行LST NFIMSI命令，查看AUSF支持的号段信息是否和规划的一致。如果AUSF支持的号段信息和规划值一致，执行3。如果AUSF支持的号段信息和规划值不一致，再次进行配置后仍无法解决问题请执行4。 执行LST NFMSISDN命令和LST NFROUTINGIND，查看UDM支持的号段信息是否和规划的一致。如果UDM支持的号段信息和规划值一致，调测结束。如果UDM支持的号段信息和规划值不一致，再次进行配置后仍无法解决问题请执行4。 收集信息并寻求技术支持。在“MML命令行-UNC”窗口上执行命令EXP MML命令将当前配置数据导出为MML脚本文件并保存。收集并保存上述所有查询信息。收集归纳所有信息并联系华为技术支持解决。 |

**说明** 

每个xml文件记录条数不能超过30万条，如果单个NFType的号段若超过30万条记录，需要拆分为多个xml文件。

相关概念

- **IMSI号段**

  支持XML导入IMSI号段类型的NF：AUSF、PCF、UDM、UDR、CHF、CUSTOM\_OCS，对应**ADD NFIMSI**命令号段类配置，XML模板如下（IMSI号段长度必须是15位，SEGEND大于等于SEGSTART），其中蓝色文字部分为现网应用可以根据实际号段进行修改的内容：

        <data>
            <table name="AUSFIMSI" version="1.0" reparse="false">
                            <record NFGROUPID="ausf-00000001" SEGSTART="800000000000000" SEGEND="800000000099999"/>
