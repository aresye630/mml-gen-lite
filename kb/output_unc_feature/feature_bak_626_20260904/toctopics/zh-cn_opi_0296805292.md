# NRF解决方案垂直分层组网+双活容灾部署配置实例

## 操作场景

- NRF双活容灾组网的相关配置已完成，详细参考NRF解决方案基本功能配置实例（NRF双活容灾+ NF注册/更新/去注册、NF订阅/通知+NF发现）。
- 主备NRF上的号段信息配置已完成，且主备配置一致。
- 对于大型运营商网络，为了便于实现灵活自动化网络管理，需要分层部署NRF，最高层NRF实现运营商网络内所有NF/NFS管理。

  本章节以双层组网为例，如图1所示。

  **图1** 双层+容灾组网举例

## 必备事项

前提条件

- 各组NRF双活容灾组网的相关配置已完成，详细参考NRF解决方案基本功能配置实例（NRF双活容灾+ NF注册/更新/去注册、NF订阅/通知+NF发现）。
- 各个NRF的基础配置和NF基本功能、NF发现配置已完成，详细参考NRF解决方案基本功能配置实例的NRF侧配置。
- 主备NRF上的号段信息配置已完成，且号段信息配置一致。
- 安全相关配置已完成，访问授权和Token认证只需要在L-NRF层配置（Token分配只可能发生在目标NF注册的NRF上），TLS认证需要在所有NRF上配置，详细参考NRF解决方案安全配置实例（NRF容灾+NF访问授权&NF认证）。

## 操作步骤

NRF分层组网配置

NRF双层组网的L-NRF和H-NRF的网络位置及规划如图2所示，其中L-NRF支持向H-NRF注册。

**图2** 不同层NRF的网络位置和南北向NRF组

其中，**AMF区域标识的路由信息：**

H-NRF1和H-NRF2上AMF区域标识的路由信息：

AMF区域标识为01的AMF实例组归属LGP1，

AMF区域标识为02的AMF实例组归属LGP2。

所以，例如L-NRF1处管辖的AMF发现区域标识为02的AMF时，路由顺序为：L-NRF1（L-NRF1本身和配置路由都查不到，向上层查询）→H-NRF1（H-NRF1根据配置查询到AMF区域标识为02的AMF实例组归属LGP2，即L-NRF3/L-NRF4）→L-NRF3

/*- - - - - - - - - - - - - - - - L-NRF1上的配置- - - - - - - - - - - - - - - - - - - - */
//一、配置NRF的基本功能数据，完成NRF作为一个基本的NF的配置。
//NRF侧路由配置已完成。

//配置NRF基础数据。
//配置运营商信息、运营商签约用户的Home PLMN。
ADD NGMNO: NOID=0, FULLNAME="Operator A", SHORTNAME="OA";
ADD NGHPLMN: NOID=0, MCC="123", MNC="03";

//打开NRF基本功能、NF发现的License。
SET LICENSESWITCH: LICITEM="LKV2NFBNR01", SWITCH=ENABLE;
SET LICENSESWITCH: LICITEM="LKV2NFDNR01", SWITCH=ENABLE;
//配置NRF实例信息，此步骤配置后系统会为NRF自动分配InstanceID信息。
ADD NFUUID: NFTYPE=NfNRF, NFINSTANCENAME="NRF_Instancename_l1";

//配置NRF服务化接口数据，用于跟其他NF对接交互。
//增加NRF服务化接口的IP地址。
ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.0.7", VPNINSTNAME="VRF_SBI", DESC="FOR SBI Server";
ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.0.7", VPNINSTNAME="VRF_SBI", DESC="FOR SBI Client";

//配置Nnrf接口的HTTP信息。
ADD HTTPLEGRP: INDEX=3, DESC="NRF";
//增加NRF作为服务器端的HTTP本端实体。
ADD HTTPLE: INDEX=5, HTTPLEGRPIDX=3, LETYPE=SERVER, IPTYPE=IPv4, IPV4="172.16.0.7", PORT=31000, VPNNAME="VRF_SBI", TLSFLG=NO, DESC="NRF Server";
//增加NRF作为客户器端的HTTP本端实体。
ADD HTTPLE: INDEX=6, HTTPLEGRPIDX=3, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="172.16.0.7", VPNNAME="VRF_SBI", DESC="NRF Client";
ADD SBIAPLE: INDEX=3, HTTPLEGRPIDX=3, NFTYPE=NFTypeNRF, DESCRIPTION="NRF";

//二、配置NRF分层组网。
//在NRF上配置打开NRF分层组网的License配置开关。
SET LICENSESWITCH: LICITEM="LKV2NRLNF01", SWITCH=ENABLE;

//配置NRF互联的NRF相关信息，为相邻且相连的NRF之间建立联系。
ADD NRF: NRFINSTANCENAME="Instancename_h1_NRF", TLS=FALSE;
ADD NRFADDR: NRFINSTANCENAME="Instancename_h1_NRF", IPADDRESSTYPE=IPTypeV4, IPV4ADDRESS="10.10.0.7", PORT=31000;
ADD NRFPARA: NRFINSTANCENAME="Instancename_h1_NRF", WAITINTERVAL=60, MAXRETRYTIMES=6;
ADD NRF: NRFINSTANCENAME="Instance_h2_NRF", TLS=FALSE;
ADD NRFADDR: NRFINSTANCENAME="Instance_h2_NRF", IPADDRESSTYPE=IPTypeV4, IPV4ADDRESS="10.20.0.7", PORT=31000;
ADD NRFPARA: NRFINSTANCENAME="Instance_h2_NRF", WAITINTERVAL=60, MAXRETRYTIMES=6;

//L-NRF和H-NRF的南北向配置有两种方案，根据需要选择其中一种。
//方案一：L-NRF和H-NRF间是注册的南北向关系。
//配置L-NRF和H-NRF的注册信息，低层NRF向上一级NRF注册。
//配置L-NRF1的Profile和Service信息，用于携带向上层NRF注册。
ADD NFPROFILE: NFINSTANCENAME="NRF_Instancename_l1", NFTYPE=NfNRF, NFSTATUS=Registered, PRIORITY=1;
ADD NFSERVICE: NFINSTANCENAME="NRF_Instancename_l1", SRVINSTANCEID="service_instance_l1_0", SERVICENAME=NrfNfm, NFSERVICESTATUS=REGISTERED;
ADD NFSERVICE: NFINSTANCENAME="NRF_Instancename_l1", SRVINSTANCEID="service_instance_l1_1", SERVICENAME=NnrfDisc, NFSERVICESTATUS=REGISTERED;
ADD NFSERVICEVER: NFINSTANCENAME="NRF_Instancename_l1", SRVINSTANCEID="service_instance_l1_0", APIFULLVERSION="1.0.0.0";
ADD NFSERVICEVER: NFINSTANCENAME="NRF_Instancename_l1", SRVINSTANCEID="service_instance_l1_1", APIFULLVERSION="1.0.0.0";
//在L-NRF1上配置向H-NRF注册。
ADD NFREGNRF: NFTYPE=NRF, NRFINSTANCENAME="Instancename_h1_NRF", PRIORITY=1;
ADD NFREGNRF: NFTYPE=NRF, NRFINSTANCENAME="Instance_h2_NRF", PRIORITY=2;
//触发L-NRF1向H-NRF注册。
ACT NFONLINE: NFINSTANCENAME="NRF_Instancename_l1";

//配置NRF之间的南北向关系，即确定每个NRF在网络中所处的位置。
//在L-NRF1上配置对应的北向H-NRF组HGP1信息。

ADD NRFBINDGRP: NRFINSTNAME="Instancename_h1_NRF", GROUPNAME="HGP1", ISREGED=FALSE, PRIORITY=1;
