## 操作场景

NRF支持NF/NFS服务发现功能，当NF需要某些特定服务时，向NRF请求发现可用服务，NRF基于已注册的NF/NFS进行筛选，将可用NF/NFS发送给NF。NRF支持基于不同选择条件进行特定NF的选择，有助于不同组网方式下的NF选择。目前NRF主要支持：

- AMF基于多维属性策略选择SMF、PCF、SMSF。
- SMF基于多维属性策略选择UDM、PCF。

**说明** 

- SMF基于SUPI或GPSI选择CHF系统直接支持，无需配置。
- 当被选择的NF或NF服务注册了多个IP时，AMF随机选择其中一个IP进行业务，当此IP故障时，AMF再随机选择其他IP；当故障的IP恢复正常后，此IP地址继续作为备选IP进入后续随机选择的范围。
- NF服务发现过程中，NF对查询发现结果列表有缓存功能，NF服务发现缓存时长可以自定义配置。配置方法请参考《UNC产品文档》“网络部署 > 初始配置与调测”。
- NF注册到NRF时，如果注册信息中没有携带IP地址，只有FQDN，NF间交互时需要使用DNS查询获取对端NF的IP地址，DNS查询需要配置。配置方法请参考《UNC产品文档》“网络部署 > 初始配置与调测”。
- 当AMF同时配置了多种选择策略时，NRF会同时基于所有选择条件选择符合的SMF；如果没有同时满足多种选择策略的SMF时，NRF返回空代表没有符合的SMF。

## 操作步骤

配置AMF灵活选择其他NF

**任务场景1**

AMF为本网用户选择融合PGW-C功能的SMF。

**配置脚本1**

- NRF侧配置

  ```
  //打开NF发现的License配置开关，适用于NRF。
  SET LICENSESWITCH: LICITEM="LKV2NFDNR01", SWITCH=ENABLE;
  ```
- AMF侧配置

  ```
  //打开NF发现的License配置开关，适用于AMF。
  SET LICENSESWITCH: LICITEM="LKV2NFDAM01", SWITCH=ENABLE;
  //AMF为本网用户选择融合PGW-C功能的SMF。
  ADD SMFSELPLCY:SUBRANGE=HOME_USER, EPSIWKCOND=UE_SUBSCRIPTION_DATA-1;
  ```

**任务场景2**

AMF为本网用户基于用户TAI位置选择SMF。

**配置脚本2**

- NRF侧配置

  ```
  //打开NF发现的License配置开关，适用于NRF。
  SET LICENSESWITCH: LICITEM="LKV2NFDNR01", SWITCH=ENABLE;
  ```
- AMF侧配置

  ```
  //打开NF发现的License配置开关，适用于AMF。
  SET LICENSESWITCH: LICITEM="LKV2NFDAM01", SWITCH=ENABLE;
  //AMF为本网用户基于用户TAI位置选择SMF。
  ADD SMFSELPLCY:SUBRANGE=HOME_USER, TAISW=YES;
  ```

**任务场景3**

## 验证方法

1. **调测AMF根据UE能力选择融合PGW-C功能的SMF。**
   1. 进入“MML命令行-UNC”窗口。
   2. 分别在AMF侧和NRF侧，执行****LST LICENSESWITCH****查询本特性对应的License配置开关是否打开。
      - 如果“SWITCH”为“ENABLE”，请执行1.c。
      - 如果“SWITCH”为“DISABLE”，则执行**SET LICENSESWITCH**命令打开本特性对应的License配置开关。
   3. 创建HTTP接口跟踪。
   4. 5G用户接入4/5G融合网络，访问5G业务。
   5. HTTP接口跟踪中观察到，AMF向NRF发起SMF服务发现流程NFDiscover request，NFDiscover request消息携带AMF对SMF的发现参数除target-nf-type，requester-nf-type，service-names，DNN、S-NSSAI等基本发现参数外，还包含pgw-ind参数，且“pgw-ind”的值为“true”。
      - 如果是，请执行1.f。
      - 如果否，请执行1.i。
   6. HTTP接口跟踪中观察，NRF是否向AMF按照请求条件返回SMF。
      - NRF向AMF返回响应成功（200 OK）， 响应中携带NFProfile，NFProfile中包含SMF实例的IP地址或FQDN以及SMF注册的其他关键属性，请执行1.g。
      - NRF向AMF返回响应失败（非200 OK），NRF返回nfInstances为空的数组，请执行1.h。
   7. 在AMF侧，通过**DSP NFCACHE**命令检查AMF上保存的SMF的Profile信息是否与HTTP接口跟踪中NRF返回的SMF Profile信息一致。
      - 如果是，调测结束。
      - 如果否，请执行1.j。
   8. 在NRF上执行**DSP REGNFINSTANCE**观察是否有符合的SMF已注册。
      - 如果是，请执行1.j。
      - 如果否，说明NRF中确实没有符合条件的SMF，属于正常返回，请根据需要部署符合条件的SMF，调测结束。
   9. 执行**LST SMFSELPLCY**命令查看对应用户的SMF选择策略，查看“融合SMF/PGW-C选择条件”是否为“NULL”。
      - 如果是，请参考配置AMF灵活选择其他NF配置AMF根据UE能力选择融合PGW-C功能的SMF，重新执行1.c调测，如果仍无法解决问题请执行1.j。
      - 如果否，请执行1.j。
   10. 收集信息并联系华为技术支持解决。
2. **调测AMF根据UE位置选择SMF。**
   1. 进入“MML命令行-UNC”窗口。
   2. 分别在AMF侧和NRF侧，执行**LST LICENSESWITCH**查询本特性对应的License配置开关是否打开。
      - 如果“SWITCH”为“ENABLE”，请执行2.c。
      - 如果“SWITCH”为“DISABLE”，则执行**SET LICENSESWITCH**命令打开本特性对应的License配置开关。
   3. 创建HTTP接口跟踪。
   4. 5G用户接入5G融合网络，访问5G业务。
   5. HTTP接口跟踪中观察到，AMF向NRF发起SMF服务发现流程NFDiscover request，NFDiscover request消息携带AMF对SMF的发现参数除target-nf-type，requester-nf-type，service-names，DNN、S-NSSAI等基本发现参数外，还包含tai参数。
      - 如果是，请执行2.f。
      - 如果否，请执行2.i。
   6. HTTP接口跟踪中观察，NRF是否向AMF按照请求条件返回SMF。
      - NRF向AMF返回响应成功（200 OK）， 响应中携带NFProfile，NFProfile中包含SMF实例的IP地址或FQDN以及SMF注册的其他关键属性，请执行2.g。
      - NRF向AMF返回响应失败（非200 OK），NRF返回nfInstances为空的数组，请执行2.h。
   7. 在AMF侧，通过**DSP NFCACHE**命令检查AMF上保存的SMF的Profile信息是否与HTTP接口跟踪中NRF返回的SMF Profile信息一致。
      - 如果是，调测结束。
      - 如果否，请执行2.j。
   8. 在NRF上执行**DSP REGNFINSTANCE**观察是否有符合的SMF已注册。
      - 如果是，请执行2.j。
      - 如果否，说明NRF中确实没有符合条件的SMF，属于正常返回，请根据需要部署符合条件的SMF，调测结束。
   9. 执行**LST SMFSELPLCY**命令查看对应用户的SMF选择策略，查看“是否使用TAI”是否为“是”。
      - 如果是，请执行2.j。
      - 如果否，请参考配置AMF灵活选择其他NF配置AMF根据UE位置选择SMF，重新执行2.c调测，如果仍无法解决问题请执行2.j。
   10. 收集信息并联系华为技术支持解决。

      - 如果否，请执行3.i。

      - 如果否，请执行3.j。

      - 如果是，请执行3.j。
      - 如果否，说明NRF中确实没有符合条件的SMF，属于正常返回，请根据需要部署符合条件的SMF，调测结束。

      - 如果是，请执行3.j。
      - 如果否，请参考配置AMF灵活选择其他NF配置AMF选择特定位置区域的SMF，重新执行3.f调测，如果仍无法解决问题请执行3.j。

    5. HTTP接口跟踪中观察到，SMF向NRF发起PCF服务发现流程NFDiscover request，NFDiscover request消息携带SMF对PCF的发现参数除target-nf-type，requester-nf-type，service-names等基本发现参数外，还包含SUPI参数。
       - 如果是，请执行11.f。
       - 如果否，请执行11.i。
    6. HTTP接口跟踪中观察，NRF是否向SMF按照请求条件返回PCF。
       - NRF向SMF返回响应成功（200 OK）， 响应中携带NFProfile，NFProfile中包含PCF实例的IP地址或FQDN以及PCF注册的其他关键属性，请执行11.g。
       - NRF向SMF返回响应失败（非200 OK），NRF返回nfInstances为空的数组，请执行11.h。
    7. 在SMF侧，通过**DSP NFCACHE**命令检查SMF上保存的PCF的Profile信息是否与HTTP接口跟踪中NRF返回的PCF Profile信息一致。
       - 如果是，调测结束。
       - 如果否，请执行11.j。
    8. 在NRF上执行**DSP REGNFINSTANCE**观察是否有符合的PCF已注册。
       - 如果是，请执行11.j。
       - 如果否，说明NRF中确实没有符合条件的PCF，属于正常返回，请根据需要部署符合条件的PCF，调测结束。
    9. 执行**LST APNPCCFUNC**命令查看对应用户的PCF选择策略，查看“选择PCF方式”是否为“IMSI-1”。
       - 如果是，请执行11.j。
       - 如果否，请参考配置SMF侧灵活选择其他NF配置SMF基于IMSI（SUPI）选择PCF，重新执行11.c调测，如果仍无法解决问题请执行11.j。
    10. 收集信息并联系华为技术支持解决。
