# 配置SBI接口（N20/N21）

- 操作场景
- 必备事项
- 操作步骤

## 操作场景

SMSF的服务化接口为Nsmsf，与参考点的对应关系如下。参考点是指5G系统服务化架构映射到传统架构后，对应传统网元之间点对点的接口，用来代表NF之间交互的参考模型，并不是真实的接口。

**图1** Nsmsf接口示意图

**图2** 服务化接口协议栈图

服务化接口间采用相同的协议栈，传输层统一采用HTTP/2协议，应用层携带不同的服务消息。因为底层的传输方式相同，所有的服务化接口就可以在同一总线上进行传输，支撑业务灵活上线。

**说明** 

HTTP/2（HyperText Transport Protocol 2.0）：下一代超文本传输协议。基于HTTP协议的信息交换分为四个过程：建立连接、发送请求信息、发送响应信息、关闭连接。

TLS（Transport Layer Security）：安全传输层协议。在两个通信应用程序之间提供保密性和数据完整性。

- 已经获取网设LLD文档。

数据

**说明** 

本文以IPv4组网为例说明。

- 如果是IPv6组网，请将逻辑接口地址规划为IPv6地址。
- 如果是IPv4v6双栈组网，则对逻辑接口配置双栈地址即可。

## 操作步骤

进入“MML命令行-UNC”窗口。

增加SMSF服务化接口数据。

1. 增加SMSF服务化接口的IP地址，用于和AMF、UDM等NF的对接。

   ```
   ADD LOGICIP:IPVERSION=IPv4, LOGICIPV4="10.2.180.15", VPNINSTNAME="_public_", DESC="FOR SBI";
   ```
2. 配置SMSF服务化接口的HTTP信息。

   ```
   ADD HTTPLEGRP:INDEX=6, DESC="SMSF";
   ```
3. 配置SMSF分别作为HTTP服务的服务端和客户端的本端端点信息。

   ```
   ADD HTTPLE:INDEX=11, HTTPLEGRPIDX=6, LETYPE=SERVER, IPTYPE=IPv4, IPV4="10.2.180.15", PORT=8080, VPNNAME="_public_", TLSFLG=NO, DESC="SMSF_Server";
   ADD HTTPLE:INDEX=12, HTTPLEGRPIDX=6, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="10.2.180.15", VPNNAME="_public_", DESC="SMSF_Client";
   ```
4. 配置SMSF服务化接口的接入点信息。

   ```
   ADD SBIAPLE:INDEX=6, HTTPLEGRPIDX=6, NFTYPE=NFTypeSMSF, DESCRIPTION="SMSF"
   ```

配置SMSF实例信息，用于后续向NRF注册。

1. 配置SMSF的实例名称，配置后系统会为SMSF自动分配InstanceID信息。

   ```
   ADD NFUUID:NFTYPE=NfSMSF, NFINSTANCENAME="SMSF_Instance_0";
   ```
2. 配置SMSF实例的Profile信息，在SMSF向NRF进行注册/更新时携带。

   ```
   ADD NFPROFILE: NFINSTANCENAME="SMSF_Instance_0", NFTYPE=NfSMSF, NFSTATUS=Registered;
   ```
3. 配置SMSF提供的服务实例及其版本信息。

   ```
   ADD NFSERVICE: NFINSTANCENAME="SMSF_Instance_0", SRVINSTANCEID="Service_Instance_0", SERVICENAME=NsmsfSms;
   ADD NFSERVICEVER: NFINSTANCENAME="SMSF_Instance_0", SRVINSTANCEID="Service_Instance_0", APIFULLVERSION="1.R15.0.0";
   ```

配置NRF数据。

1. 配置NRF信息。

   当配置非UUID格式的NRF实例名称时，请提前规划保证各NRF实例名称的前18位字符不能相同。

   ```
   ADD NRF: NRFINSTANCENAME="NRF_Instance_0", TLS=FALSE, PRIORITY=0;
   ```
2. 配置NRF的地址信息。

   ```
   ADD NRFADDR: NRFINSTANCENAME="NRF_Instance_0", IPADDRESSTYPE=IPTypeV4, IPV4ADDRESS="10.16.0.7", PORT=31000;
   ```
3. **可选**：配置NRF协议参数。当开启订阅功能开关时，可以增加订阅条件。当目标NF触发订阅条件和通知事件时，NRF向源NF发送通知。

   ```
   ADD NRFPARA: NRFINSTANCENAME="NRF_Instance_0", WAITINTERVAL=5, MAXRETRYTIMES=3, LOADCARRYINHB=FALSE, SUBSCRISWITCH=ON, OAUTH2SWITCH=OFF;
   ADD SUBCONDITION: NFTYPE=NfUDM, CONDITION=NfInstanceId-1&NFType-0&ServiceName-0&AmfRegionId-0&AmfSetId-0&GuamiList-0&PlmnId-0&NetworkSlice-0&NfGroup-0&Rev1-0&Rev2-0&Rev3-0, REQNOTIFEVENT=NF_REGISTERED-1&NF_DEREGISTERED-1&NF_PROFILE_CHANGED-1;
   ADD SUBCONDITION: NFTYPE=NfAMF, CONDITION=NfInstanceId-1&NFType-0&ServiceName-0&AmfRegionId-0&AmfSetId-0&GuamiList-0&PlmnId-0&NetworkSlice-0&NfGroup-0&Rev1-0&Rev2-0&Rev3-0, REQNOTIFEVENT=NF_REGISTERED-1&NF_DEREGISTERED-1&NF_PROFILE_CHANGED-1;
   ```
4. **可选**：当网络中规划了双主或者主备NRF时，需要配置本步骤。双主NRF场景下，NF对接的优先级高的NRF为本地DC的NRF；主备NRF场景下，NF对接的优先级高的NRF为主NRF。

   ```
   ADD NRF: NRFINSTANCENAME="NRF_Instance_1", TLS=FALSE, PRIORITY=1;
   ADD NRFADDR: NRFINSTANCENAME="NRF_Instance_1", IPADDRESSTYPE=IPTypeV4, IPV4ADDRESS="10.26.0.7", PORT=31000;
   ADD NRFPARA: NRFINSTANCENAME="NRF_Instance_1", WAITINTERVAL=5, MAXRETRYTIMES=3, LOADCARRYINHB=FALSE, SUBSCRISWITCH=ON, OAUTH2SWITCH=OFF;
   ADD SUBCONDITION: NFTYPE=NfUDM, CONDITION=NfInstanceId-1&NFType-0&ServiceName-0&AmfRegionId-0&AmfSetId-0&GuamiList-0&PlmnId-0&NetworkSlice-0&NfGroup-0&Rev1-0&Rev2-0&Rev3-0, REQNOTIFEVENT=NF_REGISTERED-1&NF_DEREGISTERED-1&NF_PROFILE_CHANGED-1;
   ADD SUBCONDITION: NFTYPE=NfAMF, CONDITION=NfInstanceId-1&NFType-0&ServiceName-0&AmfRegionId-0&AmfSetId-0&GuamiList-0&PlmnId-0&NetworkSlice-0&NfGroup-0&Rev1-0&Rev2-0&Rev3-0, REQNOTIFEVENT=NF_REGISTERED-1&NF_DEREGISTERED-1&NF_PROFILE_CHANGED-1;
   ```

   **说明** 

   - 请保证已完成NF到双主或者主备NRF的路由数据配置。
   - 请提前规划**ADD NRFPARA**中“WAITINTERVAL”和“MAXRETRYTIMES”的值，确保NF对NRF的故障探测时长比NRF探测NF的时长要短，避免因链路故障NF还未来得及倒换就被NRF判定为故障。NF探测时长请参考WSFD-114002 NRF双活容灾特性概述中“原理概述”>“可靠性机制”小节。
5. SMSF向NRF发起注册，激活SMSF注册状态。

   ```
   ACT NFONLINE: NFINSTANCENAME="SMSF_Instance_0";
   ```
