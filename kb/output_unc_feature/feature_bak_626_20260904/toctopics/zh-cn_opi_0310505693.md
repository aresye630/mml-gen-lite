## 操作场景

本操作指导介绍在运行网络中激活QCI扩展特性的操作过程。

**说明** 

适用于SGW-C、PGW-C、SMF。

## 对系统的影响

该操作对系统正常运行无影响。

## 必备事项

前提条件

- 请仔细阅读WSFD-109204 QCI 扩展特性概述。
- 完成加载License。

## 操作步骤

1. 进入“MML命令行-UNC”窗口。
2. 打开本特性的License配置开关。

   ****SET LICENSESWITCH****

   **说明** 

   SGW-C和PGW-C分离场景，可能存在PGW-C有扩展QCI的license但是SGW-C无扩展QCI的license的情况。此情况下SGW-C收到携带扩展QCI的专有承载创建请求时的处理受软参控制：

   BIT844 控制SGW-C在无扩展QCI的license时，收到携带扩展QCI的专有承载激活请求是否允许激活成功。

   - 取值为0时，允许激活成功，使用标准QCI。
   - 取值为1时，不允许激活。
3. （可选）配置5G QoS缺省参数，用于纠错。

   **SET 5GCQOSCORRT**
4. （可选）配置EPS QoS缺省参数，用于纠错。

   **SET DEFEPSQOS**
5. （可选）增加、查询标准QCI。

   **ADD STDQOSID**

   **LST STDQOSID**
6. 配置扩展QCI和标准QCI的映射关系的缺省值以及扩展QCI的部分控制开关（例如漫游用户的扩展QCI开关）。

   **SET EXTENQCIATTR**

   **说明** 

   UNC漫游用户使用扩展QCI接入时，可以通过软参BIT\_1858 控制漫游用户使用扩展QCI接入时UNC是否将扩展QCI按照本地配置映射成为标准的QCI处理。

   - 值为0时，按照本地配置映射成标准QCI处理。
   - 值为1时，不按照本地配置映射。
7. 配置/新增扩展QCI和标准QCI的映射关系。

   **ADD EXTENDQCIMAP**
8. 配置QCI到Pre-R8 QoS参数的映射规则。

   **SET EPSQCI2PRER8**
9. （可选）当PCF向SMF发送的N7接口消息中未包含qosChars信元时，需配置扩展QCI的QoS特征。

   **ADD QOSCHARS**

   **说明** 

   当软参DWORD506 BIT4的值为“1”时，无需配置**ADD QOSCHARS**。

## 任务示例

任务描述

运营商规划扩展QCI 64用于支付类业务，在UNC上配置：

- 允许漫游用户使用扩展QCI进行接入网络
- Ga接口话单消息用扩展QCI
- Gy接口CCR消息用扩展QCI
- Radius鉴权和计费请求消息用扩展QCI
- N40接口请求消息用扩展QCI
- 扩展QCI映射为标准QCI的缺省值为1
- 新增扩展QCI 64向标准QCI 8的映射规则

脚本

//打开License配置开关。

```
SET LICENSESWITCH: LICITEM="LKV2UNCQCI1", SWITCH=ENABLE;
```

//允许漫游用户使用扩展QCI进行接入网络，Ga接口话单消息/Gy接口CCR消息/Radius鉴权和计费请求消息/N40接口请求消息用扩展QCI，扩展QCI映射为标准QCI的缺省值为1。

```
SET EXTENQCIATTR:QCICTRLFLAG=ENABLE,GASHOWFLAG=ENABLE,GYSHOWFLAG=ENABLE,RADIUSSHOWFLAG=ENABLE,N40SHOWFLAG=ENABLE,EXTQCIMAPDEFQCI=1;
```

//新增扩展QCI 128向标准QCI 8的映射规则。

```
ADD EXTENDQCIMAP:EXTENDQCI=128,STANDARDQCI=8;
```

//（可选）当PCF向SMF发送的N7接口消息中未包含qosChars信元时，需配置扩展QCI的QoS特征。

```
ADD QOSCHARS: FQI=128, RESOURCETYPE=NON_CRITICAL_GBR, PRIORITYLEVEL=10, PACKETDELBUDGET=1, PACKETERRRATE="4E-6", AVERWINDOW=1;
```
