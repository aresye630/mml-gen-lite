## 操作场景

- NRF采用跨DC（DC1和DC2）的1+1主备组网。DC1内的NF配置DC1内的NRF为高优先级，配置DC2内的NRF为低优先级；DC2内的NF配置DC2内的NRF为高优先级，配置DC1内的NRF为低优先级。
- 本操作指导介绍在运行网络中分别在两个DC新增2台NRF用于设备间地理容灾或者将2个单机运行的NRF改造组成主备容灾的操作过程。

  **说明** 

  NRF容灾部署不建议使用NRF主备容灾，推荐使用NRF双活容灾，NRF双活容灾可靠性更高，也更符合NRF内部容灾的实现原理。

## 必备事项

前提条件

- 完成加载License。
- 待改造的2个单机的NRF需要先升级到UNC 20.6.0及后续版本。
- 已按照自身组网完成NRF主、备之间的路由配置，对于IPv4组网，各配置场景请参考“初始配置与调测”中自动部署配置动态路由OSPF+BFD组网（IPv4）、配置静态路由+BFD组网（IPv4）、配置BGP over OSPF/静态路由+BFD（IPv4）或手动部署配置动态路由OSPF+BFD组网（IPv4）、配置静态路由+BFD组网（IPv4）、配置BGP over OSPF/静态路由+BFD（IPv4）。
- 已按照自身组网完成NRF主、备之间的路由配置，对于IPv6组网，各配置场景请参考“初始配置与调测”中自动部署配置动态路由OSPFv3+BFD组网（IPv6）、配置静态路由+BFD组网（IPv6）、配置BGP over OSPFv3/静态路由+BFD（IPv6）或手动部署配置动态路由OSPFv3+BFD组网（IPv6）、配置静态路由+BFD组网（IPv6）、配置BGP over OSPFv3/静态路由+BFD（IPv6）。

数据

## 操作步骤

NF侧操作步骤

请严格按照操作步骤的顺序进行操作。

NRF侧操作步骤

1. 在NRF1和NRF2上分别配置主备容灾组。
   1. 配置主备容灾实例。

      **ADD DRINST**
   2. 配置主备NRF容灾实例通信地址信息，用于数据同步通道建立。

      **ADD DRCOMM**

      **说明** 

      此命令针对每个NRF需要配置两次，分别为本端NRF实例通信地址信息和对端NRF实例通信地址信息，并且需要先配置本端NRF实例通信地址信息。
2. NRF1和NRF2上的1都完成后，在NRF1和NRF2上分别打开主备容灾的License开关。

   **SET LICENSESWITCH**
3. **可选：**NRF1和NRF2上的2都完成后，在NRF1和NRF2上分别先关闭容灾通道开关，打开主备备份状态忽略开关。

   **说明** 

   如果是新建的2个NRF组成主备NRF，则不需要执行此步骤。

   1. 初始先关闭容灾通道开关。

      **SET DBSOFTPARA**
   2. 打开主备备份状态忽略开关，忽略数据备份状态，NRF允许直接处理业务。

      **SET NRFDRRTSTASW**
4. **可选：**在NRF1和NRF2上分别再打开容灾通道开关，关闭主备备份状态忽略开关，触发NRF间数据同步。

   **说明** 

   如果是新建的2个NRF组成主备NRF，则不需要执行此步骤。

   1. 对同一个NRF，请在3.a执行关闭容灾通道开关1分钟后，打开容灾通道开关，数据可以实时同步。

      **SET DBSOFTPARA**
   2. 关闭主备备份状态忽略开关，NRF进入实时备份状态时，才允许处理业务。

      **SET NRFDRRTSTASW**

## 验证方法

**操作场景**

该任务用于调测NRF主备容灾可靠性功能。

**必备事项**

- 前提条件

  操作步骤已配置完成。
- 数据

  该操作无需准备数据。
- 工具

  OM Portal跟踪

**操作步骤**

| 0    | 1                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
|:-----|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 测试目的 | 验证NRF1故障后，NRF2可以继续业务，NRF1故障恢复后业务连续。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 背景信息 | NRF1和NRF2上数据一致，NF对接的高优先级NRF为NRF1。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 检查点  | 主备的NRF是否进行了数据同步。（调测步骤1~5）NRF1故障后，NRF2是否可以正常处理业务。（调测步骤6~8） NRF1故障恢复后，NRF1是否可以继续正常处理业务。（调测步骤9~11）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 调测步骤 | 执行LST LICENSESWITCH查询NRF主备容灾功能对应的License配置开关是否打开。如果“SWITCH”为“ENABLE”，请执行2。如果“SWITCH”为“DISABLE”，则执行SET LICENSESWITCH命令打开本特性对应的License配置开关。 创建HTTP接口跟踪。NF实例化成功后，向NRF1发送注册请求，HTTP接口跟踪中观察，注册请求消息体是否包含NF实例信息。如果是，请执行4。如果否，检查和修改AMF的注册信息，并重新发起NF注册。 HTTP接口跟踪中观察，NRF1是否返回注册成功（201 Created）的消息。如果是，请执行5。如果否，请执行12。 分别在NRF1、NRF2上执行DSP REGNFINSTANCE命令确认NF的注册数据是否完全相同。如果是，请执行6。如果否，请执行12。 构造NRF1停止服务，与NRF2连接中断。HTTP接口跟踪中观察，NF是否检测到主用NRF异常，随即发送服务化请求给NRF2，包括：发送NF更新请求。 新增某个NF注册。 新增某个NF去注册。 发送订阅请求。 发送订阅通知。 发送PCF、AMF、SMF、UDM、AUSF服务发现请求。 如果是，请执行8。如果否，请执行12。 HTTP接口跟踪中观察，NRF2是否均能正常处理业务，无异常。如果是，请执行9。如果否，请执行12。 构造主用NRF1恢复。HTTP接口跟踪中观察，NF是否检测到NRF1恢复正常（手动配置了切回），随即发送服务化请求给NRF1，包括：发送NF更新请求。 新增某个NF注册。 新增某个NF去注册。 发送订阅请求。 发送订阅通知。 发送PCF、AMF、SMF、UDM、AUSF服务发现请求。 如果是，请执行11。如果否，请执行12。 HTTP接口跟踪中观察，NRF1是否继续正常处理业务，无异常。如果是，调测结束。如果否，请执行12。 收集信息并联系华为技术支持解决。 |

| 0    | 1                                                                                                                                                                                                                                                                                                                                                                                                       |
|:-----|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 测试目的 | 验证NRF数据同步到硬盘，重启后数据不丢失。                                                                                                                                                                                                                                                                                                                                                                                  |
| 检查点  | 检查NRF故障前后，NRF上的NF信息是否一致。                                                                                                                                                                                                                                                                                                                                                                                |
| 调测步骤 | 执行LST LICENSESWITCH查询NRF主备容灾功能对应的License配置开关是否打开。如果“SWITCH”为“ENABLE”，请执行2。如果“SWITCH”为“DISABLE”，则执行SET LICENSESWITCH命令打开本特性对应的License配置开关。 创建HTTP接口跟踪。NF实例化成功后，NF向NRF1发送注册请求；NF发送更新请求，更新部分关键属性；NF发送订阅请求。分别在NRF1、NRF2上执行DSP REGNFINSTANCE命令确认NF的注册、 更新、订阅信息是否一致。如果是，请执行5。如果否，请执行8。 NRF1和NRF2下电。NRF2恢复。在NRF2上执行DSP REGNFINSTANCE命令查询NF的注册、更新、订阅信息是否正确，是否与重启前数据一致，数据无丢失。如果是，调测结束。如果否，请执行8。 收集信息并联系华为技术支持解决。 |

## 任务示例

任务描述

现网2个单机运行的NRF组成主备容灾组，NRF信息如下：

NRF1：容灾实例标识为0，用于数据同步的通信IP地址为10.5.5.1。

NRF2：容灾实例标识为1，用于数据同步的通信IP地址为10.5.5.2。

脚本

- **NRF侧**配置
  1. 两个NRF分别基础数据配置
     - NRF1配置

       ```
       //NRF侧路由配置已完成。

       //配置运营商相关信息。
       //配置运营商信息。
       ADD NGMNO: NOID=0, FULLNAME="Operator A", SHORTNAME="OA";
       //配置运营商签约用户的Home PLMN
       ADD NGHPLMN: NOID=0, MCC="123", MNC="03";

       //配置NRF实例信息，此步骤配置后系统会为NRF自动分配InstanceID信息。
       ADD NFUUID: NFTYPE=NfNRF, NFINSTANCENAME="NRF_INSTANCE_0";

       //配置NRF服务化接口数据，使NRF“挂在总线上”，用于跟其他NF对接交互。
       //增加NRF服务化接口的IP地址。
       ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.0.7", VPNINSTNAME="VRF_SBI", DESC="FOR SBI Server";
       ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.0.8", VPNINSTNAME="VRF_SBI", DESC="FOR SBI Client";
       //配置Nnrf接口的HTTP信息。
       ADD HTTPLEGRP: INDEX=3, DESC="NRF";
       //增加NRF作为服务器端的HTTP本端实体。
       ADD HTTPLE: INDEX=5, HTTPLEGRPIDX=3, LETYPE=SERVER, IPTYPE=IPv4, IPV4="172.16.0.7", PORT=8080, VPNNAME="VRF_SBI", TLSFLG=NO, DESC="NRF Server";
       //增加NRF作为客户器端的HTTP本端实体。
       ADD HTTPLE: INDEX=6, HTTPLEGRPIDX=3, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="172.16.0.8", VPNNAME="VRF_SBI", DESC="NRF Client";
       //配置服务化接口的接入点信息。
       ADD SBIAPLE: INDEX=3, HTTPLEGRPIDX=3, NFTYPE=NFTypeNRF, DESCRIPTION="NRF";

       //配置HTTP属性。当NF Profile中包含信元的元素个数超多时，NF的注册、更新、发现等相关请求或响应都可能为产生超大报文，为了避免接收HTTP响应/请求消息体等超时时间内超大报文未发送完成导致业务失败的情况，此NF上可以通过规划配置HTTP属性，协助完成超大报文消息的成功发送，避免发送/请求报文不完整，导致业务处理异常。
       SET HTTPCONF: CLIENTRCVRSPTMT=15, SERVERRCVBDTMT=15, SERVERSNDRSPTMT=15, MAXBODYSIZE=10, MAXJSONLEAFNUM=100000;

       //配置NRF可选信息。
       //修改NRF定时器。
       SET NRFTIMER: NFTYPE=AMF, HBTIMES=3, HEARTBEATTIMER=5, DISCVALIDTIMER=86400, SUBVALIDTIMER=86400;
       ```

       ```
       //可选：如果号段类NF注册时没有携带支持的号段信息，在NRF上也没有通过配置命令或号段导入的方式配置支持的号段信息，NRF上可以配置这种号段类NF注册后不能被发现或检索，后续变更NRF也不会触发通知，避免由于号段未配置完成/漏配置被认为支持所有号段信息导致基本流程失败。
       SET NRFTAKEPARARULE:NFTYPE=UDM,NOSEGGUARDSW=FUNC_ON;

       //可选：独立部署IMS的PCF支持全网号段的用户，不属于未配置/漏配号段信息的情况，针对这种PCF，NRF支持控制此类PCF注册后能够被发现、订阅/通知或检索，运营商需要提前在NRF上配置独立部署IMS的PCF支持的DNN以便NRF识别和控制其注册后可用。
       ADD NRFIMSDNN: DNN="huawei.com";

       //配置可靠传输能力。
       SET SDRTRANS: FLATTYPE=FABRIC, TRANSABILITY=RELIABILITY, OPT=NOTSET;

       //打开订阅流程开关。
       ADD NRFPARA: NRFINSTANCENAME="NRF_Instance_0", SUBSCRISWITCH=ON;
       ```

  3. 2个NRF上分别配置：NF注册/更新/去注册、NF订阅/通知功能。

