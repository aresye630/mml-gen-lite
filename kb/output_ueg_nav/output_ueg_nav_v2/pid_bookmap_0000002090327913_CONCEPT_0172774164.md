#### 功能描述

此组命令用于对HTTPS通信时使用的相关证书进行加载等操作。认证方式可以分为单向验证和双向验证两种方式：

- 单向验证：仅在服务端需要加载“CAVERIF(CA证书)”或“ROOTVERIF(根证书)”、“DEVVERIF(设备证书)”和“KEYFILE(密钥文件)”。通信过程中仅客户端对服务端进行验证，服务端不对客户端进行验证。
- 双向验证：服务端需要加载“CAVERIF(CA证书)”或“ROOTVERIF(根证书)”、“DEVVERIF(设备证书)”和“KEYFILE(密钥文件)”，客户端需要加载“CAVERIF(CA证书)”或“ROOTVERIF(根证书)”、“DEVVERIF(设备证书)”和“KEYFILE(密钥文件)”。通信过程中客户端和服务端进行相互的验证。

  当软参“HTTPSAUTHSWITCH（HTTPS鉴权开关）”为“1”（即设置为双向验证）时，为提升通信安全性，也可加载“CRLF(证书吊销列表文件)”，用于在建立TLS/SSL连接时校验客户端的CA证书是否在吊销列表中，如果是已经被吊销的证书，则无法建立连接。

客户端与服务器使用HTTPS协议进行通信的过程如图1所示。

**图1** HTTPS认证通信原理图

**过程说明**

1. 客户端发送连接请求给服务端，服务端回应请求消息。
2. 服务端将服务端证书以及同证书相关的信息（例如域名和公钥）发送给客户端进行验证。如果验证通过则客户端认可此服务器的合法身份；否则会给服务端返回警告消息，询问服务端是否需要继续验证。
3. 服务器请求客户端发送证书进行验证。如果验证通过，则服务器获得用户的公钥证书；否则服务器拒绝与客户端连接。

   **说明** 

   此步骤仅适用于双向验证，在单向验证过程中服务端不对客户端进行验证。推荐使用HTTPS单向验证方式。
4. 客户端发送给服务器自己所能够支持的通信对称密码方案。服务器从接收到的方案中选择一种加密程度最高的密码方案，使用客户端的公钥加过密后返回给客户端。针对这个密码方案客户端选择一个通话密钥，用服务端的公钥加过密后发送给服务端。接收到客户端发送过来的消息，服务端用自己的私钥文件解密，获得通话密钥。
5. 安全通信建立。服务器和浏览器通过通话密钥进行安全通信。

#### 相关概念

**HTTPS协议**

在HTTP（超文本传输协议）基础上提出的一种安全的HTTP协议。HTTP协议直接放置在TCP协议之上，而HTTPS是在HTTP和TCP中间加上的一层加密层（SSL），如图2所示。

**图2** HTTPS协议栈

高层的应用协议（如HTTP、FTP、Telnet等）能透明地建立于TLS/SSL协议之上。其在应用层协议通信之前就已经完成加密算法、通信密钥的协商以及服务器认证工作。在此之后应用层协议所传送的数据都会被加密，从而保证通信的安全性。

**数字证书**

数字证书采用PKI（Public Key Infrastructure），利用一对互相匹配的密钥进行加密和解密。每个用户为自己设定一把仅为本人所知的私钥，用于解密和签名。同时设定一把一组用户共享的公钥，用于加密和验证签名。当发送一份保密文件时，发送方使用接收方的公钥对数据加密，而接收方则使用自己的私钥解密。加解密过程是一个不可逆过程，即只有使用公钥对应的私钥才能解密。

**说明** 

用户也可以使用私钥对发送信息加以处理，形成数字签名。由于私钥为用户独有，数字签名可以代表发送者的身份，防止发送者对发送信息的抵赖。接收方通过验证数字签名可以判断信息是否被篡改过。

**证书链**

为验证一个用户的公钥证书，需要获得签发这个用户证书的CA的公钥，才能检查用户证书上的签名。一个公钥证书需要让其上一级CA证明它的身份，验证公钥的过程成为一个叠代过程并形成一个证书链。 例如有以下证书链： 根证书->CA证书->服务端证书。如果需要认证服务端证书，就需要用CA证书，而需要认证CA证书，就必须使用根证书。

**根证书**

根CA（Certification Authority）是认证体系中第一个证书颁发机构，它是所有信任的起源，是自签名CA（使用自己的私钥为自己签名）。根CA为自己颁发的证书即为根证书。根CA可以为其他CA创建证书，也可以为其他计算机、用户和服务创建证书。

**公钥证书**

含有公钥的数字证书。为保证公钥证书的正确性，公钥证书往往需要签发CA对其进行签名。

**私钥文件**

用户密钥对中的私钥文件。为保护私钥文件的私密性，可以对私钥文件进行加密保护，即只有知道私钥的密码才能正常使用私钥。

#### 注意事项

为了提高通信传输的安全性，推荐使用HTTPS认证方式，因为https模式是一种安全的协议，传输过程中会进行加密处理。但同时PGW的处理速度会下降，PGW Web LMT或DMS WebUI的登录、加载、命令传输和报文传输性能会降到HTTP方式的90%。
