# 数据校验管理

- 配置原则

#### 功能描述

本组命令用于指导操作员对本端USCDB网元内的数据进行校验，包括正向校验、正向路由校验、反向校验和反向路由校验。

在升级、扩容、容灾接管、模块故障等场景下，由于需要进行主、备平面切换，以及传输、模块等故障原因将导致数据无法及时同步，USCDB网元的局内数据、容灾局间数据会造成数据不一致，此时可通过本组命令完成数据校验，从而保证数据的一致性。

#### 相关概念

**Channel数据**

Channel数据是一种配置数据，用于计算用户标识在DRU节点中的分布。DRU(Data Routing Unit)模块、DSU(Data Service Unit)模块、非维护中心的DSG（Data Service Gateway）模块向维护中心的DSG模块申请Channel数据，再由维护中心向前述三种模块返回channel数据。这三种模块根据Channel数据可以查找到用户路由数据所在的DRU Cluster。各模块与Channel数据之间的关系图如图1所示。

**反向校验**

反向校验又称为反向水平校验，包括以下类型：

- 在局内，反向校验是一个Cluster内的备节点向主节点发起的校验。如果备节点中存在某用户数据，而主节点中不存在，则以主节点为标准，将备节点中用户删除。
- 在局间，反向校验是容灾局向主用局发起的用户数据的校验。如果容灾局中存在某用户数据，而主用局中不存在，则以主用局为准，将容灾局中用户删除。
- 在局间，全局数据的反向校验是容灾局向主用局发起的校验。如果容灾局中存在某全局数据，而主用局中不存在，则以主用局为准，将容灾局中全局数据删除。容灾接管时，反向校验由主用局发起。

反向校验是保证主备节点、主用局容灾局数据一致性的重要手段之一。

**反向路由校验**

反向路由校验又称为反向垂直校验，是一个DRU Cluster内的主节点向一个DSU Cluster中主节点发起的校验。如果DRU主节点中存在某个用户的路由数据，而对应的DSU主节点中不存在该用户数据，则将DRU节点中路由数据删除。反向校验是保证DSU和DRU节点数据一致性的重要手段之一。

**全局数据**

全局数据是和整个系统相关的数据，包括业务处理用到的模板数据、操作员数据等。全局数据保存在DRU（Data Routing Unit）模块的内存数据库中。

**正向校验**

正向校验又称为正向水平校验，包括以下类型：

- 在局内，正向校验是一个Cluster内的主节点向备节点发起的校验，如果备节点中数据与主节点不一致，则以主节点为标准，将备节点中数据修改正确。
- 在局间，全局数据的正向校验是主用局向容灾局发起的校验。如果主用局的数据与容灾局的数据不一致，则以发起方的数据为准，将对端的数据修改正确。容灾接管时，正向校验由容灾局发起。
- 在局间，用户数据的正向校验是主用局和容灾局互相发起的校验。如果主用局的数据与容灾局的数据不一致，则以最新的数据为准，将对端的数据修改正确。

正向校验是保证主备节点、主用局容灾局数据一致性的重要手段之一。

**正向路由校验**

正向路由校验又称为正向垂直校验，是一个DSU Cluster内的主节点向一个DRU Cluster中主节点发起的校验。如果DSU主节点中存在某个用户数据，而对应的DRU主节点中不存在该用户的路由数据，则将DRU节点中的路由数据修改正确。正向校验是保证DSU和DRU节点数据一致性的重要手段之一。

## 目录内容

- 数据校验管理
  - 局间数据一致性检查（CHK LOCATIONCONS）
  - 显示清除垃圾路由数据的结果(DSP JUNKROUTE)
  - 启动Channel数据CRC检查(STR CHANNELCRC)
  - 重置内存库校验(RST MDBVERIFY)
  - 删除垃圾路由数据(CLR JUNKROUTE)
  - 启动局间全局数据校验(STR GLBDATAVFY)
  - 显示内存库校验结果(DSP MDBVERIFY)
