# 版本补丁管理

- 术语解释
- 功能描述
- 注意事项

#### 术语解释

无。

#### 功能描述

版本补丁管理包括对服务器补丁和热补丁进行管理：

- 如需解决软件已知缺陷或者增加新需求，可通过服务器补丁管理功能通过新文件覆盖文件或新增文件，重启软件模块来解决这些缺陷或者实现新需求。服务器补丁包含加载和回退两个操作，加载成功后，补丁状态变为更新态，回退成功后补丁被删除。当补丁文件需要中断业务进程并重启后生效时，这种类型的服务器补丁又叫做冷补丁。
- 如需在系统运行过程中修改系统以消除缺陷，或需在系统运行过程中添加属性，可通过热补丁管理功能在不影响业务运行的情况下加载补丁文件并升级系统。热补丁管理包括加载补丁文件、激活补丁、去激活补丁、确认补丁、删除补丁、回退补丁文件、显示补丁状态等功能。热补丁有空闲态、去激活态、激活态、运行态等四种状态。四种状态间的转换如图1所示。

#### 注意事项

- 出于安全性考虑，仅系统管理员有权限执行补丁管理操作。
- 补丁被删除后，状态变为空闲态。此时如需重新对补丁进行操作，需重新加载该补丁。
- 各补丁可能具有相关性。对一个补丁进行操作时，其他相关补丁的状态也会发生相应转变。例如，补丁8与补丁2、补丁3相关，且均处于未激活态。当补丁8被激活，补丁2、补丁3也同时被激活。
- 处于激活态的补丁，当所在进程复位或重启后补丁状态为去激活态。
- 主机侧进程复位时，会向后台OMU请求补丁状态以加载相应的补丁文件，遵循如下规则:
  - 备进程的补丁版本及状态以主进程为准。
  - 主进程的补丁版本及状态依赖于该进程当前的补丁状态及同类型进程的状态，符合以下规则: 当该进程上的补丁版本比同类型的进程上处于运行态的最高补丁版本高时，以该进程上的补丁状态为准；当该进程上的补丁版本低于或等于同类进程上最高运行态补丁时，将该进程的补丁状态同步为同类处于运行态的最高版本补丁状态。
