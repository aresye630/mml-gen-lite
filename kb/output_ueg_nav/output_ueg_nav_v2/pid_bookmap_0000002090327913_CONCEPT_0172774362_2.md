# 流量策略管理

- 注意事项
- 配置原则

#### 功能描述

该组命令主要用于对USCDB的流量策略进行管理，包括增加、删除、修改和查询流量策略的功能。在USCDB设备正常运行过程中，系统始终对自身的负荷状态进行监控。随着收到FE发送的消息流量的不断增加，系统的负荷也会逐步加重。当出现负荷过载的时候，系统开始启动流量控制机制，并依据不同的流量策略对各类FE发送的消息流量进行控制，保证系统始终处于饱和稳定的状态。并随着流量的变化实时地进行流量的动态调整。

#### 相关概念

**流量控制**

流量控制是指当发生消息拥塞时，虽然会丢弃掉超出系统承受能力范围之外的过载消息，但可以确保容量内的消息成功，确保大部分用户业务能够正常进行。USCDB提供的流控机制包括：

- 通过CPU进行的流控

  - CPU使用率超过CPU流量控制启动阈值时启动流控，优先丢弃优先级低的消息。
  - CPU使用率低于CPU流量控制结束阈值时解除流控。
- 通过消息时延进行的流控

  - 消息时延超过对应模块时延起控阈值时启动流控，优先丢弃优先级低的消息。
  - 消息时延低于对应模块时延解控阈值时解除流控。

**说明** 

可通过在“USCDB MML命令” 界面执行**LST FLOWCTRL**查询流量控制配置或执行**LST PGWFLOWCTRL**查询PGW流量控制配置。

**流量策略**

流量策略是指在系统正常运行时，根据业务情况对接入的用户设置的允许每秒处理的最大消息数量。系统可以处理的最大消息数量由License控制。根据系统的处理能力、正常运行时的业务情况，分配给不同的用户不同的流量。每个应用的链接的控制总量可以从局点部署的配置情况中获取，系统最大的消息数量可以从系统License的合同值获取。

流量策略对应用的流量分配方式如表1所示。

| 分配方式             | 描述说明                                                                               |
|:-----------------|:-----------------------------------------------------------------------------------|
| 统一消息流量控制         | 对所有应用不预分配消息流量。当系统的流量达到流控阈值时统一控制。                                                   |
| 按应用分配消息流量        | 按照各种应用预分配消息流量，流量之和小于等于系统总消息流量。当某个应用的消息流量达到分配的流量限额时，进行单独控制。                         |
| 统一控制和按应用分配消息流量并存 | 部分应用预分配流量，另一部分应用不预分配流量。当分配流量的应用达到流量限额时，系统对其流量进行单独控制；未分配流量的应用不单独控制，当其流量达到流控阈值时统一控制。 |

#### 注意事项

系统在启用流量策略管理之前需要先申请按TPS（Transaction Per Second）销售的License。

**说明** 

License按TPS（Transaction Per Second）销售的流量策略功能，该版本暂不支持。

#### 配置原则

本命令组无特殊配置原则。
