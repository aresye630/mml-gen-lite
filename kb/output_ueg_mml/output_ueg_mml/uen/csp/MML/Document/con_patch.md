## 命令功能

该命令用于请求系统对指定的模块执行确认补丁操作。命令成功运行后参数指定的补丁状态变为运行态。

如果不输入模块号，表示对整个网元下所有补丁状态处于激活态的进程进行确认操作。

该命令的使用场景为：当处于激活状态的补丁在运行中没有出现异常，操作员希望该补丁程序完全替代原有节点程序运行时，就可以使用该命令对已激活的补丁执行确认操作。

## 注意事项

- 操作员在使用**ACT PATCH**命令对补丁激活后，可以使用本命令对补丁进行确认，否则模块重启后，补丁将无法生效。确认后，补丁状态进入运行状态，操作员将不能使用**DEA PATCH**命令对补丁执行去激活操作。可以使用**ROL PATCH**命令或者**RMV PATCH**将确认的补丁删除。
- 只能确认处于激活状态的补丁。
- 确认成功后补丁处于运行状态。
- 网元ID为0时是对CSP网元的模块进行操作，网元ID>4时是对业务网元的模块进行操作。
- 正常情况下应该对同一网元的同一模块类型所有模块进行确认补丁操作，对于同一网元下同一模块类型的模块只针对其中部分模块进行了确认补丁的操作，则可能会造成模块功能不一致的问题，此时会有2375号告警(同一类型模块确认的补丁个数不一致告警)上报。当发现有该告警上报时，请针对该模块类型的所有模块做相同的补丁操作，以保证模块功能一致。 此时，该告警会自动清除。
- 当部分进程加载失败，报文中显示“补丁正在初始化，操作失败”时，节点正在进行补丁恢复。请稍后重试此操作，如果重试三次问题仍然没有解决，请联系华为技术支持处理。

## 参数说明

| 参数标识   | 参数名称   | 参数说明                                                                                                                                                                                  |
|:-------|:-------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| MEID   | 网元ID   | 可选必选说明：必选参数。 参数含义：标识一个补丁操作的关键字段之一，用于请求系统需要对哪一个网元实例实施操作。 取值范围： 0～1023。 默认值： 无。 配置原则：操作员可以通过在LST ME命令查询获得所有的网元实例ID。                                                                     |
| MN     | 模块号    | 可选必选说明：必选参数。 参数含义：用于请求系统需要对指定网元下哪一个模块实施操作。 取值范围： 0～4294967294 默认值： 无。 配置原则：操作员可以通过在MEID指定的网元实例上使用LST MODULE命令查询模块号及对应的模块类型，然后根据模块号进行补丁操作。缺省为对指定网元下所有相应的模块实施补丁操作。对指定模块实施操作一般只用于故障处理场景。 |
| AS     | 主备标记   | 可选必选说明：必选参数。 参数含义：用于请求系统需要对指定模块的主或备进程实施补丁操作。 取值范围： “ACTIVE(主)”“STANDBY(备)” 默认值： 无。 配置原则：其值域类型为枚举类型。缺省为对主、备进程都实施补丁操作。对指定模块的主备实施操作一般只用于故障处理场景。                                          |
| PNAME  | 补丁名称   | 可选必选说明：必选参数。 参数含义：标识补丁操作的关键字段之一。 取值范围：长度不超过32的字符串。 默认值：无。 配置原则：命名规则是SPHXXX或HPXXXX，其中SPHXXX表示热补丁，HPXXXX表示紧急热补丁。以补丁名称进行操作时，是对补丁包中所有单个补丁文件进行相应操作。该参数大小写不敏感。                              |

## 使用实例

1. 确认补丁：“网元ID”为“0”，“模块号”为“3017”，“主备标记”为“主”，“补丁名称”为“SPH001”:

   `CON PATCH: MEID=0, MN=3017, AS=ACTIVE, PNAME="SPH001";`

   ```
   %%CON PATCH: MEID=0, MN=3017, AS=ACTIVE, PNAME="SPH001";%%
   RETCODE = 0  操作成功

   操作结果如下
   ------------
     网元ID  =  0
     模块号  =  3017
   主备标记  =  主
   补丁名称  =  SPH001
   补丁状态  =  运行
   操作结果  =  成功
   (结果个数 = 1)

   ---    END
   ```
2. 确认补丁：“网元ID”为“5”，“主备标记”为“主”，“补丁名称”为“SPH001”:

   `CON PATCH: MEID=5, AS=ACTIVE, PNAME="SPH001";`

   ```
   %%CON PATCH: MEID=5, AS=ACTIVE, PNAME="SPH001";%%
   RETCODE = 0  操作成功

   操作结果如下
   ------------
     网元ID  =  5
     模块号  =  1000
   主备标记  =  主
   补丁名称  =  SPH001
   补丁状态  =  运行
   操作结果  =  成功
   (结果个数 = 1)

   ---    END
   ```

## 输出结果说明

| 输出项名称   | 输出项解释                                                                                                             |
|:--------|:------------------------------------------------------------------------------------------------------------------|
| 网元ID    | 该参数标识了网元ID。                                                                                                       |
| 模块号     | 该参数标识了所加载补丁的模块号。                                                                                                  |
| 主备标记    | 该参数标识了执行补丁操作的模块状态。其值域类型为枚举类型。 取值说明： “ACTIVE(主)”“STANDBY(备)”                                                       |
| 补丁名称    | 用于标识补丁名称。命名规则是SPHXXX或HPXXXX，其中SPHXXX表示热补丁，HPXXXX表示紧急热补丁。以补丁名称进行操作时，是对补丁包中所有单个补丁文件进行相应操作。                          |
| 补丁状态    | 补丁操作的结果信息之一，用于表示补丁单元的运行状态。其值域范围为枚举类型。 取值说明： “运行”：表示补丁安装成功。“激活”：表示补丁安装过程中的中间状态。“去激活”：表示补丁安装过程中的中间状态。“空闲”：表示没有安装补丁。 |
| 操作结果    | 用于描述补丁操作的结果。                                                                                                      |
