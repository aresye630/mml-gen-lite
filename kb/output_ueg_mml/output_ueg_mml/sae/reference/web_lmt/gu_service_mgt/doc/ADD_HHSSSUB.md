## 命令功能

该操作用于在HSS的业务数据库中增加一个IMS用户的信息，包括：

1. 唯一标识该IMS用户的SUBID，可以使用能力集模板为该IMS用户的签约能力集信息，也可以设置该用户的“一致性标识”。
2. 1个到2个支持HTTP Digest鉴权、SIP Digest鉴权、Early AKA鉴权或者Trusted Access鉴权模式的IMPI，可以使用计费地址模板为IMPI签约计费地址信息。
3. 1个到10个IMPU，可以使用IMPU模板和ServiceProfile模板为这些IMPU设置签约业务信息，并将这些IMPU设置为同一个隐式注册集和别名组。

当HSS用户模型同时满足以上特征时，操作员可以使用该命令进行一键式开户，以提升开户效率。

## 注意事项

- 执行该命令开户时，不能预先通过**ADD HIMSI**设置“IMPI”或“IMPI2”与IMSI的关联关系。
- 当**SET HSYSTEMPARA**命令中“一键式开户指令是否支持设置主卡”参数设置为“TRUE”，且该命令中参数“IMPI的鉴权类型”或“IMPI2的鉴权类型”取值为“AKA(IMS AKA)”时，设置该命令携带的第一个IMSI为主卡，通过该方式设置的主卡和通过**MOD HMSIM**设置主卡的效果一样。
- 当参数“IMPI的鉴权类型”或“IMPI2的鉴权类型”取值为“AKA(IMS AKA)”时，携带的“IMSI”或“IMSI2”不能预先通过**ADD KI**命令添加KI记录。
- 当参数“IMPI的鉴权类型”为“HDA”或者“SDA”时，存在“HA1值”和“用户名称”、“密码”两种加密方式。对于一个“IMPI”，“HA1值”和“用户名称”、“密码”只能存在一种，即只存在“HA1值”或只存在“用户名称”和“密码”的组合。推荐使用HA1值。
- 当参数“IMPI2的鉴权类型”为“HDA”或者“SDA”时，存在“HA1值2”和“用户名称2”、“密码2”两种加密方式。对于一个“IMPI”，“HA1值2”和“用户名称2”、“密码2”只能存在一种，即只存在“HA1值2”或只存在“用户名称2”和“密码2”的组合。推荐使用HA1值2。
- 当**SET MAPCONF**命令中的“是否启用随机密钥”参数为“TRUE”，本命令中的“IMPI的鉴权类型”或“IMPI2的鉴权类型”参数为“HDA(HTTP Digest)”或“SDA(SIP Digest)”，执行该命令时如果未执行**SET DEFAULTK2SNO**命令设置默认HK2，则执行该命令时会返回错误。
- 当**SET MAPCONF**命令中参数“ADD HHSSSUB命令是否检查IMSI和MSISDN的对应关系”取值为“TRUE”时，对于VoLTE用户，必须先执行**ADD SUB**在2G/3G/4G开户后，才能执行**ADD HHSSSUB**命令在IMS域进行开户。
- 当**SET MAPCONF**命令中参数“ADD HHSSSUB命令是否检查IMSI和MSISDN的对应关系”取值为“TRUE”时，执行该命令需要检查“IMSI”和“MSISDN”的对应关系，当请求中同时携带了“IMSI”和“MSISDN”，则通过该“IMSI”查询2G/3G/4G表。
  - 如果“IMSI”记录存在，且查询的“MSISDN”和命令请求中携带的“MSISDN”相同，则命令执行成功。
  - 如果“IMSI”记录存在，但是查询的“MSISDN”和命令请求中携带的“MSISDN”不同，则命令执行失败。
  - 记录“IMSI”记录不存在，则通过“MSISDN”号码查询2G/3G/4G表。
    - 如果“MSISDN”记录存在，则命令执行失败。
    - 如果“MSISDN”记录不存在，则正常进行IMS开户。

  当**SET MAPCONF**命令中参数“ADD HHSSSUB命令是否检查IMSI和MSISDN的对应关系”取值为“FALSE”时，则不检查“IMSI”和“MSISDN”的对应关系。
- 当通过**SET HSYSTEMPARA**命令设置“USINGHLRSNFORIMS（是否启用IMS-HSS的分权分域功能）”软参为“TRUE(TRUE)”时，执行该命令时需要注意：
  - 引用用户签约的“HLR序列号”下的计费模板、IMPU基本信息模板、ServiceProfile模板及能力集模板。
  - 本命令的“系统序列号”与签约IMS用户模板对应的“HLR序列号”要一致。
- 在混合组网下，如存在异常场景下进行跨SP数据迁移时，需要通过设置“USERDATAMIGEXCEPENHANCESW（用户数据迁移容错能力增强开关）”软参支持数据的兼容处理，避免因为UDB和PaasDB数据模型不一致而处理失败。
  - 插件包schemamap.xml文件中配置RDN冲突节点（rdnconflictexcepproc），即从5G接入查询4G用户和用户数据迁移过程中该节点存在冲突记录时，若该软参为“1”，根据timestampfield配置字段取最新的一条数据，无timestampfield配置，随机取一条数据；若软参为“0”，则从5G接入查询4G用户和迁移失败。
  - 插件包schemamap.xml文件中配置无父节点的节点（noparentnodeexcepproc），即从5G接入查询4G用户和用户数据迁移过程中该节点无父节点记录时，若软参为“1”，忽略该节点数据不处理；若软参为“0”，则从5G接入查询4G用户和迁移失败。
