## 命令功能

**须知** 

本命令属于高危命令，执行不当会造成用户的补充业务失效，因此执行该命令前，需要与华为技术支持确认后才可以实施。

该命令用于将UDM对接的业务实体地址按照支持“PLMN自定义补充业务”的不同添加到业务实体表中，以及对业务实体表中的记录进行删除。

在语音呼叫或短消息等流程中，UDM在收到SRI/SRI\_FOR\_SM消息时，会检查对应业务的业务实体表，从而判断如何进行下一步。在这个判断过程中，通过该命令配置的业务实体表可以实现以下功能之一或之二：

- 包含全部支持特定补充业务的业务实体，和SRI/SRI\_FOR\_SM消息源地址进行匹配，从而判断源地址中的业务实体是否支持对应的补充业务，并实现相应补充业务的功能。
- 包含全部支持特定补充业务的业务实体，供UDM进行查询，从而将消息路由到业务实体表中支持对应补充业务的业务实体上，并由该业务实体来进行下一步的处理。
- 作为灰名单或白名单，和SRI/SRI\_FOR\_SM消息源地址进行匹配，当源地址中的业务实体在对应的业务实体表中时，不进行某些特定的处理。

业务实体表的具体功能请参见参数说明中的“PLMN自定义补充业务”枚举值的说明。

## 注意事项

该命令不允许进行批操作。

| SESERVICE  | PLMN自定义补充业务   | 仅当“操作类型”取值为“ADD”或“DELETE”时，该参数有效。用于标识业务实体作用的PLMN自定义补充业务。 取值范围：RBT：对应的业务实体为支持彩铃业务的GMSC（Gateway Mobile Switching Center）。UDM在处理SRI消息时，如果发现用户签约了主叫端局彩铃（即用户签约的自定义补充业务码，运营商通过SET MAPSERV命令定义，并通过MOD PLMNSS命令为用户签约），则首先判断发起SRI请求的GMSC是否在SELIST表的RBT业务中有配置: 是，则说明该GMSC支持彩铃，在返回MSRN的SRI响应消息中携带其签约的所有主叫端局彩铃业务码。否，则说明该GMSC不支持彩铃，在返回MSRN的SRI响应消息中不携带彩铃业务码。 CRGMSC：在彩铃业务中，若GMSC不支持彩铃，通过增加支持彩铃呼叫转接的CR-GMSC来实现彩铃业务，参数“PLMN自定义补充业务”设置为“CRGMSC”，参数“地址号码”配置为可以提供彩铃呼叫转接的GMSC。SOR：对应的业务实体为可以支持SOR（Supporting of Optimal Routing）功能的GMSC。优化路由功能可以减少网间话路资源，提升网络利用率和网络性能。必须已通过SET MAPCONF命令将“是否支持SOR功能”参数值设置为“TRUE”，即UDM支持SOR功能。GMSCPRE：对应的业务实体为可以提供定制局点彩铃的GMSC，当选择此项时，“地址号码”和“虚拟漫游号码前缀”为必选参数。UDM在处理SRI消息时，如果SRI请求消息中携带GMSC号码，则根据业务实体表和最大匹配的原则，在业务实体类型为GMSCPRE的记录中，获取对应的虚拟漫游号码前缀。如果携带GMSC号码，且在业务实体表中匹配到，则将获取的虚拟漫游号码前缀和去掉了国家码前缀的MSISDN号码一起组成虚拟漫游号码。如果未携带GMSC号码或者匹配不到GMSC号码，但之前配置了一条全0的默认号码前缀记录，则取该默认前缀和去掉了国家码前缀的MSISDN号码一起组成虚拟漫游号码。如果匹配不到虚拟漫游号码前缀，且未配置默认前缀，或组成的虚拟漫游号码长度超过最大值15，则按非彩铃用户正常进行后续SRI处理，UDM向被叫VMSC正常获取MSRN漫游号码。 如果正常生成虚拟漫游号码，则在SRI响应消息中，返回虚拟漫游号码给GMSC。 MIMSI：对应的业务实体为支持一号多卡的MSC。当选择此项时，“PREFIX”为必选参数。一号多卡业务分为主附卡、同振、顺振、平等卡四种。其中同振和顺振需要VLR支持。当UDM收到SRI消息时，如果判断VLR不支持同振或顺振，即以下两种情况：VLR没有通过ADD VLRTYP命令进行增加VLR类型数据，以关联NCC（Network Capability Configuration）模板。VLR已通过ADD VLRTYP命令关联了NCC模板，但NCC模板中“是否支持同振或顺振”取值为“NR”，即VLR不支持同振顺振功能。 此时如通过本命令添加了支持同振顺振的MSC号码前缀到业务实体表中，UDM则会到业务实体表中寻找一个支持同振顺振的MSC，将该MSC的号码前缀和用户的MSISDN号码组成虚拟漫游号码。UDM返回SRI响应消息到VLR，消息中携带该虚拟漫游号码。之后VLR发送IAM消息至支持同振顺振的MSC，并由该MSC代替VLR重新发送SRI消息到UDM取漫游信息。 SMSCF：对应的业务实体为支持短消息前转（SMSCF）的HLR。此项是为了防止短消息前转死循环进行设置，将所有支持短消息前转的HLR添加到业务实体表中。如果设置了支持短消息前转的业务实体表，则在进行短消息前转之前，本局HLR会判断SRI消息的源地址是否在支持短消息前转的业务实体表中： 是，说明发送SRI请求消息的对端是支持短消息前转的HLR，为防止经过若干次前转之后重新前转到该HLR，造成死循环，短消息不再进行前转，直接返回SRI响应消息。否，说明发送SRI请求消息的对端是短消息中心SMSC，不会出现死循环，本局HLR根据用户配置的短消息前转号码，并进行短消息前转。 WSM：对应的业务实体为欢迎短消息的AS。UDM在向AS下发USSD请求消息的时候，需要知道AS的GT地址，通过配置此项，在位置更新确认之后，UDM会根据此项配置的支持欢迎短消息的业务实体表查询AS_GT地址，并发送USSD请求，AS在接收到USSD请求之后发送欢迎短消息。 NPMSC：对应的业务实体为支持携出用户附着的MSC。NPMSC用来管理和存储携出用户数据，在归属HLR获取漫游号码的同时指明用户携出的运营商路由码RN（Routing Number），同时为携出用户提供短信转发功能。SMSROUTE：对应的业务实体为支持短消息重定向的SMS_Router地址。如果配置多个SMS_Router地址，则按照轮询方式选择地址。SMSGRAY：对应的业务实体为不需要短消息重定向的SMSC，选择此项将SMSC地址添加到短消息重定向灰名单中，UDM对灰名单中的SMSC不进行短消息重定向。当UDM支持全局性的短消息重定向，即通过SET MAPSERV命令设置了参数“短消息重定向类型”取值为“Global”时，UDM收到SRI_FOR_SM短消息取路由请求消息后，判断被叫用户是否签约了用户级的短消息重定向。如果没有签约，则判断请求消息中的源地址是否匹配SELIST业务实体表中的SMS-Router地址或SMSGRAY地址： 是，按普通短消息取路由处理，处理后给SMSC发送响应消息。否，在SELIST业务实体表中轮选SMS-Router的地址，将SRI_FOR_SM短消息取路由请求消息转发出去。 说明：SMSROUTE和SMSGRAY两个枚举值的区别如下：在UDM对SRI_FOR_SM消息是否重定向的判断中，SMS-Router地址和SMSGRAY地址列表的作用是相同的，但不触发短消息重定向的原因不同。当SRI_FOR_SM消息的源地址匹配业务实体表中的SMS-Router地址时，说明消息的源地址是SMS-Router，所以不会再触发短消息重定向；而对SMSGRAY地址列表中的地址不再触发短消息重定向，是为了防止短消息重定向业务和其他短消息应用业务冲突，对设定的SMSC不进行短消息重定向。在UDM确定需要进行短消息重定向之后，只会根据SMS-Router列表中的地址进行轮选，并转发SRI_FOR_SM消息，而跟SMSGRAY地址列表无关。 SPECVLR：对应的业务实体为特定VLR。GMLC：对应的业务实体为支持LCS增强特性的GMLC。在LCS业务流程中，当UDM收到GMLC发送的SRIFORLCS（Send Routing Info for LCS）消息或RIR请求消息时，如检查到以下两种情况：用户没有签约LCS业务。用户签约了LCS业务，但SRIFORLCS请求消息或RIR请求消息中携带的GMLC地址和用户签约的LCS模板中的GMLC地址不匹配。 此时，UDM如继续检查到已通过SET MAPCONF命令设置了“是否支持对SRIFORLCS进行特殊处理”参数或“是否支持对RIR进行特殊处理”参数取值为“TRUE”时，即支持对SRIFORLCS消息或RIR请求消息进行特殊处理，并且SRIFORLCS请求消息或RIR请求消息中携带的GMLC地址在业务实体表中已经配置，则正常返回用户的位置信息，并且跳过GMLC的区域限制检查。 GROUPSIM：对应的业务实体为支持多SIM用户组业务的GMSC。当选择此项时，“虚拟漫游号码前缀”为必选参数。在MultiSIM短消息的发送流程中，UDM收到GMSC发送的SRIFORSM消息，当满足以下三个条件时：UDM检查到SRIFORSM消息中携带的发送目标号码为组MSISDN号码。GMSC不支持MultiSIM功能。语音接收号码未配置（通过MOD GROUPSIM命令中的“语音接收号码”参数配置）。 则UDM检查SELIST中是否配置了支持多SIM用户组业务的GMSC地址：是，消息中携带虚拟漫游号码，由SET SELIST命令配置的号码前缀和用户的MSISDN号码组成。GMSC发送IAM消息至支持多SIM用户组业务的GMSC，并由该GMSC重新发送SRI消息到UDM取漫游信息。否，拒绝此次呼叫。 IMSSF：对应的业务实体为用于处理camel业务的网元IM-SSF（IP Multimedia Service Switching Function）。在IM-SSF获取IM-CSI智能业务数据的流程中，IM-SSF向UDM发送ATSI消息查询用户的CSI数据。UDM检查当前IM-SSF是否在SET SELIST中设置的IM-SSF地址列表中，是则在CS动态信息表（通过LST DYNSUB命令可以查看）中记录IM-SSF地址，否则不记录IM-SSF地址。之后UDM向IM-SSF返回ATSI响应消息，包含所需要的CSI数据。 ICSSMSROUTER：对应的业务实体为支持ICS业务的SMS-Router。UDM在收到SRIFORSM取路由消息之后，如果用户签约了ICS业务（用户签约的PLMNSS和通过SET MAPSERV配置的参数“ICS业务的PLMN自定义补充业务”的值相同），则检查是否通过SET SELIST命令配置了ICSSMSROUTER类型的业务实体表，如果相应的SELIST业务实体表已进行了配置，则从表中轮选一个SMS-Router的地址，在响应消息中携带，GMSC收到响应消息之后，根据消息中的SMS-Router的地址向SMS-Router发送Forward_SM_For_MT消息。 MMS：对应的业务实体为支持多媒体短消息的SMSC。在MultiSIM短消息的发送流程中，SMSC向主号码发送SRIFORSM消息，UDM检查SRI消息的源地址是否为支持MMS（Multimedia Messaging Service）的短消息中心SMSC，即源地址是否在参数值为MMS的SELIST业务实体表中；是则UDM继续检查用户是否配置了MMS接收号码（通过设置MOD GROUPSIM命令中的“MMS接收号码”参数进行配置），并查询该MMS接收号码是否为本HLR用户；如果是本HLR用户，则在响应消息中返回该MMS接收号码用户的MSC地址，如果不是本HLR用户，则对该用户模拟发送SRIforSM(处理同短消息前转)。 SAIADDR：对应的业务实体为在VLR取鉴权集流程中不需要UDM记录的VLR。为了保持UDM与VLR数据的一致性，UDM需要在鉴权时在CS动态信息中记VLR地址录（通过LST DYNSUB命令可以进行查询），并在完成注册之后进行清除。在位置更新流程中，如果UDM检测到当前的鉴权VLR地址与当前注册的VLR地址不相同，则会在则在CS动态信息中记录。而如果通过SET SELIST命令设置了不需要UDM记录的VLR白名单，则会对白名单中的VLR地址不进行记录。 说明：通过SET MAPCONF命令的中“是否支持鉴权时记录VLR地址”参数控制是否开启支持记录鉴权VLR地址信息，默认值为“FALSE”，即不支持记录鉴权VLR地址。如果没有配置SET MAPCONF支持此功能，则不会记录VLR地址，也就不用配置VLR白名单。 CSFBPROXY：对应的业务实体为CSFB Proxy。在移动终呼漫游重试流程中，UE检测到联合附着MSC(即Old MSC)非当前服务的MSC，会向当前服务MSC(即New MSC)发起位置更新请求。UDM收到位置更新请求后，会检查Old MSC的地址是否在“PLMN自定义补充业务”参数值为“CSFBPROXY”的SELIST业务实体表中，是则说明Old MSC为CSFBPROXY，UDM将CLR消息的发送时机延迟到位置更新结束后才发送，同时CLR消息中携带New VLR的地址。 SPECGT：当参数“地址号码”配置为支持冰岛组网时，选择此项。当选择此项时，“地址号码”和“IMSI/ISDN号码前缀”为必选参数。HPLMNSNGREY：用于设置本运营商网络中与UDM交互的GMSC、SMSC或SCP设备灰名单。当与UDM交互的设备在该灰名单中，则当SET MAPSERV中“本局信息选取方式”参数设置为“OMU_HLRSN”或“OMU_IMSIPREFIX”时，选取本局GT和HLR号码时使用ADD HLRSNOFI命令配置的“归属GT”和“归属HLR号码”作为本局信息。当与UDM交互的设备不在该灰名单中，则当SET ## 使用实例

1. 在业务实体表中增加一条支持彩铃业务的GMSC地址记录，设置“HLR序列号”为“1”，“操作类型”为“ADD”，“PLMN自定义补充业务”为“RBT”，“地址号码”为“861380755001”：

   ```
   SET SELIST: HLRSN=1, OPTYPE=ADD, SESERVICE=RBT, ADDR="861380755001";
   ```
2. 在业务实体表中增加一条可以提供定制局点彩铃的GMSC地址记录，设置“HLR序列号”为“1”，“操作类型”为“ADD”，“PLMN自定义补充业务”为“GMSCPRE”，“地址号码”为“861380755002”，“虚拟漫游号码前缀”为“4600000”：

   ```
   SET SELIST: HLRSN=1, OPTYPE=ADD, SESERVICE=GMSCPRE, ADDR="861380755002", PREFIX="4600000";
   ```
3. 在业务实体表中删除一条支持一号多卡的GMSC虚拟漫游号码前缀记录，设置“HLR序列号”为“1”，“操作类型”为“DELETE”，“PLMN自定义补充业务”为“MIMSI”，“虚拟漫游号码前缀”为“4600000”：

   ```
   SET SELIST: HLRSN=1, OPTYPE=DELETE, SESERVICE=MIMSI, PREFIX="4600000";
   ```
4. 在业务实体表中删除所有的业务实体记录，设置“HLR序列号”为“1”，“操作类型”为“DELETEALL”：

   ```
   SET SELIST: HLRSN=1, OPTYPE=DELETEALL;
   ```
