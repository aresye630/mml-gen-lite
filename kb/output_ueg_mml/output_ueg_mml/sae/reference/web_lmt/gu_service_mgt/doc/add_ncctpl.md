## 命令功能

该命令用于在UDM中增加一条NCC（Network Capability Configuration）模板数据记录。在开局时，完成硬件安装、软件安装之后，需要通过华为操作维护系统完成本局数据和对接数据的配置。其中，在进行本局数据的配置时，需要使用**ADD VLRTYP**/**ADD SGSNTYP**命令增加VLR/SGSN类型数据相关的“NCC模板ID”，其目的是使UDM能够根据VLR/SGSN实际所支持的业务和MAP版本，进行相关业务与相关MAP流程的处理，提高UDM与VLR/SGSN在网络中的兼容性。

上述所说的“NCC模板ID”，是通过该命令进行定义的，每个NCC模板对应一套业务和MAP流程的处理规则，这些规则的制定是根据VLR/SGSN实际所支持的业务和MAP版本的情况来进行。如果不按照VLR/SGSN实际的支持情况进行配置，就会导致UDM与VLR/SGSN的网络兼容性差。例如：

- VLR实际不支持对Cancel location消息中的私有信元进行处理，使用该命令增加NCC模板时，参数“Cancel location中的私有信元”应设置为“NR（CancelLocation请求中的私有信元不下发到VLR）”，在UDM上使用**ADD VLRTYP**命令对VLR增加该NCC模板ID后，UDM在下发业务数据时，Cancel location消息中的私有信元不下发到该VLR。否则，VLR会收到Cancel location消息中的私有信元，但由于无法处理，会向UDM返回无法处理的相关消息。这种UDM和VLR之间进行的无效消息传输，占用了网络资源。
- UDM支持比较高的MAP版本，如MAP Phase 3，而VLR只支持比较低的MAP版本，如MAP Phase 2。当UDM按照MAP Phase 3的能力发起独立插入用户数据、Cancel location、提供漫游号码等操作时，由于VLR不支持该MAP版本，就会进行版本协商（即要求UDM按照MAP Phase 2的能力重新发起相关操作），导致消息量倍增，增加了链路资源的消耗。

综上，如果能根据VLR/SGSN对相关业务和MAP版本的实际支持情况对NCC模板进行定义，并在VLR/SGSN类型数据配置过程中使用该模板，就能使UDM向VLR/SGSN发起MAP消息时，按照NCC模板中设定的VLR/SGSN实际支持的MAP版本发起MAP操作，避免进行版本协商，或使UDM不向VLR/SGSN下发VLR/SGSN无法处理的消息，减少链路资源消耗，从而提高UDM与VLR/SGSN在网络中的兼容性。

## 注意事项

- 本命令的MAP版本与**SET MAPSERV**命令中参数“MAP版本”比较，取最小值。如果VLR/SGSN存在NCC模板，则在流程中按照MAP版本最小值下发。如果VLR/SGSN不存在NCC模板，则取**SET MAPSERV**命令中参数“MAP版本”进行下发。
- 需要指出的是，本命令中所描述的系统初始设置值，是指操作员执行该命令未输入数值时系统设置的参数值，可以通过**LST NCCTPL**命令查询。
- 若参数描述中没有明确说明MME/S4SGSN，则该功能只适用于VLR/SGSN。
- 同一个“HLR序列号”中增加的NCC模板记录数不能超过3000条。

## 使用实例

为VLR/SGSN设置网络支持能力数据操作员需要执行以下操作。

1. 在“HLR序列号”为“1”的UDM上增加NCC模板数据记录。其中，“模板ID”为“2”，“模板名”为“VLR1”，“位置更新”为“MAPV2”，“恢复用户数据”为“MAP Phase3”，“取鉴权集”为“MAP Phase2”，“MPTY”为“SX”，“PLMN自定义补充业务-1”为“SR”：

   ```
   ADD NCCTPL: HLRSN=1, TPLID=2, TPLNAME="VLR1", UPL=MAPV2, RSD=MAPV3, SAI=MAPV2, MPTY=SX, PLMNSS-1=SR;
   ```
2. 执行**ADD VLRTYP**/**ADD SGSNTYP**命令给VLR/SGSN设置NCC模板。此处以VLR举列说明。

   ```
   ADD VLRTYP: HLRSN=1, VLRPREFIX="8613800", TYPE=LOCAL, NCCTPL=2;
   ```

该命令执行异常，会返回对应的错误码。常见错误码如表1所示。
