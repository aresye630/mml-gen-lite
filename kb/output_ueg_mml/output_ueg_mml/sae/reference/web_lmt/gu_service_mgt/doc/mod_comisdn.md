# 修改COMISDN业务(MOD COMISDN)

- 命令功能
- 注意事项
- 参数说明
- 使用实例
- 输出结果说明

## 命令功能

此操作用来给用户签约、去签约以及修改COMISDN业务。

## 注意事项

- IMSI、ISDN、IMSIFILE、ISDNFILE是条件可选参数，有且只能有一个参数出现。
- RECORDCOUNT一定不能与IMSIFILE或ISDNFILE同时出现。
- 每个COMMON ISDN最多有100个OWN ISDN(包括COMMON ISDN自己)，如果超出100个，则返回“超过最大限制”错误。
- 如果一个号码已是其他号码的COMMON ISDN，则不允许该号码作为其他号码的OWN ISDN，否则返回“业务冲突”错误。但COMMON ISDN可以是自己的OWN ISDN。
- 如果用户签约了COMISDN业务，则不能使用**MOD MSIM**命令同时签约多SIM业务。
- COMISDN业务还与其他许多业务存在冲突，不能同时签约。这些业务包括：一卡多号、一号多卡、FM、VVDN、ALS、LINKED SIM、Home Zone、M2M COMISDN和M2M ISDN-Less。
- 只有非激活的辅号码用户才可设置“是否允许接收短消息”参数，当参数“是否激活用户”设置为“TRUE”时，不能同时设置“是否允许接收短消息”为“TRUE”。
- 执行该命令不携带“是否激活用户”，只是携带“是否允许接收短消息”时

  - 当“是否允许接收短消息”为“TRUE”时，对于激活辅号码用户返回ERR3125：业务冲突；对于非激活辅号码用户/主用户正常操作。
  - 当“是否允许接收短消息”为“FALSE”时，对于激活辅号码用户/非激活辅号码用户正常操作；对于主用户返回ERR4092：禁止修改多SIM业务主用户的短消息接收权限。
- 在混合组网下，如存在异常场景下进行跨SP数据迁移时，需要通过设置“USERDATAMIGEXCEPENHANCESW（用户数据迁移容错能力增强开关）”软参支持数据的兼容处理，避免因为UDB和PaasDB数据模型不一致而处理失败。
  - 插件包schemamap.xml文件中配置RDN冲突节点（rdnconflictexcepproc），即从5G接入查询4G用户和用户数据迁移过程中该节点存在冲突记录时，若该软参为“1”，根据timestampfield配置字段取最新的一条数据，无timestampfield配置，随机取一条数据；若软参为“0”，则从5G接入查询4G用户和迁移失败。
  - 插件包schemamap.xml文件中配置无父节点的节点（noparentnodeexcepproc），即从5G接入查询4G用户和用户数据迁移过程中该节点无父节点记录时，若软参为“1”，忽略该节点数据不处理；若软参为“0”，则从5G接入查询4G用户和迁移失败。

## 参数说明

| 参数标识        | 参数名称          | 参数说明                                                                                                                                                                                    |
|:------------|:--------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| IMSI        | IMSI          | IMSI号码，E.212格式的编码，为6～15位的十进制数字。                                                                                                                                                         |
| ISDN        | MSISDN        | MSISDN号码，E.164格式的编码，为1～15位的十进制数字。                                                                                                                                                       |
| RECORDCOUNT | 用户个数          | 用户的数目，最大100000个。如果只有一个用户，该参数不必提供。 该参数提供，代表以指定的IMSI、MSISDN为起始号码，号码连续的RECORDCOUNT个用户。                                                                                                     |
| IMSIFILE    | IMSI文件名       | IMSI文件名称，1～16个字母或数字组成。IMSIFILE是由多个不连续的IMSI号码组成的批操作文件，每个IMSI号码占一行。                                                                                                                       |
| ISDNFILE    | MSISDN文件名     | ISDN文件名称，1～16个字母或数字组成。ISDNFILE是由多个不连续的MSISDN号码组成的批操作文件，每个MSISDN号码占一行。                                                                                                                   |
| PROV        | 是否提供COMISDN业务 | 是否提供COMISDN业务。 取值范围： TRUE：提供 FALSE：不提供 说明：必选参数。                                                                                                                                         |
| COMISDN     | COMISDN号码     | 仅当本命令中的“是否提供COMISDN业务”参数为“TRUE”时该参数有效。COMISDN号码，表示COMMOM ISDN或多SIM群组的主用户。E.164格式的编码，为1～15位的十进制数字。 说明：签约时COMISDN是必选参数。                                                                   |
| OVERIDE     | COMISDN超越属性   | 仅当本命令中的“是否提供COMISDN业务”参数为“TRUE”时该参数有效。COMISDN超越属性，表示是否依据HLR的NCC设置来下发COMMON ISDN。 取值范围： TRUE：不需要依据NCC的配置下发COMMON ISDN。 FALSE：需要依据NCC的配置下发COMMON ISDN。 缺省值：FALSE                          |
| ACTMT       | 是否激活用户        | 仅当本命令中的“是否提供COMISDN业务”参数为“TRUE”时该参数有效。是否激活用户，表示该用户是否做为多SIM群组的激活用户。激活用户用于接听多SIM群组所有成员的入呼叫（语音和短信），非激活用户不能接听多SIM群组成员的入呼叫。 取值范围： TRUE：激活用户 FALSE：非激活用户 说明：该参数只有在主用户签约多SIM业务时才有效，且缺省值为FALSE。 |
| ORDER       | 成员序号          | 仅当本命令中的“是否提供COMISDN业务”参数为“TRUE”时该参数有效。用于标识该用户在多SIM增强群组中的成员序号。 取值范围：2～100 说明：该参数只有在主用户签约多SIM增强业务时才有效，且主用户的成员序号为1，不允许修改。                                                                  |
| SMSMTALLOW  | 是否允许接收短消息     | 仅当本命令中的“是否提供COMISDN业务”参数为“TRUE”时该参数有效。用于控制是否允许辅号接收短消息。 取值范围： TRUE：允许 FALSE：不允许 默认值：FALSE。 说明：该参数只有在增加、修改多SIM增强用户的场景下有效。                                                                 |

## 使用实例

1. 为IMSI号码为460000009123456的用户提供COMISDN业务，COMISDN号码为460000001111111，COMISDN超越属性为TRUE。

   MOD COMISDN: IMSI="460000009123456", PROV=TRUE, COMISDN="460000001111111", OVERIDE=TRUE;
2. 为IMSI号码为460000009123456的用户撤销COMISDN业务。

   MOD COMISDN: IMSI="460000009123456", PROV=FALSE;

## 输出结果说明

该命令执行正常，会返回命令执行成功的提示信息。

该命令执行异常，会返回对应的错误码。常见错误码如表1所示。

| 错误码     | 错误码解释                  | 原因分析                                                                                                                                    | 处理建议                                                                                                                                                              |
|:--------|:-----------------------|:----------------------------------------------------------------------------------------------------------------------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ERR1010 | 参数冲突                   | “IMSI”、“MSISDN”、“IMSI文件名”、“MSISDN文件名”四个参数中有两个以上的参数被输入。 “用户个数”与“IMSI文件名”或“MSISDN文件名”同时被输入。 当参数“是否激活用户”设置为“TRUE”时，同时设置“是否允许接收短消息”为“TRUE”。 | 根据实际情况，重新输入参数，确保满足条件。 “IMSI”、“MSISDN”、“IMSI文件名”、“MSISDN文件名”四个参数是可选参数，必须有且只能有一个参数出现。“用户个数”不能与“IMSI文件名”或“MSISDN文件名”同时配置。当参数“是否激活用户”为“TRUE”时，不能设置“是否允许接收短消息”为“TRUE”。 |
| ERR3125 | 业务冲突                   | 当输入的用户为签约了多SIM增强业务的已激活辅卡用户时，“SMSMTALLOW”参数取值为“TRUE”。                                                                                    | 当输入的用户为签约了多SIM增强业务的已激活辅卡用户时，不允许签约接收短消息功能，因此不需要输入“SMSMTALLOW”参数，或将该参数设置为“FALSE”。                                                                                   |
| ERR4092 | 禁止修改多SIM业务主用户的短消息接收权限。 | 当输入的用户为签约了多SIM增强业务的主卡用户时，“SMSMTALLOW”参数取值为“FALSE”。                                                                                      | 当输入的用户为签约了多SIM增强业务的主卡用户时，不允许修改其短消息接收权限，因此不需要输入“SMSMTALLOW”参数。                                                                                                     |
