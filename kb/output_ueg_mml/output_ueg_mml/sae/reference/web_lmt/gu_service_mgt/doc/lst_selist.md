# 查询业务实体(LST SELIST)

- 输出结果说明

## 命令功能

该命令用于查询业务实体表的配置信息。

- 若需要查询某个地址号码所对应的补充业务详细信息，请将“操作类型”参数设为“ONE”，并输入“地址号码”参数。
- 若需要查询某个补充业务所对应的业务实体表，请将“操作类型”参数设为“SERVICE”，并输入“PLMN自定义补充业务”参数。
- 若需要查询全部业务实体表的配置信息，请将“操作类型”参数设为“ALL”，“地址号码”和“PLMN自定义补充业务”参数不输入。

## 注意事项

无。

| SESERVICE | PLMN自定义补充业务 | 用于根据补充业务查找业务实体表记录时，输入要查询的补充业务类型。仅当“操作类型”取值为“SERVICE”时，该参数有效且为必选参数。 取值范围：RBT：对应的业务实体为支持彩铃业务的GMSC（Gateway Mobile Switching Center）。UDM在处理SRI消息时，如果发现用户签约了主叫端局彩铃（即用户签约的自定义补充业务码，运营商通过SET MAPSERV命令定义，并通过MOD PLMNSS命令为用户签约），则首先判断发起SRI请求的GMSC是否在SELIST表的RBT业务中有配置: CRGMSC：在彩铃业务中，若GMSC不支持彩铃，通过增加支持彩铃呼叫转接的CR-GMSC来实现彩铃业务，参数“PLMN自定义补充业务”设置为“CRGMSC”，参数“地址号码”配置为可以提供彩铃呼叫转接的GMSC。SOR：对应的业务实体为可以支持SOR（Supporting of Optimal Routing）功能的GMSC。优化路由功能可以减少网间话路资源，提升网络利用率和网络性能。必须已通过SET MAPCONF命令将“是否支持SOR功能”参数值设置为“TRUE”，即UDM支持SOR功能。GMSCPRE：对应的业务实体为可以提供定制局点彩铃的GMSC。UDM在处理SRI消息时，如果SRI请求消息中携带GMSC号码，则根据业务实体表和最大匹配的原则，在业务实体类型为GMSCPRE的记录中，获取对应的虚拟漫游号码前缀。如果携带GMSC号码，且在业务实体表中匹配到，则将获取的虚拟漫游号码前缀和去掉了国家码前缀的MSISDN号码一起组成虚拟漫游号码。如果未携带GMSC号码或者匹配不到GMSC号码，但之前配置了一条全0的默认号码前缀记录，则取该默认前缀和去掉了国家码前缀的MSISDN号码一起组成虚拟漫游号码。如果匹配不到虚拟漫游号码前缀，且未配置默认前缀，或组成的虚拟漫游号码长度超过最大值15，则按非彩铃用户正常进行后续SRI处理，UDM向被叫VMSC正常获取MSRN漫游号码。 如果正常生成虚拟漫游号码，则在SRI响应消息中，返回虚拟漫游号码给GMSC。 MIMSI：对应的业务实体为支持一号多卡的MSC。一号多卡业务分为主附卡、同振、顺振、平等卡四种。其中同振和顺振需要VLR支持。当UDM收到SRI消息时，如果判断VLR不支持同振或顺振，即以下两种情况：VLR没有通过ADD VLRTYP命令进行增加VLR类型数据，以关联NCC（Network Capability Configuration）模板。VLR已通过ADD VLRTYP命令关联了NCC模板，但NCC模板中“是否支持同振或顺振”取值为“NR”，即VLR不支持同振顺振功能。 此时如通过本命令添加了支持同振顺振的MSC号码前缀到业务实体表中，UDM则会到业务实体表中寻找一个支持同振顺振的MSC，将该MSC的号码前缀和用户的MSISDN号码组成虚拟漫游号码。UDM返回SRI响应消息到VLR，消息中携带该虚拟漫游号码。之后VLR发送IAM消息至支持同振顺振的MSC，并由该MSC代替VLR重新发送SRI消息到UDM取漫游信息。 SMSCF：对应的业务实体为支持短消息前转（SMSCF）的HLR。此项是为了防止短消息前转死循环进行设置，将所有支持短消息前转的HLR添加到业务实体表中。如果设置了支持短消息前转的业务实体表，则在进行短消息前转之前，本局HLR会判断SRI消息的源地址是否在支持短消息前转的业务实体表中： 是，说明发送SRI请求消息的对端是支持短消息前转的HLR，为防止经过若干次前转之后重新前转到该HLR，造成死循环，短消息不再进行前转，直接返回SRI响应消息。否，说明发送SRI请求消息的对端是短消息中心SMSC，不会出现死循环，本局HLR根据用户配置的短消息前转号码，并进行短消息前转。 WSM：对应的业务实体为欢迎短消息的AS。UDM在向AS下发USSD请求消息的时候，需要知道AS的GT地址，通过配置此项，在位置更新确认之后，UDM会根据此项配置的支持欢迎短消息的业务实体表查询AS_GT地址，并发送USSD请求，AS在接收到USSD请求之后发送欢迎短消息。 NPMSC：对应的业务实体为支持携出用户附着的MSC。NPMSC用来管理和存储携出用户数据，在归属HLR获取漫游号码的同时指明用户携出的运营商路由码RN（Routing Number），同时为携出用户提供短信转发功能。SMSROUTE：对应的业务实体为支持短消息重定向的SMS_Router地址。SMSGRAY：对应的业务实体为不需要短消息重定向的SMSC，选择此项将SMSC地址添加到短消息重定向灰名单中，UDM对灰名单中的SMSC不进行短消息重定向。当UDM支持全局性的短消息重定向，即通过SET MAPSERV命令设置了参数“短消息重定向类型”取值为“Global”时，UDM收到SRI_FOR_SM短消息取路由请求消息后，判断被叫用户是否签约了用户级的短消息重定向。如果没有签约，则判断请求消息中的源地址是否匹配SELIST业务实体表中的SMS-Router地址或SMSGRAY地址： 是，按普通短消息取路由处理，处理后给SMSC发送响应消息。否，在SELIST业务实体表中轮选SMS-Router的地址，将SRI_FOR_SM短消息取路由请求消息转发出去。 说明：SMSROUTE和SMSGRAY两个枚举值的区别如下：在UDM对SRI_FOR_SM消息是否重定向的判断中，SMS-Router地址和SMSGRAY地址列表的作用是相同的，但不触发短消息重定向的原因不同。当SRI_FOR_SM消息的源地址匹配业务实体表中的SMS-Router地址时，说明消息的源地址是SMS-Router，所以不会再触发短消息重定向；而对SMSGRAY地址列表中的地址不再触发短消息重定向，是为了防止短消息重定向业务和其他短消息应用业务冲突，对设定的SMSC不进行短消息重定向。在UDM确定需要进行短消息重定向之后，只会根据SMS-Router列表中的地址进行轮选，并转发SRI_FOR_SM消息，而跟SMSGRAY地址列表无关。 NCCTPL命令的“是否支持锚定处理”配置）。当前VMSC没有配置或者状态配置为“NR”，则不触发锚定，继续从VMSC获取用户漫游号码，并按原有的CS域呼叫流程进行处理。当前VMSC配置为“SR”，则支持锚定。 IPSMGW_ADDR_BLST：当需要查询IP-SM-GW（IP Short Message Gateway）地址的黑名单时选择此项。当UDM收到IP-SM-GW发送的短消息发送状态报告：如果该消息的IP-SM-GW地址在黑名单中时，则UDM不处理该消息。如果该消息的IP-SM-GW地址不在黑名单中时，则UDM处理该消息。 如果用户没有动态或静态的IP-SM-GW地址，则UDM根据SET MAPCONF命令中“是否使用MAP层携带的短消息中心地址与IP-SM-GW地址进行比较”参数的值来判断该消息的IP-SM-GW地址是否在黑名单中： 当UDM收到SMS-GMSC发送的短消息发送状态报告：如果用户的静态IP-SM-GW地址中某一个或动态IP-SM-GW地址在黑名单中时，则UDM处理该消息。如果用户的静态或动态IP-SM-GW地址都不在黑名单中时，则UDM不处理该消息。 说明：当SET MAPCONF命令的“是否支持在短消息取路由消息中将IP-SM-GW地址直接返回给短信中心”、“在SRI_FOR_SM流程中请求MSISDN携带ICS前缀时，HSS回复响应时是否携带IP_SM_GW地址”参数设置为“TRUE”，且IP-SM-GW地址在Bypass列表中时，UDM按照没有签约相应的IP-SM-GW地址进行处理。 NRBT：对应的业务实体为不支持NRBT彩铃业务的GMSC。UDM处理SRI消息时，当同时满足如下条件时SRI响应消息中会携带NRBT彩铃业务数据，否则不携带NRBT彩铃业务数据。SRI请求消息中携带IN-Capability信元。 按照最大匹配的原则，GMSC地址不在“PLMN自定义补充业务”参数值为“NRBT”的SELIST业务实体表中。 被叫用户签约了NRBT彩铃业务。 被叫用户所在VLR不在NCC模板控制的限制下发范围。 IPUSSD_ADDR_BLST：当IP-USSD-AS产生故障，且CS网络正常时，可以配置IP-USSD-AS地址黑名单列表，将USSD消息转发给CS域处理。当IP-USSD-AS地址在配置的黑名单列表内时，HLR/HSS将USSD REQUEST或USSD NOTIFY消息继续转发给MSC/VLR处理。说明：受SET SELIST命令最多只能添加1000条业务实体地址的限制，该黑名单记录在HLR/HSS中最多只能配置1000个，且允许记录多个用户的IP-USSD-AS地址。 SMSC：对应的业务实体为短消息中心。短消息中心退网，地址变化时使用该功能，配置短消息通知黑名单，短消息地址在黑名单列表中，则不发送短消息通知给短消息中心，同时会删除短消息等待列表中的短消息地址。短消息中心故障的场景使用该功能，在故障恢复后，不能再发送短消息。 SMSGRAY_FOR_IP_SM_GW: 对应的业务实体为不需要触发到IP_SM_GW地址的设备。检查SRI_FOR_SM短消息取路由请求消息中的源地址是否匹配SMSGRAY_FOR_IP_SM_GW地址。（如果携带TCAP地址则匹配TCAP地址前缀， 没有携带TCAP地址则匹配MAP的SMSC地址前缀。）是，消息不转发给IP_SM_GW地址处理。否，按照原有流程处理SRI_FOR_SM短消息取路由请求消息。 默认值：无。 |
