## 命令功能

该命令用于查询UPCF的对端BSF、CHF、AMF、SCP、UDR、NWDAF、PCF网元缓存信息。

在NRF服务注册、发现流程中，NCS服务需要将**ADD DISCNFPROFILE**命令对应的配置信息发送给PES服务保存，在NCS服务重启时，NCS服务从PES服务获取的NF缓存对应的配置信息，并使用该配置信息重新做服务发现。因此，在遇到对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元业务异常问题处理时，可先通过本命令查询对应的异常网元缓存信息，再通过**CLR NFCACHE**命令进行清除对应的网元缓存信息，以保证业务消息正常处理。当执行本命令时，NCS服务或者PES服务将输出缓存文件，通过分析UPCF网元缓存文件中的“nfinstid”、对端的“bsfinfo”、“chfinfo”、“amfinfo”、“udrinfo”、“scpinfo”、“nwdafInfo”、“nwdafInfoList”或者是“pcfinfo”字段信息与对端网元数据配置的一致性，可以用于辅助问题的定位处理：

- 网元缓存文件在OM Portal环境上的收集方法：
  1. 在环境主页面上，选择“监控分析 > 运行日志 >  服务日志收集”；
  2. “应用名称”选择“upcf网元”；
  3. 勾选需要收集日志的服务名称：“PcfPolicyEngineService、PcfNrfClientService”；
  4. 选择所需的“时间区间”，点击“开始收集”，显示日志收集状态为“成功”后，可以下载文件到本地。具体界面如下图1所示：

     **图1** 服务日志收集界面
- 网元缓存文件输出所在目录：
  - PES服务：“/opt/csplog/{appid}/PcfPolicyEngineService/export/log”。
  - NCS服务：“/opt/csplog/{appid}/PcfNrfClientService/export/log”。
- 网元缓存文件名称及保存机制：
  - PES服务缓存文件：pes\_{ProcessNo}\_nfcache\_yyyymmddhhmmss.log。PES每个服务实例最多保存5个缓存文件（只比较ProcessNo\_nfcache\_yyyymmddhhmmss），超过5个时，系统会自动删除最老的文件。
  - NCS服务缓存文件：ncs\_{实例ID}\_nfcache\_yyyymmddhhmmss.log。NCS每个服务实例最多保存5个缓存文件（只比较nfcache\_yyyymmddhhmmss），超过5个时，系统会自动删除最老的文件。

**对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元业务异常问题处理思路1**：当定位为对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元出现下线等情况导致业务异常时，此时可确定PES服务必定还存在缓存信息，导致UPCF业务消息仍继续发送给已下线对端网元处理，因此可以通过本命令先查询PES服务缓存信息，并执行**CLR NFCACHE**命令清除缓存信息，观察业务是否恢复正常？如未恢复正常，则说明NCS服务也存在缓存信息，继续执行本命令查询NCS服务缓存信息，再执行**CLR NFCACHE**命令清除缓存信息。

**对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元业务异常问题处理思路2**：当定位为对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元出现下线等情况导致业务异常时，可直接通过本命令先查询NCS服务缓存信息，并执行**CLR NFCACHE**命令清除缓存信息。如本命令查询系统中不存在NCS服务缓存信息，则说明仅PES服务存在缓存信息，继续执行本命令查询PES服务缓存信息，再执行**CLR NFCACHE**命令清除缓存信息即可。

## 参数说明

| 参数标识        | 参数名称   | 参数说明                                                                                                                                                                                                                                                                                                                                                        |
|:------------|:-------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| SERVICETYPE | 服务类型   | 可选必选说明：必选参数 参数含义：用于指示系统需要按照哪个服务类型来查询服务缓存信息。 取值范围： NCS(NCS)PES(PES) 默认值：无。 配置原则：无。                                                                                                                                                                                                                                                                           |
| NFTYPE      | 网元类型   | 可选必选说明：必选参数 参数含义：用于指示系统需要查询UPCF哪个对端网元类型的服务缓存信息。 取值范围： BSF(BSF)CHF(CHF)AMF(AMF)SCP(SCP)UDR(UDR)NWDAF(NWDAF)PCF(PCF) 默认值：无。 配置原则：根据故障定位业务异常是哪个对端网元类型导致，则查询哪个对端网元的缓存信息。                                                                                                                                                                                        |
| INSTANCENO  | 实例号    | 可选必选说明：可选参数 参数含义：用于指示系统需要查询UPCF哪个PES服务实例的缓存信息。 取值范围：长度不超过256的字符串。 默认值：无。 配置原则：仅当“SERVICETYPE”取值为“PES”时，该参数显示，表示PES的实例号，可通过DSP SERVICEINFO命令查询获取。当不输入时，表示广播查询所有的PES服务实例缓存信息；当输入时，只查询指定PES服务实例的缓存信息。                                                                                                                                                          |
| NFINSID     | 网元实例标识 | 可选必选说明：可选参数 参数含义：用于标识一个网元实例的唯一通用识别码，由运营商统一规划，建议格式为“xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx”。例如：4947a69a-f61b-4bc1-b9da-47c9c5d14b64。 取值范围：长度不超过36的字符串。 默认值：无。 配置原则：表示NCS或者PES微服务里面的网元实例标识，如果是静态网元实例标识，可通过LST DISCNFPROFILE命令查询获取；如果LST DISCNFPROFILE命令查询没有结果，则说明是动态网元实例标识，需联系对端NF进行确认和获取。当不输入时，表示查询对应NCS或者PES微服务的所有网元实例缓存信息；当输入时，只查询指定NCS或者PES微服务里对应网元实例的缓存信息。 |

## 使用实例

现网出现对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元下线导致用户业务异常，此时需要对UPCF网元中的缓存信息进行清理（以下仅以BSF网元举例，其中“实例号”、“网元实例标识”等参数请以实际环境信息为准）。

**处理方式1：先清理PES缓存，查看问题是否解决？如未解决，则继续清理NCS缓存。**

1. 执行**DSP SERVICEINFO**命令查询PES服务的“实例号”。假设“INSTANCENO”为“539738218”。
2. 执行**LST DISCNFPROFILE**命令查询PES服务的“网元实例标识”，假设“NFINSID”为“6947a69a-f61b-4bc1-b9da-47c9c5d14b07”。如果**LST DISCNFPROFILE**命令查询没有结果，则说明是动态网元实例标识，需联系对端NF进行确认和获取。
3. 执行本命令查询PES服务的缓存信息，其中“实例号”为步骤1的查询结果，“网元实例标识”为2的查询结果。

   ```
   DSP NFCACHE: SERVICETYPE=PES, NFTYPE=BSF, INSTANCENO="539738218", NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07";
   ```
4. 执行**CLR NFCACHE**命令清除PES服务缓存信息，“网元类型”假设为“BSF”，“实例号”、“网元实例标识”为步骤1、2的查询结果，“强制清除”为“NO(否)”。然后观察业务是否恢复正常。
   - 恢复正常 -> 结束
   - 业务异常 -> 5
5. 执行本命令查询NCS服务的缓存信息，其中“网元实例标识”为步骤2的查询结果。

   ```
   DSP NFCACHE: SERVICETYPE=NCS, NFTYPE=BSF, NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07";
   ```
6. 执行**CLR NFCACHE**命令清除NCS服务缓存信息，“网元类型”假设为“BSF”，网元实例号为步骤2的查询结果，“强制清除”为“NO(否)”。

**处理方式2：直接查询NCS是否存在故障对端网元缓存信息？如无，则直接清理UPCF网元的PES缓存即可。**

1. 执行**LST DISCNFPROFILE**命令查询网元实例标识，假设“NFINSID”为“6947a69a-f61b-4bc1-b9da-47c9c5d14b07”。

   如果**LST DISCNFPROFILE**命令查询没有结果，则说明是动态网元实例标识，需联系对端NF进行确认和获取。
2. 执行本命令查询是否存在NCS服务的缓存信息？其中“网元实例标识”为步骤1的查询结果。
   - 是 -> 3
   - 否 -> 4

   ```
   DSP NFCACHE: SERVICETYPE=NCS, NFTYPE=BSF, NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07";
   ```
3. 执行**CLR NFCACHE**命令清除NCS服务的缓存信息，“网元类型”假设为“BSF”，“网元实例号”为步骤1的查询结果，“强制清除”为“NO(否)”。
4. 执行**DSP SERVICEINFO**命令查询PES服务的“实例号”。假设“INSTANCENO”为“539738218”。
5. 执行本命令查询PES服务的缓存信息，其中“实例号”为步骤4的查询结果，“网元实例号”为步骤1的查询结果。

   ```
   DSP NFCACHE: SERVICETYPE=PES, NFTYPE=BSF, INSTANCENO="539738218", NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07";
   ```
6. 执行**CLR NFCACHE**命令清除PES服务缓存信息，“网元类型”假设为“BSF”，“实例号”为步骤4的查询结果，“网元实例号”为步骤1的查询结果，“强制清除”为“NO(否)”。

## 输出结果说明

该命令执行正常，会返回命令执行成功的提示信息和相关参数，各参数含义请参见本命令的参数解释。

该命令执行异常，会返回对应的错误码。常见错误码如表1所示。

|   错误码 | 错误码解释      | 原因分析                                       | 处理建议                                             |
|------:|:-----------|:-------------------------------------------|:-------------------------------------------------|
| 58067 | 指定的实例号不存在。 | 输入了“INSTANCENO”参数，但是该参数对应的取值不是任意1个PES的实例号。 | 输入的“INSTANCENO”参数取值要通过DSP SERVICEINFO命令查询结果列表获取。 |
