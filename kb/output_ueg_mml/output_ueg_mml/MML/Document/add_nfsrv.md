## 命令功能

**须知** 

此命令是高危命令，如果执行不当会导致系统异常，影响业务处理。具体影响为如果误添加，会导致NRF上面存在不可信的PCF网元信息，导致对端NF选择到非预期的PCF实例。

该命令用于增加本端网元注册实例信息。网元实例通过NRF注册，能被其他网元发现并进行业务交互。

UPCF通过动态发现的方式注册到NRF，进而与SMF/AMF等网元对接时，必须配置此命令。此命令通过配置和索引参数，携带本端PCF网元实例的全量信息注册到NRF，供其他网元发现并进行业务交互。

## 注意事项

- 首次注册：新增网元实例信息后，如果“网元状态”为“REGISTERED(正常工作状态)”，系统需要发起向NRF的注册。
- 周期心跳注册：注册完成后，系统需要周期性地进行心跳注册，以维持自己的状态。
  - 如果参数“心跳周期”等于0，则心跳周期以首次注册时NRF返回的心跳间隔为准，系统需要为每个网元实例保存NRF返回的心跳周期。如果NRF未返回心跳值，使用系统缺省心跳周期60s。
  - 如果参数“心跳周期”不等于0，则首次注册时填写到注册信息中，心跳周期仍以NRF返回的心跳间隔为准。
- “网元公共信息标识”、“网元信息标识”和“网元服务组”这三个参数所定义的“网元类型”与增加的网元实例信息的“网元类型”必须相同。
- 本命令索引的“PLMN组名称”、“S-NSSAI组名称”、“网元信息标识”、“网元服务组”、“网元服务范围组名称”、“网元SCP域组名称”、“网元集合组名称”、“NSI列表”和“位置”参数不能配置为“NULL”，若其中某个参数配置为“NULL”，则对应参数不生效。
- 在执行本命令添加新PCF实例信息时若UPCF存在着在线用户，则PCF的实例变更会导致对端NF选择PCF的结果发生变更，建议在UPCF上强制在线用户下线后再重新上线。
- 系统支持最多配置8条网元实例信息。

## 使用实例

增加一个“配置方式”为“COMMAND(命令模式)”的网元实例。“网元实例名称”为“pcf-application-002”，“网元类型”为“PCF(策略控制功能)”，“网元状态”为“REGISTERED(正常工作状态)”，“NRF所属组信息”为“nrfgroup-01”，“PLMN组名称”为“nfplmn”，“S-NSSAI组名称”为“snssai-group-01”，“网元公共信息标识”为“cominfo\_01”，“网元信息标识”为“pcfinfo\_01”，“网元服务范围组名称”为“nfserscope”，“网元实例标识”为“c89aabf9-2ee9-11eb-8717-0255c2cb00a7”，“号段配置检查开关”为“TRUE(TRUE)”：

```
ADD NFSRV: NFINSNAME="pcf-application-002", NFTYPE=PCF, NFSTATUS=REGISTERED, NRFGROUP="nrfgroup-01", CONFMODE=COMMAND, NFPLMNGRP="nfplmn", NFSNSSAIGRP="snssai-group-01", NFCOMINFOID="cominfo_01", NFINFOID="pcfinfo_01", NFSERSCOPEGRP="nfserscope", NMFLAG=NO, UPDATEMETHOD=PUT, NFINSID="c89aabf9-2ee9-11eb-8717-0255c2cb00a7", RANGEGRPCHK=TRUE;
```
