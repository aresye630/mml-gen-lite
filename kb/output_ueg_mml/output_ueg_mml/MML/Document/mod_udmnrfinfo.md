## 命令功能

**须知** 

本命令属于高危命令，执行不当会造成业务呼损或系统严重过载甚至崩溃，因此执行该命令前，需要与华为技术支持确认后才可以实施。

该命令用于修改NRF的信息。在该命令中，系统通过“NRF名称”参数来唯一标识一条NRF信息。

- **命令作用**：该命令用于配置UDM需要注册到的NRF信息时，当组网中部署了多个NRF网元时，支持修改目标NRF的所属组及优先级等信息。

## 注意事项

- 如果修改NRF所属的Group，且旧Group被某个NFSRV引用，则应该保证数据修改后旧Group下至少还剩下一个NRF。操作员可以先使用**LST UDMNFSRV**命令查询旧Group是否被NFSRV引用，若被引用，则使用**LST UDMNRFINFO**命令查询旧Group内NRF的个数。
- 当前版本暂不支持在“NRF URI2”中配置域名，修改时推荐使用IP地址配置。
- 当凌晨自动校验或执行**VRY NRFDATA**命令手动校验NRFClient内存数据时，在校验该MML命令的过程中，无法执行该命令，若运行该命令，则提示“360155 该MML数据正在校验中，请稍后再试”。

## 参数说明

| 参数标识               | 参数名称                | 参数说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
|:-------------------|:--------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| NRFNAME            | NRF名称               | 可选必选说明：必选参数 参数含义：标识一条NRF数据记录的关键字段（其取值不能被修改），用于指定需要对哪一条NRF数据记录的参数进行修改或调整。 取值范围：长度不超过32的字符串。 参数来源：该参数全局唯一且需UDM与NRF端协商获取此参数名。操作员可以使用LST UDMNRFINFO命令查询获得。 默认值：无。 配置原则：无。                                                                                                                                                                                                                                                                                                                         |
| NRFGROUP           | NRF所属组信息            | 可选必选说明：可选参数 参数含义：用于标识一个NRF所属组的信息。 取值范围：长度不超过32的字符串，只允许输入：0～9，a～z，A～Z，“-”和“_”。 参数来源：该参数仅由本端UDM通过ADD UDMNRFINFO命令自行定义并添加，可通过执行LST UDMNRFINFO命令获取详细“NRF所属组信息”配置情况。 默认值：无。 配置原则：无。                                                                                                                                                                                                                                                                                                                |
| NRFURI             | NRF URI             | 可选必选说明：可选参数 参数含义：用于标识NRF的URI。 取值范围：长度不超过300位的字符串，包含协议类型(http/https)、FQDN域名或IP、端口（可选）等信息。举例：https://192.168.1.1:8080。 参数来源：该参数由待UDM发起注册的NRF端提供，全局规划，且唯一。 默认值：无。 配置原则： 一般由NRF对端或运营商规划，需要NRF与UDM协商一致，若不一致，则会导致UDM注册失败。支持配置不携带端口的NRF URL，当未配置端口时，HTTP默认使用80端口，HTTPS默认使用443端口。当此参数配置为“FQDN”时，需要通过ADD UDMFQDNINFO命令设置“FQDN”下所关联的IP地址。若设置的IP地址同时存在IPV4与IPV6，则根据以下原则选择链路：当IPV6和IPV4链路状态都可用时，优先选择IPV6链路。当IPV6链路状态不可用时，优先选择可用的IPV4链路。当IPV4和IPV6链路状态均为不可用时，继续轮询选择可用链路。当存在多个可用的同类型IPV4或者IPV6链路时，轮询选择可用链路。 |
| NRFURI2FLAG        | 是否配置NRF URI2        | 可选必选说明：可选参数 参数含义：用于标识“NRF URI2”字段的有效性。 取值范围： TRUE(是)FALSE(否) 参数来源：该参数由本端UDM自行定义。 默认值：TRUE(是)。 配置原则： 当取值为“TRUE(是)”时，“NRF URI2”才显示。当取值为“TRUE(是)”且“NRF URI2”为空时，执行本命令不修改原有NRF URI2的配置。如果已经配置“NRF URI2”，当取值为“FALSE(否)”时，已经配置的NRF URI2内容会被清空。                                                                                                                                                                                                                                                      |
| NRFURI2            | NRF URI2            | 可选必选说明：可选参数 参数含义：用于UDM端标识待注册NRF的第二个URI。 取值范围：长度不超过300位的字符串，包含协议类型(http/https)、IP、端口（可选）等信息。举例：http://[fc03::fc10:fc23:fc56:fc63:fc71]:8080。 参数来源：该参数由待UDM发起注册的NRF端提供，全局规划，且唯一。 默认值：无。 配置原则： 一般由NRF对端或运营商规划，需要NRF与UDM协商一致，若不一致，则会导致UDM注册失败。支持配置不携带端口的NRF URL，当未配置端口时，HTTP默认使用80端口，HTTPS默认使用443端口。配置“NRF URI2”时需与“NRF URI”参数的IP类型不同，一个为IPV4一个为IPV6，否则会上报360188错误码。当“NRF URL”配置为FQDN时，“NRF URI2”无法配置，否则会上报360189错误码。                                                                             |
| PRI                | 优先级                 | 可选必选说明：可选参数 参数含义：用于标识NRF的优先级。NF在注册时，优先向高优先级的NRF注册。由于在实际组网中会存在多个NRF的场景，UDM本端能通过标识可注册的不同NRF的优先级，便于UDM注册时，优先向高优先级的NRF注册。 取值范围：1～15 参数来源：该参数由运营商根据组网实际情况进行规划。 默认值：无。 配置原则：同一个“NRF所属组信息”组内NRF的优先级不允许重复，反之，则会上报300012错误码。数字越小优先级越高。                                                                                                                                                                                                                                                                 |
| ENABLEGZIP         | NF注册消息是否启用Gzip压缩    | 可选必选说明：可选参数 参数含义：用于标识UDM向NRF发送注册请求时是否启用Gzip压缩数据来减少请求消息大小。 取值范围：FALSE(不启用)：表示不启用Gzip压缩数据。TRUE(启用)：表示启用Gzip压缩数据后再发送注册消息，GZIP编码方式相比NULL编码方式能够在一定程度节省网元内存消耗。 参数来源：该参数由本端UDM自行定义。 默认值：无。 配置原则：该参数设置为“TRUE”之前需要确认与对端压缩能力是否一致。如果与对端压缩能力不一致，请求将会被拒绝。                                                                                                                                                                                                                                                  |
| ENABLENFSERVICEMAP | Nfservices字段使用MAP格式 | 可选必选说明：可选参数 参数含义：用于标识NRFClient在注册、更新、订阅/通知、服务发现、GET查询等业务流程中，是否使用MAP格式（nfServiceList格式）。 取值范围： TRUE(是)：使用nfServiceList格式。FALSE(否)：使用nfServices数组格式。 参数来源：该参数由本端UDM自行定义。 默认值：无。 说明：系统由不支持该功能的版本升级到该版本，升级后通过LST UDMNRFINFO命令查询该参数取值为“NULL”，此时含义同取值“FALSE”，表示使用nfServices数组格式。 配置原则：该参数开启前需确认NRF是否支持nfServiceList格式，若NRF不支持nfServiceList格式，则不能开启该参数。                                                                                                                                              |

## 使用实例

该命令仅用于除“NRF名称”参数外的其他参数修改场景，参数修改配置示例步骤如下：

1. 执行**RMV UDMNRFINFO**命令删除错误配置记录之前，须先使用**LST UDMNFSRV**命令查询NRF所属组被网元实例引用：

   ```
   %%LST UDMNFSRV: NFINSNAME="udm-application-001";%%
   RETCODE = 0  操作成功

   操作结果如下:
   -------------
       网元实例名称  =  udm-application-001
       网元实例标识  =  f716585a-cb75-474c-9202-6e8ce59d3651
      NRF所属组信息  =  udm-nrfgroup-01
           网元类型  =  统一数据管理
           网元状态  =  正常工作状态
           配置方式  =  命令模式
         PLMN组名称  =  nfplmn1
      S-NSSAI组名称  =  UDM
            NSI列表  =  NULL
               位置  =  NULL
   网元公共信息标识  =  cominfo_01
       网元信息标识  =  cominfo_01
     网元服务持续性  =  是
         网元服务组  =  UDM1
       上报网管标志  =  不上报网管
           更新方法  =  PUT更新
           心跳周期  =  0
           更新标识  =  触发更新
           恢复时间  =  2020-08-31 10:36:20
       网元实例信息  =  NULL
   (结果个数 = 1)

   ---    END
   ```
2. 继续执行**LST UDMNRFINFO**命令查询待删除NRF注册信息中“NRF所属组信息”参数的取值：

   ```
   %%LST UDMNRFINFO: NRFNAME="nrf-01";%%
   RETCODE = 0  操作成功

   操作结果如下:
   -------------
               NRF所属组信息  =  nrfgroup-01
                     NRF名称  =  nrf-01
                     NRF URI  =  https://192.168.1.1:8080
                      优先级  =  2
   NF注册消息是否启用Gzip压缩 =  不启用
   (结果个数 = 1)

   ---    END
   ```
3. 根据1，2步执行结果判断第1步的查询结果中的“NRF所属组信息”参数的取值是否与步骤2中查询“NRF所属组信息”参数的取值一致，
   - 若一致，请执行a，b两步完成NRF注册信息修改操作。
     1. 执行**RMV UDMNFSRV**删除网元实例：

        ```
        %%RMV UDMNFSRV: NFINSNAME="udm-application-001";%% 
        RETCODE = 0  操作成功
        ---    END
        ```
     2. 执行**MOD UDMNRFINFO**修改目标参数，如将“NRF所属组信息”参数由nrfgroup-02修改为nrfgroup-01：

        ```
        MOD UDMNRFINFO: NRFNAME="nrf-01", NRFGROUP="nrfgroup-01";
        ```
   - 若不一致，执行**MOD UDMNRFINFO**修改目标参数，如将“NRF所属组信息”参数由nrfgroup-02修改为nrfgroup-01：

     ```
     MOD UDMNRFINFO: NRFNAME="nrf-01", NRFGROUP="nrfgroup-01";
     ```
4. 再次执行**LST UDMNRFINFO**命令查询当前配置与其规划是否一致

   ```
   %%LST UDMNRFINFO: NRFNAME="nrf-02";%%
   RETCODE = 0  操作成功

   操作结果如下:
   -------------
               NRF所属组信息  =  nrfgroup-01
                     NRF名称  =  nrf-02
                     NRF URI  =  http://192.168.1.1:8080
                      优先级  =  2
   NF注册消息是否启用Gzip压缩 =  不启用
   (结果个数 = 1)

   ---    END
   ```
