# 增加NRF信息(ADD UDMNRFINFO)

## 命令功能

该命令用于配置UDM需要注册到的NRF信息。

- **命令作用**：当组网中部署了多个NRF网元时，支持配置目标NRF的所属组及优先级等信息。
- **该命令的使用场景**：UDM在建链前须作为客户端向NRF服务端发起注册请求，通过本命令配置目标NRF的URI、优先级等信息，从而确保UDM可以按预期注册到目标的NRF上。
- **命令可选/必选说明**：该命令在NRF注册场景是必选配置命令。

## 注意事项

- 当前版本暂不支持在“NRF URI2”中配置域名，推荐使用IP地址配置。
- 当凌晨自动校验或执行**VRY NRFDATA**命令手动校验NRFClient内存数据时，在校验该MML命令的过程中，无法执行该命令，若运行该命令，则提示“360155 该MML数据正在校验中，请稍后再试”。

## 参数说明

| 参数标识               | 参数名称                | 参数说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
|:-------------------|:--------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| NRFGROUP           | NRF所属组信息            | 可选必选说明：必选参数 参数含义：该参数仅用于UDM本端标识UDM当前注册的NRF所有组信息，该参数在执行ADD UDMNFSRV命令进行NRF注册信息实例化时，用于关联目标NRF的URI、优先级等信息。 取值范围：长度不超过32位的字符串，只允许输入：0～9，a～z，A～Z，“-”和“_”。 参数来源：该参数仅由本端UDM自行定义。 默认值：无。 配置原则：若该“NRF所属组信息”不存在，则创建该NRF组。                                                                                                                                                                                                                                                                                      |
| NRFNAME            | NRF名称               | 可选必选说明：必选参数 参数含义：用于UDM在本端标识NRF在系统中的名称，由于在实际组网中会存在多个NRF的场景，UDM可通过此参数标识具体向哪个NRF发起的注册请求。 取值范围：长度不超过32位的字符串，只允许输入：0～9，a～z，A～Z，“-”和“_”。 参数来源：该参数全局唯一且该名称须与NRF端配置保持一致。 默认值：无。 配置原则： NRF网元数量最多为1000个。该参数全局唯一，不能重复。                                                                                                                                                                                                                                                                                         |
| NRFURI             | NRF URI             | 可选必选说明：必选参数 参数含义：用于UDM端标识待注册NRF的URI。 取值范围：长度不超过300位的字符串，包含协议类型(http/https)、FQDN域名或IP、端口（可选）等信息。举例：http://192.168.1.1:8080。 参数来源：该参数由待UDM发起注册的NRF端提供，全局规划，且唯一。 默认值：无。 配置原则： 一般由NRF对端或运营商规划，需要NRF与UDM协商一致，若不一致，则会导致UDM注册失败。支持配置不携带端口的NRF URL，当未配置端口时，HTTP默认使用80端口，HTTPS默认使用443端口。当此参数配置为“FQDN”时，需要通过ADD UDMFQDNINFO命令设置“FQDN”下所关联的IP地址。若设置的IP地址同时存在IPV4与IPV6，则根据以下原则选择链路：当IPV6和IPV4链路状态都可用时，优先选择IPV6链路。当IPV6链路状态不可用时，优先选择可用的IPV4链路。当IPV4和IPV6链路状态均为不可用时，继续轮询选择可用链路。当存在多个可用的同类型IPV4或者IPV6链路时，轮询选择可用链路。 |
| NRFURI2            | NRF URI2            | 可选必选说明：可选参数 参数含义：用于UDM端标识待注册NRF的第二个URI。 取值范围：长度不超过300位的字符串，包含协议类型(http/https)、IP、端口（可选）等信息。举例：http://[fc03::fc10:fc23:fc56:fc63:fc71]:8080。 参数来源：该参数由待UDM发起注册的NRF端提供，全局规划，且唯一。 默认值：无。 配置原则： 一般由NRF对端或运营商规划，需要NRF与UDM协商一致，若不一致，则会导致UDM注册失败。支持配置不携带端口的NRF URL，当未配置端口时，HTTP默认使用80端口，HTTPS默认使用443端口。 “NRF URI2”与“NRF URI”的IP类型不同，一个为IPV4一个为IPV6，否则会上报360188错误码。当“NRF URL”配置为FQDN时，“NRF URI2”无法配置，否则会上报360189错误码。                                                                                        |
| PRI                | 优先级                 | 可选必选说明：必选参数 参数含义：用于UDM本端标识NRF的优先级。由于在实际组网中会存在多个NRF的场景，UDM本端能通过标识可注册的不同NRF的优先级，便于UDM注册时，优先向高优先级的NRF注册。 取值范围：1～15 参数来源：该参数由运营商根据组网实际情况进行规划。 默认值：无。 配置原则：同一个“NRF所属组信息”组内NRF的优先级不允许重复，反之，则会上报300012错误码。数字越小优先级越高。                                                                                                                                                                                                                                                                                       |
| ENABLEGZIP         | NF注册消息是否启用Gzip压缩    | 可选必选说明：可选参数 参数含义：用于标识UDM向NRF发送注册请求时是否启用Gzip压缩数据来减少请求消息大小。 取值范围：FALSE(不启用)：表示不启用Gzip压缩数据。TRUE(启用)：表示启用Gzip压缩数据后再发送注册消息，GZIP编码方式相比NULL编码方式能够在一定程度节省网元内存消耗。 默认值：FALSE(不启用) 参数来源：该参数由本端UDM自行定义。 配置原则：该参数设置为“TRUE”之前需要确认与对端压缩能力是否一致。如果与对端压缩能力不一致，请求将会被拒绝。                                                                                                                                                                                                                                                |
| ENABLENFSERVICEMAP | Nfservices字段使用MAP格式 | 可选必选说明：可选参数 参数含义：用于标识NRFClient在注册、更新、订阅/通知、服务发现、GET查询等业务流程中，是否使用MAP格式（nfServiceList格式）。 取值范围： TRUE(是)：使用nfServiceList格式。FALSE(否)：使用nfServices数组格式。 默认值：FALSE(否)。 参数来源：该参数由本端UDM自行定义。 说明：系统由不支持该功能的版本升级到该版本，升级后通过LST UDMNRFINFO命令查询该参数取值为“NULL”，此时含义同取值“FALSE”，表示使用nfServices数组格式。 配置原则：该参数开启前需确认NRF是否支持nfServiceList格式，若NRF不支持nfServiceList格式，则不能开启该参数。                                                                                                                                             |

## 使用实例

对于5G场景下的新建局，网元之间通信可以通过在NRF服务端完成服务发现等配置及UDM端完成NRF注册配置共同实现的。UDM端的注册配置即NRF与UDM对接配置，增加一条NRF网元注册信息是对接配置步骤中必配信息之一。详细操作步骤如下：

1. 执行**LST UDMNRFINFO**，确认当前系统未配置任何注册信息。
2. 规划增加一条NRF网元注册信息所需参数取值，详细参数规划示例如下，
   - “NRF所属组信息”：本端自行规划名字为“nrfgroup-01”。
   - “NRF名称”：根据运营商全网规划可用的NRF中选择目标NRF名为“nrf-01”。
   - “NRF URI”：根据“NRF名称”选择目标NRF，与NRF对端确定其参数取值为“http://192.168.1.1:8080”。
   - “NRF URI2”：根据“NRF名称”选择目标NRF，与NRF对端确定其参数取值为：“http://[fc03::fc10:fc23:fc56:fc63:fc71]:8080”。
   - “优先级”：如果UDM可发起注册的NRF存在多个，建议此参数根据实际情况提前设定好注册优先级，例如“优先级”=“2”。

   其余参数，根据实际情况选择配置，若无特殊诉求可直接选用默认配置。

   **脚本示例如下**：

   ```
   ADD UDMNRFINFO: NRFGROUP="nrfgroup-01", NRFNAME="nrf-01", NRFURI="http://192.168.1.1:8080", NRFURI2="http://[fc03::fc10:fc23:fc56:fc63:fc71]:8080", PRI=2;
   ```
3. 继续执行**LST UDMNRFINFO**查看配置信息与规划内容是否一致，若不一致可执行 **MOD UDMNRFINFO**命令修改配置错误的地方或可执行**RMV UDMNRFINFO**删除错误配置记录，再重新执行步骤2中的**ADD UDMNRFINFO**命令添加NRF注册信息。
