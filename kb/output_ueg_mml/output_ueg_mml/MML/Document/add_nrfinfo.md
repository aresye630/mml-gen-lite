## 命令功能

该命令用于配置PCF需要注册到的NRF信息。

- **命令作用**：当组网中部署了多个NRF网元时，支持配置目标NRF的所属组及优先级等信息。
- **该命令的使用场景**：该命令主要用于PCF与其他网元之间采用**动态建链**（另一种建链方式：静态建链，表示PCF不通过NRF注册流程与其他网元通信，而是PCF直接与目标通信网元直连）的场景。PCF在建链前须作为客户端向NRF服务端发起注册请求，通过本命令配置目标NRF的URI、优先级等信息，从而确保PCF可以按预期注册到目标的NRF上。
- **命令可选/必选说明**：该命令在NRF注册场景是必选配置命令。

## 注意事项

- **命令生效条件**：执行该命令立即生效。
- **最大记录条数**：系统最大可以添加64条记录。
- **其他注意事项**：PCF向NRF注册的超时时长固定为15s，不可修改。

## 参数说明

| 参数标识       | 参数名称     | 参数说明                                                                                                                                                                                                                                |
|:-----------|:---------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| NRFGROUP   | NRF所属组信息 | 可选必选说明：必选参数 参数含义：该参数仅用于PCF本端标识PCF当前注册的NRF所有组信息，该参数在执行ADD NFSRV命令进行NRF注册信息实例化时，用于关联目标NRF的URI、优先级等信息。 取值范围：长度不超过32的字符串，只允许输入：0～9，a～z，A～Z，“-”和“_”。 参数来源：该参数仅由本端PCF自行定义。 默认值：无。 配置原则：无。                                                 |
| NRFNAME    | NRF名称    | 可选必选说明：必选参数 参数含义：用于PCF在本端标识NRF在系统中的名称，由于在实际组网中会存在多个NRF的场景，PCF可通过此参数标识具体向哪个NRF发起的注册请求。 取值范围：长度不超过32的字符串，只允许输入：0～9，a～z，A～Z，“-”和“_”。 参数来源：该参数全局唯一且该名称须与NRF端配置保持一致。 默认值：无。 配置原则： 该参数全局唯一，不能重复。NRF网元数量最多为64个。                            |
| NRFURI     | NRF URI  | 可选必选说明：必选参数 参数含义：用于PCF端标识待注册NRF的URI。 取值范围：长度不超过128位的字符串，包含协议类型(http/https)、IP、端口等信息。举例：https://192.168.1.1:8080。 参数来源：该参数由待PCF发起注册的NRF端提供，全局规划，且唯一。 默认值：无。 配置原则：一般由NRF对端或运营商规划，需要NRF与PCF协商一致，若不一致，可能会导致PCF注册失败。                     |
| PRI        | 优先级      | 可选必选说明：必选参数 参数含义：用于PCF本端标识NRF的优先级。由于在实际组网中会存在多个NRF的场景，PCF本端能通过标识可注册的不同NRF的优先级，便于PCF注册时，优先向高优先级的NRF注册。 取值范围：1～15 参数来源：该参数由运营商根据组网实际情况进行规划，该参数仅由PCF自行根据取值范围进行定义。 默认值：无。 配置原则： 同一个“NRF所属组信息”组内NRF的优先级不允许重复，反之，则会上报300012错误码。数字越大优先级越低。 |
| DURATION   | 超时时长     | 可选必选说明：可选参数 参数含义：该参与主要用于PCF主动通过心跳消息进行PCF与NRF之间链路状态探测时，本端自定义的一个超时时长参数。该参数用于标识PCF向NRF发送心跳请求消息时，对端NRF在正常时间段内没有回响应，那么超过正常回响应的时长即为超时时长。 取值范围：5～10 单位：秒 参数来源：该参数由本端自行定义。 默认值：5。 配置原则：无。                                                   |
| TIMES      | 失败次数     | 可选必选说明：可选参数 参数含义：用于标识PCF向NRF发起注册后，会主动通过心跳消息进行链路探测，当NRF响应PCF的心跳消息达到超时时长则PCF本地标记为一次响应失败，而此参数用于统计从NRF注册开始PCF累计的心跳消息的失败次数。若PCF向NRF发送心跳消息的失败次数大于设定的次数时，PCF将上报“ALM-34226 NRF心跳故障”告警。 取值范围：3～10 单位：次 参数来源：该参数由本端自行定义。 默认值：3。 配置原则：无。       |
| ENCODETYPE | 编码方式     | 可选必选说明：可选参数 参数含义：用于标识PCF与NRF之间通信消息内容的编码方式。 取值范围： NULL(NULL)：表示不编码。GZIP(GZIP)：表示消息内容以GZIP格式压缩后再发送，GZIP编码方式相比NULL编码方式能够在一定程度节省网元内存消耗。 参数来源：该参数由本端自行定义。 默认值：NULL(NULL)。 配置原则：当PCF端选择GZIP编码方式时，需NRF对端配置支持GZIP格式的解码能力。                   |

## 使用实例

对于5G场景下的新建局，网元之间通信选择动态建链即PCF通过与服务注册的方式完成与其他网元如SMF等之间的通信时，动态建链是通过在NRF服务端完成服务发现等配置及PCF端完成NRF注册配置共同实现的。PCF端的注册配置即NRF与PCF对接配置，增加一条NRF网元注册信息是对接配置步骤中必配信息之一。详细操作步骤如下：

1. 执行**LST NRFINFO**，确认当前系统未配置任何注册信息。
2. 规划增加一条NRF网元注册信息所需参数取值，详细参数规划示例如下，
   - “NRF所属组信息”：本地自行规划名字为“nrfgroup-01”。
   - “NRF名称”：根据运营商全网规划可用的NRF中选择目标NRF名为“nrf-01”。
   - “NRF URI”：根据上一步选择的目标NRF，与NRF对端确定其URI为“https://192.168.1.1:8080”。
   - “优先级”：如果PCF可发起注册的NRF存在多个，建议此参数根据实际情况提前设定好注册优先级；如果PCF可以发起注册的NRF仅一个，那么此参数在取值范围内随机配置即可，例如“优先级”=“2”。
   - “超时时长”：根据实际需要进行配置，例如配置为“6”，没有特殊需求也可以直接使用默认配置值“5”。
   - “失败次数”：根据实际需要进行配置，例如配置为“5”，没有特殊需求也可以直接使用默认配置值“3”。

   其余参数，根据实际情况选择配置，若无特殊诉求可直接选用默认配置。

   **脚本示例如下**：

   ```
   ADD NRFINFO: NRFGROUP="nrfgroup-01", NRFNAME="nrf-01", NRFURI="https://192.168.1.1:8080", PRI=2, DURATION=5, TIMES=3;
   ```
3. 继续执行**LST NRFINFO**查看配置信息与规划内容是否一致，若不一致可执行 **MOD NRFINFO**命令修改配置错误的地方或可执行**RMV NRFINFO**删除错误配置记录，再重新执行该命令添加NRF注册信息。

## 输出结果说明

该命令执行正常，会返回命令执行成功的提示信息。

该命令执行异常，会返回对应的错误码。常见错误码如表1所示。
