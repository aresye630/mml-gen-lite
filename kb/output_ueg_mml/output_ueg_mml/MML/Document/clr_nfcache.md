## 命令功能

**须知** 

- 此命令是高危命令，如果执行不当会影响业务处理，需联系华为技术支持确认后再执行。
- 该操作为系统高危操作，需要第二个具有二次授权权限的用户授权后才能执行该操作。请输入授权用户名和密码。

该命令用于清除UPCF网元的缓存信息。

在NRF服务注册、发现流程中，NCS服务需要将**ADD DISCNFPROFILE**命令对应的配置信息发送给PES服务保存，在NCS服务重启时，NCS服务从PES服务获取的NF缓存对应的配置信息，并使用该配置信息重新做服务发现。因此，在遇到对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元业务异常问题处理时，可先通过**DSP NFCACHE**命令查询对应的异常网元缓存信息，再通过**CLR NFCACHE**命令进行清除对应的网元缓存信息，以保证业务消息正常处理。

- **对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元业务异常问题处理思路1**：当定位为对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元出现下线等情况导致业务异常时，此时可确定PES服务必定还存在缓存信息，导致UPCF业务消息仍继续发送给已下线对端网元处理，因此可以通过**DSP NFCACHE**命令先查询PES服务缓存信息，并执行**CLR NFCACHE**命令清除缓存信息，观察业务是否恢复正常？如未恢复正常，则说明NCS服务也存在缓存信息，继续执行**DSP NFCACHE**命令查询NCS服务缓存信息，再执行**CLR NFCACHE**命令清除缓存信息。
- **对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元业务异常问题具体处理思路2**：当定位为对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元出现下线等情况导致业务异常时，可直接通过**DSP NFCACHE**命令先查询NCS服务缓存信息，并执行**CLR NFCACHE**命令清除缓存信息。如**DSP NFCACHE**命令查询系统中不存在NCS服务缓存信息，则说明仅PES服务存在缓存信息，继续执行**DSP NFCACHE**命令查询PES服务缓存信息，再执行**CLR NFCACHE**命令清除缓存信息即可。

## 参数说明

| 参数标识        | 参数名称   | 参数说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
|:------------|:-------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| SERVICETYPE | 服务类型   | 可选必选说明：必选参数 参数含义：用于指示系统需要按照哪个服务类型来清除服务缓存信息。 取值范围： NCS(NCS)PES(PES) 默认值：无。 配置原则：以DSP NFCACHE命令查询哪个微服务存在缓存信息为准，则按哪个微服务进行缓存清理操作。                                                                                                                                                                                                                                                                                                                                                                                                  |
| NFTYPE      | 网元类型   | 可选必选说明：必选参数 参数含义：用于指示系统需要清除UPCF哪个对端网元类型的服务缓存信息。 取值范围： BSF(BSF)CHF(CHF)AMF(AMF)SCP(SCP)UDR(UDR)NWDAF(NWDAF)PCF(PCF) 默认值：无。 配置原则：根据故障定位业务异常是哪个对端网元类型导致，则清除哪个对端网元的缓存信息。                                                                                                                                                                                                                                                                                                                                                           |
| INSTANCENO  | 实例号    | 可选必选说明：可选参数 参数含义：用于指示系统需要清除UPCF哪个PES服务实例的缓存信息。 取值范围：长度不超过256的字符串。 默认值：无。 配置原则：仅当“SERVICETYPE”取值为“PES”时，该参数显示，表示PES的实例号，可通过DSP SERVICEINFO命令查询获取。当不输入时，表示清除对应对端网元类型的所有PES服务实例缓存信息；当输入时，只清除对端网元类型的指定PES服务实例缓存信息。                                                                                                                                                                                                                                                                                                                 |
| NFINSID     | 网元实例标识 | 可选必选说明：可选参数 参数含义：用于标识一个网元实例的唯一通用识别码，由运营商统一规划，建议格式为“xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx”。例如：4947a69a-f61b-4bc1-b9da-47c9c5d14b64。 取值范围：长度不超过36的字符串。 默认值：无。 配置原则：表示NCS或者PES微服务里面的网元实例标识，如果是静态网元实例标识，可通过LST DISCNFPROFILE命令查询获取；如果LST DISCNFPROFILE命令查询没有结果，则说明是动态网元实例标识，需联系对端NF进行确认和获取。当不输入时，表示刷新对应NCS或者PES微服务的所有网元实例缓存信息；当输入时，只刷新指定NCS或者PES微服务里对应网元实例的缓存信息。                                                                                                                                                                    |
| FORCE       | 强制清除   | 可选必选说明：可选参数 参数含义：用于标识是否强制清除网元缓存信息。 取值范围： YES(是)：本参数的配置与“触发发现”参数的配置相互关联。当参数“触发发现”取值为“YES(是)”时，UPCF不清理NF缓存，仅进行服务发现，并根据NRF的发现响应更新NF缓存。当参数“触发发现”取值为“NO(否)”时，UPCF仅清理NF缓存，不进行服务发现。 NO(否)：本参数的配置与NRF是否全故障（通过DSP NFCACHE命令查询）的状态相互关联。当参数“触发发现”取值为“YES(是)”时，如果NRF全故障，则UPCF不会清理NF缓存，也不会进行服务发现；如果NRF不是全故障，则UPCF会进行服务发现，但不会清理NF缓存。当参数“触发发现”取值为“NO(否)”时，如果NRF全故障，则UPCF不会清理NF缓存，也不会进行服务发现；如果NRF不是全故障，则UPCF仅清理NF缓存，而不进行服务发现。 默认值：NO(否)。 配置原则：当NRF全故障时，通过DSP NFCACHE命令查询缓存信息存在问题，则配置为“NO(否)”，否则配置为“YES(是)”。如果NRF不是全故障，则不用配置，处理原则与配置为“NO(否)”一致。 |
| TRIGGERDISC | 触发发现   | 可选必选说明：可选参数 参数含义：用于指示是否根据NFCACHE关联的发现条件进行服务发现。 取值范围：本参数的配置与“强制清除”参数的配置相互关联。 YES(是)：当参数“强制清除”取值为“YES(是)”时，UPCF不清理NF缓存，仅进行服务发现，并根据NRF的发现响应更新NF缓存。当参数“强制清除”取值为“NO(否)”时，如果NRF全故障，则UPCF不会清理NF缓存，也不会进行服务发现；如果NRF不是全故障，则UPCF会进行服务发现，但不会清理NF缓存。 NO(否)：当参数“强制清除”取值为“YES(是)”时，UPCF仅清理NF缓存，不进行服务发现。当参数“强制清除”取值为“NO(否)”时，如果NRF全故障，则UPCF不会清理NF缓存，也不会进行服务发现；如果NRF不是全故障，则UPCF仅清理NF缓存，而不进行服务发现。 默认值：YES(是)。 配置原则：如果清除本地缓存后，需要从NRF重新获取对端数据，则将本参数设置为“YES”。                                                                                       |

## 使用实例

现网出现对端BSF/CHF/AMF/SCP/UDR/NWDAF/PCF网元下线导致的用户业务异常，此时需要对UPCF网元中的缓存信息进行清理（以下仅以BSF网元举例，其中“实例号”、“网元实例标识”等参数请以实际环境信息为准）。

**处理方式1：先清理PES缓存，查看问题是否解决？如未解决，则继续清理NCS缓存。**

1. 执行**DSP SERVICEINFO**命令查询PES服务的“实例号”。假设“INSTANCENO”为“539738218”。
2. 执行**LST DISCNFPROFILE**命令查询PES服务的“网元实例标识”，假设“NFINSID”为“6947a69a-f61b-4bc1-b9da-47c9c5d14b07”。如果**LST DISCNFPROFILE**命令查询没有结果，则说明是动态网元实例标识，需联系对端NF进行确认和获取。
3. 执行**DSP NFCACHE**命令查询PES服务的缓存信息，其中“实例号”为步骤1的查询结果，“网元实例标识”为2的查询结果。
4. 执行本命令清除PES服务缓存信息，“网元类型”假设为“BSF”，“实例号”为步骤1的查询结果，“网元实例标识”为2的查询结果，“强制清除”为“NO(否)”。然后观察业务是否恢复正常。
   - 恢复正常 -> 结束
   - 业务异常 -> 5

   ```
   CLR NFCACHE: SERVICETYPE=PES, NFTYPE=BSF, INSTANCENO="539738218", NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07";
   ```
5. 执行**DSP NFCACHE**命令查询NCS服务的缓存信息，其中“网元实例标识”为步骤1的查询结果。
6. 执行本命令清除NCS服务缓存信息，“网元类型”假设为“BSF”，“实例号”为步骤1的查询结果，“网元实例标识”为2的查询结果，“强制清除”为“NO(否)”。

   ```
   CLR NFCACHE: SERVICETYPE=NCS, NFTYPE=BSF, NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07";
   ```

**处理方式2：直接查询NCS是否存在故障对端网元缓存信息？如无，则直接清理UPCF网元的PES缓存即可。**

1. 执行**LST DISCNFPROFILE**命令查询网元实例标识，假设“NFINSID”为“6947a69a-f61b-4bc1-b9da-47c9c5d14b07”。如果**LST DISCNFPROFILE**命令查询没有结果，则说明是动态网元实例标识，需联系对端NF进行确认和获取。
2. 执行**DSP NFCACHE**命令查询是否存在NCS服务的缓存信息？其中“网元实例标识”为步骤1的查询结果。
   - 是 -> 3
   - 否 -> 4
3. 执行本命令清除NCS服务缓存信息，“网元类型”假设为“BSF”，“网元实例标识”为步骤1的查询结果，“强制清除”为“NO(否)”。

   ```
   CLR NFCACHE: SERVICETYPE=NCS, NFTYPE=BSF, NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07";
   ```
4. 执行**DSP SERVICEINFO**命令查询PES服务的“实例号”。假设“INSTANCENO”为“539738218”。
5. 执行**DSP NFCACHE**命令查询PES服务的缓存信息，其中“实例号”为步骤4的查询结果。
6. 执行本命令清除PES服务缓存信息，“网元类型”假设为“BSF”，“实例号”为步骤4的查询结果，“网元实例标识”为步骤1的查询结果，“强制清除”为“NO(否)”，“触发发现”为YES(是)。

   ```
   CLR NFCACHE: SERVICETYPE=PES, NFTYPE=BSF, INSTANCENO="539738218", NFINSID="6947a69a-f61b-4bc1-b9da-47c9c5d14b07", FORCE=NO, TRIGGERDISC=YES;
   ```

## 输出结果说明

该命令执行正常，会返回命令执行成功的提示信息。

该命令执行异常，会返回对应的错误码。常见错误码如表1所示。

|   错误码 | 错误码解释      | 原因分析                                       | 处理建议                                             |
|------:|:-----------|:-------------------------------------------|:-------------------------------------------------|
| 58067 | 指定的实例号不存在。 | 输入了“INSTANCENO”参数，但是该参数对应的取值不是任意1个PES的实例号。 | 输入的“INSTANCENO”参数取值要通过DSP SERVICEINFO命令查询结果列表获取。 |
