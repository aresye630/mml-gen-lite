# 修改MTP动作属性（MOD MTPACTIONPROP）

- 命令功能
- 注意事项
- 操作用户权限
- 参数说明
- 使用实例

#### 命令功能

**适用NF：MPF**

此命令用于修改MtpActionProp配置，只有已经添加成功的MtpActionProp才能够修改。可以通过命令，修改MTP策略相关的动作属性，包括Gate、URL Redirect、CaQos动作。支持配置不同业务发起端定义不同的上下行报文处理动作。

#### 注意事项

- 该命令执行后立即生效。
- MOD MTPACTIONPROP用于修改具体业务场景下的动作，支持的场景有：

  - 上行发起业务的QoS更新。
  - 下行发起业务的QoS更新。
  - 上行发起业务的URL重定向。
  - 下行发起业务的URL重定向。
  - 上行发起业务的上行门控。
  - 上行发起业务的下行门控。
  - 下行发起业务的上行门控。
  - 下行发起业务的下行门控。
- 如果上行或下行发起业务的相应策略没有配置，则按照默认Pass处理。

#### 操作用户权限

G\_1，管理员级别命令组；G\_2，操作员级别命令组

#### 参数说明

| UPINITUPGATE   | 上行发起上行门控  | 可选必选说明：可选参数 参数含义：设置上行发起业务的上行门控动作。 数据来源：本端规划 取值范围：枚举类型。 PASS：表示业务报文直接通过。DISCARD：表示业务报文直接丢弃。 默认值：无 配置原则： 如果运营商需要定义上行发起的业务命中该MTP动作属性时，上行报文的门控动作是通过，则配置为PASS。如果运营商需要定义上行发起的业务命中该MTP动作属性时，上行报文的门控动作是丢弃，则配置为DISCARD。 |

#### 使用实例

假如运营商需要定义一个MTP动作属性，要求对于上行发起的业务，上下行报文均可以正常通过，下行发起的业务，上下行报文均丢弃。
修改一个MTP动作属性，“MTPACTPROPNAME”为“TestMtpActPropName”，“UPINITUPGATE”为“PASS”，“UPINITDNGATE”为“PASS”，“DNINITUPGATE”为“DISCARD”，“DNINITDNGATE”为“DISCARD”：

```
MOD MTPACTIONPROP:MTPACTPROPNAME="TestMtpActPropName",UPINITUPGATE=PASS,UPINITDNGATE=PASS,DNINITUPGATE=DISCARD,DNINITDNGATE=DISCARD;
```
