# 营帐配额重置（RST PPROVQTA）

## 命令功能

**须知** 

本命令执行不当可能触发清理用户配额记录，详见产品手册注意事项。因此执行该命令前，需要与华为技术支持确认后才可以实施。

本命令用于重置已签约的营帐业务配额，通过该命令可以指定重置业务下关联的多个Provisioning或UPCC类型配额，并支持对当前用户剩余的配额分别执行累加操作。

## 注意事项

- 执行该命令时，仅当不指定配额累加操作时，若命令中携带的业务在该用户没有签约，UPCF会为该用户签约此业务。

  - 组用户不支持签约M2M共享业务。
  - 存在第二标识的用户不支持签约M2M共享业务。
  - 指定M2M共享业务下关联的Provisioning类型配额的初始值不能为0。
  - 用户签约的业务为M2M共享业务时，如果未设置生效时间，则默认采用当前系统时间减5秒的时间为该业务生效时间。
- 执行该命令时，一次仅可以为一个业务进行配额重置。每个业务最多允许指定20个Provisioning或UPCC类型的配额名称。
- 执行该命令时，携带配额的管理类型必须是UPCC管理或者Provisioning管理，且配额的复位方式必须是不复位。
- 该命令不支持主从用户场景。如果被执行请求的用户是主用户（主用户必须有关联的从用户）或从用户，则直接返回失败。
- 执行该命令时，获取Provisioning类型的配额初始值优先级为：“QTAVALUE\_X” > “Custom Initial Value” > UPCF Web UI上的配额值，其中X取值为1~20，“Custom Initial Value”为**LST PQUOTA**命令的输出参数。
  - 当本命令不携带“QTAROLLOVER\_X”参数时：
    - 当获取的配额初始值为非0时，若携带了“QTANAME\_X”，则执行配额重置操作；若未携带“QTANAME\_X”，则配额保持现状。
    - 当“QTAVALUE\_X”未携带配额初始值但UPCF Web UI上的配额值为0时，系统会清理用户配额数据。
    - 当“QTAVALUE\_X”取值为0时，系统会清理用户配额数据。
    - 执行配额重置操作时，若用户配额不存在，则系统会补全用户配额。
    - 系统清理用户配额数据时，若用户配额不存在，则不处理。
  - 当本命令携带“QTAROLLOVER\_X”参数且取值为“Rollover”时：
    - 若获取的配额初始值为0，则用户配额不累加；若获取的配额初始值为非0，则用户配额累加。
    - 若用户配额不存在，则系统会补全用户配额，用户配额不累加。
- 执行本命令时如下两种场景会清理掉对应配额记录：
  - 场景一需同时满足如下条件：
    - 执行本命令时不携带“QTAROLLOVER\_X”参数时。
    - 命令中对应配额的“QTAVALUE\_X”参数未携带。
    - 在UPCF Web UI的业务管理界面上操作配额的配额值为0。
  - 场景二需同时满足如下条件：
    - 执行本命令时不携带“QTAROLLOVER\_X”参数时。
    - 命令中对应配额的“QTAVALUE\_X”参数为0时。

## 使用实例

营帐配额重置：“用户标识”为“46010381014\*\*\*\*”，“业务”为“Volume\_5M”，“配额名称\_1”为“Quota1”, “总量\_1”为“20480”，“配额累加标记\_1”为“Rollover”，“配额名称\_2”为“Quota2”， “总量\_2”为“20480”，“配额累加标记\_2”为“Rollover”，“配额累加最大值\_2”为“30720”：

```
RST PPROVQTA: USRIDENTIFIER="46010381014****", SRVNAME="Volume_5M", QTANAME_1="Quota1", QTAVALUE_1=20480, QTAROLLOVER_1=Rollover, QTANAME_2="Quota2", QTAVALUE_2=20480, QTAROLLOVER_2=Rollover, QTAMAXROLLOVERVALUE_2=30720;
```
