# 用户签约套餐（ADD PSRVPKG）

## 命令功能

本命令用于为用户签约一个套餐，包含套餐名称、订购时间、生效时间、截止时间、漫游类型和联系方式等信息。

用户只有签约了套餐，才能根据签约信息使用所签约的套餐。

## 注意事项

- 一个用户最多可签约的业务数（包含已实例化的动态签约业务数）由PGW系统参数“MaxSrvNumPerSub”控制，默认签约32个业务，最多支持签约64个业务（其中MULTI\_SERVICE\_APN类型的业务不能超过10个，BOD\_SERVICE类型的业务不能超过10个，BOD\_SERVICE类型且默认激活的业务最多一个）。
- 一个用户最多可签约的配额数（包含已实例化的动态签约业务数）由PGW系统参数“MaxQuotaNumPerSub”控制，默认签约32个配额，最多支持签约80个配额。
- 一个用户最多可签约5个套餐。
- 不能为用户签约包含相同业务的套餐。
- 当用户签约套餐时，该用户下此套餐的所有业务相关的通知抑制记录将会被清除。如果该用户下存在从用户，那么从用户下此套餐的所有业务相关的通知抑制记录也会被清除。
- 当从用户签约套餐时，若该套餐中某业务关联的配额与从用户已设置的虚拟配额相同时，从用户不能签约该套餐。
- 一个用户不能签约包含多个关联同一Provisioning定义配额的业务的套餐。
- 一个用户已存在Provisioning定义配额，若用户要签约的套餐中包含关联该配额的业务，则用户不能签约该套餐。
- 当给组用户签约套餐时，即将签约的套餐中的业务都必须为组业务，即业务的参数“是否组业务”取值为“Yes”。
- 当给普通用户和组成员用户签约套餐时，即将签约的套餐中的业务都必须为非组业务，即业务的参数“是否组业务”取值为“No”，且签约的业务的配额与虚拟配额的名称不能相同。
- 一个组用户最多可签约的组业务数由PGW系统参数“MaxGrpSrvNumPerGrpSub”控制，默认签约10个组业务，最多支持签约30个组业务。
- 一个组用户最多可签约的组共享配额数由PGW系统参数“MaxGrpSrvNumPerGrpSub”控制，默认签约10个组共享配额，最多支持签约30个组共享配额。
- 用户再次签约有平滑期业务时，按本次签约业务生效时间重新计算激活业务，忽略上次业务的平滑期。
- “所属网络类型”为“LocalService”的用户不支持签约套餐。

## 参数说明

| 参数标识                | 参数名称   | 参数说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
|:--------------------|:-------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| USRIDENTIFIER       | 用户标识   | 用于指定为哪个用户签约套餐，必须是已存在的用户。该参数必须先由ADD PSUB命令定义，然后才能在此处索引。 取值范围：长度不超过255的字符串。 默认值：无。 配置原则：不支持英文逗号（,）、英文分号（;），等号（=）、英文双引号（"）、英文单引号（'），连续两个及以上的百分号（%%），连续两个及以上的空格（ ）、mml报文起始符标识（+++）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| SRVPKGNAME          | 套餐     | 用于指定用户要签约的某个套餐，必须是已存在的套餐且该套餐需要在UPCF上配置。 用户签约套餐时，必须注意业务和套餐中的业务，套餐与套餐之间的业务，是否存在互斥关系，说明如下。 取值范围：长度不超过32的字符串。 默认值：无。  说明： 当互斥组的类型（包括订购互斥和激活互斥）和互斥操作（包括替换和拒绝）不同时，分别对应四种不同的情况： 订购互斥+拒绝 当要订购的套餐和已经订购的套餐在同一个订购互斥组，则不能订购要订购的业务。 订购互斥+替换 要订购的套餐业务不能和已经订购的套餐业务在同一个订购互斥组，否则要订购的套餐会操作失败。 激活互斥+拒绝 当要激活的套餐和已经激活的套餐在同一个激活互斥组，则不能激活要激活的套餐。 激活互斥+替换 当要激活的套餐和已经激活的套餐在同一个激活互斥组，视互斥组内套餐的优先级决定激活哪个套餐。如果要激活的套餐优先级高于已经激活的套餐优先级，则去激活已经激活的套餐，激活要激活的套餐，反之则不能激活该套餐。                                                                                                                                                                                                                           |
| SRVPKGSUBSCRIBEDATE | 订购时间   | 表示用户订购套餐的时间，时间格式为YYYY&MM&DD&HH&MM&SS。 取值范围：可通过控件配置时间。 默认值：无。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| SRVPKGSTARTDATETIME | 生效时间   | 表示用户订购套餐的生效时间，时间格式为YYYY&MM&DD&HH&MM&SS。 取值范围：可通过控件配置时间。 默认值：无。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| SRVPKGENDDATETIME   | 截止时间   | 表示用户所订购套餐的失效时间，时间格式为YYYY&MM&DD&HH&MM&SS，当系统时间等于截止时间后，用户不能使用该套餐。 取值范围：可通过控件配置时间。 默认值：无。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| SRVPKGROAMINGTYPE   | 漫游类型   | 表示用户签约套餐的漫游类型，用于判断套餐与套餐间的生效时间与截止时间的区间是否有重复。 取值范围：“NULL”：表示签约的套餐不是本地、漫游类型。“Local”：表示签约的套餐为本地类型。“Roaming”：表示签约的套餐为漫游类型。 默认值：NULL。  说明： 用户同时签约两个或以上的漫游或者本地类型的业套餐时，需要判断生效时间与截止时间的区间是否有重复，有重复则新订购的套餐失败。若签约套餐的漫游类型既不是漫游也不是本地，则生效时间与截止时间的区间不做限制。若签约套餐的生效时间和截止时间没有配置，则不需判断生效时间与截止时间的区间是否有重复。用户订购套餐对于时间区间重复，针对主、从用户特性，不做限制，即主、从用户都订购了同一个套餐，生效时间与截止时间以自己的为准。 下面以“漫游类型”为“漫游”举例： 用户没有订购漫游类型的套餐，现在需要新订购漫游类型的套餐，则不受约束。用户已订购了漫游类型的套餐，现在需要新订购漫游类型的套餐。新订购套餐时，必须保证新订购套餐的“生效时间”和“截止时间”与所有已订购的套餐的“生效时间”和“截止时间”时间之间没有交叉。若存在新订购套餐“生效时间”为空，则必须保证其“截止时间”与原订购套餐的“生效时间”和“截止时间”之间没有交叉。若存在新订购套餐“截止时间”为空，则必须保证其“生效时间”与原订购套餐的“生效时间”和“截止时间”之间没有交叉。若存在已订购套餐的“生效时间”和“截止时间”均为空的情况，则新订购套餐不受此订购关系的约束。 |
| SRVPKGCONTACTMETHOD | 联系方式   | 用于指定用户使用该套餐时的通知消息方式。 取值范围： “SMS”：表示以短信方式发送用户通知消息。“E-Mail”：表示以电子邮件方式发送用户通知消息。“SMS&E-Mail”：表示以短信和电子邮件方式发送用户通知消息。“None”：表示用户通知消息方式以开户（ADD PSUB）命令中设置的为准。 默认值：None。  说明： 联系方式也能在开户（ADD PSUB）命令中设置，当该命令设置的联系方式为“SMS”、“E-Mail”或“SMS&E-Mail”时，联系方式以本命令设置的为准。                                                                                                                                                                                                                                                                                                                                                                                                             |

## 使用实例

用户签约套餐：“用户标识”为“46010381014\*\*\*\*”，“套餐”为“Volume\_ServPkg”，“订购时间”为“2010&11&23&16&05&49”,“生效时间”为“2010&11&23&16&05&50”，“截止时间”为“2010&12&01&00&00&00”，“漫游类型”为“Local”，“联系方式”为“SMS”。

```
ADD PSRVPKG: USRIDENTIFIER="46010381014****", SRVPKGNAME="Volume_ServPkg", SRVPKGSUBSCRIBEDATE=2010&11&23&16&05&49, SRVPKGSTARTDATETIME=2010&11&23&16&05&50, SRVPKGENDDATETIME=2010&12&01&00&00&00, SRVPKGROAMINGTYPE=Local, SRVPKGCONTACTMETHOD=SMS;
```
