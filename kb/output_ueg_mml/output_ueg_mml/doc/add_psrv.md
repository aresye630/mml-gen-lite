# 用户签约（ADD PSRV）

## 命令功能

本命令用于为用户签约一个业务，包含业务名称、订购时间、生效时间、截止时间、使用状态、漫游类型、有效期、工作日生效时间段选择、休息日生效时间段选择和联系方式等信息。

签约业务的同时设定Provisioning管理的配额初始值。

用户只有签约了业务，才能根据签约信息使用所签约的业务。

## 注意事项

- 一个用户最多可签约的业务数（包含已实例化的动态签约业务数）由PGW系统参数“MaxSrvNumPerSub”控制，默认签约32个业务，最多支持签约64个业务（其中MULTI\_SERVICE\_APN类型的业务不能超过10个，BOD\_SERVICE类型的业务不能超过10个，BOD\_SERVICE类型且默认激活的业务最多一个）。
- 一个用户最多可签约的配额数（包含已实例化的动态签约配额数）由PGW系统参数“MaxQuotaNumPerSub”控制，默认签约32个配额，最多支持签约80个配额。
- 一个用户只能有一个帐户，即用户所签约的业务中，若为业务配置了帐户，则必需是同一个帐户。
- 当用户签约业务时，该用户下与此业务相关的通知抑制记录将会被清除。如果该用户下存在从用户，则从用户下此业务相关的通知抑制记录也会被清除。当本次操作为重复签约时，不删除通知记录，只影响业务的有效期。
- 从用户默认共享主用户的业务、帐户和配额。
- 主、从用户签约含有相同配额的业务时，处理方式如下：
  - 主用户签约业务S1，S1中包含配额Q1，因为从用户默认签约主用户签约的业务，因此不建议从用户签约含有Q1配额的业务。
  - 从用户签约业务S1，S1中包含配额Q1，因为从用户默认签约主用户签约的业务，因此不建议主用户签约含有Q1配额的业务。
  - 主用户签约业务S1，S1中包含配额Q1，当从用户设置可以共享主用户配额Q1的虚拟配额时，系统不支持从用户签约包含配额Q1的业务。
- 用户自定义时间段与系统定义时间段业务，不建议在同一业务中同时使用。
- 设置工作日或者休息日时间段选择参数时，勾选DELETEALL选项表示用户签约的自定义时间段业务在工作日或休息日所有时间段无效。
- 一个用户不能签约多个关联同一Provisioning定义配额的业务。
- 一个组用户最多可签约的组业务数由PGW系统参数“MaxGrpSrvNumPerGrpSub”控制，默认签约10个组业务，最多支持签约30个组业务。
- 一个组用户最多可签约的组共享配额数由PGW系统参数“MaxGrpSrvNumPerGrpSub”控制，默认签约10个组共享配额，最多支持签约30个组共享配额。
- 当不同的业务关联了相同Provisioning管理的配额时，若用户在签约其中一个业务后，需要修改该Provisioning管理的配额初始值，则只能通过MOD PSRV命令来进行修改，而不能通过ADD PSRV命令来进行修改。
- 如果业务只关联了UPCC Dynamic类型的配额，则无法通过本命令重复签约该业务。
- 当用户通过签约业务来激活Turbo Button业务时，如果该业务的所有配额已经耗尽，且激活时长开关已打开，则返回激活失败。
- 只有组用户才能签约多配额记录重复订购的组业务。
- 用户再次签约有平滑期业务时，按本次签约业务生效时间重新计算激活业务，忽略上次业务的平滑期。
- “所属网络类型”为“LocalService”的用户仅支持签约“VRM\_BD\_SERVICE\_LOCAL”类型的业务，其他网络类型的用户不支持签约“VRM\_BD\_SERVICE\_LOCAL”类型的业务。
- 组用户不支持签约M2M共享业务。
- 从用户或关联了从用户的主用户不支持签约M2M共享业务。
- 存在第二标识的用户不支持签约M2M共享业务。
- 指定M2M共享业务下关联的Provisioning类型配额的初始值不能为0。
- 用户签约的业务为M2M共享业务时，如果未设置生效时间，则默认采用当前系统时间减5秒的时间为该业务生效时间。
- 用户首次订购或激活前重复订购“激活下发时计算”或“有效期内激活下发时计算”类型的多实例非组业务时，若业务是“激活下发时计算”，则不可以携带“生效时间”、“截止时间”，可以携带“持续时间”；若是“有效期内激活下发时计算”，则不允许携带“生效时间”，必须携带“截止时间”，可以携带“持续时间”。
- 用户激活业务后重复订购“激活下发时计算”或“有效期内激活下发时计算”类型的多实例非组业务时，命令允许携带“生效时间”、“截止时间”，或者携带“持续时间”，“持续时间”不能和“生效时间”或“截止时间”同时携带。
