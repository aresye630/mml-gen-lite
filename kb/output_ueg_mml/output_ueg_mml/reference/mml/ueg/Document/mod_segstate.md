## 命令功能

**须知** 

本命令属于高危命令，执行不当会造成业务损失，因此执行该命令前，需要与华为技术支持确认后才可以实施。

本命令用于修改业务模块（CCU/HSF/ACF/DSG/BSG/APF）的隔离状态。

- 隔离CCU模块后，CCU模块置为隔离状态， 去激活CCU模块绑定的链路。
- 隔离HSF模块后， HSF模块置为隔离状态， 去激活HSF模块绑定的链路。
- 隔离ACF模块后，ACF模块置为隔离状态， 处于去激活状态。
- 隔离DSG模块后，DSG模块置为隔离状态，处于去激活状态。
- 隔离BSG模块后，BSG模块置为隔离状态， 去激活BSG模块绑定的链路。
- 隔离APF模块后，APF模块置为隔离状态， 处于去激活状态。

本命令使用场景如下：

- 当系统需要缩容时，使用该命令隔离需要调整的业务模块。如果某个业务模块被隔离，则后续的业务将会被转发到其他业务模块进行处理。
- 在网元扩容场景下，当希望新扩容的业务模块暂时不处理业务时，可执行本命令将业务模块设置为隔离状态。
- 在业务模块异常时，可执行本命令将业务模块设置为隔离状态。
- 在升级场景下，当需要按照平面实现业务模块隔离时，可执行本命令将该平面的业务模块设置为隔离状态。

## 注意事项

- 执行本命令隔离特定的业务模块后：
  - 其它模块将不再向该业务模块转发消息。
  - 系统总处理能力下降。
  - 如果系统剩余业务模块已经满负荷运转，不能接管这部分隔离的业务模块的业务量，则会产生业务损失。
- 执行本命令隔离一个平面的业务模块时，需要检查另外一个平面的业务模块隔离状态，当另外一个平面下存在处于隔离状态的业务模块时，命令执行失败。
- 去激活过程中，检查链路状态， 如果去激活失败， 需要再次执行去激活操作。模块处于隔离状态时，拒绝对端重新建链。
- 如果将隔离态的模块修改为非隔离态时，将激活模块绑定的链路，对于手动执行去激活而非隔离状态去激活的链路，不允许激活。
- 执行本命令进行隔离和解隔离操作后，操作可以通过执行**DSP SEGSTATE**命令确认模块的隔离状态。
- 该命令仅在紧急排除故障的情况下执行，并且需要华为技术工程师对操作方案进行评估，评估通过后方可实施。
- 该命令不允许进行批操作。

## 参数说明

| 参数标识    | 参数名称   | 参数说明                                                                                                                                                                                               |
|:--------|:-------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| TYPE    | 隔离模式   | 用于指定隔离模式。 取值范围：POD(POD)：按照Pod模式进行隔离。MODULE(MODULE)：按照模块模式进行隔离。POD_MAX_MODULE(POD最大模块)：按照指定Pod下的模块类型中模块号最大的模块进行隔离。PLANE(平面)：按照平面模式进行隔离。 默认值：无。                                                      |
| PODNAME | Pod名称  | 仅当本命令中“隔离模式”参数为“POD(POD)”或“POD_MAX_MODULE(POD最大模块)”时，该参数有效。用于指定Pod名称。操作员可以使用LST PODINFO命令查询获得。 取值范围：长度不超过128的字符串。 默认值：无。                                                                           |
| MID     | 模块号    | 仅当本命令中“隔离模式”参数为“MODULE(MODULE)”时，该参数有效。用于指定模块号。操作员可以使用LST MODULE命令查询获得。 取值范围：1～1023                                                                                                                |
| MTYPE   | 模块类型   | 仅当本命令中“隔离模式”参数为“POD_MAX_MODULE(POD最大模块)”时，该参数有效。用于指定模块类型。 取值范围：CCU(CCU)ACF(ACF)DSG(DSG)BSG(BSG)APF(APF) 默认值：无。                                                                                     |
| PLAINFO | 平面信息   | 仅当本命令中“隔离模式”参数为“PLANE(平面)”时，该参数有效。用于指定平面信息。 取值范围： PLANE0(PLANE0)：平面0 PodPLANE1(PLANE1)：平面1 Pod 默认值：无。                                                                                              |
| SSTA    | 业务模块状态 | 用于指定待修改业务模块的隔离状态。 取值范围：FALSE(非隔离)：对处于隔离状态的业务模块设置为非隔离状态。TRUE(隔离)：对处于非隔离状态的业务模块设置为隔离状态。 默认值：无。                                                                                                       |
| SEGSRC  | 隔离处理来源 | 仅当本命令中的“业务模块状态”参数为“TRUE(隔离)”时该参数有效。用于指定触发隔离Pod或者模块命令操作的来源。 取值范围：0位～32位的字符串。 默认值：无。 说明：当“隔离处理来源”设置为“KPI monitor”，使用DSP SEGSTATE查询，查询结果显示为“KPI 监控中心”。当“隔离处理来源”设置为其他值，使用DSP SEGSTATE查询，查询结果显示为“NULL”。 |

## 使用实例

1. 由于局点话务量升高，为有效提供服务，经过讨论、评估，最终确认需要将局点处于隔离状态的Pod设置为非隔离状态。携带参数如下：
   - “隔离模式”为“POD(POD)”
   - “Pod名称”为“vUDM\_98”
   - “业务模块状态”为“FALSE(非隔离)”

   命令执行如下：

   ```
   MOD SEGSTATE: TYPE=POD, PODNAME="vUDM_98", SSTA=FALSE;
   ```
2. 由于局点话务量长期降低，为有效利用资源，经过讨论、评估，最终确认需要对局点业务模块进行缩容。携带参数如下：
   - “隔离模式”为“MODULE(MODULE)”
   - “模块号”为“81”
   - “业务模块状态”为“TRUE(隔离)”命令执行如下：

   ```
   MOD SEGSTATE: TYPE=MODULE, MID=81, SSTA=TRUE;
   ```
3. 由于局点需要进行模块迁移，为有效提供服务，经过讨论、评估，最终确认需要将局点处于隔离状态的Pod对应类型模块号最大的模块设置为隔离状态。携带参数如下：
   - “隔离模式”为“POD\_MAX\_MODULE(POD最大模块)”
   - “Pod名称”为“vUDM\_98”
   - “模块类型”为“CCU”
   - “业务模块状态”为“TRUE(隔离)”

   命令执行如下：

   ```
   MOD SEGSTATE: TYPE=POD_MAX_MODULE, PODNAME="vUDM_98", MTYPE=CCU, SSTA=TRUE;
   ```
4. 升级场景下，需要按照平面实现业务模块隔离。携带参数如下：
   - “隔离模式”为“PLANE(平面)”
   - “平面信息”为“PLANE0(PLANE0)”
   - “业务模块状态”为“TRUE(隔离)”

   命令执行如下：

   ```
   MOD SEGSTATE: TYPE=PLANE, PLAINFO=PLANE0, SSTA=TRUE;
   ```

该命令执行正常，会返回命令执行成功的提示信息。

该命令执行异常，会返回对应的错误码。常见错误码如表1所示。

| 360080 | 指定的POD不存在。                         | 当“隔离模式”参数为“POD(POD)”或“POD_MAX_MODULE(POD最大模块)”时，输入的“Pod名称”所指定的Pod不存在。                                                     | 使用LST PODINFO命令查询后，重新输入数据库中已存在的“Pod名称”。                  |
