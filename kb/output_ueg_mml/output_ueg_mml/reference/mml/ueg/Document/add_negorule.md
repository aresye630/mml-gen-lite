# 增加协商规则(ADD NEGORULE)

- 命令功能
- 注意事项
- 参数说明
- 使用实例

## 命令功能

**须知** 

该命令属于高危命令，新增或修改用户的鉴权算法及其优先级的协商规则，将会带来安全风险或导致业务受损，建议保持系统默认配置。因此执行该命令前，需要与华为技术支持确认后才可以实施。

该命令用于在配置数据库中增加一条方法协商规则记录。

方法协商规则主要作用是协商并设置不同类用户的鉴权算法及鉴权算法的优先级，如果UIM首次对终端进行鉴权被拒绝，将会按优先级依次往下再次进行鉴权，如都被终端拒绝，则鉴权失败。

**说明** 

该命令仅在Full-stack虚机场景下支持。

## 注意事项

- 该命令在“第一阶段”和“第二阶段”中总共可以增加255条记录，如超过255条，会提示失败。
- 算法必须根据优先级依次填写（例如不允许出现填写“第一优先鉴权算法”和“第三优先鉴权算法”，而没有填写“第二优先鉴权算法”的情况）。
- 算法之间不可以有重复（例如不允许出现“第一优先鉴权算法”和“第二优先鉴权算法”都填写成“PEAP”的情况）。
- 执行该命令设置不同的“匹配规则”，对系统的影响及处理建议：
  - 当“匹配规则”取值在0~8之间时，要求系统配置的算法与协议中定义identity的首字符为0~8对应的算法保持一致。如果不一致，会存在业务受损的风险。
  - 当“匹配规则”取值为非0~8之间时，由于MsChapV2和EAP-SIM的安全性低于EAP-AKA和EAP-AKA'，建议在第一阶段较低优先级鉴权算法（如“第三优先鉴权算法”或“第四优先鉴权算法”）中配置。如在第一阶段较高优先级鉴权算法中配置，会存在安全风险。

  **说明** 

  根据RFC4186（EAP-SIM），RFC4187（EAP-AKA），RFC5448（EAP-AKA'），3GPP 23.003协议中说明：

  - 当identity的首字符0，2，4时，用于标识UE使用EAP-AKA的全认证，伪随机NAI认证和快速NAI认证。
  - 当identity的首字符1，3，5时，用于标识UE使用EAP-SIM的全认证，伪随机NAI认证和快速NAI认证。
  - 当identity的首字符6，7，8时，用于标识UE使用EAP-AKA'的全认证，伪随机NAI认证和快速NAI认证。

## 参数说明

| 参数标识              | 参数名称        | 参数说明                                                                                                                                                                                                                                          |
|:------------------|:------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| IDENTITY          | 匹配规则        | 用于指定一个方法协商的匹配规则，在同一个方法使用阶段中不能重复。 取值范围：长度不超过127的字符串。 默认值：无。                                                                                                                                                                                    |
| METHOD_USED_PHASE | 方法使用阶段      | 用于指定方法协商规则的使用阶段。 取值范围： PHASE1(第一阶段)：表示在TLS隧道建立之前使用方法协商规则的阶段。PHASE2(第二阶段)：表示在TLS隧道建立之后使用方法协商规则的阶段。 默认值：无。                                                                                                                                      |
| METHOD1           | 第一优先鉴权算法    | 用于指定鉴权算法的优先级。 仅当本命令中的“方法使用阶段”参数为“PHASE1(第一阶段)”时，该参数有效。 取值范围：SIM(EAP-SIM)：EAP-SIM鉴权功能AKA(EAP-AKA)：EAP-AKA鉴权功能PEAP(EAP-PEAP)：PEAP鉴权功能MSCHAPV2(MSCHAPV2)：MS-CHAPv2鉴权功能AKA2(EAP-AKA')：EAP-AKA'鉴权功能 默认值：无。                                         |
| METHOD2           | 第二优先鉴权算法    | 用于指定鉴权算法的优先级。 仅当本命令中的“方法使用阶段”参数为“PHASE1(第一阶段)”时，该参数有效。 取值范围：SIM(EAP-SIM)：EAP-SIM鉴权功能AKA(EAP-AKA)：EAP-AKA鉴权功能PEAP(EAP-PEAP)：PEAP鉴权功能MSCHAPV2(MSCHAPV2)：MS-CHAPv2鉴权功能AKA2(EAP-AKA')：EAP-AKA'鉴权功能 默认值：无。                                         |
| METHOD3           | 第三优先鉴权算法    | 用于指定鉴权算法的优先级。 仅当本命令中的“方法使用阶段”参数为“PHASE1(第一阶段)”时，该参数有效。 取值范围：SIM(EAP-SIM)：EAP-SIM鉴权功能AKA(EAP-AKA)：EAP-AKA鉴权功能PEAP(EAP-PEAP)：PEAP鉴权功能MSCHAPV2(MSCHAPV2)：MS-CHAPv2鉴权功能AKA2(EAP-AKA')：EAP-AKA'鉴权功能 默认值：无。                                         |
| METHOD4           | 第四优先鉴权算法    | 用于指定鉴权算法的优先级(目前本版本有3种鉴权算法，4种鉴权优先级，“第四优先的鉴权算法”作为扩展预留)。 仅当本命令中的“方法使用阶段”参数为“PHASE1(第一阶段)”时，该参数有效。 取值范围：SIM(EAP-SIM)：EAP-SIM鉴权功能AKA(EAP-AKA)：EAP-AKA鉴权功能PEAP(EAP-PEAP)：PEAP鉴权功能MSCHAPV2(MSCHAPV2)：MS-CHAPv2鉴权功能AKA2(EAP-AKA')：EAP-AKA'鉴权功能 默认值：无。 |
| METHOD1_IN_PHASE2 | 阶段二第一优先鉴权算法 | 用于指定在阶段二中方法协商阶段过程中的第一优先鉴权算法。 仅当本命令中的“方法使用阶段”参数为“PHASE2(第二阶段)”时，该参数有效。 取值范围：MSCHAPV2(MSCHAPV2)：表示MSCHAPV2鉴权功能。 默认值：无。 注意：该参数为必选参数。                                                                                                             |

## 使用实例

1. 增加一条协商规则，携带以下参数：
   - “匹配规则”为“20”
   - “方法使用阶段”为“PHASE1(第一阶段)”
   - “第一优先鉴权算法”为“PEAP(EAP-PEAP)”
   - “第二优先鉴权算法”为“SIM(EAP-SIM)”
   - “第三优先鉴权算法”为“AKA(EAP-AKA)”

   执行命令如下：

   ```
   ADD NEGORULE: IDENTITY="20", METHOD_USED_PHASE=PHASE1, METHOD1=PEAP, METHOD2=SIM, METHOD3=AKA;
   ```
2. 增加一条协商规则，携带以下参数：
   - “匹配规则”为“30”
   - “方法使用阶段”为“PHASE2(第二阶段)”
   - “阶段二第一优先鉴权算法”为“MSCHAPV2(MSCHAPV2)”

   执行命令如下：

   ```
   ADD NEGORULE: IDENTITY="30", METHOD_USED_PHASE=PHASE2, METHOD1_IN_PHASE2=MSCHAPV2;
   ```
