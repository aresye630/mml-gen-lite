## 操作场景

UPCF支持VoNR方案，用于部署IMS应用，为基本呼叫业务提供保障的带宽，确保用户享用优质语音和高清视频。当5G用户接入IMS网络发起基本呼叫时，AF（即IMS域的P-CSCF）通过Rx接口向UPCF发起资源预留请求，将会话相关的属性，如应用标识、媒体类型、媒体流状态、媒体流描述等上报给UPCF，UPCF根据AF上报的信息和本地配置的业务策略进行策略判断，将生成的QoS规则通过N7接口下发给SMF执行策略控制。

## 必备事项

前提条件

- 操作员已了解GWFD-025903 Rx接口(使用Diameter协议)VoNR策略控制特性概述。
- 操作员已了解“VoNR业务和特性描述”。
- 已完成配置UPCF与AF（基于Diameter协议）的对接数据。

## 操作步骤

- 登录“UEG MML命令”界面。
  1. 执行ADD APN命令，添加“VoLTE-APN”类型的APN。

     该命令用来防止数据业务的规则下发给IMS。命令举例如下：

     ```
     ADD APN: PCRFID=1, APNID=1, APNNAME="ims", APNTYPE=VoLTE-APN, APNMATCHTYPE=FullMatching;
     ```
  2. 执行**MOD PCFINSP**命令，修改软参VRM\_SERVICEINFOSTATUSMODE的取值。

     ```
     MOD PCFINSP:INSPN=VRM_SERVICEINFOSTATUSMODE, INSPV=2;
     ```

     **说明** 

     早期预留场景下，需要根据实际场景配置软参“VRM\_SERVICEINFOSTATUSMODE”的值，该场景软参配置为“2”。

- 登录UPCF Web UI界面。

配置条件组。

导航入口为“策略管理 > 策略 > 条件组”。

**说明** 

- 当业务的使用需要设置控制条件时，需要配置条件组。若某规则不配置条件组，表示在同一业务里其他条件都匹配不上时，才触发此规则。
- 条件组是一个或多个条件的组合。条件组中的各条件之间可以是“与”的关系，也可以是“或”的关系。条件之间的与/或关系由参数“关系”的取值决定。

配置5G动作组。

导航入口为“策略管理 > 策略 > 5G动作组”。

**说明** 

此场景需配置5G动作：Ambr、Arp、DefaultQosInformation、SessionRuleAction、BasicInfoAction、FlowDescription、FlowInformation、QoSData、TrafficControlData、DynamicPccRule和DynamicPccRuleIMS，相关应用场景如下：

- Ambr：用于设置会话类型的上下行带宽。
- Arp：当需要配置“类型”为“QoSData”和“DefaultQosInformation”的动作组时必须配置此动作。
- DefaultQosInformation：用于设置会话类型的QoS信息。
- SessionRuleAction：需要配置会话类型规则，需要配置此动作。
- BasicInfoAction：用于设置QoS流的方式为IMS信令。
- FlowDescription：当需要下发流方向时需配置此动作。
- FlowInformation：当需要下发流信息时需配置此动作。
- QoSData：当需要进行带宽控制时均需配置此动作，若不配置则表示不限制Qos。
- TrafficControlData：当需要做门限控制时，配置此动作。在下发流描述时，如果不配默认为放通该流，当需要限制流时，此动作必须配置。此场景根据AF请求的Flow-Status，下发门限策略。
- DynamicPccRule：需要配置动态类的业务规则，需要配置此动作。
- DynamicPccRuleIMS：VoNR场景需要配置此动作。

请增加如下5G动作组和动作：

- 动作组AG\_N7\_ambr：动作类型为Ambr
- 动作组AG\_VoNR\_ARP：动作类型为Arp
- 动作组AG\_N7\_def：动作类型为DefaultQosInformation
- 动作组AG\_N7\_sessRule：动作类型为SessionRuleAction
- 动作组AG\_BasicRule：动作类型为BasicInfoAction
- 动作组AG\_N7\_FlowD：动作类型为FlowDescription
- 动作组AG\_N7\_Finfo：动作类型为FlowInformation
- 动作组AG\_N7\_QoSData、AG\_VoNR\_QoSData1、AG\_VoNR\_QoSData2和AG\_PreReserved\_QoSData：动作类型为QoSData
- 动作组AG\_N7\_TrafficCtrl和AG\_VoNR\_TrafficControlData：动作类型为TrafficControlData
- 动作组AG\_N7\_pccRule和AG\_PreReserved\_IMS：动作类型为DynamicPccRule
- 动作组AG\_VoNR\_DynamicPccRuleIMS1、AG\_VoNR\_DynamicPccRuleIMS1\_B、AG\_VoNR\_DynamicPccRuleIMS2、AG\_VoNR\_DynamicPccRuleIMS2\_B：动作类型为DynamicPccRuleIMS
