## 操作场景

**接口介绍**

SMF的服务化接口为Nsmf，与参考点的对应关系如下。参考点是指5G系统服务化架构映射到传统架构后，对应传统网元之间点对点的接口，用来代表NF之间交互的参考模型，并不是真实的接口。

| 参考点   | 网元间的交互    | 服务化接口     |
|:------|:----------|:----------|
| N10   | SMF<->UDM | Nsmf、Nudm |
| N11   | AMF<->SMF | Namf、Nsmf |

**图1** 服务化接口协议栈图

服务化接口间采用相同的协议栈，传输层统一采用HTTP/2协议，应用层携带不同的服务消息。因为底层的传输方式相同，所有的服务化接口就可以在同一总线上进行传输，支撑业务灵活上线。

**说明** 

HTTP/2（HyperText Transport Protocol 2.0）：下一代超文本传输协议。基于HTTP协议的信息交换分为四个过程：建立连接、发送请求信息、发送响应信息、关闭连接。

TLS（Transport Layer Security）：安全传输层协议。在两个通信应用程序之间提供保密性和数据完整性。

园区风筝M有两种运行模式：

- 正常模式：中心侧SMF对接中心侧UDM。
- 应急模式：应急SMF与园区内本地DC的UDM对接，使用园区统一规划的IP地址，VRF。数据在园区内封闭传输。

本文配置仅关注应急SMF的配置。

**配置建议**

- SMF的服务化接口业务IP地址不能和SMF其他接口业务IP地址共用。
- SMF的服务化接口端口号没有明确时，使用HTTP知名端口号8080。
- 一个NF类型需要配置一个HTTP本端端点组和对应的HTTP本端端点，然后根据实际部署NF数量配置分别配置对应的SBI端点并绑定对应的HTTP本端端点组。

以下配置数据以及步骤均以UEG双DC组网场景的配置规划为例进行介绍。

## 操作步骤

**配置SMF服务化接口数据**

如果要配置v4v6双栈类型的服务化接口，该服务化接口的业务逻辑IP地址需要配置v4和v6类型的IP地址（通过**ADD LOGICIP**配置），相应的HTTP链路也需要配置v4和v6类型IP地址（通过**ADD HTTPLE**配置）。

**说明** 

当本端以及对端都配置了v4v6双栈类型的IP地址时，UNC侧可以通过将软参**DWORD1 BIT24**设置为**“1”**来确保在业务流程中优选IPv6地址进行建链。

1. 增加SMF服务化接口的IP地址。

   ```
   //DC1
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="10.16.0.4", VPNINSTNAME="VPN_CN", DESC="FOR Server SBI";
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="10.16.0.5", VPNINSTNAME="VPN_CN", DESC="FOR Client SBI";
   //DC2
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="10.16.0.6", VPNINSTNAME="VPN_CN", DESC="FOR Server SBI";
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="10.16.0.7", VPNINSTNAME="VPN_CN", DESC="FOR Client SBI";
   ```
2. 配置SMF服务化接口的HTTP本端端点组及其包含的分别作为HTTP服务的服务端和客户端的本端端点信息。

   1. 配置HTTP本端端点组信息。

      ```
      //DC1
      ADD HTTPLEGRP: INDEX=2, DESC="SMF";
      //DC2
      ADD HTTPLEGRP: INDEX=2, DESC="SMF";
      ```
   2. 配置分别作为HTTP服务的服务端和客户端的本端端点信息。

      ```
      //DC1
      ADD HTTPLE: INDEX=3,HTTPLEGRPIDX=2, LETYPE=SERVER, IPTYPE=IPv4, IPV4="10.16.0.4", PORT=8080, VPNNAME="VPN_CN", TLSFLG=NO, DESC="SMF Server";
      ADD HTTPLE: INDEX=4,HTTPLEGRPIDX=2, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="10.16.0.5", VPNNAME="VPN_CN", DESC="SMF Client";
      //DC2
      ADD HTTPLE: INDEX=3,HTTPLEGRPIDX=2, LETYPE=SERVER, IPTYPE=IPv4, IPV4="10.16.0.6", PORT=8080, VPNNAME="VPN_CN", TLSFLG=NO, DESC="SMF Server";
      ADD HTTPLE: INDEX=4,HTTPLEGRPIDX=2, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="10.16.0.7", VPNNAME="VPN_CN", DESC="SMF Client";
      ```
3. 配置SMF服务化接口接入点信息。

   ```
   //DC1
   ADD SBIAPLE: INDEX=2, HTTPLEGRPIDX=2, NFTYPE=NFTypeSMF, DESCRIPTION="SMF";
   //DC2
   ADD SBIAPLE: INDEX=2, HTTPLEGRPIDX=2, NFTYPE=NFTypeSMF, DESCRIPTION="SMF";
   ```

**配置SMF到AMF的服务化接口**

4. 配置到AMF的数据，包括AMF的Profile、Service、PLMN等信息。

   **说明** 

   SMF可以基于DNN、DNAI、切片、TAI、PLMN选择AMF，园区可以基于规划的选择条件进行配置，此处以PLMN为例说明配置过程。

   ```
   //DC1
   ADD PNFPROFILE: NFINSTANCEID="AMF_Instance_0", NFTYPE=NfAMF, NFSTATUS=Registered, IPADDRESSTYPE=IPTypeV4, IPV4ADDRESS1="172.16.1.5", PORT=8080;
   ADD PNFSERVICE: NFINSTANCEID="AMF_Instance_0", SRVINSTANCEID="Service_Instance_0", SERVICENAME=NamfComm, SCHEMA=http, NFSERVICESTATUS=REGISTERED;
   ADD PNFSERVICE: NFINSTANCEID="AMF_Instance_0", SRVINSTANCEID="Service_Instance_1", SERVICENAME=NamfEvts, SCHEMA=http, NFSERVICESTATUS=REGISTERED;
   ADD PNFPLMN:NFINSTANCEID="AMF_Instance_0",MCC="123", MNC="03";
   //DC2
   ADD PNFPROFILE: NFINSTANCEID="AMF_Instance_1", NFTYPE=NfAMF, NFSTATUS=Registered, IPADDRESSTYPE=IPTypeV4, IPV4ADDRESS1="172.16.1.6", PORT=8080;
   ADD PNFSERVICE: NFINSTANCEID="AMF_Instance_1", SRVINSTANCEID="Service_Instance_0", SERVICENAME=NamfComm, SCHEMA=http, NFSERVICESTATUS=REGISTERED;
   ADD PNFSERVICE: NFINSTANCEID="AMF_Instance_1", SRVINSTANCEID="Service_Instance_1", SERVICENAME=NamfEvts, SCHEMA=http, NFSERVICESTATUS=REGISTERED;
   ADD PNFPLMN:NFINSTANCEID="AMF_Instance_1",MCC="123", MNC="03";
   ```

**配置SMF到UDM的服务化接口**

5. 配置到UDM的数据，包括UDM的Profile、Service、PLMN信息、支持的SUPI范围等信息。

   **说明** 

   - UEG中AMF和SMF共部署，如果在配置AMF的时候已经配置和UDM的对接配置，则本步骤无需重复配置。
   - SMF可以基于DNN、DNAI、切片、TAI、PLMN、SUPI、GPSI、RouteID、GroupID选择UDM，园区可以基于规划的选择条件进行配置，此处以PLMN、SUPI为例说明配置过程。

   ```
   //DC1
   ADD PNFPROFILE: NFINSTANCEID="UDM_Instance_0", NFTYPE=NfUDM, NFSTATUS=Registered, IPADDRESSTYPE=IPTypeV4, IPV4ADDRESS1="10.255.255.179", PORT=8080, PRIORITY=10;
   ADD PNFSERVICE: NFINSTANCEID="UDM_Instance_0", SRVINSTANCEID="Service_Instance_0", SERVICENAME=NudmSdm, SCHEMA=http, NFSERVICESTATUS=REGISTERED;
   ADD PNFSERVICE: NFINSTANCEID="UDM_Instance_0", SRVINSTANCEID="Service_Instance_1", SERVICENAME=NudmUecm, SCHEMA=http, NFSERVICESTATUS=REGISTERED;
   ADD PNFPLMN:NFINSTANCEID="UDM_Instance_0",MCC="123", MNC="03";
   ADD PNFSUPI: INDEX=1,NFINSTANCEID="UDM_Instance_0", QUERYTYPE=START_END, RANGESTART="123031200100001",RANGEEND="123031200100001";
   ```

## 验证方法

1. 检查到周边NF的路由数据，目的地址为对端NF的服务化接口地址。

   ```
   NGPING: IPTYPE=IPv4, VPNNAME="VPN_CN", SRCIPV4ADDR="172.16.0.6", DSTIPV4ADDR="172.16.1.5";
   ```

   - **预期结果**：看到响应报文，并且报文中有成功收发包的个数。
   - **异常结果**：无法收到对端的响应报文。
2. 检查服务化接口链路状态。
   - 检查SMF作为服务端时的链路状态。作为服务端时，只有在正常业务流程时才能查询到链路状态信息。

     ```
     DSP SBILINKSTATUS: ENTITYTYPE=Server;
     ```

     - **预期结果**：“链路状态”为“Normal”。
     - **异常结果**：“链路状态”为“Fault”。
   - 检查SMF作为客户端时的链路状态。作为客户端时，无论是否有业务流程都能查询到链路状态信息。

     ```
     DSP SBILINKSTATUS: ENTITYTYPE=Client, LOCALNFTYPE=NFTypeSMF;
     ```

     - **预期结果**：“链路状态”为“Normal”。
     - **异常结果**：“链路状态”为“Fault”。
