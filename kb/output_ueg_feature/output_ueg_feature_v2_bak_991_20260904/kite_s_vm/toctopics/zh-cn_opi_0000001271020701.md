# 配置内置NAT支持安全域路由

## 操作场景

UEG使用内置NAT支持安全域路由功能时，需要通过本章配置内容进行激活。

## 必备事项

前提条件

- 已登录OM Portal。
- 已完成配置NAT基本功能License开关。

数据

| 类别                  | 参数名称                      | 取值样例        | 获取方法     | 说明                                                       |
|:--------------------|:--------------------------|:------------|:---------|:---------------------------------------------------------|
| ADD ROUTEPOLICY     | 路由策略名字（POLICYNAME）        | a           | 本端规划     | 配置路由策略信息。                                                |
| ADD ROUTEPOLICYNODE | 路由策略名字（POLICYNAME）        | a           | 已配置数据中获取 | 已通过ADD ROUTEPOLICY命令配置，可以使LST ROUTEPOLICY命令进行查询。         |
| ADD ROUTEPOLICYNODE | 路由策略节点号（NODESEQUENCE）     | 10          | 本端规划     | 配置路由策略的路由策略节点。                                           |
| ADD ROUTEPOLICYNODE | 匹配模式（MATCHMODE）           | permit      | 本端规划     | 配置路由策略的路由策略节点。                                           |
| ADD APPLYNEXTHOP    | 路由策略名字（POLICYNAME）        | userprofile | 本端规划     | 已通过ADD ROUTEPOLICY命令配置，可以使LST ROUTEPOLICY命令进行查询。         |
| ADD APPLYNEXTHOP    | 路由策略节点号（NODESEQUENCE）     | a           | 已配置数据中获取 | 已通过ADD ROUTEPOLICYNODE命令配置，可以使LST ROUTEPOLICYNODE命令进行查询。 |
| ADD APPLYNEXTHOP    | 是否是对等体IP地址（ISPEERADDRESS） | FALSE       | 本端规划     | 配置基于IPv4信息路由下一跳。                                         |
| ADD APPLYNEXTHOP    | 下一跳地址（NEXTHOP）            | 192.168.0.1 | 本端规划     | 配置基于IPv4信息路由下一跳。                                         |

## 操作步骤

UEG上的数据配置

1. 配置路由策略名称。

   **ADD ROUTEPOLICY**
2. 添加路由策略节点。

   **ADD ROUTEPOLICYNODE**
3. 设置路由下一跳。

   IPv4时：**ADD APPLYNEXTHOP**

NAT上的数据配置

4. 选择“应用管理 > NAT”，进入NAT的CLI执行界面。
5. 进入系统视图。

   **system-view**
6. 进入TrafficLink视图。

   **trafficlink-view**
7. 配置非匿名虚拟接口。

   **sysvif name *xxx* ipv4** ***xxx*** **encaptype gtpu**

   **说明** 

   - 相同名称的虚拟接口新配置会覆盖已有配置。使用**undo sysvif all**恢复默认值。
   - 虚拟接口配置的地址不能与对接网元的地址段重叠。
8. 配置TrafficLink。

   **trafficlink *xxx* sysvif *xxx* srvvpn *xxx* upvpn *xxx* downvpn *xxx***

   **说明** 

   - 方向VPN是由UpVPN和DownVPN构成，用于组网需要。使信任区域和非信任区域的用户报文不能直接互相转发，默认下一跳为NAT内部处理模块。信任区域侧上规划的VPN为UpVPN，非信任区域侧规划的VPN为DownVPN。不同VPN间路由隔离，通过引入BGP协议完成UpVPN和DownVPN的路由交互。
   - 绑定UpVPN，DownVPN和业务VPN。UpVPN和DownVPN来自于网络规划，VPN名称需要与VNRS的配置保持一致。
   - U口、D口配置的VPN全局唯一，配置TrafficLink需要校验VPN是否已经存在，如果存在配置失败。如果冲突请排查
   - 允许**nat-policy**和TrafficLink配置相同的业务VPN，支持U口业务允许部分流量进行NAT处理，部分流量进行Trafficlink处理。
   - Trafficlink配置规格为256。
9. 进入nap-view视图。

   **nap-view**
10. 配置包过滤策略。

    **packet-policy** ***xxx*** **nap-filter-group** ***xxx*** **vpn-instance *xxx* uplink action****permit****priority** ***x***

    **packet-policy** ***xxx*** **nap-filter-group** ***xxx*** **vpn-instance *xxx* downlink action****permit****priority** ***x***

## 任务示例

任务描述

将VNRS上IPv4地址类型的路由引流至NAT，完成安全域路由配置。

脚本

//配置路由策略名称。

```
ADD ROUTEPOLICY: POLICYNAME="a";
```

//添加路由策略节点。

```
ADD ROUTEPOLICYNODE: POLICYNAME="a", NODESEQUENCE=10, MATCHMODE=permit;
```

//设置路由下一跳。

```
ADD APPLYNEXTHOP: POLICYNAME="a", NODESEQUENCE=10, ISPEERADDRESS=FALSE, NEXTHOP="192.168.0.2";
```

//NAT上的配置。

```
<NAT>system-view
[NAT]trafficlink-view  //进入trafficlink视图  
[NAT-trafficlink]sysvif name sysvifauto ipv4 192.168.0.2 encaptype gtpu    //配置非匿名Vif
[NAT-trafficlink]trafficlink t1 sysvif sysvifauto srvvpn srvvpn upvpn upvpn downvpn dnvpn  //配置非匿名TrafficLink
[NAT-trafficlink]q
[NAT]nap-view    //进入nap视图
[NAT-nap]packet-policy pp1 nap-filter-group testfiltergroup vpn-instance srvvpn uplink action permit priority 200  //配置上行包过滤策略
[NAT-nap]packet-policy pp1 nap-filter-group testfiltergroup vpn-instance srvvpn downlink action permit priority 100  //配置下行包过滤策略
```
