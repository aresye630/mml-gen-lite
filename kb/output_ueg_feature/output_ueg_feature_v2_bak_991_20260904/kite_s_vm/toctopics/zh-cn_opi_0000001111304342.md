## 操作场景

在不同场景下或针对不同运营商，支持两种方式下发动态Traffic Rule和动态DNS Rule。通过**SET MPFATTR**命令设置MPF属性配置，即管理面MEPM和MPF之间的Mm5接口可以处理的消息类型，从而设置不同的下发方式，两种场景不会同时存在：

- “MM5MSGTYPE”参数配置为APPD：表示管理面MEPM向MPF下发规则的模式是APPD（APP Descriptor）模式，Mm5接口的一条HTTPS请求消息中的APPD包含一个APP实例的动态Traffic Rule、动态DNS Rule、APP依赖的服务和APP提供的服务等信息。
- “MM5MSGTYPE”参数配置为SPEC\_RULE：表示管理面MEPM向MPF下发规则的模式是指定Rule模式，Mm5接口的一条HTTPS请求消息中仅包含一个APP实例的动态Traffic Rule或者动态DNS Rule。

**说明** 

适用于MPF。

## 必备事项

前提条件

请仔细阅读动态分流规则下发。

数据

| 类别          | 参数名称                  | 取值样例   | 获取方法   | 说明                                                                                                                              |
|:------------|:----------------------|:-------|:-------|:--------------------------------------------------------------------------------------------------------------------------------|
| SET MPFATTR | Mm5接口消息类型（MM5MSGTYPE） | APPD   | 全网规划   | APPD：表示Mm5接口处理的消息类型的Rule模式为APPD模式。SPEC_RULE：表示Mm5接口处理的消息类型的Rule模式为指定Rule模式。                                                     |
| SET MPFATTR | MEP ID（MEPID）         | mepid  | 全网规划   | 该参数在“MM5MSGTYPE”配置为“SPEC_RULE”时不需要配置，因为Mm5接口下发指定Rule时会携带MEP ID信息。该参数在“MM5MSGTYPE”配置为“APPD”时为可选参数，用于配置MEP ID信息，如果不配置则表示使用默认值mpf。 |

## 操作步骤

1. 设置MPF属性配置。

   **SET MPFATTR**

   **注意** 

   该命令属于高危命令，“Mm5接口消息类型”的APPD类型和指定SPEC\_RULE类型互斥，配置成功后会导致另一种类型消息不作处理，请谨慎执行。“Mm5接口消息类型”默认配置为APPD。

## 任务示例

任务描述

配置管理面MEPM通过Mm5接口下发动态规则的模式是APPD模式。

脚本

//配置管理面MEPM通过Mm5接口下发动态规则的模式是APPD模式。

```
SET MPFATTR: MM5MSGTYPE=APPD, MEPID="mepid";
```
