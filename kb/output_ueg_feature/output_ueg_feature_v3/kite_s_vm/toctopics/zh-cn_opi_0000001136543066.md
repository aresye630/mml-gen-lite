# 配置用户下行路由

## 操作场景

为保证用户下行数据包能正常到达MPF，通过MPF访问APP服务器的UE地址段需要在网络中发布，并最终能传递到APP服务器。

## 必备事项

前提条件

* 具备管理员权限的操作人员已经登录华为操作维护系统（登录MAE客户端或登录OM Portal）。

数据

对于表1中的用户下行路由数据：

* UEG与DC-GW之间采用BGP over静态路由时，MPF可将**ADD MPFROUTE**命令配置的用户IP地址段+外联口IP（组网路由配置）发布给DC-GW。DC-GW收到APP服务器发送的用户下行数据报文时，根据用户路由信息（目的IP是UE IP，下一跳是MPF的外联口IP）将报文发送到MPF。
* UEG与DC-GW之间采用静态路由时，需要在DC-GW上配置静态路由，静态路由的目的地址和掩码对应UE IP所在网段，下一跳是UEG的外联口IP。和APP服务器互通的外联口IP存在多个时，需要配置多条路由，即目的IP和掩码相同，下一跳IP不同。

**如下数据仅为举例，请注意修改成局点规划的数据。**

**表1** 用户下行路由

| 类别 | 参数名称 | 取值样例 | 获取方法 | 说明 |
| --- | --- | --- | --- | --- |
| **ADD VPNINST** | VPN实例名（VPNINSTANCE） | VRF\_N6x | 全网规划 | 与N6x外联口的VPN相同。 |
| **ADD MPFROUTE** | MPF路由标识（MPFROUTEID） | UEIPSEG\_01 | 本端规划 | 唯一标识一条UE地址段。 |
|  | VPN实例名（VPNINSTANCE） | VRF\_N6x | 已配置数据中获取 | 索引**ADD VPNINST**命令配置的VPN实例名。  与N6x外联口的VPN相同。 |
|  | MPF地址类型（IPVERSION） | IPV4 | 本端规划 | - |
|  | IPv4起始地址（V4STARTIP） | 10.10.1.1 | 全网规划 | 必须包含与UPF上通过MPF访问APP服务器的所有UE IPv4地址。 |
|  | IPv4结束地址（V4ENDIP） | 10.10.1.254 | 全网规划 |  |
| **ADD MPFROUTE** | MPF路由标识（MPFROUTEID） | UEIPSEG\_02 | 本端规划 | 唯一标识一条UE地址段。 |
|  | VPN实例名（VPNINSTANCE） | VRF\_N6x | 已配置数据中获取 | 索引**ADD VPNINST**命令配置的VPN实例名。  与N6x外联口的VPN相同。 |
|  | MPF地址类型（IPVERSION） | IPV6 | 本端规划 | - |
|  | IPv6前缀起始地址（V6PREFIXSTART） | FC00:1::1:1 | 全网规划 | 必须包含与UPF上通过MPF访问APP服务器的所有UE IPv6地址。 |
|  | IPv6前缀结束地址（V6PREFIXEND） | FC00:1::1:254 | 全网规划 |  |

## 操作步骤

1. 进入“MML命令行-UEG”窗口。
2. 配置VPN实例。

   ```
   ADD VPNINST: VPNINSTANCE ="VRF_N6x";
   ```
3. 配置UE地址段。

   //配置UE IPv4地址段。

   ```
   ADD MPFROUTE: MPFROUTEID="UEIPSEG_01", VPNINSTANCE ="VRF_N6x", IPVERSION=IPV4, V4STARTIP="10.10.1.1", V4ENDIP="10.10.1.254";
   ```

   //配置UE IPv6地址段。

   ```
   ADD MPFROUTE: MPFROUTEID="UEIPSEG_02", VPNINSTANCE ="VRF_N6x", IPVERSION=IPV6, V6PREFIXSTART="FC00:1::1:1", V6PREFIXEND="FC00:1::1:254";
   ```

## 验证方法

1. 在直连的DCGW上，查看是否生成到UE IP地址段的路由。
   * 是，调测结束。
   * 否，请执行2。
2. 执行**LST MPFROUTE**命令，查看UE地址段是否与规划一致。
   * 是，请联系华为技术支持工程师处理。
   * 否，请删除并配置UE地址段后重新调测。
