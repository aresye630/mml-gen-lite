# 配置HTTP信令数据

## 操作场景

接入5G SA/5G NSA/4G用户时，HTTP信令数据用于PCF/PCRF和AMF/SMF/PGW-C对接。

园区PCF/PCRF不支持与NRF通信，因此需要手动配置PCF/PCRF和AMF/SMF/PGW-C之间的服务发现。

* N7接口不支持传递PTT业务的策略，因此，部署PTT业务时，需要配置PCRF与PGW-C之间的Gx接口数据。详细配置请参见配置PCF与PCEF（基于Diameter协议）的对接数据。
* 未部署PTT业务的场景，为简化配置，PCF/PCRF与SMF/PGW-C均通过N7接口对接。不需要配置PCRF与PGW-C之间的Gx接口数据。

  通过N7接口对接时，需要在SMF/PGW-C上通过**SET POLICYMODE**命令将“FORCED（指定策略接口）”设置为“Npcf（Npcf接口）”。

## 必备事项

前提条件

已完成配置PCF基础数据。

数据

**如下数据仅为举例，请注意修改成局点规划的数据。**

容灾组网中，同一UEG内的PCF/PCRF和AMF/SMF/PGW-C对接，不同UEG内不交叉对接。即：如下表格中，DC1的PCF/PCRF和DC1的AMF/SMF/PGW-C对接，DC2的PCF/PCRF和DC2的AMF/SMF/PGW-C对接。

PCF作为客户端时，使用SMF/AMF请求中携带的SMF/AMF信息创建HTTP链路，不需要手动配置SMF/AMF的IP及端口等信息。

如已完成配置PCF基础数据中的HTTP IP数据配置，则不需要重复规划。

**表1** HTTP IP数据（服务化接口数据）

| 类别 | 参数名称 | 取值样例  （DC1） | 取值样例  （DC2） | 获取方法 | 说明 |
| --- | --- | --- | --- | --- | --- |
| **ADD HLBDEVADDR** | DEVAID（设备地址标识） | 2 | 2 | 本端规划 | 网元内存在多条记录时，该参数不能重复。 |
|  | VPNNAME（VPN名称） | VRF\_SBI | VRF\_SBI | 已规划数据中获取 | 本端服务化接口IP，用于和SMF/AMF互通。   * 双DC场景，两个DC的服务化接口IP地址不能重复，如DC1用样例值，DC2用10.201.200.47等。 * 表格中未特殊说明的参数，两个DC保持一致。 |
|  | IPVER（IP版本） | IPV4 | IPV4 | 本端规划 |  |
|  | IP（IPV4地址） | 10.200.200.47 | 10.201.200.47 | 全网规划 |  |
|  | HTTPSFUNC（HTTPS功能） | OFF | OFF | 与对端协商 | * AMF、SMF与PCF均由同一个UEG设备实现，可不开启HTTPS。 * HTTP端口号默认为8080，HTTPS端口号默认为443。 |

文档

获取网设LLD文档。

## 操作步骤

1. 登录“UEG MML命令”界面。
2. 配置HTTP IP，用于和AMF/SMF/PGW-C通信。如已完成配置PCF基础数据中的HTTP IP数据配置，则不需要重复配置。

   //DC1：

   ```
   ADD HLBDEVADDR: DEVAID=2, VPNNAME="VRF_SBI", IPVER=IPV4, IP="10.200.200.47", HTTPSFUNC=OFF;
   ```

   //DC2：

   ```
   ADD HLBDEVADDR: DEVAID=2, VPNNAME="VRF_SBI", IPVER=IPV4, IP="10.201.200.47", HTTPSFUNC=OFF;
   ```
3. 设置HTTP客户端链路的管理模式。

   ```
   SET HTTPCLIENTCFG: LINKCTLMODE=NEW;
   ```

## 验证方法

检查PCF-AMF/SMF链路。

1. 登录“UEG MML命令”界面。
2. 执行**DSP HLBPEERL**命令：参数“对端标识”和“链路标识”与规划数据一致。检查“链路状态”参数项的返回结果。

   * 在线 => PCF-AMF/SMF链路正常，PCF-AMF/SMF设备对接调测结束。
   * 离线 => 3
3. 登录OM Portal界面，选择“监控分析 > 告警管理”，查看系统是否有上报“34163 PCF与NF之间的HTTP链路故障”告警。
   * 是 => 根据告警帮助进行处理。
   * 否 => 4
4. 请联系华为技术支持处理。
