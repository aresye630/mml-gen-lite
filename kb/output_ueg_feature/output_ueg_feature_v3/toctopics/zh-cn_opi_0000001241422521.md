# 配置AMF服务化接口数据（N8/N11/N12/N14/N15）

## 操作场景

AMF的服务化接口为Namf，与参考点的对应关系如下。参考点是指5G系统服务化架构映射到传统架构后，对应传统网元之间点对点的接口，用来代表NF之间交互的参考模型，并不是真实的接口。

**表1** 服务化接口与参考点模式对应关系

| 参考点 | 网元间的交互 | 服务化接口 |
| --- | --- | --- |
| N8 | AMF<->UDM | Namf、Nudm |
| N11 | AMF<->SMF | Namf、Nsmf |
| N12 | AMF<->AUSF | Nausf、Namf |
| N14 | AMF<->AMF | Namf、Namf |
| N15 | AMF<->PCF | Namf、Npcf |

园区风筝L有三种部署模式：

* L1：AMF对接中心侧UDM/AUSF，需要运营商规划业务IP地址，VRF。由于数据要出园区，因此从安全性角度考虑，AMF和UDM/AUSF间建议配置IPSec隧道。
* L1-1: L1-1是在风筝L1的基础上，变化了和UDM的对接关系。AMF支持直连对接大网主备UDM，本地直连对接UEG L的UDM，和大网2个UDM都直连对接，和园区UDM对接，保持盒子式的组网，仅和本风筝L的UDM直连对接，不对接其他风筝L的UDM。
* L2：AMF与园区内本地DC和对端DC的UDM/AUSF对接，这样使用园区统一规划的IP地址，VRF。数据在园区内封闭传输。

除此以外，L1和L2模式中AMF对接UDM和AUSF的其他配置无差异。

**图1** 服务化接口协议栈图

服务化接口间采用相同的协议栈，传输层统一采用HTTP/2协议，应用层携带不同的服务消息。因为底层的传输方式相同，所有的服务化接口就可以在同一总线上进行传输，支撑业务灵活上线。

HTTP/2（HyperText Transport Protocol 2.0）：下一代超文本传输协议。基于HTTP协议的信息交换分为四个过程：建立连接、发送请求信息、发送响应信息、关闭连接。

TLS（Transport Layer Security）：安全传输层协议。在两个通信应用程序之间提供保密性和数据完整性。

**配置建议**

* AMF的服务化接口业务IP地址不能和AMF其他接口业务IP地址共用。
* AMF的服务化接口端口号没有明确时，使用HTTP知名端口号8080。
* 一个NF类型需要配置一个HTTP本端端点组和对应的HTTP本端端点，然后根据实际部署NF数量配置分别配置对应的SBI端点并绑定对应的HTTP本端端点组。

以下配置数据以及步骤均以UEG双DC组网场景的配置规划为例进行介绍。

## 必备事项

前提条件

* 具备管理员权限的操作人员已经登录华为操作维护系统（登录U2020/MAE客户端或登录OM Portal）。
* 已完成组网路由配置。

* 如果本接口采用IPv6组网，则需要开通逻辑接口支持IPv6特性，即加载对应的License项“81203214 LKV3G5V6LI01 逻辑接口支持IPv6”。
* 已经获取网设LLD文档。

数据

本文以IPv4组网为例说明。

* 如果是IPv6组网，请将逻辑接口地址规划为IPv6地址。
* 如果是IPv4v6双栈组网，则对逻辑接口配置双栈地址即可。

## 操作步骤

**配置****AMF服务化接口数据**

如果要配置IPv4v6双栈类型的服务化接口，该服务化接口的业务逻辑IP地址需要配置IPv4和IPv6类型的IP地址（通过**ADD LOGICIP**配置），相应的HTTP链路也需要配置IPv4和IPv6类型的IP地址（通过**ADD HTTPLE**配置）。

当本端以及对端都配置了IPv4v6双栈类型的IP地址时，UNC侧可以通过将软参**DWORD1 BIT24**设置为**“1”**来确保在业务流程中优选IPv6地址进行建链。

1. 增加AMF服务化接口的IP地址。

   ```
   //DC1
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.1.3", VPNINSTNAME="VPN_CN", DESC="FOR Server SBI";
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.1.4", VPNINSTNAME="VPN_CN", DESC="FOR Client SBI";
   //DC2
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.1.5", VPNINSTNAME="VPN_CN", DESC="FOR Server SBI";
   ADD LOGICIP: IPVERSION=IPv4, LOGICIPV4="172.16.1.6", VPNINSTNAME="VPN_CN", DESC="FOR Client SBI";
   ```
2. 配置AMF服务化接口的HTTP信息。

   1. 配置HTTP本端端点组信息。

      ```
      //DC1
      ADD HTTPLEGRP: INDEX=1, DESC="AMF";
      //DC2
      ADD HTTPLEGRP: INDEX=1, DESC="AMF";
      ```
   2. 配置分别作为HTTP服务的服务端和客户端的本端端点信息。

      ```
      //DC1
      ADD HTTPLE: INDEX=1, HTTPLEGRPIDX=1, LETYPE=SERVER, IPTYPE=IPv4, IPV4="172.16.1.3", PORT=8080, VPNNAME="VPN_CN", TLSFLG=NO, DESC="AMF Server";
      ADD HTTPLE: INDEX=2, HTTPLEGRPIDX=1, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="172.16.1.4", VPNNAME="VPN_CN", DESC="AMF Client";
      //DC2
      ADD HTTPLE: INDEX=1, HTTPLEGRPIDX=1, LETYPE=SERVER, IPTYPE=IPv4, IPV4="172.16.1.5", PORT=8080, VPNNAME="VPN_CN", TLSFLG=NO, DESC="AMF Server";
      ADD HTTPLE: INDEX=2, HTTPLEGRPIDX=1, LETYPE=CLIENT, IPTYPE=IPv4, IPV4="172.16.1.6", VPNNAME="VPN_CN", DESC="AMF Client";
      ```
3. 配置AMF服务化接口的接入点信息。

   ```
   //DC1
   ADD SBIAPLE: INDEX=1, HTTPLEGRPIDX=1, NFTYPE=NFTypeAMF, DESCRIPTION="AMF";
   //DC2
   ADD SBIAPLE: INDEX=1, HTTPLEGRPIDX=1, NFTYPE=NFTypeAMF, DESCRIPTION="AMF";
   ```
4. 配置HTTP属性。在超大报文场景下，可以通过合理设置接收HTTP响应/请求消息体的超时时间、HTTP响应/请求消息体的最大大小、请求消息中JSON数据的最大叶子节点个数等参数，避免发送/请求报文不完整，导致业务处理异常。

   核电专网场景下，不属于超大报文场景， 配置该命令可避免业务处理异常情况发生。

   ```
   //DC1
   SET HTTPCONF: SERVERRCVBDTMT=15, SERVERSNDRSPTMT=15, MAXBODYSIZE=15, MAXJSONLEAFNUM=100000;
   //DC2
   SET HTTPCONF: SERVERRCVBDTMT=15, SERVERSNDRSPTMT=15, MAXBODYSIZE=15, MAXJSONLEAFNUM=100000;
   ```

## 验证方法

1. 在服务化接口中检查对端是否可达，目的地址为对端NF的服务化接口地址。

   ```
   NGPING: IPTYPE=IPv4, VPNNAME="VPN_CN", SRCIPV4ADDR="172.16.1.5", DSTIPV4ADDR="172.16.0.7";
   ```

   * **预期结果**：看到响应报文，并且报文中有成功收发包的个数。
   * **异常结果**：无法收到对端的响应报文。
2. 检查AMF作为服务端时的链路状态。作为服务端时，只有在正常业务流程时才能查询到链路状态信息。

   ```
   DSP SBILINKSTATUS: ENTITYTYPE=Server;
   ```

   * **预期结果**：“链路状态”为“Normal”。
   * **异常结果**：“链路状态”为“Fault”。

   检查AMF作为客户端时的链路状态。作为客户端时，需有过业务流程，才会有记录。

   ```
   TST HTTPPATH: SCHEMA=HTTP, IPTYPE=IPv4, PEERPORT=8080, LOCALIPADDRIPV4="172.16.1.5", PEERIPADDRIPV4="172.16.0.7";
   ```

   * **预期结果**：“结果”为“测试成功”。
   * **异常结果**：“结果”为“测试失败”。
