# 配置HTTP信令数据

## 操作场景

接入5G SA用户时，HTTP信令数据用于UDM和AMF/SMF对接。

园区UDM不支持与NRF通信，因此需要手动配置UDM和AMF之间的服务发现。

## 必备事项

前提条件

* 已完成配置UDM基础数据。
* UDM和AMF之间外联口通信正常。

数据

**如下数据仅为举例，请注意修改成局点规划的数据。**

容灾组网中，同一UEG内的UDM和AMF对接，不同UEG内不交叉对接。即：如下表格中，DC1的UDM和DC1的AMF对接，DC2的UDM和DC2的AMF对接。

**表1** 对接的AMF信息

| 类别 | 参数名称 | 取值样例  （DC1） | 取值样例  （DC2） | 获取方法 | 说明 |
| --- | --- | --- | --- | --- | --- |
| **ADD UDMDISCNFPROF** | NFINSNAME（网元实例名称） | AMF01 | AMF02 | 全网规划 | 用于标识一个服务发现网元实例的名称，该参数全局唯一，不能重复。 |
|  | NFINSID（网元实例标识） | 4947a69a-f6b8-4bc1-b9da-47c9c5d148fd | 4947a69a-f6b8-4bc1-b9da-47c9c5d148fe | 全网规划 | 用于标识服务发现网元实例在系统中的序号，该参数为UUIDv4格式。 |
|  | NFTYPE（网元类型） | AMF | AMF | 固定取值 | 用于标识该服务发现网元实例的类型。 |
|  | NFPROFILE（网元实例信息） | {"nfInstanceId":"4947a69a-f6b8-4bc1-b9da-47c9c5d148fd","nfType":"AMF","nfStatus":"REGISTERED","ipv4Addresses":["172.16.1.5"]} | {"nfInstanceId":"4947a69a-f6b8-4bc1-b9da-47c9c5d148fe","nfType":"AMF","nfStatus":"REGISTERED","ipv4Addresses":["172.17.1.5"]} | 全网规划 | 用于标识服务发现网元实例的详细信息，该参数为JSON格式。   * "nfInstanceId"值与“NFINSID”取值一致。 * "ipv4Addresses"是AMF的服务化接口IP（服务端地址）。 |

文档

获取网设LLD文档。

## 操作步骤

1. 登录“UEG MML命令”界面。
2. 增加AMF服务发现网元实例信息。

   //DC1：

   ```
   //AMF01:
   ADD UDMDISCNFPROF: NFINSNAME="AMF01", NFINSID="4947a69a-f6b8-4bc1-b9da-47c9c5d148fd", NFTYPE=AMF, NFPROFILE="{\"nfInstanceId\":\"4947a69a-f6b8-4bc1-b9da-47c9c5d148fd\",\"nfType\":\"AMF\",\"nfStatus\":\"REGISTERED\",\"ipv4Addresses\":[\"172.16.1.5\"]}";
   ```

   //DC2：

   ```
   //AMF02:
   ADD UDMDISCNFPROF: NFINSNAME="AMF02", NFINSID="4947a69a-f6b8-4bc1-b9da-47c9c5d148fe", NFTYPE=AMF, NFPROFILE="{\"nfInstanceId\":\"4947a69a-f6b8-4bc1-b9da-47c9c5d148fe\",\"nfType\":\"AMF\",\"nfStatus\":\"REGISTERED\",\"ipv4Addresses\":[\"172.17.1.5\"]}";
   ```

   UDM无法与NRF通信，需要手动配置UDM与AMF的服务发现。

## 验证方法

1. 登录“UEG MML命令”界面。
2. 执行**NGPING**命令，查询UDM与AMF之间能否互通。
   * 正常，调测结束。
   * 不正常，请联系华为技术支持工程师。
