# 管理系统日志

* 对系统的影响

## 操作场景

系统日志用于监测网元的硬件资源、虚拟资源、操作系统、软件等运行状态，从而进一步分析网元的软硬件隐患和故障。针对系统日志，OM Portal提供了查询、搜索以及导出的功能。

用户可以通过执行**GET LOGFILE**命令，获取系统日志文件。

## 对系统的影响

该操作对系统无影响。

## 必备事项

前提条件

* 已登录OM Portal。
* 操作员拥有安全管理员权限。

数据

该操作无需准备数据。

## 操作步骤

1. 选择“安全 > 日志审计”，进入日志审计页面。
2. 在左侧导航栏单击“系统日志”。
   * 查询系统日志

     “系统日志”界面显示系统当前的所有系统日志。
   * 搜索系统日志

     “系统日志”界面提供按“级别”、“事件名称”搜索，以及“高级搜索”功能，支持按“导出条数”选择导出日志数量。

     **图1** 系统日志

     **表1** 系统日志参数信息

     | 参数名 | 参数含义 |
     | --- | --- |
     | 导出条数 | 支持用户按照不同数目对系统日志进行导出，不支持过滤筛选。  + 5千：导出最多5千条。 + 1万：导出最多1万条。 + 5万：导出最多5万条。 + 10万：导出最多10万条。 默认值：5千条。 |
     | 级别 | 支持用户按照不同重要级别对系统日志进行过滤筛选。  + 所有级别：包括下列所有级别的系统日志。 + 紧急：表示致命错误，系统已不可用，如系统崩溃等。 + 警报：记录可能导致系统异常的事件日志。 + 严重：表示严重错误，用于系统运行环境严重受损，甚至丧失部分功能，无法继续的情况下记录错误状态信息。 + 错误：记录系统运行过程中发生的错误，例如与服务器的连接失败、数据库访问失败等。 + 警告：记录系统运行过程中系统可能出现的问题或异常，这些问题或异常不会导致系统处理出错，但是有潜在危险。 + 通知：记录系统正常运行过程中重要的通知类信息记录。 + 信息：记录系统的运行过程和过程中涉及的关键步骤，如模块启动、主备倒换等。 + 调试：记录系统的调试相关事件日志。 默认值：所有级别。 |
     | 事件名称 | 支持用户按照在系统中的发生事件对系统日志进行过滤筛选。  其中操作系统记录的系统日志，“事件名称”会体现为操作系统日志中“kernel”或“程序名”的取值。  取值范围：系统上所有事件的发生情况。  默认值：无。 |
     | 高级搜索 | 支持设置自定义的搜索条件，按照条件对系统日志进行查询搜索。  详见“表2 系统日志高级搜索参数说明”。 |

     **图2** 高级搜索

     **表2** 系统日志高级搜索参数说明

     | 参数名 | 参数含义 | 参数取值 |
     | --- | --- | --- |
     | 事件名称 | 系统中发生的事件名称。 | 取值范围：系统中发生的所有事件名称。  默认值：无。 |
     | 网元名称 | 事件发生的网元名称。 | 取值范围：系统已部署的网元名称。  默认值：所有网元。 |
     | 开始时间段 | 事件发生的开始时间段。 | 取值范围：  + 开始时间：由日期和时间点组成。   - 日期：可单击日历按钮选择任何日期，取值格式为：yy-MM-dd，如2018-12-24。   - 时间点：可输入具体的时间，24小时时间制，格式为：hh:mm:ss，如14:43:11，默认为当前时间。 + 结束时间：取值规则与“开始时间”相同。 默认值：无。 |
     | 服务名称 | 事件发生的服务名称。 | 取值范围：系统所有已部署的服务名称。  默认值：无。 |
     | 日志级别 | 事件发生对系统的影响程度。 | 取值范围：  + 所有级别：包括下列所有级别的系统日志。 + 紧急：表示致命错误，系统已不可用，如系统崩溃等。 + 警报：记录可能导致系统异常的事件日志。 + 严重：表示严重错误，用于系统运行环境严重受损，甚至丧失部分功能，无法继续的情况下记录错误状态信息。 + 错误：记录系统运行过程中发生的错误，例如与服务器的连接失败、数据库访问失败等。 + 警告：记录系统运行过程中系统可能出现的问题或异常，这些问题或异常不会导致系统处理出错，但是有潜在危险。 + 通知：记录系统正常运行过程中重要的通知类信息记录。 + 信息：记录系统的运行过程和过程中涉及的关键步骤，如模块启动、主备倒换等。 + 调试：记录系统的调试相关事件日志。 默认值：所有级别。 |
     | 事件结果 | 事件发生的结果。 | 取值范围：  + 所有事件发生结果：包括事件成功、失败、部分成功和未知的系统日志。 + 成功：事件正常发生时的系统日志。 + 失败：事件未正常发生时的系统日志。 + 部分成功：该事件只有部分正常发生时的系统日志。 + 未知：系统发生异常，无法确认该事件是否正常发生时的系统日志。 默认值：所有事件结果。 |
   * 导出系统日志

     在系统日志界面，单击“导出”。等待1～2分钟，日志导出为默认的\*.csv格式，并自动下载到浏览器默认下载路径。

     可根据所选导出数量对查询出来的结果进行导出，一次最多可以导出100000条日志。如果所查询的记录数量超过100000条，则需要分批次导出，比如按照事件结果分为“成功”、“失败”、“部分成功”、“未知”导出。
   * 审计日志服务平稳运行后，用户可执行如下命令查看审计日志数据的存储。
     1. Windows操作系统通过“putty.exe”工具使用**mtuser**用户登录OMU；Linux操作系统通过终端模拟器使用**mtuser**用户登录OMU。

        仅在Fullstack虚机场景下涉及登录OMU操作，非Fullstack虚机场景请联系华为技术支持。

        维护接口IP地址获取方法为：

        1. 执行MML命令**DSP NODE**，配置“网元ID”为“0”，查询并记录节点名称和节点IP（风筝M或L场景下，虚拟机类型为CSP\_A或CSP\_A\_ARM的节点；风筝S场景下，虚拟机类型为OMU的任一OMU节点）。
        2. 执行MML命令**DSP NODERES**，配置“资源类型”为“PORT(网口)”，“节点名称”为“步骤1记录的节点名称”，查询“网口平面”为“Ext-OM”的IP地址，即为维护接口IP地址。

        如果“网口平面”没有“Ext-OM”，登录PaaSOM-1节点，执行ssh **mtuser**@*nodeIP*（步骤1查询到的节点IP），登录节点。PaaSOM-1节点IP地址可以从现网网设文档获取。
     2. 执行**ssh mtuser@<*GaussDB所在节点IP*>**登录所在GaussDB节点。然后执行**su root**切换至root用户。
     3. 通过**which docker**检查容器引擎类型，并进入GaussDB容器。
        + 如果存在docker可执行文件，如下命令所示。

          ```
          PaaSOM-1:/home/mtuser # which docker
          /usr/bin/docker
          ```

          执行**docker ps |grep gauss**获取GaussDB dockerId。

          执行**docker exec -it -u root *dockerId* sh**进入GaussDB容器。
        + 如果没有找到docker可执行文件，如下命令所示。

          ```
          PaaSOM-1:/home/mtuser # which docker
          which: no docker in (/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin)
          ```

          执行**crictl ps |grep gauss**获取GaussDB containerdID。

          ```
          inipv6-csp-a-0:/home/mtuser # crictl ps |grep gauss
          d7706d396a48a       registry.fusionstage.local:20202/csp/cspgaussdb_docker:23.0.0.B159                About an hour ago    Running             gauss-softwarecomp              0                   6c60ce978ec69
          ```

          执行**crictl inspect containerdID | grep "pid"**获取GaussDB容器实例的pid。

          ```
          inipv6-csp-a-0:/home/mtuser # crictl inspect d7706d396a48a |grep "pid"
              "pid": 45803,
                      "pid": 1
                      "type": "pid"
          ```

          执行**nsenter -t pid -a**进入GaussDB容器实例。

          仅非三方CaaS场景下产生-bash: EulerOS\_history: command not found报错。

          ```
          inipv6-csp-a-0:/home/mtuser # nsenter -t 45803 -a
          -bash: EulerOS_history: command not found
          [root@gaussdb-6a19b165-0 /]#
          ```

          执行**unset PROMPT\_COMMAND**忽略-bash: EulerOS\_history: command not found错误。

          仅非三方CaaS场景下需要执行此步骤。

          ```
          [root@gaussdb-6a19b165-0 /]# unset PROMPT_COMMAND
          [root@gaussdb-6a19b165-0 /]#
          ```
     4. 执行**su - dbuser -c "gsql -d auditdb -p 23521 -U auditdbuser -h localhost****"**，输入GaussDB数据库AUDITDB的用户密码， 进入AUDITDB数据库，其中Gauss数据库AUDITDB的用户默认密码可以从《GaussDB数据库用户默认账号》获取。
     5. 执行**select \* from T\_OPERATIONLOG;**查看系统操作类操作日志。
     6. 执行**select \* from T\_QUERYLOG;**查看系统查询类操作日志。
     7. 执行**select \* from T\_SECURITYLOG;**查看系统安全日志。
     8. 执行**select \* from T\_CSPSYSTEMLOG;**查看系统日志。
     9. 执行**select \* from BACKUPCONFIG\_INFO;**查看审计日志日志留存期配置内容。
