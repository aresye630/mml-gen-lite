# 手工备份物理数据库

* 操作场景
* 对系统的影响
* 必备事项
* 操作步骤

#### 操作场景

在重大操作前为了系统的安全性需要手工对物理数据库进行备份，以保证在操作过程中出现异常时使用已备份的数据快速恢复到重大操作前的运行状态。主要包括以下重大操作前：

* 扩容虚拟机
* 预割接或第一次割接

#### 对系统的影响

物理数据库的备份操作会占用系统大量资源，应该在系统低业务量的时段下（例如凌晨2:00～4:00）进行。

#### 必备事项

**前提条件**

NDF（Network Data Function）模块必须已经配置。

**数据**

如果是第一次启用以FTP方式保存备份的功能，则必须获取如表1所示的数据。

**表1** 基础数据

| 类别 | 参数名称 | 取值样例 | 说明 |
| --- | --- | --- | --- |
| **MOD BACKUP** | IP类型 | IPV4 | 用于表示IP地址类型，由工程设计输出。 |
|  | 本地IPV4地址 | 192.168.0.123 | 用于指定访问远程备份服务器的本地IPV4地址，由工程设计输出。 |
|  | IP地址的VPN名称 | VRF\_CC\_DATA | 用于指定“本地IPV4地址”或“本地IPV6地址”的VPN名称。由运营商统一规划。 |
|  | 服务器IPV4地址 | 192.168.0.4 | 远程备份服务器IPV4地址。由运营商统一规划。 |
|  | 服务器用户名 | ftpuser | 远程备份服务器用户名。由运营商统一规划。 |
|  | 服务器密码 | ab12CD34#56 | 该参数表示远程备份服务器密码。由运营商统一规划。 |
|  | 服务器路径 | / | 备份镜像文件在远程备份服务器上的保存路径。由运营商统一规划。 |
|  | 服务器端口 | 21 | 备份镜像文件上传远程备份服务器使用的端口。由运营商统一规划。 |

#### 操作步骤

1. 登录“USCDB MML命令”界面。
2. 执行**LST BACKUP**命令通过检查是否已经存在备份配置信息。

   ```
   LST BACKUP;
   ```

   如果查询出来的结果中各参数配置不为空，则表示已经配置过备份信息。

   * 是 => 4
   * 否 => 3
3. 执行**MOD BACKUP**命令设置备份配置信息。

   以IP类型为IPv4举例：

   ```
   MOD BACKUP: BAKSWH=自动备份开关, BAKDAY=自动备份时间点, STOTIM=保存的最大周期的个数, STOTYP=备份数据保存方式, IPVER=IP类型, LIPV4=本地IPV4地址, IPVPNNAME=IP地址的VPN名称, FTPIPV4=服务器IPV4地址, FTPUSR=服务器用户名, FTPPAS=服务器密码, FTPPATH=服务器路径, FTPPORT=服务器端口号;
   ```

   * 参数“备份数据保存方式”设置为“NOSTOSERVER(不保存到服务器)”时，表示将物理数据库的数据备份到虚拟硬盘。
   * 参数“备份数据保存方式”设置为“FTPSERVER(保存到FTP服务器)”或“SFTPSERVER(保存到SFTP服务器)”时，表示将物理数据库的数据备份到第三方存储介质。
4. 在执行**BKP DB**命令备份物理数据库过程中，如果NDF模块发生主备倒换，备份任务将会丢失。此时执行**DSP PHYDB**命令查询物理数据库状态为“Running”，需要在NDF模块倒换完成后重新备份物理数据库。

   执行**BKP DB**命令备份物理数据库。根据备份数据大小，备份时间需要几分钟到几十分钟。

   ```
   BKP DB:;
   ```
5. 执行**DSP PHYDB**命令查看物理数据库的备份状态。

   ```
   DSP PHYDB
   ```

   * 输出报文中“资源状态”为“Backing up”时，表示数据库正在备份。
   * 输出报文中“资源状态”为“Running”时，表示数据库的备份已经完成。
6. 执行**DSP BKPLIST**命令查看备份的操作结果、备份列表及时间戳信息。

   ```
   DSP BKPLIST:;
   ```

   输出报文中“操作结果”为“成功”时，表示此次数据库备份任务成功。
