# 从Master节点恢复内存数据库

* 操作场景
* 对系统的影响
* 必备事项
* 操作步骤

#### 操作场景

同个Cluster中的一个DRU/DSU节点发生异常后，一般情况下节点会自动从Master恢复数据，也可通过手工重新启动节点的方式恢复节点的数据，重新启动时节点会从Master节点进行内存数据库数据加载。

从Master节点恢复内存数据库会加载Master节点中最近一次的合法全量备份数据文件和Redo文件进行数据恢复。

#### 对系统的影响

恢复内存数据库过程中业务不可用，操作前请联系华为技术支持确认。

#### 必备事项

**前提条件**

节点状态异常，并已通过维护手段定位出需要进行重新加载数据的异常DRU/DSU节点。

**数据**

该操作无需准备数据。

#### 操作步骤

1. 登录“USCDB MML命令”界面。
2. 执行**MOD INSP**命令设置节点数据恢复的数据加载源为Master节点。参数具体取值如下：

   * “INSPT”取值为“FE”。
   * “INSPN”取值为“LDRSOURCE”。
   * “INSPV”取值为“1”。
   * “FETYPEN”根据异常节点所属“业务类型”进行取值，可以通过**LST NODE**命令查看节点所属“业务类型”。

   ```
   MOD INSP: INSPT=FE, INSPN=LDRSOURCE, INSPV=1, FETYPEN="网元类型";
   ```
3. 针对每个已经定位出来的异常节点，分别执行**RST MODULE**命令复位节点，节点在复位过程中自动重新加载数据。

   ```
   RST MODULE: MID=模块号, MT=模块类型;
   ```

   * 单个DRU/DSU节点的加载时长大约为3min。
   * 如需加载数据到对应模块的缓存中，请在节点复位完成后再次执行**RST MODULE**命令重启该模块。需重启的模块类型根据FE的具体场景决定。
4. 待接近加载完成的时间时，执行**DSP NODE**命令查看节点的数据加载状态和加载源信息。

   ```
   DSP NODE:;
   ```

   查看各节点的“节点状态”信息：

   * 如果为“初始化”、“加载中”、“加载完毕 ”或“初始化完成”表示节点还处在数据加载状态。
   * 如果为“Master”或“Slave”表示节点的数据已经加载完。

   查看各节点的“加载源”和步骤2中配置信息一致。
5. 执行**DSP LOADINFO**命令确认节点的“加载源”为“Master”。

   ```
   DSP LOADINFO:;
   ```
6. 节点完成数据加载后，执行**MOD INSP**命令恢复节点数据加载源的默认值。参数具体取值如下：

   * “INSPT”取值为“FE”。
   * “INSPN”取值为“LDRSOURCE”。
   * “INSPV”取值为“0”。
   * “FETYPEN”的取值为通过**LST NODE**命令查询到的故障节点所属的“业务类型”。

   ```
   MOD INSP: INSPT=FE, INSPN=LDRSOURCE, INSPV=0, FETYPEN="网元类型";
   ```
