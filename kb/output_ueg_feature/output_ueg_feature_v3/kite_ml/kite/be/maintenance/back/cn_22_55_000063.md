# 手工备份内存数据库到第三方服务器

* 操作场景
* 对系统的影响
* 必备事项
* 操作步骤

#### 操作场景

重大操作前（主要包括扩容虚拟机、业务改造等）为了系统的安全性需要手工对内存数据库进行备份，以保证在操作过程中出现异常时可以快速使系统恢复到操作前的运行状态。除了上述的手工备份内存数据库到虚拟机硬盘和自带空间，还可以手工备份内存数据库到第三方服务器中。

第三方服务器上的备份文件是按日期分目录进行保存，请定期清理服务器上旧的备份目录，防止备份文件不断堆积而导致第三方服务器硬盘空间不足。

#### 对系统的影响

备份内存数据库对系统有以下影响，备份内存数据库请在系统业务低峰期（例如凌晨2:00～4:00）进行:

备份操作会占用系统较多的资源，对系统的性能有影响。

#### 必备事项

**前提条件**

* 已通过登录“USCDB MML命令”界面执行**ADD RFTPSERVER**/**ADD RSFTPSERVER**命令配置第三方服务器。在该场景下配置规则如下：
  + “远端服务器类型” 配置为“DATAMTN(维护)”。
  + “FTP本端工作目录”/“SFTP本端工作目录”配置为“BACKUPNODE”。
  + “本端IPV4地址”/“本端IPV6地址”配置为业务IP类型为DMA的DPU模块的IPv4/IPv6地址，该IP地址由**ADD SRVIPADDR**命令配置。
  + “传输方向”需分别配置对应的“上传”和“下载”两条数据。
  + 当远端服务器支持FTP时，通过**ADD RFTPSERVER**配置第三方服务器。

    ```
    ADD RFTPSERVER: SERVERTYPE=DATAMTN, SERVERNAME="ftpserver1", IPVER=IPV4, SERVERIPV4="10.94.1.131", SERVERPORT=21, USERNAME="name", PWD="***********", CFM="***********", RWORKDIR="realtime", LWORKDIR="BACKUPNODE", TRANSDIRECTION=DOWNLOAD, LOCALIPV4="10.93.1.131";
    ```

    ```
    ADD RFTPSERVER: SERVERTYPE=DATAMTN, SERVERNAME="ftpserver2", IPVER=IPV4, SERVERIPV4="10.94.1.131", SERVERPORT=21, USERNAME="name", PWD="***********", CFM="***********", RWORKDIR="realtime", LWORKDIR="BACKUPNODE", TRANSDIRECTION=UPLOAD, LOCALIPV4="10.93.1.131";
    ```
  + 当远端服务器支持SFTP时，通过**ADD RSFTPSERVER**配置第三方服务器。

    ```
    ADD RSFTPSERVER: SERVERTYPE=DATAMTN, SERVERNAME="sftpserver1", IPVER=IPV4, SERVERIPV4="10.94.1.131", SERVERPORT=22, USERNAME="name", PWD="******", CFM="******", RWORKDIR="realtime", LWORKDIR="BACKUPNODE", TRANSDIRECTION=DOWNLOAD, LOCALIPV4="10.93.1.131";
    ```

    ```
    ADD RSFTPSERVER: SERVERTYPE=DATAMTN, SERVERNAME="sftpserver2", IPVER=IPV4, SERVERIPV4="10.94.1.131", SERVERPORT=22, USERNAME="name", PWD="******", CFM="******", RWORKDIR="realtime", LWORKDIR="BACKUPNODE", TRANSDIRECTION=UPLOAD, LOCALIPV4="10.93.1.131";
    ```
* 第三方服务器预留充裕的用于备份的硬盘空间，评估磁盘空间大小可参考相关计算方法。
* 已通过PGW Web LMT的“系统管理”窗口执行**DSP DB**命令查询“State”为“NOBACKUP”、“TASK FINISH”、“TASK ABNORMAL”或“TASK TIMEOUT”。

**数据**

该操作无需准备数据。

#### 操作步骤

1. 登录“USCDB MML命令”界面。
2. 执行**MOD INSP**命令，通过设置THIRDSPACEBACKUP(第三方备份开关)来打开内存数据库备份到第三方服务器功能。

   ```
   MOD INSP: INSPT=FE, INSPN=THIRDSPACEBACKUP, INSPV=1, FETYPEN="网元类型";
   ```
3. 执行**LST INSP**命令查询软参THIRDSPACEBACKUP状态查询备份开关状态是否与步骤2操作结果一致，如果不一致，请重复步骤2。

   ```
   LST INSP: INSPT=FE, INSPN=THIRDSPACEBACKUP, FETYPEN="网元类型";
   ```
4. 登录PGW Web LMT MML命令界面，进入“系统管理”窗口。
5. 执行**BKP DB**命令备份本局的内存数据库到第三方服务器，其中参数“位置信息”为“Local”，参数“UPTHIRDSERVER”为“YES”。

   * 当“业务类型”为FE时：

     ```
     BKP DB: SERVICETYPE="SUP-FE", DIRECTORY=EMGRST, LOCINFO=Local, UPTHIRDSERVER=YES;
     ```
   * 当“业务类型”为USCDB时：

     ```
     BKP DB: SERVICETYPE="USCDB", DIRECTORY=EMGRST, LOCINFO=Local, UPTHIRDSERVER=YES;
     ```

   * 备份时长受FE业务模型、局点容量和网络带宽的影响。总备份时长 = 文件写磁盘时长 + 文件传输时长 + 各模块中间处理环节耗时 +节点备份预留时长+文件上传到第三方服务器时长。
   * 此处以一组数据计算备份时长的参考值：
     + DRU 3GB，DSU 9GB节点内存库大小，备份文件大小分别约为1GB和3GB。DRU/DSU的比例为1:3，每个DSU开户100W，对于3000W的局点大概部署30个DSU Cluster，10个DRU Cluster。磁盘IO带宽约 80MB/s，网络带宽（1Gb网卡）为1Gb/s，即128MB/s。
     + 文件写磁盘时长 = (30\*3 + 10\*1)\*1024 / 80 = 1280s。DMA与DPU之间文件传输时长 = (30\*3 + 10\*1)\*1024 / 128 = 800s。每个文件在各模块中间处理环节耗时60秒，共30\*60 = 1800s。节点备份时长预留900s。从DPU所在Pod上传到第三方服务器的时长=800s。备份到第三方服务器的总时长 = 1280 + 800 + 1800 + 900 +800= 4860s =93分钟。
6. 待接近备份完成的时间时，执行**DSP DB**命令查看备份状态。

   * 当“业务类型”为FE时：

     ```
     DSP DB: SERVICETYPE="SUP-FE";
     ```
   * 当“业务类型”为USCDB时：

     ```
     DSP DB: SERVICETYPE="USCDB";
     ```

   查看本局的内存数据库“State”信息：

   * 如果为“TASK FINISH”表示已经备份完。
   * 如果不是“TASK FINISH”表示还没有备份完或备份失败。
