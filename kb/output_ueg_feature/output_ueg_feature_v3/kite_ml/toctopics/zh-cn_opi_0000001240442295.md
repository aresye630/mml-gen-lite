# USM Gtpu接口跟踪

* 操作场景
* 必备事项
* 操作步骤

## 操作场景

* 此跟踪用于GTPU的消息跟踪，应用于N4等接口控制面消息的问题定位与分析。
* 系统运行出现故障需要进行GTPU定位排除故障。
* 维护人员调试设备运行情况。

  + 设备出口跟踪中能够显示消息，不代表跟踪到的消息一定从本设备向外发送成功，请关注系统其他异常告警和性能统计。
  + 跟踪功能主要用于保障网络运营和服务、检测通信传输中的故障和错误，该功能涉及使用个人用户标识和用户通信内容。建议您只有在所适用法律法规允许的目的和范围内方可启用相应的功能。在使用用户通信内容的过程中，您应采取足够的措施以确保用户的通信内容受到严格保护。
  + 操作员在现场使用跟踪功能时，消息跟踪中的IP地址、端口等信息仍然是用户的真实信息，是未被加密的。

## 必备事项

前提条件

* 具备管理员权限的操作员已经登录OM Portal。
* 维护人员具有接口消息跟踪权限。

数据

| 类别 | 参数名称 | 取值样例 | 获取方法 | 说明 |
| --- | --- | --- | --- | --- |
| USM GTPU接口跟踪 | IP地址类型 | IPv4/IPv6 | 本端规划 | 接口地址类型 |
|  | 本端IPv4地址/本端IPv6地址 | 192.168.0.1/2001:0db8::1 | 本端规划 | 本端CP地址，可以通过“DSP RDSPFCPSESSINFO”或“LST CPGTPUADDR”命令查询。 |
|  | 对端IPv4地址/对端IPv6地址 | 192.168.0.2/2001:0db8::2 | 全网规划 | 对端UP地址，设备级Gtpu通过“DSP RDSPFCPSESSINFO”命令查询，会话级Gtpu通过“DSP PFCPSESSIONINFO”命令查询隧道类型为29的IP地址。 |

## 操作步骤

1. 进入跟踪操作界面：登录OM Portal，在OM Portal主界面依次选择“监控分析”->“消息跟踪”，进入跟踪导航树界面，如图1 消息跟踪操作界面所示。

   **图1** 消息跟踪操作界面
2. 填写用户跟踪任务参数：在左侧跟踪导航树界面选择“UEG”->“AMF#SMF业务跟踪”->“USM GTPU接口跟踪”后，单击“创建跟踪任务”，进入USM GTPU接口跟踪任务创建的界面，依次填写“任务名称”、“跟踪时长”、“定位条件”和“组合条件”参数，如图2 USM GTPU接口跟踪参数配置对话框所示。

   **图2** USM GTPU接口跟踪参数配置对话框
3. 在对话框中进行参数配置，参数说明如表1 用户跟踪参数配置说明所示。

   **表1** 用户跟踪参数配置说明

   | 参数名称 | 参数说明 | 取值范围 | 默认值 |
   | --- | --- | --- | --- |
   | 任务名称 | 该次跟踪任务的名称 | - | - |
   | IP地址类型 | - | IPv4/IPv6 | IPv4 |
   | 本端IPv4地址/本端IPv6地址 | - | IPv4地址/IPv6地址 | － |
   | 对端IPv4地址/对端IPv6地址 | - | IPv4地址/IPv6地址 | － |
   | 路径信息 | - | 选中/未选中 | 选中 |
   | 隧道消息 | - | 选中/未选中  说明：  * 全选时，GTPU路径信息和GTPU隧道消息都会上报。 * 只选GTPU路径信息或者GTPU隧道消息时，只会上报选中的类型消息进行上报。 * 都不选时，没有消息上报。 | 选中 |
   | 跟踪时长 | 该参数用于指定该次跟踪任务的时长。 | 1分钟~720小时59分钟 | 1（小时） |
4. 单击“确认”，启动跟踪任务。
