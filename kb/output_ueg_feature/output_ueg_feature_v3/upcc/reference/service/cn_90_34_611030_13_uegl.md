# VoLTE紧急呼叫流程配置

#### 操作场景

Rx接口是UPCF与AF（Application Function）之间的接口，用于部署VoLTE（Voice over LTE）应用，包括基本呼叫（语音/视频呼叫）和紧急呼叫等业务。UPCF支持部署该特性，为紧急呼叫业务提供可靠的质量保证，保证用户在各种紧急的情况下，能够顺利拨打紧急呼叫号码。

此场景中，紧急呼叫采用独立的APN（Access Point Name）。当用户使用VoLTE紧急呼叫业务时，针对业务是否为紧急呼叫，享有不同的资源分配优先级，并实行不同的计费策略。VoLTE业务的详细配置信息，请参见随VoLTE解决方案发布的《VoLTE产品文档》。

#### 对系统的影响

本特性对系统无影响。

#### 必备事项

**前提条件**

* 操作员已了解GWFD-025902 Rx接口(使用Diameter协议)VoLTE策略控制特性概述。
* 已完成配置UPCF与AF（基于Diameter协议）的对接数据。

| IMS Emergency业务IMS\_Emergency\_Service | 此业务包括一个策略：IMS\_Emergency\_Policy。 | 此业务用来建立IMS Emergency业务的专属承载，只在收到来自AF的授权请求时触发（AFSessionAuthorization）。  说明：  * 需要配置一个应用映射将AF侧的业务标识（VOLTE\_Emergency\_Application）与UPCF上配置的AF激活的业务（IMS\_Emergency\_Service）对应起来。 * AF激活的业务不需要用户签约。当用户使用紧急呼叫等VoLTE业务时，AF会向UPCF发送AAR消息请求建立媒体专属承载，消息中携带业务标识AVP“AF-Application-Identifier”，通过UPCF上配置的应用映射来激活UPCF上对应的业务。 |
| 策略Emergency\_APN\_Policy | 此策略在用户从Emergency APN上线时被调用，触发器为IPCANSessionEstablish，包含规则：Emergency\_APN\_Rule1和Emergency\_APN\_Rule2。 | - |
| 规则Emergency\_APN\_Rule1 | * 条件：无。 * 动作：DefaultBearerQoS（QCI=5，ARP=1）。 | 建立默认承载时，必须配置动作DefaultBearerQoS，从而下发QoS。 |
| 规则Emergency\_APN\_Rule2 | * 条件：无。 * 动作：    + QoSAction：QCI为5，ARP为1。   + ChargingAction：“RatingGroup”为1（1代表不计费）。 * 业务流：上下行业务流均取默认值“Any IP Protocol”。 |  |
| 策略IMS\_Emergency\_Policy | 此策略在用户使用IMS Emergency业务时被调用，触发器为AFSessionAuthorization，包含规则：Emergency\_Yes\_Rule和Emergency\_No\_Rule。 | 用户使用IMS Emergency业务，可以根据是否紧急会话来设置条件。 |
| 规则Emergency\_Yes\_Rule | * 条件：为紧急呼叫（IsEmergencySession=Yes）。 * 动作：    + QoSAction：QCI为1，ARP为1。   + ChargingAction：RatingGroup为7。   + GateAction：FlowStatus为ApplicationSession.FlowStatus。 | * 定义是否紧急会话时，条件“对象属性”选用对象ApplicationSession下的IsEmergencySession属性。 * 动作ChargingAction：若对端为华为PDN-GW，不管用户需求是否需要改变计费策略，均需配置动作ChargingAction。“RatingGroup”的取值需与在线/离线计费系统（如OCS）协商一致。 * 动作GateAction：“FlowStatus”的取值为AF在AAR消息中携带的AVP“FlowStatus”。 * 属于AF侧激活的业务下规则“类型”建议都配置为“Dynamic”。 |
| 规则Emergency\_No\_Rule | * 条件：为普通呼叫（IsEmergencySession=No）。 * 动作：    + QoSAction：QCI为1，ARP为2。   + ChargingAction：RatingGroup为8。   + GateAction：FlowStatus为ApplicationSession.FlowStatus。 |  |

#### 操作步骤

1. 完成VoLTE基本呼叫流程配置。
2. 登录“UEG MML命令”界面。
   1. 执行ADD APN命令，添加“VoLTE-APN”和“Emergency-APN”类型的APN。

      流控场景下需要保证紧急呼叫，用于配置VoLTE紧急呼叫APN。命令举例如下：

      ```
      ADD APN: PCRFID=1, APNID=2, APNNAME="SOS", APNTYPE=VoLTE-APN, APNMATCHTYPE=FullMatching;
      ADD APN: PCRFID=1, APNID=3, APNNAME="SOS", APNTYPE=Emergency-APN, APNMATCHTYPE=FullMatching;
      ```

      “APNNAME”的取值需要以运营商实际规划的APN名称为准。
   2. 配置Rx特性的相关软参。

      执行**MOD PCFINSP**命令，设置参数“UPM\_SUBCTRL”为“1”，即宽松签约模式。

      ```
      MOD PCFINSP: INSPN=UPM_SUBCTRL, INSPV=1;
      ```
3. 登录UPCF WebUI界面。
4. 配置条件组。

   导航入口为“策略管理 > 策略 > 条件组”。

   * 当业务的使用需要设置控制条件时，需要配置条件组。若某规则不配置条件组，表示在同一业务里其他条件都匹配不上时，才触发此规则。
   * 条件组是一个或多个条件的组合。条件组中的各条件之间可以是“与”的关系，也可以是“或”的关系。条件之间的与/或关系由参数“关系”的取值决定。

   需要配置两个条件组，用于判断是否紧急呼叫。条件组的数据规划如表2所示，详细参数说明请参见条件组参数表。

5. 配置动作组。

   导航入口为“策略管理 > 策略 > 动作组”。

   此场景需配置动作：DefaultBearerQoS、QoSAction、ChargingAction和GateAction，相关应用场景如下：
   * DefaultBearerQoS：当需要建立默认承载时必须配置此动作。
   * QoSAction：当需要进行带宽控制时均需配置此动作，若不配置则表示不限制Qos。
   * ChargingAction：当需要做计费策略控制时，配置此动作（若对端为华为GGSN或者华为PDN-GW，此动作必须配置）。其中属性“RatingGroup”的取值需与在线/离线计费系统（如OCS）协商一致。
   * GateAction：当需要做门限控制时，配置此动作。在下发流描述时，如果不配GateAction，默认为放通该流，当需要限制流时，此动作必须配置。此场景根据AF请求的Flow-Status，下发门限策略。

   * 动作组AG1\_Emergency\_APN：动作DefaultBearerQoS
   * 动作组AG2\_Emergency\_APN：动作QoSAction和ChargingAction
   * 动作组AG\_Yes\_Emergency：动作QoSAction、GateAction和ChargingAction
   * 动作组AG\_No\_Emergency：动作QoSAction、GateAction和ChargingAction

   导航入口为“业务管理 > 业务 > 业务”。
