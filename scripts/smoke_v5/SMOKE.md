# v5 冒烟集说明（SMOKE.md）

- 位置：`materials/scripts/smoke_v5/`
- 容器内路径：`/opt/expgv/scripts/smoke_v5/`
- 定位：**产品验收级冒烟**（区别于原「交付验收级」25 条）
- 配套审计报告：`原冒烟集问题反查.md`

---

## 一、为什么要扩冒烟集

原冒烟集 25 条（A~E 组）+ UI 点击冒烟 1 个，交付前 **25/25 全绿**，
但用户一上手就抓到 7 个问题。

**反查结论**：原冒烟集是「交付验收」性质（证明"镜像装配正确"），
不是「产品验收」性质（证明"产品可用"）。四类系统性问题：
**太粗（只判存在性）/ 跳过步骤（链路断点）/ 不关注体验 / 判据错位**。

详见 `原冒烟集问题反查.md`。

## 三、判据升级对照（粗 → 细）

| 原判据 | 新判据 | 升级点 |
|---|---|---|
| 文件存在 | 文件非空 + **行数阈值 + 有真实内容** | 空产物能被抓 |
| 集合非空 | **逐产品条数 + 分布断言** | "某产品一条没导"能被抓 |
| 接口有响应 | **响应内容质量**（无噪音/真因可读） | 内部信号外露能被抓 |
| 任务终态 | **跨表状态一致**（task vs gen） | 僵尸状态能被抓 |
| 无报错 | **不得静默**（应有明确成败） | 静默失败能被抓 |

## 四、使用方法

### 容器内

```bash
# 完整跑（含判别力自检）
bash /opt/expgv/scripts/smoke_v5/run_smoke.sh --sid <session_id>

# 只跑新增组
bash run_smoke.sh --sid <sid> --groups FGH

# 快速模式（跳过 agent 真调，H 组只跑静态项）
bash run_smoke.sh --sid <sid> --quick

# 只跑判别力自检
bash run_smoke.sh --selftest-only
```

### 单独跑某组

```bash
python3 smoke_f_api.py      --base http://localhost:8600 --sid <sid>
python3 smoke_g_quality.py  --sid <sid> [--gen g4]
python3 smoke_h_experience.py --sid <sid> [--only H4,H5]
python3 smoke_selftest.py
```

### 结果

落盘到 `/tmp/smoke_out/`：`cases_abcde.json` / `smoke_f.json` / `smoke_g.json` / `smoke_h.json`

## 五、执行纪律

| # | 纪律 |
|---|---|

## 六、已验证记录（2026-09-18，容器内实跑）

### 实跑中踩到并已修掉的坑（值得记录）

| 坑 | 现象 | 修法 |
|---|---|---|
| **`GROUPS` 是 bash 保留变量** | 赋值被 `$UID`(1000) 覆盖 → 所有组都不执行 | 改名 `GRPS` |
| **`[ cond ] && exit 0` 在 `set -e` 下提前退出** | selftest 后脚本直接结束 | 改 `if ... then exit 0; fi` |
| **`sys.executable` 在 stdin 模式下为空** | G7 检索 rc=1 | 由 run_smoke.sh `export SMOKE_PY` |
| **Milvus Lite 抢库（G6 占用 → G7 失败）** | G6 PASS 但 G7 全部"无命中 rc=1" | **G6 改走子进程**（`close()` 不释放锁） |

**最后一条正是本方案第七节预警的"用例自己抢库会把好产品判成坏的"** ——
实测印证：G6 用连接后不释放，后续 G7 检索全部误判为失败。
