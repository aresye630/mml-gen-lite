# 受限动态算子设计（送审稿）

> 目标：当 7 个固定算子写不出来时，允许 agent 提交受限表达式。
> 安全边界是本设计的核心，先送审再实现。

## 安全模型

### 允许的 AST 节点（白名单）

```python
ALLOWED_NODES = {
    ast.Expression, ast.BinOp, ast.UnaryOp, ast.BoolOp, ast.Compare,
    ast.Call,           # 但只允许下面的方法
    ast.Name, ast.Constant, ast.Subscript, ast.Slice,
    ast.IfExp,          # 三元：a if cond else b
    ast.Str / ast.Num,  # 兼容旧版
}
```

### 允许的字符串方法（白名单）

```python
ALLOWED_STR_METHODS = {
    'replace', 'startswith', 'endswith', 'split', 'join', 'strip',
    'lower', 'upper', 'lstrip', 'rstrip', 'format',
}
```

### 禁止的

- `import` / `__import__` / 任何属性访问（除白名单方法）
- 函数定义、class、lambda、comprehension
- `eval` / `exec` / `open` / `__class__` / `__globals__`
- 任意属性链（`a.b.c`）
- 赋值、循环

## 执行环境

```python
def safe_eval(expr, ctx):
    """受限求值。"""
    # 1. AST 校验
    tree = ast.parse(expr, mode='eval')
    _validate(tree)

    # 2. 编译执行，超时保护
    code = compile(tree, '<derive>', 'eval')
    with _timeout(1.0):
        return eval(code, {'__builtins__': {}}, _build_ctx(ctx))
```

`_build_ctx` 只注入：
- `x`：当前值
- `ctx`：只读 dict（CSV 列 + 内部键）
- 白名单方法通过包装类提供，不直接暴露 `str`

## 变量约定

| 变量 | 说明 |
|---|---|
| `x` | 当前值（被变换的字符串） |
| `ctx['列名']` | 用户 CSV 的列 |
| `ctx['_seq']` | 实例序号 |

## 示例

```python
# 现有算子写不出的情况：取前 8 个字符加后缀
"x[:8] + '_' + ctx['制式']"

# 条件变换
"x.replace('grp','pool') if x.startswith('grp-') else x"

# 多段替换
"x.replace('grp','map').replace('-deft','')"
```

## 模板里的写法

```
值列：${SCRIPT} x[:8] + '_' + ctx['制式']
```

**与固定算子的区别：`${SCRIPT}` 前缀显式标记，便于审计。**

## 成本与风险

### 开销
- 只在该行首次遇到时执行一次 AST 校验
- 执行本身 < 1ms
- 可忽略

### 风险
| 风险 | 缓解 |
|---|---|
| 表达式写错 → 生成错值 | 展开后跑 G21 + C2 校验；值里出现异常字符可检出 |
| 恶意代码 | AST 白名单 + `__builtins__` 清空 + 超时 |
| 不可复现 | 表达式存在产物 CSV 里，可审计可复现 |

## 与「澄清」的关系

```
优先级：
  1. 固定算子能写 → 用固定算子（确定性最高）
  2. 固定算子写不出，但受限脚本能写 → 用受限脚本（记录在产物里）
  3. 都写不出 → 澄清（人工确认）
```

## 需要确认

1. AST 白名单是否足够（会有遗漏吗）
2. 超时 1 秒是否合理
3. `${SCRIPT}` 这个标记形式可以吗
