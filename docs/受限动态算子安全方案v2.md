# 受限动态算子：安全方案（讨论稿 v2）

## 核心思路：不靠 AST 白名单单打独斗，用「代理对象」限制能力

AST 白名单只能挡住语法层面的危险，挡不住「合法语法 + 危险对象」。
更稳的做法是：注入给 eval 的所有对象都是受限代理，能做的事天然有限。

## 三层防护

### 第 1 层：AST 白名单（语法层）

允许的节点：
```python
ALLOWED = {
    ast.Expression,     # 整体
    ast.BinOp,          # a + b
    ast.UnaryOp,        # not a
    ast.BoolOp,         # a and b
    ast.Compare,        # a == b
    ast.Call,           # f(...)
    ast.Attribute,      # 但限定 name 必须在方法白名单
    ast.Name,           # 变量
    ast.Constant,       # 常量
    ast.Subscript,      # ctx['x']
    ast.Slice,          # x[:8]
    ast.IfExp,          # a if c else b
    ast.Tuple,          # (a, b)
    ast.List,           # [a, b]
    ast.Index,          # 兼容旧版
}
```

禁止：Import / Lambda / FunctionDef / ClassDef / Comprehension /
     Starred / Await / Yield / Global / Nonlocal / NamedExpr / JoinedStr

Attribute 特殊处理：
```python
if isinstance(node, ast.Attribute):
    if node.attr not in ALLOWED_METHODS:
        raise SecurityError(f'禁止访问属性 .{node.attr}')
```

### 第 2 层：代理对象（能力层）★ 最关键

不把 raw `str` 注入，注入的是 `SafeStr`：

```python
class SafeStr:
    """受限字符串。只暴露白名单方法，且返回值也是 SafeStr。"""
    __slots__ = ('_v',)
    ALLOWED = {
        'replace', 'startswith', 'endswith', 'split', 'rsplit',
        'strip', 'lstrip', 'rstrip', 'lower', 'upper',
        'join', 'format', 'zfill', 'lstrip',
    }

    def __init__(self, v):
        object.__setattr__(self, '_v', str(v))

    def __getattr__(self, name):
        if name not in self.ALLOWED:
            raise SecurityError(f'SafeStr 不允许 .{name}')
        real = getattr(self._v, name)
        def wrapper(*a, **kw):
            # 参数里的 SafeStr 要还原
            args = [_unwrap(x) for x in a]
            r = real(*args, **kw)
            return _wrap(r)      # 返回值也包成 SafeStr
        return wrapper

    def __add__(self, o): return SafeStr(self._v + _unwrap(o))
    def __radd__(self, o): return SafeStr(_unwrap(o) + self._v)
    def __getitem__(self, k): return SafeStr(self._v[k])
    def __eq__(self, o): return self._v == _unwrap(o)
    def __str__(self): return self._v
    def __repr__(self): return f"SafeStr({self._v!r})"
```

**关键点**：`SafeStr.__getattr__` 只放行白名单方法，
所以 `x.__class__` 会直接 `SecurityError`，连 AST 校验都不用。
即使 AST 校验漏了，代理层也拦住。

### 第 3 层：执行沙箱

```python
def safe_eval(expr, ctx):
    tree = ast.parse(expr, mode='eval')
    _validate_ast(tree)                     # 第 1 层

    safe_ctx = {k: _wrap(v) for k, v in ctx.items()}   # 第 2 层
    env = {
        '__builtins__': {},                  # 无内置函数
        'x': SafeStr(ctx.get('_self', '')),
        'ctx': _SafeDict(safe_ctx),          # 只读 dict 代理
        'len': len, 'str': str,              # 少数安全函数
    }
    code = compile(tree, '<derive>', 'eval')
    with _timeout(1.0):                      # 第 3 层
        r = eval(code, env)
    return str(r)
```

`_SafeDict` 只允许读，禁止写：

```python
class _SafeDict(dict):
    def __setitem__(self, k, v):
        raise SecurityError('ctx 只读')
    def __getitem__(self, k):
        if k.startswith('__'):
            raise SecurityError(f'ctx 不允许访问 {k}')
        return super().__getitem__(k)
```

## 模板里的写法

```
值列：${SCRIPT} x[:8] + '_' + ctx['制式']
```

`${SCRIPT}` 前缀显式标记，便于审计和统计。

## 与固定算子的关系

```
优先级：
  1. 固定算子能写 → 用固定算子（确定性最高，零开销）
  2. 固定算子写不出，受限脚本能写 → 用受限脚本（记录在产物里，可审计）
  3. 都写不出 → 澄清（人工确认）

agent 用完受限脚本后，如果发现某个脚本反复出现，
可以考虑把它「固化」成新算子（但这个固化动作是人做的，不是 agent）。
```

## 成本

| 项 | 开销 |
|---|---|
| AST 校验 | 每行首次约 0.1ms，可缓存 |
| 代理对象创建 | 每行 1-2 次，可忽略 |
| eval 执行 | < 1ms |
| 超时保护 | 仅在死循环时触发 |

**结论：开销可忽略，不构成性能问题。**
