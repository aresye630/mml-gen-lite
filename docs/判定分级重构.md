# 判定分级重构（讨论稿）

> 背景：用户明确不接受「派生算子树出错 → fatal → 回炉」。
> 现有 G21 是 fatal，会触发死循环。

## 现状问题

```
G21（csv↔mml 一致性）现在是 fatal：
  params.csv 里有但 mml 里没有 → fatal → agent 回炉

问题：
  1. 派生算子写错一处 → 整批判死 → 回炉 15-20 分钟
  2. 回炉后可能还错 → 死循环
  3. 而且派生错是「值不对」，不是「配不出」，不该阻断
```

## 判定分级原则

**按「错了会怎样」分级，而不是按「哪道门」分级。**

| 级别 | 含义 | 处理 |
|---|---|---|
| **fatal** | 配置下不去 / 会出事 | 阻断，必须修 |
| **blocking** | 缺内容，用户能看出来 | 阻断，但给明确修法 |
| **warn** | 有疑问但不影响下发 | 提示，可继续 |
| **info** | 仅供参考 | 记录 |

## 各门重新分级

### 应该 fatal 的（配置本身不合法）
```
G11 唯一性     同一对象重复 ADD → 下发会报错
G12 参数格式   参数值格式非法 → 下发会报错
G17 规模       超出规格上限 → 下发会失败
G19 虚假依据   引用了不存在的 EXP 行 → 依据不可信
C2  引用悬空   ADD 引用的父对象不存在 → 挂不上
G22 占位符     【待填写】没填 → 下发会失败
```

### 应该是 warn 的（内容缺失或疑问）
```
G20 规划覆盖   规划表某行没被引用 → 可能有意为之
G21 csv↔mml    csv 有但 mml 没有 → 可能是派生错误，不阻断
G18 族覆盖     意图提到的族没配 → 可能意图理解偏差，不阻断
```

### 关键改动：G21 从 fatal → warn

**理由：**
```
1. G21 比的是「agent 自己的 csv」和「agent 自己的 mml」
   —— 两者不一致说明 agent 内部有问题，但不代表配置不能用

2. 派生算子写错时：
   csv 里是模板表达式 → mml 里是展开后的值
   G21 拿模板去比，永远对不上 → 必然 fatal
   
   等等，这是个 bug！派生展开后 csv 已经被覆盖成实际值了，
   所以 G21 不该报。如果报了，说明展开没写回 csv。
```

## 派生算子出错的处理

```
方案：派生失败的行「不进入产物」

展开时：
  · 成功的行 → 写入展开后的 csv（实际值）
  · 失败的行 → 记录到「待确认」清单，不写入 csv
  · G21 比对时，两边都没有这些行 → 不报 fatal

UI 上：
  · 产物面板显示「3 行派生失败，需人工确认」
  · 用户能看到具体是哪几行的哪个表达式出问题
  · 用户可以改模板表达式后重新展开
```

**这样：不阻断整批，问题显式暴露给用户。**
