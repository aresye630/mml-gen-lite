# 「照着配」的处理方案（基于 86 单实测）

> 2026-11-12
> 用户问题：数据清单有可能给业务段，意图是参照已有的随便一个配置，怎么处理？

## 一、实测信息分布

对 86 单统计「意图给了参照对象吗」+「数据清单给了业务段吗」：

| 组合 | 单数 | 占比 | 含义 |
|---|---|---|---|
| 两者都有 | 15 | 17% | 可直接走参照流程 |
| 只有业务段 | 17 | 20% | 需要自动找参照对象 |
| 只有参照 | 4 | 5% | 业务段要问用户 |
| 两者都无 | 50 | 58% | 本来就不需要参照 |

**关键结论：58% 不是失败，是「意图只是新建对象，不涉及照谁配」。**

## 二、四个场景的处理方式

### 场景 A：参照对象 + 业务段都有（17%）

```
意图：「APN sos 按现网 ims.wh 存量配齐」
清单：sos_sig_pcc_p_g / up_sos / sos_sig_cbb_offline

Step 1 提取参照链
  exp_refs(seed=('APN', 'ims.wh')) → 沿引用提取闭环
  实测 ims_sig 链：8 个族 9 条命令

Step 2 反推业务段
  清单里 sos_sig_pcc_p_g 剥掉 _pcc_p_g → 业务段 = sos_sig
  清单里 up_sos 剥掉 up_ → 业务段 = sos

Step 3 按后缀规律补全缺失族名
  实测覆盖：
    URRGROUP      _ch_p        91%  → sos_sig_ch_p
    PCCPOLICYGRP  _pcc_p_g     94%  → 清单已给
    URR           _cbb_offline 43%  → 清单已给
    RULE          无规律            → 清单已给 r_sos_sig
    USERPROFILE   无规律            → 清单已给 up_sos
    UPBINDUPG     无规律            → 待填或按 68.8% 规律推

Step 4 参数值分类
  枚举/常量     照抄
  引用名        按 Step 2/3 的映射替换
  唯一 ID       按现网规律推断（URRID = RG + 10000）
  业务数据      清单取值 or 【待填写】

Step 5 自洽校验 + 输出
```

**自动化程度：90%（剩余 10% 是 UPBINDUPG 这类多规律族）**

### 场景 B：只有业务段，没给参照对象（20%）

```
意图：「新增 URR sos_sig_cbb_offline」

Step 1 自动选参照
  方法：用目标名字的结构去现网找同构对象
    目标 sos_sig_cbb_offline
    → 剥掉末尾已知后缀 _cbb_offline → 骨架 <biz>_cbb_offline
    → exp_query(family='URR') 找所有同骨架的
    → 得到 12530_01_cbb_offline / 139yxlj_00_cbb_offline ...
    → 选业务段最相似的（同段、同长度优先）

Step 2 之后同场景 A
```

**自动化程度：70%（自动选参照可能选错，需在结果里标明选了谁）**

### 场景 C：只有参照对象，没给业务段（5%）

```
意图：「按现网 cmnet 配齐」
清单：没给具体名字

处理：
  1. 提取参照链（cmnet 的完整闭环）
  2. 业务段无法确定
  → 不生成命令
  → 输出「参照链清单 + 待填业务段」进澄清
```

**自动化程度：0%，但产出结构化的澄清项，用户填一次就够。**

### 场景 D：两者都无（58%）

```
意图：「新增规则」「调整 PLMN」
→ 不涉及参照
→ 走正常流程：exp_stats 拿族 → exp_attr_chain 拿属性族 → exp_query 查写法
```

## 四、需要补的算子（P0）

按用户纠正：**靠 name 类参数依赖推导，不靠字符骨架归纳。**

```python
def resolve_name_derivation(exp_path, family_a, family_b):
    """用「参数依赖」推导 A 族名字 → B 族名字的关系。

    做法：
      1. 找 B 族的哪个参数引用了 A 族（参数名含 A 族身份参数名 + 值域验证）
      2. 收集所有 (B.名字, 该参数值) 配对
      3. 对每对算「变换」：A名字 → B名字 需要什么操作
      4. 统计变换的众数，给覆盖率

    与旧 exp_pairs 的区别：
      旧：只有 PREFIX_REPLACE 算子
      新：补 SUFFIX_REPLACE / SEGMENT_REPLACE / BIZ_REPLACE
    """
```

**算子清单（从实测配对归纳出来的）：**

| 算子 | 例 | 覆盖率 |
|---|---|---|
| PREFIX_REPLACE | `u_p_x` → `up_group_x` | 68.8% |
| SUFFIX_REPLACE | `x_ch_p` → `x_pcc_p_g` | 需补 |
| BIZ_REPLACE | `<biz1>_ch_p` → `<biz2>_ch_p` | 需补（跨业务平移） |
| IDENTICAL | `up_x` → `up_x` | 100% |

## 五、性能影响

| 场景 | 占比 | 额外耗时 |
|---|---|---|
| A 两者都有 | 17% | +15-20s（参照链提取 + 规律推导） |
| B 只有业务段 | 20% | +20-30s（多一步自动选参照） |
| C 只有参照 | 5% | +10s（只产出澄清） |
| D 都无 | 58% | 0 |

**全量加权：0.17×18 + 0.20×25 + 0.05×10 = 8.6s/单平均**
**相对单工单 500-900s，劣化约 1-2%。**
