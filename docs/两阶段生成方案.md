# 两阶段生成方案（终版）

## 用户裁定

1. 阶段 1 只写规划表，不写别的产物
2. **纯靠 context 有风险，要落盘**（用户明确担心）
3. 先不做前端
4. 阶段 2 发现问题走澄清流程

## Handover 设计（核心）

### 原则：文件是唯一真相源，会话不复用

```
阶段 1  fresh 启动 → 产出 analysis_code/命令族规划.md
                    ↓
        （人工审核：可直接编辑这个 md 文件）
                    ↓
阶段 2  fresh 启动 → 读 analysis_code/命令族规划.md（完整，不截断）
                    → 按规划填充 params.csv / mml.txt
```

**关键：阶段 2 不用 `--resume`，走 fresh。**

理由（实测验证的风险）：
- 现有 `revise` 动作复用 agent 会话（`--resume`），依赖上下文
- 上下文可能被压缩/截断，导致规划信息丢失
- 摘要路径 `.agent/prev_summary.md` 会截断到 4000 字

### 落盘的文件清单

| 文件 | 阶段1 产出 | 阶段2 读取 | 说明 |
|---|---|---|---|
| `analysis_code/命令族规划.md` | ✅ 写 | ✅ 读（完整） | 唯一的 handover 载体 |
| `analysis_code/配置分析.md` | ❌ 不写 | ✅ 写 | 阶段2 才产出 |
| `analysis_code/params.csv` | ❌ 不写 | ✅ 写 | 阶段2 才产出 |
| `analysis_code/mml.txt` | ❌ 不写 | ✅ 写 | 阶段2 才产出 |
| `analysis_code/方案澄清.json` | ⚠️ 可写 | ✅ 写 | 阶段1 有疑问也要能提 |

## 规划表格式（含人工修改标记）

```markdown
# 命令族规划

> 本文件是阶段1的输出，人工可直接编辑。
> 阶段2 会严格按本文件的规划填充，不做增删。
> 人工修改请在行末标注 `★人工调整`。

## 总览
本次共需配置 5 类对象，预计 1294 条命令。

| # | 数据清单表 | 业务对象 | 对象数量 | 现网已有 | 选择的命令族 | 动作 | 判断依据 | 状态 |
|---|---|---|---|---|---|---|---|---|
| 1 | 地址池清单 | 地址池 | 190 | 190 | MOD POOL | 修改 | 现网同池名 190 条，只需改冗余功能 | 确认 |
| 2 | 隧道清单 | GRE 隧道 | 184 | 0 | ADD GRETUNNEL | 新增 | 现网无 Tunnel300-483 | 确认 |
| 3 | 接口地址清单 | 接口 IPv4 地址 | 184 | 0 | ADD IFIPV4ADDRESS | 新增 | 与隧道配套 | 确认 |
| 4 | 接口与VPN对应关系 | 接口绑定 VPN | 184 | 0 | ADD IPBINDVPN | 新增 | 每隧道绑一个 VPN | 确认 |
| 5 | 路由规划 | 静态路由 | 184 | 0 | ADD SRROUTE | 新增 | 每隧道一条 /32 | 确认 |

## 配套关系
| 主族 | 配套族 | 置信度 | 是否需要 | 说明 |
|---|---|---|---|---|
| ADD GRETUNNEL | ADD IFIPV4ADDRESS | high | 是 | 隧道需要接口地址 |
| ADD GRETUNNEL | ADD IPBINDVPN | high | 是 | 隧道需绑 VPN |
| ADD GRETUNNEL | ADD SRROUTE | high | 是 | 隧道需路由 |
| MOD POOL | ADD POOLGROUP | high | ★人工调整=否 | 本次只改冗余功能，池组不变 |

## 不确定项
（无）

## 待人工确认
- 是否需要同时配置 POOLBINDGROUP？（现网池组绑定关系是否需要更新）
```

### 状态列取值

| 状态 | 含义 | 阶段2 行为 |
|---|---|---|
| `确认` | 按此执行 | 必须配 |
| `★人工调整` | 人工改过 | 按改后的配 |
| `跳过` | 人工标记不需要 | 不配 |
| `待定` | 有疑问 | 阶段2 走澄清，不擅自决定 |

## 后端接口

### 改 `/run`，加 stage 参数

```python
# POST /api/v1/sessions/{sid}/run
{
  "intent": "...",
  "stage": "plan",          # 'plan' | 'fill'（默认 fill，兼容旧行为）
  "product": "UDG"
}
```

**stage='plan' 时：**

```python
# 1. action 强制为 fresh（阶段1 不复用会话）
action = 'fresh'

# 2. 产物写入白名单：只允许 命令族规划.md 和 方案澄清.json
_ALLOWED_PLAN_STAGE = {'命令族规划.md', '方案澄清.json'}

# 3. 完成后写入 meta
meta['stage'] = 'plan_done'
meta['plan_file'] = str(adir / '命令族规划.md')
```

**stage='fill' 时：**

```python
# 1. 检查 命令族规划.md 是否存在
if not (adir / '命令族规划.md').exists():
    raise HTTPException(400, '缺少命令族规划.md，请先跑阶段1')

# 2. action 强制为 fresh（不复用阶段1 的会话）
action = 'fresh'

# 3. prompt 里注入规划表全文（从文件读，不截断）
plan_text = (adir / '命令族规划.md').read_text(encoding='utf-8')
```

### 产物写入约束（mcp_io.py）

```python
_ALLOWED_PLAN_STAGE = {'命令族规划.md', '方案澄清.json'}

def tool_artifact_write(args):
    stage = os.environ.get('AGENT_STAGE', 'fill')
    if stage == 'plan' and filename not in _ALLOWED_PLAN_STAGE:
        return {'error': f'阶段1（规划）只允许写 {_ALLOWED_PLAN_STAGE}，'
                         f'不能写 {filename}。请先完成规划。'}
```

## 阶段 prompt 差异

### 阶段 1（规划）

只替换「本次任务」之后的部分：

```
【本次任务】
<intent>

【数据清单】
<说明>

【★ 本轮只做规划，不写配置】
你的唯一产物是 analysis_code/命令族规划.md，格式见下。
禁止写 mml.txt / params.csv / 配置分析.md。

规划要求：
1. 数据清单里每个表 → 判断对应哪类业务对象 → 选命令族
2. 用 exp_query 查该族在现网有多少条
3. 现网有 → MOD；现网无 → ADD；要删除 → RMV
4. 用 exp_siblings 查配套族，列出必须一起配的
5. 数据清单有多少行，对象数量就必须是多少

<规划表格式模板>

【重要】
- 拿不准的族写到「不确定项」，不要硬凑
- 判断依据要写清楚（现网多少条、为什么选这个族）
```

### 阶段 2（填充）

```
【本次任务】
<intent>

【数据清单】
<说明>

【★ 已确认的命令族规划】
<规划表全文，从文件读取，不截断>

【本轮按上述规划填充】
要求：
1. 规划里状态为「确认」或「★人工调整」的，必须配
2. 状态为「跳过」的，不配
3. 状态为「待定」的，写进方案澄清，不要擅自决定
4. 对象数量严格按规划表
5. 参数值优先从数据清单取，取不到的按现网规律补（标 @src=exp:derive）
6. 补不了的填【待填写】并写进澄清

【禁止】
- 不要在规划之外增加命令族
- 不要减少规划里的对象数量
- 如果认为规划有问题，写进方案澄清，不要自己改
```
