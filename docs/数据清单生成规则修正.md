# 数据清单生成规则修正方案

> 2026-11-12
> 来源：用户指出两个问题
>   1. 「按现网同类APN「ims」的存量做法配齐（其中 IPBINDVPN 的 IFIPADDR/SUBNETMASK 单独设置）」
>      —— 意图里不该出现参数名，人不会这么写，这么写不如直接配
>   2. 「把引号还原出来就行了，表头不能是参数名，要用通用自然语言描述（可多样）」

## 一、问题拆解

### 问题 1：意图里的「缺参数说明」是错误设计

```
❌ 错误做法（我上轮提的）：
   按现网同类APN「ims」配齐（其中 IPBINDVPN 的 IFIPADDR/SUBNETMASK 单独设置）

原因：
  · IPBINDVPN / IFIPADDR / SUBNETMASK 都是 MML 参数名 → 违反意图红线
  · 人不会这么写，这么写等于直接给命令
  · 意图的粒度应该是「业务对象 + 动作 + 参照」，不是参数清单

✅ 正确做法：
   按现网同类APN「ims」的存量做法配齐
   缺的参数由 params.csv 补（标【待填写】）
```

### 问题 2：参数级覆盖率的算法错了

```
❌ 我的算法：参照对象的参数集 ∩ GT 参数集 / GT 参数集
   把 IP 地址、掩码这类「每个对象天然不同」的参数也算进覆盖率分母
   → NC20260911001996 的 IPBINDVPN 覆盖率算成 75%（因为缺 IFIPADDR/SUBNETMASK）
   → 但实际上这两个参数本来就该由数据清单给，不可能从参照抄

✅ 正确算法：只看「可从参照抄的参数」
   见下文「二、参数三分类」
```

### 问题 3：数据清单混入了枚举和常量

```
❌ 现状（NC20260820001773）：
   ## SGSN/SGW IP与RAT类型间的映射关系（新增，2 行）
   | IP 版本 |
   |---------|
   | IPV4    |     ← 枚举值，不该列成表
   | IPV6    |

✅ 应该：枚举在意图里说（「IPv4 和 IPv6 各一套」），或干脆不提（agent 自己判断）
```

## 二、参数三分类（数据驱动）

实测 86 单 GT 的 790 个参数按「是否引号」分：

```
引号值参数:   195 个  ← 数据清单该给的
非引号参数:   596 个  ← 枚举/数字，不进数据清单
交叉:           1 个（VIRTUALAPN，GT 原文引号不一致）
```

### 引号值参数再细分（按「能否从参照抄」）

| 类型 | 判别 | 例 | 处理 |
|---|---|---|---|
| **引用名** | 值是另一族的对象名 | `VRFNAME="ChinaMobile_Gn"` | 意图说「按 X 配齐」时，参照的引用值可平移 |
| **开放数据** | 值无规律、每对象不同 | `IFIPADDR="172.23.10.1"` | **数据清单给**，不进覆盖率分母 |
| **常量字符串** | 同族内所有对象值一样 | `SUBNETMASK="255.255.255.255"` | 可从参照抄，**计入**覆盖率 |

### 覆盖率重算规则

```python
def calc_coverage(gt_params_by_obj, ref_params):
    """只统计「可从参照抄」的参数。"""
    # 1. 找出 GT 里「同族内所有对象值都一样」的参数（含常量和引用名）
    const_params = {k for k in all_keys
                    if len({o[k] for o in objs if k in o}) == 1}
    # 2. 开放数据（每对象不同）= 不进分母
    varied_params = all_keys - const_params
    # 3. 覆盖率只看 const_params
    return len(const_params & ref_params) / len(const_params)
```

**这样 NC20260911001996 的 IPBINDVPN 覆盖率会从 75% 升到 100%**（IFIPADDR 是每对象不同的，不计入）。

## 三、数据清单生成规则

### 规则 1：只还原引号值

```python
# 从 GT 的 raw 命令里判断参数是否有引号
m = re.search(rf'\b{pname}\s*=\s*("?[^",;]+"?)', raw)
if not m.group(1).startswith('"'):
    continue    # 非引号（枚举/数字）不进数据清单
```

### 规则 2：表头用自然语言，且可多样

**要求**：表头不能是参数名，要用业务描述，且允许不同写法（IP地址 / IPADDR / v4地址 都可）。

**实现**：三档映射，优先级从高到低

```python
# 第 1 档：人工精校映射（覆盖高频参数，~60 个）
PARAM_BIZ_CURATED = {
    'IFIPADDR': '接口IP地址',
    'SUBNETMASK': '掩码',
    'APN': 'APN',
    'DNN': 'DNN',
    'VRFNAME': 'VRF名称',
    'USERPROFILENAME': '用户模板名称',
    ...
}

# 第 2 档：语素规则推导（覆盖剩余参数，实测 165/195 有效）
MORPHEMES = { 'ADDR': '地址', 'NAME': '名称', 'IP': 'IP', ... }
def infer_cn_name(pname): ...

# 第 3 档：推不出时用「对象类型 + 序号」兜底（不暴露参数名）
#   例：SQN → 「标识1」「标识2」（同一族的多个未映射参数按序号）
```

### 规则 3：表头的多样性（允许同义写法）

```python
# 同一参数可以有多个等价表头，随机选一个（模拟人的写法差异）
HEADER_VARIANTS = {
    'IFIPADDR': ['接口IP地址', 'IP地址', '接口地址', 'v4地址'],
    'SUBNETMASK': ['掩码', '子网掩码', '掩码长度'],
    'USERPROFILENAME': ['用户模板名称', '模板名', '用户模板'],
    'POOLNAME': ['地址池名称', '池名', '地址池'],
}
# 用 hash(pname) 固定选择，保证同一参数在同一份清单里写法一致
```

**为什么需要多样性**：用户原话「可以做多样性描述，比如IP地址，IPADDR，v4地址等等」。
目的是让意图/清单看起来像不同人写的，避免 agent 学到「特定词 → 特定参数」的硬映射。

### 规则 4：同族不同形态要分表

```
❌ 现状：
   ## 规则（新增，4 行）
   | 优先级 | 规则名称 | 名称 |
   | 60000 | fzmqly_01_r |  |          ← 无流过滤器（空单元格）
   | 10000 | fzmqly_01_r | any_f_f |    ← 有流过滤器

✅ 应该分两张表：
   ## 规则（新增，2 行）        ← 不带流过滤器
   ## 规则（带流过滤器，新增，2 行）  ← 带流过滤器
```

**判据**：同族内按「引号参数集合」分组，集合不同的分表。

## 五、验收判据

```
1. 数据清单表头里，参数名出现次数 == 0
   （用 GT 里全部参数名做正则扫描）

2. 数据清单只含引号值
   （抽查 10 单，每个单元格的值必须能在 GT 里找到带引号的对应）

3. 覆盖率重算后，26 单建参照的参数覆盖率分布
   目标：>= 90% 的单占 80% 以上

4. 同族同形态不会再出现空单元格
   （扫描所有数据清单，空单元格数 == 0，除非该参数确实可选）

5. 意图里参数名出现次数 == 0
```

