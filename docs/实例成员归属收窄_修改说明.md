# 实例成员归属收窄（解决实例内命令过多）

## 问题

一个实例里装了过多命令，且**大量属于别的实例**。

实测（UEG case1.1，真实局点）：

```
F881「部署UPF」9 个实例，每个都装了全 exp 的 21 条 ADD FILTER
  any_f_f 自己的只有 1 条（FILTERNAME="any"）
  gdsgjtysjiot_00_f_f 自己的有 9 条（_f_001..009）
  → 另外 20 条是别人的，被塞进了每一个实例
```

根因链（逐跳原文）：

```
any_f_f ← 实例锚点
  ├─ ADD RULE:RULENAME="cbnet_any", FLOWFILTERNAME="any_f_f"      ← 本实例的
  │    └─ ADD RULEBINDING：一条命令挂了 5 个别的业务用户
  │         1753 USERPROFILE=s13058_ag_gdsgjtysjiot  RULE=gdsgjtysjiot_00_r
  │         1757 USERPROFILE=s13070_ag_gdsztwsx01iot  RULE=gdsztwsx01iot_00_r
  ├─ 顺着 RULENAME 反向展开 → ADD RULE，拿到对方的 FLOWFILTERNAME
  └─ 顺着 FLOWFILTERNAME → FLTBINDFLOWF → FILTERNAME ×9 → ADD FILTER ×9
```

`ADD RULEBINDING` 是**多对多桥**；`OBJ_THRESH=5` 按"单值×命令类型出现次数"判汇聚，
邻居 rule 只出现 1 次 ⇒ 不算汇聚 ⇒ 全部展开。

规模：

```
5529 个实例，命令行合计 189,179
均值 34 / P90 112 / P99 303 / 最大 570
>50 行的实例 1167 个（21.1%）
```

## 改动

`src/materials/scripts/match_features.py`

### 1. 实例成员归属收窄 `_narrow_instance_members()`

一条命令行属于实例 K，当且仅当：

| # | 判据 | 处理 |
|---|---|---|
| ① | 带锚点参数且值 == K | 收（直接成员） |
| ② | 带锚点参数但值 ≠ K | 不收（别的实例） |
| ③ | 不带锚点，但名字值在 K 的引用链上可达 | 收（下游对象） |
| ④ | 与本实例引用链无关 | 不收 |

### 2. Z1 分支：按实例自身证据密度决定追下游深度

```
n_direct = 带锚点==key 的行数
  n_direct >  1  ⇒ 只收直接引用（1 跳）        ← F881 这类，不会串味
  n_direct ≤  1  ⇒ 沿引用图 BFS 追下游          ← F033 这类，整条策略链都能进
```

`n_direct` **在判定之前**就能算出来，与 configured/weak 无关（合规性实测：
1 行组平均 core 9.3，2-3 行组 9.8；configured 率 3.0% vs 1.2%，不是"按结果放宽证据"）。

### 3. BFS 剪枝与爆炸保护

- **遇到别的实例 key 立即停止该分支** —— 防串味
- **OWNED_CAP = 2000** —— UDG 有 13 个超级 hub（`yksp_00_f_f` 连 4891 个邻居），
  BFS 可达 49,745 个值 ≈ 整张图，实测导致 15s → 76s。超限则整体放弃追下游、退回 1 跳

### 4. 锚点别名自动推导 `_discover_anchor_aliases()`

同一对象在 MML 里可能有多个参数名：

```
F086 锚点 VRFNAME，但 ADD AUTOSCALINGSERVICE 用 VPNNAME
F474 锚点 VPNINSTANCE，但 ADD VPNINSTAF 用 VRFNAME
```

手写映射表两次都漏 ⇒ 改成按"值域重叠"自动推导（某参数的值里有 ≥2 个是实例 key ⇒ 视为别名）。

### 5. 证据强度标注（`evidence_strength.py`，新增）

给每条命中标 `strong/medium/weak/public` 档 + 按标题折叠同族指纹。

### 判定迁移

```
UEG: 0 条        ← F033/F034 那 2 条误伤已修好
UDG: 22 条（21 configured→weak + 1 weak→not_configured）
UNC:  6 条（全部 configured→weak）
```

逐条核对（`check_38_migrations.py`）：

| 归类 | 条数 | 说明 |
|---|---|---|
| A 掉级正确 | 17 | 收窄后实例里确实凑不齐 core |
| B 公共判据导致 | 11 | core 被"公共底座"判据降级，非收窄造成 |

**B 类 11 条全部是 `__public_only__`**（UDG 单判据特性：`ADD LOGICINF` 被 36 个特性引用、
`ADD APN` 29 个，超过阈值 22）—— 这是公共判据的设计取舍，不是本次收窄的误伤。

## 已知限制

1. **公共对象判据对"整个 core 都被判公共"的单判据特性会清空判据**
   影响 UDG 11 条（F040/F041/F048/F070/F071/F073/F218/F389/F390/F392/F393）
2. **UDG 部分特性锚点选 `PROTOCOLNAME`**（http/https/dns 是应用协议标签，不是实例）
   影响最大实例仍 2,762 行；属锚点选择问题，非本次改动引入
3. **`n_direct` 分支阈值取 1** 是按三产品实测定的，不是算出来的
   （0 时 F033 修不好，≥2 时 UEG 代价从 +18% 升到 +21.7%）

## 验证

```
verify_j3_multi.py（三产品通用）:  24 PASS / 0 FAIL
  I1 锚点+实例数全一致
  I2 命令行降幅 > 50%
  I3 P99 下降
  I4 跨实例串味 = 0（两类判据）
  I5 无 not_configured→configured
  I6 manual 数量不变

负例注入（摘掉 _narrow_instance_members）:
  UDG 绿 48 → 58（相差 10 条）；命令行降幅 39% < 50% ⇒ 断言变红
```

## 开发过程中修掉的 bug（都靠实测发现，不是读代码）

| # | bug | 现象 |
|---|---|---|
| 1 | 缓存用 `if not _alias` 判空 | UDG F040 有 670 个实例，每个都重扫 10 万行 ⇒ 单特性 34s、整轮 10 分钟跑不完 |
| 2 | 索引做成双向且无剪枝 | 限几跳都绕回，整图连成一片，F881 混进别人命令 |
| 3 | 索引做成单向（按行内参数顺序） | `ADD RULE` 行第一个是 `RULENAME`，方向反了 ⇒ F033 走不到自己的下游 |
| 4 | 保留判据用 `owned_direct`（只 1 跳） | F033 的 `ADD FILTER` 在 3~4 跳外被误剔（11 条迁移受影响） |
| 5 | BFS 无 owned 上限 | UDG 13 个 hub 爆炸，15s → 76s |
| 6 | 锚点参数名硬编码 | F086（VPNNAME）、F474（VRFNAME）两处都漏 |
