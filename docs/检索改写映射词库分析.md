# 检索改写映射词库分析

## 实测数据（2026-11-09）

用户意图里的业务名词，直接检索 KB 的命中率很低：

| 业务名词 | 直接检索 | 改写后 | 结论 |
|---|---|---|---|
| 计费策略 | 3 条但偏 | `URR` / `计费` → 命中 Gy/内容计费 | ✅ 改写有效 |
| 内容识别 | 3 条全偏 | `内容计费` → 命中「配置内容计费」 | ✅ 改写有效 |
| 业务刷新 | 全偏 | `REFRESHSRV` / `刷新服务器` → 仍全偏 | ❌ 改写无效 |
| 流过滤器协议绑定关系 | 全偏 | `FLTBINDFLOWF` / `流过滤器绑定` → 仍全偏 | ❌ 改写无效 |
| 用户模板组 | 部分 | `USERPROFILE` → 命中「配置本地PCC功能」 | ✅ 改写有效 |
| P-CSCF组配置 | 全偏 | `P-CSCF组` → 命中「P-CSCF故障时IMS业务恢复」 | ✅ 改写有效 |
| 网络切片 | 全偏 | `SNSSAI` / `切片` → 仍全偏 | ❌ 改写无效 |

**7 个里 4 个改写有救，3 个改写无效。**

## 为什么改写无效

### 原因 1：KB 里没有该特性的「业务视角」文档

```
「业务刷新」→ 实际命令是 SET REFRESHSRV
但 KB 的命令文档里没有「业务刷新」这个说法
按命令名查 SET REFRESHSRV 也偏到 SET HTTPHTRCFG
→ 向量检索对短命令名的区分度不够
```

### 原因 2：多词组合语义丢失

```
「流过滤器协议绑定关系」
拆开是：流过滤器 + 协议 + 绑定关系
对应命令可能是 FLTBINDFLOWF（流过滤器绑定流）
但「协议」是 PROTBINDFLOWF
两个族混在一起，检索抓不准
```

### 原因 3：KB 文档的标题体系与工单术语不对齐

```
工单说：「内容识别」
KB 说：「配置内容计费」「激活HTTPS业务行为识别特性」
→ 术语断层
```

## 映射词库能解决什么、不能解决什么

### 能解决（约占 40%）
```
· 术语对齐：内容识别 → 内容计费
· 缩写展开：URR → 使用量上报规则
· 产品术语：用户模板组 → USERPROFILE
```

### 不能解决（约占 60%）
```
· KB 里压根没有对应文档（业务刷新、流过滤器绑定）
· 多词组合语义（流过滤器协议绑定关系）
· 全新术语（工单里自造的说法）
```

## 三种实现方式的可靠性

| 方式 | 可靠性 | 维护成本 | 是否硬编码 |
|---|---|---|---|
| **静态词库（YAML）** | 中 | 高（要人工维护） | ⚠️ 是 |
| **agent 自主改写** | 中 | 零 | ✅ 否 |
| **从 GT 反推词库** | 高（有数据支撑） | 中 | ⚠️ 是 |

### 关键红线问题

```
用户红线：硬编码的具体值（族名、局点值）不许出现在代码/skill

静态词库如果写成：
  内容识别: [内容计费, L7FILTER, URL过滤]
                ↑ 这是族名，属于硬编码

如果写成：
  内容识别: [内容计费]     ← 只写业务同义词，不含族名
                ↑ 可接受
```

## 我的建议

### 方案 A：agent 自主改写（推荐先做）
```
在 prompt 里加一句：
  「业务名词查不到时，自己换 2-3 个说法再查：
   ① 同义词（内容识别 → 内容计费）
   ② 命令名（URR / SET REFRESHSRV）
   ③ 产品术语（用户模板组 → 用户模板）」

优点：零硬编码，不维护
缺点：依赖 agent 主动性（和 exp_siblings 一样的问题）
```

### 方案 B：从 EXP 反向验证（更可靠）
```
思路：业务名词查不到时，用 EXP 里的族名反查 KB
  「计费策略」查不到
  → 看 EXP 里有哪些族（URR 826 条 / RULE 1236 条）
  → 用这些族名去查 KB

优点：用真实数据锚定，不依赖词库
缺点：需要先知道候选族（但 exp_siblings 正好能给）
```

### 方案 C：静态词库（最不推荐）
```
只要写业务同义词、不写族名，勉强可接受
但维护成本高，且覆盖有限
```

## 结论

**映射词库有帮助但有限（约 40% 场景），且存在硬编码风险。**

**更值得做的是方案 B —— 用 EXP 里已有的族名反向查 KB：**

```
业务名词「计费策略」→ 查不到
  ↓
改用另一种锚点：EXP 里现网在这个工单涉及的网元上有哪些族？
  URR 826 条 / RULE 1236 条 / PCCPOLICYGRP ...
  ↓
用族名查 KB → 拿到文档 → 知道该怎么配
```

**这条路不依赖词库，而且 EXP 是每个工单都有的。**
