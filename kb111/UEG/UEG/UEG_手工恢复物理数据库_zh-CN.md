```text
## 操作场景
物理数据库为有带磁阵物理数据库和无磁阵物理数据库两种类型。一般来说，物理数据库在以下情况下需要进行恢复：* 预割接或第一次割接发生异常* 物理数据库异常

## 必备事项
前提条件

* 查询并获取需要恢复的备份文件。
* NDF（Network Data Function）模块必须已经配置。
```

## 3 命令模板定义
<!-- @mml:block= commands -->

### 1 登录“USCDB MML命令”界面。

### 2 执行**DSP BKPLIST**命令查询现有系统已备份的文件。

### 根据备份配置的“备份数据保存方式”参数的不同取值将会采用不同的恢复策略。可登录“USCDB MML命令”界面执行**LST BACKUP**命令，查询备份配置的“备份数据保存方式”：

### 如果“备份数据保存方式”为“保存到FTP服务器”或“保存到SFTP服务器”，表示备份文件存储在远程备份服务器，在恢复时从远程备份服务器上进行恢复。

### 如果“备份数据保存方式”为“不保存到服务器”，表示备份文件存储在虚拟机硬盘，在恢复时从虚拟机硬盘上进行恢复。

### 3 * 恢复数据库时人工保证USCDB系统没有业务处理（例如开销户等）；人工保证不对物理数据库进行操作（例如修改物理数据库密码等）。如有疑问，可以联系华为维护工程师处理。

### 在执行**RST DB**命令恢复物理数据库过程中，如果NDF模块发生主备倒换，恢复任务将会丢失。此时执行**DSP PHYDB**命令查询物理数据库状态为“Running”，需要在NDF模块倒换完成后重新恢复物理数据库。

```jinja2
RST DB:
;
```

### 执行**RST DB**命令恢复物理数据库。根据备份数据大小，恢复的时间需要几分钟到几十分钟。

```jinja2
RST DB:
;
```

### 4 执行**DSP PHYDB**命令查看物理数据库的恢复状态。

### 输出报文中“资源状态”为“Restoring”时，表示数据库正在恢复。

### 输出报文中“资源状态”为“Running”时，表示数据库的恢复已经完成。
