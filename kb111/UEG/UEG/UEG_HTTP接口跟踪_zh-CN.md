```text
## 操作场景
* 系统运行出现HTTP接口故障需要HTTP接口跟踪定位排除故障。* 维护人员调试设备运行情况。* 设备出口跟踪中能够显示消息，不代表跟踪到的消息一定从本设备向外发送成功，请关注系统其他异常告警和性能统计。* 跟踪功能主要用于保障网络运营和服务、检测通信传输中的故障和错误，该功能涉及使用个人用户标识和用户通信内容。建议您只有在所适用法律法规允许的目的和范围内方可启用相应的功能。在使用用户通信内容的过程中，您应采取足够的措施以确保用户的通信内容受到严格保护。* 操作员在现场使用跟踪功能时，消息跟踪中的IMSI、IP地址等信息仍然是用户的真实信息，是未被加密的。* 此功能受软参DWORD1 BT16&BIT17控制，可能会呈现不同的消息内容。具体可以参考DWORD1 BT16&BIT17软参说明。* 创建满规格64个HTTP接口跟踪时，OMU和业务VM CPU会有6%-7%的抬升，当CPU负载超过65%后，不建议创建HTTP接口跟踪。

## 必备事项
前提条件

* 具备管理员权限的操作员已经登录OM Portal。
* 维护人员具有接口消息跟踪权限。
```

## 3 命令模板定义
<!-- @mml:block= commands -->

### 1 填写HTTP接口跟踪任务参数：在左侧跟踪导航树界面选择“UEG”->“AMF#SMF业务跟踪”->“HTTP接口跟踪”后，单击“创建跟踪任务”，进入HTTP接口跟踪任务创建的界面，依次填写“任务名称”、“跟踪时长”和“定位条件”参数，如图1所示

### **图1** HTTP接口跟踪

### 2 在对话框中进行参数配置，参数说明如表1所示。

### **表1** HTTP接口跟踪参数配置说明

### | 参数名称 | 参数说明 | 取值范围 | 默认值 |

### | --- | --- | --- | --- |

### | 任务名称 | 该次跟踪任务的名称 | - | - |

### | 定位条件 | ip地址类型 | * IPv4 * IPv6 | - |

### |  | 本端IPv4地址 | 0.0.0.0~255.255.255.255 | - |

### |  | 本端IPv6地址 | 0:0:0:0:0:0:0:0~FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF | - |

### |  | 本端端口 | 0~65535 说明：  由于http建立链路时本端端口是随机选择的，创建HTTP接口跟踪时建议不填写改项。如需填写，可通过链路状态查询命令DSP SBILINKSTATUS查询待跟踪的端口信息。 | - |

### |  | 对端IPv4地址 | 0.0.0.0~255.255.255.255 | - |

### |  | 对端IPv6地址 | 0:0:0:0:0:0:0:0~FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF | - |

### |  | 对端端口 | 0~65535 | - |

### | 跟踪时长 | 该参数用于指定该次跟踪任务的时长 | 1分钟~720小时59分钟 | 1小时 |

### 在建立HTTP接口跟踪的时候，如果本对端地址填成全F，ipv4场景下为255.255.255.255，ipv6场景下为FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF。此时，所有经过HTTP服务化接口的消息都会向该任务中上报，并且不会影响到其他跟踪任务。由于全F任务会上报所有接口消息，性能会有影响，建议在大用户量场景下不要开启全F任务。

### 3 单击“确认”，启动跟踪任务。
