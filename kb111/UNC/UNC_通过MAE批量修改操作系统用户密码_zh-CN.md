## 操作场景
本操作适用于在VNF部署后或例行操作维护过程中对VNF进行批量操作系统用户密码修改，可极大提升运维人员的工作效率。* 请在华为技术工程师指导下，在深夜话务量低的时候（例如凌晨2:00～6:00）进行操作。* 本章节执行过程中出现的“IP地址”、“用户名”和“密码”均为示例，非真实环境。* 密码修改在下次登录时生效，即下次登录时需要使用新密码，对于已经登录的用户，密码修改操作不会导致断开连接。* 进行该操作批量修改密码后请妥善保管密码。* 请在各VNF部署完成后再进行该操作。* 此章节示例为MAE V100R024C10SPC220版本操作示例，非相同版本页面或稍有差异，请注意甄别。

## 必备事项
前提条件

* 已获取节点用户的旧密码。

  用户的默认密码参见《操作系统默认帐号》。
* 已获取MAE管理员用户账号及密码。
* 已和网管对接成功。
* 已通过华为运营商技术支持网站获取本操作所需的App文件及其签名文件。
  + App文件名称格式为UNC\_*版本号*\_AppGroup-Password-Signed.zip、CSP\_*版本号*\_SouthApp-ModPassword.zip。获取方式如下：登录华为运营商技术支持网站，选择“技术支持>产品软件>云核心网>Mobile Packet Core>5G Packet Core>UNC>UNCTools”，选择对应版本，然后在“软件”列表中获取。
  + App签名文件获取方式如下：通过华为运营商技术支持网站下载App文件时，请同步单击其“自动验证签名下载”列的“cms”获取其签名文件，签名文件后缀为.p7s。
* 已通过华为运营商技术支持网站获取本操作所需的工作流文件及其签名文件。
  + 工作流文件名称格式为UNC\_*版本号\_*FlowGroup-Password-Signed.zip、CSP\_*版本号*\_WorkFlow-ModPassword.zip。获取方式如下：登录华为运营商技术支持网站，选择“技术支持>产品软件>云核心网>Mobile Packet Core>5G Packet Core>UNC>UNCTools”，选择对应版本，然后在“软件”列表中获取。
  + 工作流文件的签名文件获取方式如下：通过华为运营商技术支持网站下载工作流文件时，请同步单击其“自动验证签名下载”列的“cms”获取其签名文件，签名文件后缀为.p7s。

上述App文件及工作流文件，同一类型的文件在MAE侧只能有一份生效，即该类型的最高版本文件生效，故请从华为运营商技术支持网站获取最高版本的App及工作流文件使用。当高版本文件加载后，再加载低版本文件会失败。

### **表1** 密码表模板文件

### | 参数分类 | 参数名称 | 填写说明  | |

### | --- | --- | ---  | |

### | 站点信息 | 部件类型（unit\_type） | 保持为“site”，无需修改。  | |

### |  | 站点名称（site\_name） | 自行命名，无具体格式要求，但不能与MAE中已存在的站点名称重复。  说明：  在MAE菜单栏中选择“配置 > 核心网边缘设备管理 > 参数配置”可查看当前MAE中已存在的站点及其站点名称。  | |

### |  | 是否修改（IsModify） | 该字段用于控制所填入的站点是否修改密码，取值范围为TRUE或FALSE。TRUE表示本次操作将修改该站点的账号密码，FALSE表示本次操作将跳过该站点的所有账号密码修改。  | |

### | VNF信息 | 部件类型（unit\_type） | 保持“VNF”，无需修改。  | |

### |  | 管理VNF实例名（mng\_vnf\_name） | 在MAE菜单栏中选择“拓扑 > 主拓扑”，查看需要修改密码的VNF名称，此处填入在“主拓扑”界面中获取的VNF名称。  | |

### |  | 维护口地址（maintain\_ip） | 维护接口的IP地址，获取方法如下。  1. 执行DSP NODE命令，获取虚拟机类型为OMU的任一节点名称。 2. 执行DSP NODERES命令，NODENAME参数使用OMU虚拟机节点名称，查询“网口平面”为“Ext-OM”的IP地址。 说明：  ARM场景下，该虚拟机类型为OMU\_ARM。  | |

### |  | 维护口所在节点名（maintain\_node） | 执行DSP NODE命令，获取虚拟机类型为OMU的虚拟机名称。  说明：  * ARM场景下，该虚拟机类型为OMU\_ARM。  | |

### |  | VNF实例名（unit\_name） | 在MAE菜单栏中选择“拓扑 > 主拓扑”，获取需要修改密码的VNF名称。  | |

### |  | 节点名（node\_name） | 虚拟机名称，可通过执行DSP NODE命令查询“虚拟机名称”列获取。  说明：  * 选择需要修改的节点虚拟机名称填入，一行仅支持填入一个虚拟机名称，如需增加，可手动增加行来增加批量修改账号密码的数量。 * 节点名（node\_name）可以填\*进行通配，表示全部虚拟机。其他匹配规则均不支持，例如不支持通过正则匹配实现部分虚拟机通配。 * 当模板文件中存在通配符行和具体的虚拟机名称行时，修改结果以下边的行为准。通用情况下，通配符行在上，具体虚拟机名称行在下。  | |

### |  | 账号类型（node\_account\_type） | 取值范围为“VM”、“VM\_GRUB”，“VM”表示修改操作系统普通用户密码，“VM\_GRUB”表示修改操作系统grub账户密码。  | |

### |  | 账号（node\_account） | 账号类型为“VM”时，支持填写“mtuser”、“sftpuser”、“root”；账号类型为“VM\_GRUB”时，仅支持填写“root”账号。  说明：  * 每次修改密码时，均需要提供维护口所在节点的mtuser用户密码。 * 修改操作系统普通用户root密码时，需要提供本节点的mtuser用户密码和维护口所在节点的root用户密码。 * 修改操作系统普通用户sftpuser密码时，需要提供本节点的mtuser和root用户密码以及维护口所在节点的root用户密码。 * 修改操作系统grub用户root密码时，需要提供本节点的mtuser和root用户密码以及维护口所在节点的root用户密码。  | |

### |  | 旧密码（current\_password） | 已在前提条件中获取。  说明：  由于当前系统机制，修改操作系统普通用户sftpuser密码和操作系统grub用户root密码无法通过旧密码登录修改，所以这两个用户修改密码的方式为通过管理员root直接设置这两个用户的新密码，故修改这两个用户密码时不会校验其旧密码的正确性。  | |

### |  | 新密码（new\_password） | 请填写新密码，新密码需满足如下要求。  * 密码区分大小写。 * 新密码长度大于等于14位且小于等于511位。 * 新密码须包含大写字母，小写字母、数字和符号四类字符，符号字符范围为~!@#%^&\*()-\_+|[{}].? * 新密码不能和操作系统用户名或者操作系统用户名的倒写一样。 * 新密码不能与历史5次旧密码相同。 * 新密码不能包含弱口令字典字符。 说明：  新老密码如果填写相同，表示这个用户的密码不修改。 |

#### 15.1 在“App解决方案版本”栏中输入本次批量修改密码的App解决方案版本。

#### App解决方案版本的格式为“CSP的App名称=CSP的解决方案版本,UCBC的App名称=UCBC的解决方案版本”，例如：

#### modpassword\_service=*XX.XX.XX*,UNC\_Pwd\_App=*XX.XX.XX*

#### CSP的App名称、CSP的解决方案版本、UCBC的App名称和UCBC的解决方案版本的获取方法：

#### 在MAE菜单栏选择“系统 > 应用管理”，进入应用管理界面，选择“应用部署 > 应用 > App管理”，在“App管理”界面确认步骤 3中已导入的UNC\_*版本号*\_AppGroup-Password-Signed.zip、CSP\_*版本号*\_SouthApp-ModPassword.zip文件信息，获取已导入文件对应的“App名称”和“解决方案版本”信息。

#### 15.2 在“流程解决方案版本”栏中输入本次批量修改密码的流程解决方案版本。

#### 流程解决方案版本的格式为“CSP的流程名称=CSP的解决方案版本,CSP的流程名称=CSP的解决方案版本,UCBC的流程名称=UCBC的解决方案版本”，例如：

#### modpassword\_createmodifypwdtask=*XX.XX.XX*,modpassword\_submodifypwdtask=*XX.XX.XX*,unc\_pwd\_subprocess=*XX.XX.XX*

#### CSP的流程名称、CSP的解决方案版本、UCBC的流程名称和UCBC的解决方案版本的获取方法：

#### 在MAE菜单栏选择“系统 > 应用管理”，进入应用管理界面，选择“应用部署 > 流程 > 流程管理”，在“流程管理”界面确认步骤 6中已导入的UNC\_*版本号\_*FlowGroup-Password-Signed.zip、CSP\_*版本号*\_WorkFlow-ModPassword.zip文件信息，获取已导入文件对应的“名称”和“解决方案版本”。
